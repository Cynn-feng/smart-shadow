# Smart Shadow 项目决策记录

更新时间：2026-09-21

本文件是当前项目的决策事实源。新方案若与本文件冲突，先新增决策记录，再改技术方案和代码。

## D-001：比赛结束后转入持续开发

- 日期：2026-09-20
- 状态：已确认
- 决策：保留比赛版代码作为历史基线，后续工作围绕可信性、可复现性、可审计性和可评测性推进。
- 原因：比赛演示目标已经完成，继续堆叠展示功能不能解决当前系统的核心工程风险。

## D-002：产品边界改为“存证与风险筛查”

- 日期：2026-09-20
- 状态：已确认
- 决策：产品对外定位为数字作品来源与版本存证、视觉相似检索和侵权风险筛查；结果需要人工核验，不自动进行法律确权、侵权裁决或 AIGC 最终鉴定。
- 原因：当前链上记录没有绑定真实用户身份，模型和阈值也没有经过完整评测。

## D-003：把六区域 CLIP 作为第一算法基线

- 日期：2026-09-20
- 状态：已确认
- 决策：保留当前六区域 CLIP 方案作为可复现实验基线，同时增加全图、单区域和其他多尺度切片对照；是否升级模型由评测结果决定。
- 原因：当前最有价值的实现是局部语义指纹组合，而不是未经验证的“精准抗裁剪”结论。

## D-004：精确匹配和语义匹配分开报告

- 日期：2026-09-20
- 状态：已确认
- 决策：原始 CID 命中、语义检索分数和风险等级必须分别保存和展示；不得用人为加分覆盖模型原始分数。
- 原因：字节级相同和视觉相似是不同证据，混成一个百分比会破坏可解释性。

## D-005：ChainMaker 是证据锚点，MySQL 是投影，Faiss 是派生索引

- 日期：2026-09-20
- 状态：已确认
- 决策：链上记录作为不可变证据源，MySQL 保存业务投影，Faiss 保存可重建的检索索引，IPFS 保存原始文件。所有层都要有状态和恢复关系。
- 原因：当前各层写入没有事务协调，必须先明确各自的权威性和可重建性。

## D-006：第一开发切片先消除“假成功”

- 日期：2026-09-20
- 状态：已确认

- 原因：如果错误被当作成功，后续数据和评测都不可信。

## D-009：AIGC 采用来源感知的开放集证据融合

- 日期：2026-09-20
- 状态：已确认方向，效果和学术新颖性待评测
- 决策：AIGC 输出采用 `human_supported`、`ai_generated_supported`、`ai_edited_supported`、`unknown_or_inconclusive` 四态；并行保存 C2PA/国标标识/水印、区域语义、低层伪影、可选重建和生成器归因的原始证据。未知生成器、证据冲突、模型不可用或置信度不足必须拒判。
- 原因：相关研究显示未知生成器和真实传播扰动会显著降低单一检测器的泛化。C2PA 能验证来源绑定和编辑历史，但不判断内容真伪；被动检测也不能替代来源证明。
- 边界：在固定数据、跨生成器和扰动评测完成前，不称为“解决 AIGC”、不宣称通用准确率或法律结论。

## D-010：算法创新以版权检索和 AIGC 取证双头为主线

- 日期：2026-09-20
- 状态：研究主线已确认，具体模型待评测
- 决策：保留六区域 CLIP 作为版权检索基线；新增独立的 artifact/重建/开放集取证头，检索分数和 AIGC 分数分开校准。优先研究“已登记原件条件下的局部 AI 编辑取证”，没有匹配原件时回退到单图检测。
- 原因：项目已有原件 CID 和区域特征，源图对照可以把整图真假问题转为局部差异证据，更贴近版权场景并可输出 ROI。
- 边界：只有消融证明在局部编辑、未知生成器和传播扰动上有改进，才能在论文或 README 中称为创新。

## D-011：商业化首个切入点是证据工作台和私有化 API

- 日期：2026-09-20；2026-09-21 更新
- 状态：阶段性市场假设
- 决策：优先服务有自有图库的电商、品牌、图片库、MCN、设计机构，以及需要合规审计的内容平台；交付批量登记、标识核验、相似检索、人工复核和证据包。第二阶段再扩展到律所/版权代理和经授权的来源监测。
- 原因：通用图片搜索和版权监测已有大厂服务，项目需要避开全网规模竞争，以私有化、中文标识、国产链和可审计证据形成差异。
- 边界：价格、留存、客户规模和市场份额都未验证；访谈和试点前不写成市场事实。

## D-012：来源过程证据纳入后续数据模型

- 日期：2026-09-20
- 状态：待阶段 3 评审后实现
- 决策：后续 EvidenceV1 和作品版本链预留 `manifest_digest`、签名者/提供者、生成/编辑动作、提示词版本、参数、人工筛选和局部编辑记录；原始文件、模型分数、人工结论和审计操作链下保存并可核验。
- 原因：AIGC 作品的版权判断取决于自然人的提示词设计、参数调整、筛选和修改过程，单独记录“AI/人类”不能表达创作贡献。

## D-013：AIGC 研究主线改为来源条件的局部编辑取证

- 日期：2026-09-20
- 状态：研究假设已确认，效果和学术新颖性待验证
- 决策：把“已登记原件 → 局部配准 → residual/artifact → ROI → 拒判”的 `Source-Conditioned Regional Edit Forensics` 作为 Smart Shadow 的首要算法创新候选；单图 AIGC 检测只作无原件时的回退基线。
- 原因：AIDE、Community Forensics、AI-GenBench、SAFE 和 DiffSeg30k 共同表明，单图闭集检测在未见生成器、传播退化和局部编辑上不稳定；Smart Shadow 已有登记原件和区域检索，可把问题约束为有向的 query→reference 差异取证。
- 边界：`source-residual-v1` 目前只是无重量依赖的 raw feature 原语，必须经过同源普通变换 hard negative、真实/合成局部编辑、跨生成器和时间切分校准后才能升级为模型结论。

## D-014：合规标签与取证状态分层

- 日期：2026-09-20
- 状态：已确认
- 决策：取证 API 保留四态 `human_supported`、`ai_generated_supported`、`ai_edited_supported`、`unknown_or_inconclusive`；面向传播/合规的适配器另输出 `verified_ai`、`user_declared_ai`、`suspected_ai`、`no_signal_or_unknown`。`no_signal_or_unknown` 永远不能映射为“人类创作”。
- 原因：中国《人工智能生成合成内容标识办法》、GB 45438-2025、C2PA 和 EU AI Act 处理的是来源/标识/传播事实，不是单一视觉分类概率。
- 边界：合规适配器不构成法律意见；C2PA、水印和视觉模型发生冲突时保留原始证据，进入人工复核。

## D-015：研究评测采用时间、开放集和真实传播三重门

- 日期：2026-09-20
- 状态：已确认
- 决策：任何算法创新必须同时报告已知/未见生成器、时间序列 next-period、局部编辑 ROI、截图/再编码/再拍摄和证据冲突矩阵，并报告 calibration、coverage-risk、unknown rate、ROI IoU、P95 延迟和成本。
- 原因：随机 IID 测试无法反映生成器迭代和真实平台传播；论文和公开 benchmark 已反复显示跨域性能下降。
- 边界：在 A0–A8 对照和外部授权数据通过前，README、论文和商业材料只称“研究假设/工程原型”，不称为通用 AIGC 解决方案。

## D-016：source-residual 先做区域定位和保守校准

- 日期：2026-09-20
- 状态：工程原语已完成；真实图片效果待验证
- 决策：保留 `source-residual-v1` 作为已登记原件条件下的 raw edit evidence，增加 `source-residual-roi-v1` 输出候选 bbox/mask，并用独立验证流生成经验 FPR 受控的 operating point；这些结果必须与 AIGC 四态、来源证据和人工复核分开保存。
- 原因：当前合成回归显示 raw score 有排序能力（AUROC 0.9259、AP 0.9079），但默认阈值 0.5 的正例召回为 0；如果不记录 ROI、校准集和拒判边界，任何固定百分比都可能造成假成功。
- 边界：上述数字只来自 30 个纯标准库合成样本，不能外推到真实 AIGC、跨生成器、社交传播或法律结论。真实授权图片、时间/生成器切分、独立校准和 A0–A8 消融通过前，不接入线上 `ai_server.py` 或 Go 网关。

## D-017：负例 conformal 只用于开放集拒判观察

- 日期：2026-09-20
- 状态：工程原语已完成；真实覆盖率待验证
- 决策：对高分表示“更像 AI”的检测器，允许在独立负例校准流上计算带有限样本修正的单侧 conformal p-value；当 p-value 不超过 `alpha` 时输出 `unknown`/需复核观察，并保留 detector、score schema、calibration ID 和负例流 digest。p-value 未拒绝负例只能表示“与该负例流一致”，不能生成 `human_supported`；拒绝负例也不能单独生成 `ai_generated_supported`。
- 原因：固定阈值和闭集 softmax 无法表达未知生成器、传播退化和校准样本有限性；先把拒判证据做成可审计的独立层，可以降低误把未知样本归入人类或已知生成器的风险。
- 边界：当前实现是负例分布上的工程校准原语，不是概率校准器、通用 conformal guarantee 或线上 AIGC 判断；必须在时间/生成器隔离、真实传播和独立审计集上报告 coverage-risk 后，才能进入融合策略。

## D-018：质量感知传播融合只保存为原始证据

- 日期：2026-09-20
- 状态：工程原语已完成；真实传播检索和模型效果待验证
- 决策：同一登记资产的近重复传播版本可以按质量分数做幂次加权，输出 `weighted_score_raw`、接受/拒绝版本、传播链、质量统计和分数离散度；该聚合只作为 detector evidence，不直接生成 AIGC 四态、版权风险等级或法律结论。
- 原因：截图、再编码、缩放和低质量版本会改变视觉模型分数。把所有版本简单平均会让低质量异常值主导结果，而直接取最高分又会放大偶然误报；先保留质量门和完整版本审计，便于后续在真实传播矩阵上比较单图、均值、质量加权和其他稳健聚合。
- 边界：当前 `aigc/near_duplicate.py` 与 `eval/near_duplicate_eval.py` 只验证标准库合成输入上的确定性、身份/schema 边界和审计行为；没有真实近重复检索器、质量估计器、跨平台传播数据或线上 detector 接入。`weighted_score_raw` 不是校准概率，低质量版本被排除也不表示其内容安全或非 AI。

## D-019：加入配对传播稳定性与反事实拒判

- 日期：2026-09-20
- 状态：工程原语已完成；真实图片与校准效果待验证
- 决策：在 source-conditioned raw score 之外，要求同一登记资产的 observed 传播版本尽可能与同传播族、无局部编辑的 `counterfactual` 版本配对。对 accepted observed 版本按 `quality_score ** quality_power × source_match_score` 加权，扣除 counterfactual 加权 p95，并根据观察分数离散度和两两差异计算稳定性因子；传播族覆盖不足、分数漂移或反事实高分时主动输出 `abstained`，不得把剩余分数直接转为 AIGC 概率。
- 原因：仅对传播版本做质量加权仍可能把某一类压缩/截图伪影误当成编辑证据。相同传播操作下的无编辑反事实可以估计该操作本身的 detector 激活，稳定性门则防止单次高分驱动结论；这把“传播鲁棒性”转成可审计的成对实验，而不是一句泛化承诺。
- 边界：当前 `aigc/propagation_stability.py` 与合成 runner 只验证标量 fixture 的确定性、配对缺口和拒判理由；反事实必须由真实 source/query 变换生成，不能在标签文件中凭空造出。该原语没有接入 `ai_server.py`、没有真实 coverage-risk/成本结果，也不解决无原件的单图 AIGC 检测。

## D-020：以 PC-SCFT 作为区域反事实研究主线

- 日期：2026-09-20
- 状态：研究假设已确认；raw 原语和离线配准已实现，真实效果待验证
- 决策：将 **Paired Counterfactual Source-Conditioned Forensic Test（PC-SCFT）** 作为 `source-conditioned` 局部取证的区域反事实研究主线。对同一登记原件、同传播族的 observed 与无编辑 counterfactual 做区域级配对，计算质量加权的 raw delta、覆盖率、稳定性和拒判原因；输出只属于原始证据层，不直接生成 AIGC 概率、四态结论或法律意见。
- 原因：传播压缩、截图和缩放会在局部产生伪影；同传播族无编辑反事实可以估计这些伪影的基线激活，减少把传播变换误认成局部 AI 编辑的风险。该路线也能把已有原件、ROI 和传播稳定性原语连接起来。
- 边界：区域配对、对齐和质量门必须先在合成 fixture 与授权图片上验收；没有可靠原件、传播族覆盖不足、分数漂移、反事实高分或输入质量不足时必须拒判。PC-SCFT 不是已证实的学术创新，必须通过 A0–A8 消融、开放集、时间切分和真实传播评测后才能对外命名。

## D-021：真实图片 adapter 的依赖、格式与失败边界

- 日期：2026-09-20
- 状态：工程切片已完成；真实图片与部署效果待验证
- 决策：真实图片第一阶段只采用锁定版本的 Pillow 12.3.0 与 NumPy 2.5.3；支持 JPEG、PNG、WebP、非动画 TIFF 和 BMP。adapter 必须限制字节/像素、验证后重新解码、识别真实格式、记录 EXIF orientation、显式处理 alpha、输出 raw/normalized digest 和质量分项；动画/多页、超像素、异常长宽比、截断、解码失败和质量不足使用固定失败原因拒绝。
- 原因：在接入重量模型或线上服务前，先固定输入边界、解码器和质量审计，避免不同文件格式、截断内容或隐式颜色处理污染取证实验。
- 边界：`quality_score` 只表示“是否适合取证”，不是 AIGC 概率；adapter 当前仅由 9 个合成 fixture 回归，digest=`1a180411885260fb89ebe7656296e8e5e6406ae48eed49334bed22c972a09e99`，不代表真实图片效果、C2PA 签名验证或生产安全。OpenCV、AVIF、JPEG 2000、PSD、PDF、RAW 和动画格式后置。

## D-022：首个商业包聚焦来源合规与私有图库证据

- 日期：2026-09-20
- 状态：商业化假设已确认；客户、收入和付费意愿待验证
- 决策：首个商业包由“来源/标识合规网关 + 私有图库来源与版本证据工作台”组成，提供 C2PA/GB 标识解析、冲突审计、原件登记、传播版本归并、相似检索、局部取证候选、人工复核和证据包。基础图搜对标腾讯云/阿里云等成熟替代，不作为 Smart Shadow 的独立壁垒；训练数据许可审计和深度伪造证据列为后续 P1/P2 独立方向。
- 原因：公开价格和产品资料显示容量/QPS 图搜已有成熟商品；最高法人工智能纠纷意见强调训练来源、参与过程、必要措施和获利等综合证据，单一 AIGC 分数不能满足复核需求。来源、版本、冲突和人工意见的可回放证据更贴合当前仓库的数据模型和可信边界。
- 边界：市场规模、客户数量、报价和收入均未验证；首批试点只使用客户授权图库，不做全网监测、自动下架、自动发函或法律裁决。任何正式报价前必须通过权限、备份、真实图片效果和证据包可用性验收。

## D-023：区域配准先作为离线 raw-evidence 工程切片

- 日期：2026-09-20
- 状态：工程切片已完成；真实图片、真实模型与线上接入待验证
- 决策：`aigc/regional_alignment.py` 负责把 adapter 输出的归一化灰度网格转换为可审计的 PC-SCFT 输入：固定版本 resize、有界平移搜索、重叠/匹配质量门、确定性区域窗口，以及 observed/counterfactual 的坐标帧一致性检查。输出只进入 `RegionalObservation` 原始证据层，不生成 AIGC 概率、四态结论或法律结论。
- 原因：如果区域配准、传播变换和局部编辑在不同坐标帧中比较，二阶差异会把几何错位误当作编辑证据；先固定算法版本和拒判原因，便于后续在授权图片上做可重复消融。
- 边界：当前 6 个单测和一个 3-case 合成 runner 只覆盖 NumPy 网格；真实图片 adapter、传播族生成、CLIP/SRM/DCT 模型、校准 coverage-risk、Go/AI 服务接入仍未完成。`match_score`、`cost_raw` 和区域 delta 都是 raw support，不是概率。

## D-024：PC-SCFT delta 采用分层保守 conformal 校准

- 日期：2026-09-20
- 状态：工程原语和合成回归已完成；真实覆盖率和误报效果待验证
- 决策：对同传播族普通变换产生的区域 delta，按 `transform_family × quality_bucket` 建立冻结 null profile；每个校准组使用 `max(0, max(region_delta))` 作为统计量，查询使用 ties-inclusive 的有限样本 p-value。精确分层不足时只能按配置记录 family/global fallback；没有兼容 null 样本时返回 `evaluated=false`，不能把缺校准误写成 unknown 或人类创作。

## D-037：联合普通传播 null 作为多流校准研究分支

- 日期：2026-09-20
- 状态：工程切片和标量合成回归已完成；真实流间依赖、授权传播链和策略级 FPR 待验证
- 决策：新增 `aigc/joint_null_calibration.py`，对同一普通传播 group 的多流 p-value 向量做 Cauchy 组合，再在 group-matched ordinary-propagation null 上建立联合经验 profile。查询先计算 `combined_p_raw` 和 `evidence_raw=1-combined_p_raw`，再用 ties-inclusive 上尾 conformal p-value 得到 `calibrated_p_value`。所有流均存在、联合 profile 支持足够、p-value 分歧不超过门且联合 null 被拒绝时才进入 `candidate_edit`；联合 null 一致时进入 `null_consistent`；流间分歧、部分支持或边界情况进入 `conflict_review`；缺 profile、缺流、stream set 不一致或样本不足进入 `insufficient`。
- 原因：Bonferroni 交集能控制保守风险，但会丢掉多个中等且一致的流证据。联合 profile 直接在普通传播 group 上学习流间依赖，避免把独立性假设和分数平均混在一起；QuAD、AIGIBench 和多流泛化论文也说明传播质量、流相关性和域漂移必须在真实矩阵中单独校准。
- 边界：Cauchy 组合和联合 profile 不是本项目独立学术创新，也不是 AIGC 概率；它必须与现有 Bonferroni 交集、单流和无 counterfactual 消融比较。当前只使用人工构造 p-value 的 scalar fixture，未验证真实流间相关性、时间/生成器隔离、质量条件、普通传播 hard negative 或真实 FPR/coverage-risk；不接 `ai_server.py`、Go 网关或 `aigc_result_v1` 四态。

## D-054：增加 blind reference specificity gate，控制错误原件选择

- 日期：2026-09-20
- 状态：已确认研究切片；真实参考库、开放集和效果待验证
- 决策：在 PC-SCFT/MPCF 的 query/reference/null 证据之后，增加一个独立的 `reference_specificity_v1` raw-evidence gate。它要求候选登记原件的 observed-minus-null contrast 与同 query、同 canonical frame、同 operator/schema、同质量和来源匹配桶的多个盲选 decoy references 对照；只有候选 contrast 超过冻结 decoy 上分位和最小 gap，且 decoy 选择集与 query 评估分区隔离时，才进入 `reference_specific_candidate`。目标是控制“错误相似原件被选中后，差异被误读为局部 AI 编辑”的误报。
- 路由：`reference_specific_candidate`、`reference_ambiguous`、`reference_null_consistent`、`insufficient`。任何 decoy 身份重复、候选/decoy 绑定不一致、选择分区未隔离、质量/来源桶不匹配或支持数不足固定拒判。
- 原因：现有 matched placebo 控制区域/传播反事实，但不能单独证明“当前登记原件比其他相似原件更特异”；开放集归因和参考检索也不能替代来源事实。盲 decoy gate 能把 reference selection 的 winner's curse 和错误原件风险显式纳入证据链。

- 实施约束：`decoy_exceedance_p_value_raw` 使用 `(1 + exceedances) / (n + 1)` 的 ties-inclusive 有限样本公式；3 个 decoy 的最小 p 值为 0.25，不能被写成 0.05 显著性。`specificity_gap_raw` 因候选/decoy contrast 各在 `[-2,2]` 而允许 `[-4,4]`。

## D-062：增加 source-conditioned propagation-tree null（SCPTN-v1）

- 日期：2026-09-21
- 状态：已批准离线研究契约；真实传播树、效果和学术增量尚未验证
- 决策：在 D-054 的 blind reference、D-058 的 view/operator stability、D-060 的 selection-aware calibration 和 D-061 的限预算采证之后，增加独立的 `source-conditioned-propagation-tree-null-v1`。它把同一登记资产的普通传播版本组织成一棵可回放树，以树为统计单位，在相同传播族、质量桶、时间桶和选择策略下，对树内版本选择后的最大 paired local delta 建立 ordinary-propagation null profile。
- 目标：处理普通传播版本之间的相关性和“从同一树中挑出最大局部差异”的选择偏差，避免把同一资产的多次传播重复计数；同时保留 source/query/counterfactual 的绑定和局部编辑候选的选择性拒判。
- 固定路由：`tree_specific_candidate`、`tree_selection_ambiguous`、`tree_null_consistent`、`insufficient`。所有 delta、树形 digest、profile p-value、support 和选择策略只属于 raw evidence；不输出 AIGC probability、作者、版权或法律字段。
- 失败门：父节点缺失、环、重复版本、多个根、跨资产/分层/schema/detector 混用、树节点未授权、普通传播 null 支持不足、selection/calibration/evaluation group 泄漏或 profile digest 不一致，均固定 `insufficient`；普通传播查询树固定 `tree_null_consistent`，不得升级为“人类创作”。
- 原因与 prior-art 边界：QuAD/ReWIND、IAPL 和 BCEA 已分别覆盖近重复质量聚合、选择最高置信视图和预算采证；SCPTN 的可证伪差异只在登记原件条件下的传播树相关性、树内 paired-delta 最大值校准和 fail-closed 回放组合。它不是新的 detector、树模型或通用传播鲁棒性结论。
- 真实评测门：冻结 G0–G6 授权 manifest 后比较 query-only、D-054、SAEC、D-061、SCPTN、去树相关性、逐版本独立 null 和完整组合；覆盖局部编辑、普通传播、错误 reference、未见生成器、下一时间窗、截图/再编码/再拍摄和低质量版本，报告 ordinary-propagation FPR、reference false-match、risk@coverage、ROI/边界 F、unknown/review、tree route flip、P50/P95、每千张成本和人工复核分钟。只改善 IID 或增加拒判时撤回为 propagation-audit sidecar。
- 边界与回滚：首轮只实现 `aigc/`、`eval/`、`tests/` 的无重量 schema、树校验、null profile、synthetic runner；不接 `aigc_result_v1`、`ai_server.py`、Go 网关、比赛页面或客户数据。回滚为删除 SCPTN 模块、测试、runner、公共导出、验证脚本接入、任务单和本节，不修改 D-054/D-058/SAEC/SAEA 或比赛版服务。

## D-063：登记检索污染感知的传播树选择校准（RSCPTN-v1）

- 日期：2026-09-21
- 状态：最小无重量离线契约已实现并通过统一轻量回归；未接线上，真实数据、商业价值和学术增量尚未验证
- 决策：在 D-062 SCPTN 的树级 ordinary-propagation null 之上，登记独立研究切片 `RSCPTN-v1`（Retrieval- and Selection-Calibrated Source-Conditioned Propagation-Tree Null）。它把 `near-duplicate retrieval → membership/tree assignment → reference/version selection → local evidence` 作为同一个可回放选择事件，在独立 ordinary-propagation placebo 上同时重放两路 raw null：`p_tree_raw` 承接 SCPTN，`p_retrieval_raw` 校准检索候选集合、候选数、排序、membership gate、decoy 和动作预算造成的端到端选择偏差。

- 固定路由：`retrieval_tree_candidate`、`retrieval_tree_null_consistent`、`review`（内部别名 `retrieval_contaminated_review`）、`open_set_unknown`、`insufficient`、`not_evaluated`。`uncertain`/`outside` 候选只能触发污染审计或拒判，不能作为软权重继续进入检验；缺 independent null、外部 split 或真实数据时固定 `not_evaluated`，禁止输出 AIGC probability、作者、版权或法律字段。
- 原因与 prior-art 边界：QuAD/AncesTree 覆盖近重复质量聚合，JOMI/CAP/PEMI 覆盖一般选择后校准，RADAR/OpenSDI/DICE 覆盖局部/开放集 detector；目前未发现将登记原件、传播树相关性、检索漏召回/误召回/植入和选择校准组合为同一可回放协议的先例。该“未发现完整组合”不是专利新颖性证明，RSCPTN 也不是新的 detector、树数据结构或 conformal 理论。
- 真实评测门：同一授权 manifest、检索器、候选预算和评测 split 上比较 query-only、QuAD-like、SCPTN、D-054、SAEC、SAEA 和 RSCPTN；加入 clean/missing/false-positive/poisoning retrieval stress、局部编辑、普通传播、错误 reference、未知生成器、下一时间窗，报告 ordinary-propagation FPR、reference false-match、risk@coverage、unknown recall、route flip、ROI/边界 F、P50/P95、存储和人工复核分钟。若收益只来自更多拒判、profile null candidate rate 超过预注册水平或检索污染无法复放，撤回为 retrieval/provenance audit sidecar。
- 当前离线切片：已新增 `aigc/retrieval_aware_tree_null.py`、`tests/test_retrieval_aware_tree_null.py` 和 `eval/retrieval_aware_tree_null_eval.py`，并接入 `aigc/__init__.py` 与轻量验证脚本；只验证双 null、检索/树绑定、污染拒判、开放集路由和字段卫生，不代表真实检索或模型效果。
- 实施边界：本切片不改 D-050–D-062 结果对象，不接 `aigc_result_v1`、`ai_server.py`、Go 网关、比赛页面或客户数据。回滚为删除 RSCPTN 模块、测试、runner、公共导出、验证脚本接入、任务单和本节，不触碰 SCPTN、线上服务或 `aigc_result_v1`。
