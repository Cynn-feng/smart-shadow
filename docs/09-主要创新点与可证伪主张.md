# Smart Shadow 主要创新点与可证伪主张

更新时间：2026-09-21

本文件是后续 Agent 判断“什么可以称为创新”的短入口。它不是效果报告，也不替代
[项目决策记录](01-项目决策记录.md)、[技术方案](03-技术方案.md)、[实施方案](04-实施方案.md)
和[算法调研](06-AIGC算法创新调研.md)。任何“已验证创新”的表述都必须同时满足本文件的真实数据门。

## 1. 一句话结论

Smart Shadow 当前最值得继续验证的创新是一个**来源条件的局部编辑取证协议**：在同一登记原件、同一 canonical frame、同一传播族 ordinary-propagation null 和同一干预算子下，对 observed query 与 matched null 的区域干预效应做成对比较，并在证据不足、冲突或跨算子不稳定时拒判。

它解决的研究问题是：局部视觉异常究竟来自局部 AI 编辑，还是来自裁剪、压缩、截图、边界、质量变化或某个 mask 算子的伪影。它不自动证明 AIGC、作者身份、版权归属或侵权责任。

## 3. D-050 的核心量

对区域或 mask `M`，定义：

```text
E_obs  = score(observed) - score(maskout(observed, M))
E_null = score(null)     - score(maskout(null, M))
contrast = E_obs - E_null
```

只有在以下条件同时满足时，`contrast` 才能进入 `grounded_consistent` 候选路由：

- observed 与 null 共享 asset/pair/frame/detector/schema、质量桶和来源匹配上下文；
- 两者使用同一 `proposal_mask_digest` 和 `intervention_operator_digest`；
- observed/null 的 mask-out 和 region-swap 都实际执行并可回放；
- ordinary-propagation null 本身通过支持数、稳定性和质量门；
- matched contrast 和 region-swap contrast 通过固定 raw gate；
- null effect、null region-swap effect 和跨算子 spread 没有超过固定上限。

当前实现只输出 raw evidence route，不输出 AIGC probability、作者/来源结论或法律结论。`null_consistent` 也不等于“人类创作”。

## 4. 与已有工作的边界

论文和公开系统已经分别覆盖局部编辑定位、原图/编辑图差异、grounded explanation、近重复质量校准、开放集检测、生成器归因、多视角和顺序取证。因此下面内容只能作为对照或工程组成：

- 普通 mask-out/deletion/insertion/AOPC faithfulness；
- ROI 或热力图定位；
- CLIP/频域/残差的单流或简单多流融合；
- 普通传播变换、近重复聚合、p-value/conformal、C2PA/水印解析；
- 自然语言解释、artifact taxonomy、生成器分类和全图 AIGC detector。

项目主张只能落在这些组成被**同一登记资产、同一传播族 null、同一坐标帧、同一干预算子和 fail-closed 回放**组织后，是否降低普通传播误报并减少人工复核成本。若去掉 null/control 后收益仍然存在，必须撤回“source-conditioned”创新主张。

## 5. 可证伪实验和真实数据门

真实授权 manifest 至少要包含 reference/query/counterfactual、人工或生成器 edit mask、传播链、质量、生成器家族、时间切分、C2PA/水印状态、权限与删除信息。固定比较：

1. query-only 或历史比赛版基线；
2. reference/query residual；
3. 去掉 ordinary-propagation null 的配对差分；
4. 普通 null + matched intervention；
5. 完整 sidecar（区域、质量、placebo、region-swap、多 operator）。

每个版本按普通传播 hard negative、已知/未见生成器、局部编辑、参考误配、截图/再编码/再拍摄和时间下一窗分层报告：ordinary-propagation FPR、risk@coverage、unknown/review 率、ROI IoU/Dice/boundary-F、mask-out/region-swap faithfulness、route flip、P50/P95、每千张成本和人工复核分钟。

只有完整协议相对去掉 null/control 的消融同时改善选择性风险、局部定位或人工复核效率，并在时间/生成器外部切分保持，才可在论文或产品材料中写“已验证创新”。否则统一写成“可回放研究协议”或“工程切片”。

## 6. 下一步建议

1. 用真实授权 manifest、独立 ordinary-propagation null 和编辑 mask 回放 D-051；没有这些输入时保持 `insufficient`。
2. 比较 single operator、multi-operator 和无 intervention sidecar，加入随机/decoy/semantic-boundary controls。
3. 在跨生成器、时间下一窗和传播扰动上报告 FPR、ROI/faithfulness、risk@coverage、P95、成本和人工复核分钟。
4. 完成 A0–A8 消融和 G0–G6 真实数据门后，再决定是否把 D-050/D-051 写入论文或产品叙事。

5. D-054 已完成 raw contract；下一真实实验要加入随机 decoy、相似 decoy、wrong-reference 和 selection/evaluation split 隔离，比较 reference false-match rate、ordinary-propagation FPR、risk@coverage、ROI/faithfulness 和人工复核分钟。若只增加拒判而没有选择性风险或复核收益，应把它保留为 provenance/review audit。

6. 后续候选方向是跨版本 `version-DAG evidence consistency`：审计父子传播边、兄弟分支和编辑后代的 new-support/off-mask/path persistence。它尚未形成批准接口，不应提前改写 `aigc_result_v1` 或作为图算法创新对外宣称。

## 7. Agent 交付规则

新 Agent 若要使用“创新”一词，必须同时写明：

- 它依赖的原件、null、mask、operator、校准 profile 和数据切分；
- 它与哪些 prior art 或消融对照不同；
- 当前证据属于源码、单测、synthetic runner、真实授权数据、线上服务还是部署；
- 失败时如何拒判、回放和回滚。

没有这些字段时，只能使用“研究假设”“可验证方向”或“工程契约”，不能写成已证明的算法创新。

## 8. D-052 反事实 mask persistence 质量门

D-052 新增四类 canonical view 对照：`factual`、`ordinary_propagation`、`decoy`、
`wrong_reference`。它是 D-050/D-051 的 sanity check，不是独立 detector。可证伪问题是：
factual evidence mask 是否跨视角保持，而匹配 null、decoy 和错误 reference 是否不再激活同一
共识区域。

只有在真实授权 manifest、编辑 mask、独立 ordinary-propagation null、decoy/错误参考 controls、
跨生成器/时间切分和质量/source-match 门同时具备时，才可比较该层相对无 mask persistence 的
ordinary-propagation FPR、`null_mask_hallucination_rate`、ROI/faithfulness、coverage-risk、
人工复核分钟和 P95。当前 `persistent_candidate`、`null_consistent`、`mask_inconsistent` 和
`insufficient` 仅是 raw evidence 路由，不能写成分割准确率、AIGC 概率、作者/来源或法律结论。

## 9. 2026-09-20 prior-art 刷新后的主张边界

本轮新增的 AIGIBench、SAFE、NTIRE、Locate-Then-Examine、PRADA、CDAL、SimLBR、IFA-Net 和 SPARED
进一步说明：整图/局部检测、区域解释、生成器归因、real-only 流形和 source/edit hard negative
都已有先例。Smart Shadow 的最小可辩护主张仍只能是“登记原件 + 同传播族 null + 同 mask/operator
的 matched-intervention + 可回放拒判”这一组合协议。

新增 A11 source/edit adversarial red-team 只用于检验协议是否被忠实但可逃逸的局部编辑击穿；它不
进入默认线上 detector。A11 必须与 A0–A8 同 manifest、同时间/生成器切分和同 ordinary-propagation
null 对照，并报告 ordinary-propagation FPR、risk@coverage、unknown/review、ROI/faithfulness、
P95、成本和人工复核分钟。外部 benchmark 的 ROC-AUC、分割或归因指标不构成 Smart Shadow 结果。

## 10. D-055 version-DAG evidence consistency

D-055 是 P1 的拓扑审计扩展：把登记原件、普通传播版本、内容编辑版本、兄弟分支和后代节点组织为可回放父子 DAG，消费已绑定的 D-050–D-054 raw sidecar，审计 `propagation_leak_raw`、`off_mask_gain_raw`、`branch_disagreement_raw` 和 `path_persistence_raw`。固定路由为 `graph_consistent`、`propagation_leak`、`branch_conflict`、`trajectory_inconsistent`、`insufficient`。

它不能单独称为图算法创新。RITA、SEED 和 C2PA Actions 已覆盖部分操作顺序或 provenance 图字段；Smart Shadow 只能检验“登记原件 + ordinary-propagation null + declared mask + 上游 evidence digest + fail-closed DAG 回放”的组合是否减少传播漏激活和人工复核成本。初版禁止 merge，多父节点直接 `insufficient`；节点或边 binding context 不一致、普通传播缺 null profile、内容编辑缺 declared mask 均拒判。

真实实验必须比较无图、单父子检查和完整 DAG sidecar，在同一授权 manifest、生成器/时间切分和普通传播 null 上报告普通传播 FPR、off-mask false activation、branch disagreement、path persistence、risk@coverage、unknown/review、ROI、P95 和人工复核分钟。当前 `evidence-graph-v1` 只通过 10 项单测和 6 个 scalar case，runner digest=`bc14e91690b9bc194d83fa88deacf35f86ab41d77641cf975e5560e943edf621`；不得把它写成 AIGC 概率、来源/作者证明、法律结论或线上能力。

## 11. 无原件 fallback 的新增对照方向

GAPL、LTD、RealStats、PROBE 和 NeuroRenderedFake 只进入研究对照：GAPL/LTD/RealStats 用于无原件 generator/open-set/calibration 分支，PROBE 用于训练期 red-team，NeuroRenderedFake 用于新增神经渲染生成器族。Authenticated Contradictions 用于 C2PA×watermark 冲突路由。它们的外部论文数字不构成 Smart Shadow 结果，`no_signal_or_unknown` 仍不能映射为人类创作。

## 12. D-057 real-family-router-v1 的主张边界（暂缓编码）

D-057 是已登记但暂缓编码的研究候选，不是已验证创新。D-056 已完成基础 open-set raw contract；D-057 拟把 ONMA real-only profile 与按
`generator_family × quality_bucket × transform_family × time_bucket` 分层的独立 family calibration
和开放集拒判组合为可回放路由。RealStats、GAPL、LIDA/IncreFA、OpenSDI 和 IAR 已覆盖其中的
real-only 统计、prototype、归因检索、开放集切分和来源追踪，因此 Smart Shadow 不能把 robust
prototype、real-only distance、family top-1、unknown reject 或 watermark/C2PA conflict 单独称为创新。

可检验主张只能写成：在来源/版本绑定、独立 real-only profile、独立 family support/calibration、
时间/传播分层、开放集拒判和完整 evidence digest 同时成立时，family hypothesis 是否比 ONMA-only、
GAPL-like prototype 和 LIDA-like retrieval 更能降低开放集风险并减少人工复核。必须覆盖
leave-one-generator-out、same-family unseen、architecture/neural-rendering unseen、next-time-window、
传播后 risk@coverage、unknown recall、family flip、P95、成本和人工复核分钟。

当前没有 `real_family_router.py`、family profile set、真实 manifest 或 D-057 runner；首轮只能通过 raw
contract 和合成拒判测试。结果固定为 `family_candidate`、`family_ambiguous`、
`real_consistent_unknown_family`、`out_of_manifold_unknown_generator`、`family_conflict_review`、
`insufficient`，禁止 probability、`human_supported`、`ai_generated_supported`、作者或法律结论。
若完整 router 只改善 closed-set Recall@1，或开放集/时间/传播风险、延迟、成本和人工复核变差，则撤回
为诊断 sidecar；provenance×watermark contradiction 保留为 P1 合规适配器。D-056 的已实现路由仍只
表示 family/real-only raw evidence，不能被升级为生成器识别或 AIGC 效果。

## 13. 2026-09-21 SAEC-v1 选择后校准（D-060）

最新一手先例覆盖审计和协议说明见 [`docs/research/2026-09-21-论文与算法创新深挖.md`](research/2026-09-21-论文与算法创新深挖.md)。D-060 已批准 `selection-aware, stratified evidence calibration`（SAEC-v1）作为阶段 7 离线契约，针对参考图检索后挑选 winner 造成的 selection bias/winner's curse：使用与评估完全分离的 selection/calibration/evaluation split，在固定 decoy 数和 ordinary-propagation 分层 profile 上校准 max statistic。

当前已有独立模块、专测和 synthetic runner：只消费 D-054/D-058 已绑定的 scalar contrast 和 evidence sidecar，不改写 `reference_specificity_v1`、`invariant-effect-v1`、`aigc_result_v1` 或线上接口。候选 raw route 为 `selection_specific_candidate`、`selection_ambiguous`、`null_consistent`、`insufficient`，禁止输出 probability、作者、版权或法律字段。无模型契约已完成，但真实授权 manifest、独立 calibration groups、blind decoy、D-058 稳定性和效果仍未验证，因此不能称为已证实算法创新或生产能力。

进入代码前必须在同一授权 manifest 上冻结 reference-selection policy、decoy 数、asset/group split、ordinary-propagation profile 和 G0–G6 门；对照至少包括 query-only、D-054、SAEC、D-058、D-054+SAEC、去 null 和去 decoy。验收看 reference false-match、ordinary-propagation FPR、risk@coverage、ROI/边界 F、unknown/review、route flip、P95、每千张成本和人工复核分钟。若收益只来自更多拒判、只在 IID/已知生成器成立，或支持不足导致频繁 global fallback，则撤回为 reference-audit sidecar。

## 14. 2026-09-21 SAEA-v1 选择感知的限预算证据采集（D-061）

D-061 已批准 `selection-aware-acquisition-v1` 作为阶段 7 的策略契约。它根据已经暴露的失败原因，在固定动作集合和 cost budget 内选择下一项 probe，并为每一步绑定 state input digest、output digest、动作顺序、raw updates、失败原因和 trace digest。当前动作包括追加 matched decoy、构造 matched null、切换 view、切换 operator 和重新对齐质量。

SAEA 的可检验主张是“在相同动作预算和相同 evidence split 下，按失败原因选择 probe 是否比固定顺序 A9 更少误升级、更少人工复核或更低 selective risk”。它不能把“会继续取证”本身称作创新，也不能替代 D-054、D-058、SAEC 的统计校准。当前 11 项专测和 5 个 scalar runner 只证明 raw contract、回放、预算和失败闭合；`selection_specific_candidate` 仍不是 AIGC 概率或法律判断。

真实实验必须在同一冻结授权 manifest 上比较 fixed-order A9、SAEA、只追加 decoy、只构造 null、view/operator-only 和 no-extra-probe，覆盖错误 reference、普通传播、局部编辑、未见生成器、下一时间窗与低质量传播，报告 ordinary-propagation FPR、reference false-match、risk@coverage、ROI/边界 F、route flip、unknown/review、P50/P95、动作成本和人工复核分钟。若收益只来自额外拒判、只在 IID/已知生成器成立，或成本和延迟超过人工收益，SAEA 应撤回为证据采集审计 sidecar。

## 14.1 2026-09-21 SAEA propagation gate（D-073 / SS-025）

SS-025 已为 SAEA standalone state 增加 generator/open-set/retrieval replay 的 fail-closed 绑定门。候选路由只能来自已绑定的 `known_family_supported` 或明确的 `generator_evidence_not_required`，以及 `replay_consistent` 或明确的 `replay_not_required`；`real_consistent` 保持中性，unknown、冲突、裸 `candidate`、支持不足、digest mismatch 和普通传播都不能被 probe 修复成候选。

这是安全和证据链修补，不是新的 detector、概率校准理论或算法创新。12 项 gate 专测和 10-case synthetic runner 只证明 schema、digest、回放顺序和拒判行为；真实开放集泛化、ordinary-propagation FPR、risk@coverage、客户和线上能力仍未验证。

## 15. 2026-09-21 SCPTN-v1 树级普通传播 null（D-062）

D-062 将同一登记资产的普通传播版本组织为单根传播树，把树作为统计单位，对树内版本选择后的最大 paired local delta 做分层 null 校准。它针对三个具体风险：同一传播树的相关版本被重复计数、从多个版本挑最大差异造成 winner's curse，以及普通传播误报被误读为局部编辑。

SCPTN 的固定 raw route 是 `tree_specific_candidate`、`tree_selection_ambiguous`、`tree_null_consistent`、`insufficient`。树必须共享登记资产、manifest、detector/schema、传播/质量/时间/source-match 分层和 selector digest；calibration profile 只接受独立资产的 ordinary-propagation 树，查询 split 与 calibration split 必须隔离。普通传播 scope 永远不会升级为 candidate，任何树形、质量、授权、支持或绑定失败都拒判。

该切片不能单独称为树算法、传播鲁棒性或 AIGC detector 创新。QuAD/ReWIND 已覆盖近重复质量聚合，IAPL 已覆盖最高置信视图选择，BCEA 已覆盖预算采证，SAEC 已覆盖 scalar winner 校准。SCPTN 只有在同一授权 manifest、相同动作预算和独立外部切分上，相对逐版本 null、去树相关性、D-054、SAEC、SAEA 和完整组合降低 ordinary-propagation FPR、reference false-match、risk@coverage 或人工复核分钟，才有资格升级为研究增量；否则保留为 propagation-audit sidecar。


## 16. 2026-09-21 RSCPTN-v1 检索污染感知的传播树选择校准（D-063）

RSCPTN 的最小可辩护表述是：在登记原件和 ordinary-propagation tree null 条件下，把
`retrieval → membership → tree → selection` 作为同一可回放事件，分别在树级和完整检索事件级
placebo profile 上校准 `p_tree_raw` 与 `p_retrieval_raw`，双门通过才允许进入
`retrieval_tree_candidate`。它不是新的 detector、传播树数据结构或 conformal 理论。

QuAD/AncesTree 已覆盖近重复检索和质量/树聚合，JOMI/CAP/PEMI/Online Selective Conformal 已覆盖
选择后校准，RADAR/OpenSDI/DICE/RITA 已覆盖局部编辑或开放集，投毒和 provenance 冲突也有独立先例。
因此只能把“登记原件 + 传播树相关性 + 漏召回/误召回/植入 stress + 选择过程完整 placebo 重放 + fail-closed
拒判”作为待证伪的组合协议，不能把其中任一组件单独称为创新。

当前 `aigc/retrieval_aware_tree_null.py`、专测和 synthetic runner 已完成无重量契约；路由和 digest
只属于 raw sidecar。真实实验必须冻结 retrieval archive、候选预算、membership/tree shape、selection key
和授权 split，并与 query-only、QuAD-like、SCPTN、D-054、SAEC、SAEA、去检索重放和逐节点 null 对照，
覆盖 clean/missing/false-positive/poisoning、普通传播、wrong-reference、unknown generator 和
next-time-window。若收益只来自更多拒判、污染 profile 无法独立重放或人工/P95/存储成本变差，撤回为
retrieval/provenance audit sidecar。

## 17. 2026-09-21 下一轮候选：SIPA、DRCS、CEAT（尚未批准编码）

二轮先例审计将 RSCPTN 的可辩护范围收窄后，提出三个后续候选；它们都必须先通过 ALG-001 的真实事件回放和 G0–G6 数据门：

- **SIPA-v1（Split-Index Provenance Audit）**：把选择索引与独立 holdout index/evidence 分流，检验 winner 的来源条件局部效应是否在漏召回、误召回和检索投毒下仍成立。它不是新的检索器或校准理论。
- **DRCS-v1（Dual-Registry Confounder Separation）**：把 asset registry 与 generator fingerprint registry 分开，比较来源特异证据和生成器伪影混淆。它不是新的生成器归因模型。
- **CEAT-v1（Cross-Fitted Evidence Audit Trail）**：将 SAEA 的自适应 probe 放进独立 ordinary-null 的 cross-fitted e-process 对照。现有 e-value/选择后校准已有理论，项目不主张新的统计理论。

三者当前只属于研究输入，不改 `aigc_result_v1`、线上服务或商业接口。验收必须使用相同 coverage/action budget，报告 ordinary-propagation FPR、reference false-match、risk@coverage、unknown/review、ROI/边界 F、P95、成本和人工复核分钟；若只提升 closed-set/IID、只增加 unknown 或成本变差，撤回为 audit sidecar。

## 19. D-070 PE-CEA-v1 的主张边界

PE-CEA-v1 是按传播严重度分层的 ordinary-null envelope 与局部效应曲线审计。它可以检验“局部效应是否相对同层普通传播持续超额”，但不能单独证明 AIGC、作者、来源、版权或侵权。`envelope_candidate` 仍只是进入人工复核的 raw route，`null_consistent` 不等于人类创作，`curve_inconsistent` 和 `insufficient` 都必须保留拒判证据。

只有在同一冻结授权 manifest、相同 action budget/candidate coverage、独立 ordinary-propagation null、编辑 mask、wrong-reference/decoy、生成器/时间外部切分和 G0–G6 对照上，相对 paired-delta、propagation-stability、SCPTN/RSCPTN 及去 envelope 消融同时降低误报或人工复核成本，且不靠增加 unknown、降低 coverage 或恶化 P95，才能讨论研究增量；否则保留为 propagation-audit sidecar。

## 20. 2026-09-21 DRCS-v1：双注册表混淆分离（研究候选）

论文先例已经覆盖 source/query paired detection、局部编辑定位、re-edit attribution、无原件生成器归因、
开放集拒判、真实传播鲁棒性和水印/C2PA adapter。因而 DRCS 不能把“两个 registry”“多流融合”或“生成器
分类”单独包装成创新。唯一可检验的窄主张是：把登记原件/版本/ordinary-null 的 `asset_registry` 与
生成器/real-only/open-set/水印/C2PA 的 `generator_registry` 分开，在同一检索和证据回放中区分来源特异
局部效应、只有生成器信号、普通传播一致和跨层冲突。

固定 raw route 为 `source_specific_edit_candidate`、`generator_only_unknown`、
`ordinary_propagation_consistent`、`source_generator_conflict_review`、`insufficient`。只有来源
registry 的 matched effect、blind decoy/wrong-reference、ordinary-null、mask/operator/canonical-frame
和独立 split 同时通过，才可进入第一个 route；generator signal 不得替代来源证据；普通传播不能升级为人类；
冲突必须 review。结果不输出 AIGC probability、作者、版权或侵权结论。

DRCS 当前为 D-071/SS-023 `deferred`，真实 ALG-001、G0–G6 和同预算对照前不编码。必须比较 query-only、
asset-only、generator-only、双 registry、去 null、去 decoy 和错误 reference，覆盖 unknown generator、
next-time-window、再编码/截图/再拍和 provenance×watermark conflict；若收益只来自更多拒判、closed-set/IID
或 generator registry 污染来源判断，撤回为 provenance/confounder audit sidecar。

## 21. 主要创新点的当前排序和商业边界

当前最值得继续验证的创新不是“又一个 AIGC detector”，而是可回放、可拒判的来源条件证据协议：登记原件、同
传播族 ordinary-propagation null、选择/版本事件 replay、matched local intervention、生成器信号分离、
冲突队列和人工复核一起受同一 manifest/digest 约束。该组合仍是研究假设，不能称专利新颖性或已验证学术增量。

商业上优先验证 `metadata_mutation_guard + provenance_conflict_replay` 旁路：记录导入/导出前后原始字节、
manifest/claim、C2PA/GB/IPTC、provider/platform/content ID、工具版本、签名失效和删除恢复，输出 `pass`、
`gap`、`conflict`、`insufficient`。它的价值指标是证据回放成功率、字段完整率、冲突复核分钟、权限/删除演练和
人工基线变化；客户、价格、收入、合规认证、生产部署和 ROI 仍未验证。

## 22. 训练来源、物理成像和取证对抗的禁止外推

相似检索、生成器归因和视觉近邻只能支持“登记原件与 query 的版本/传播关系”或生成器证据线索，不能证明某模型训练过该作品、不能证明作者身份，也不能证明版权或侵权。若没有可审计的训练删样本/干预实验，项目不得使用 `training-data attribution`、`used in training` 或等价表述。

结果字段应分开 `digital_origin`、`physical_capture` 和 `aigc_signal`：打印/扫描、截图或再拍可能改变二元 synthetic 判定，不能把物理载体状态混入 AIGC 事实。`FFIM` 类主动取证对抗和水印移除红队必须作为后续压力测试；C2PA/水印不同步进入冲突复核，缺失信号不能回写为人类创作。

本节约束不新增 detector，也不改变现有 raw route；它用于防止研究结果、外部论文指标和合成 fixture 被写成训练来源、作者、法律或通用 AIGC 结论。

## 23. 2026-09-21 官方市场扩展：readiness checker 与 EvidenceSidecar（D-074 / SS-028）

官方资料审计只支持把市场方向收敛为可回放的证据工作流输入，不支持声称已有客户、收入、ROI、合规认证或生产 SLA。当前两个 P0 入口是：单法域、单内容类型的 `MetadataMutationGuardV1 + provenance_conflict_replay` readiness checker，以及接入既有私有 DAM/MAM 的 `EvidenceSidecarV1 + Review Workbench`。前者核对原始字节、C2PA/GB/IPTC/EXIF/XMP、平台/内容 ID、工具版本和导出链中的缺失、变更与冲突；后者回放原件—版本—传播—权限—reviewer—删除墓碑链路。

它们都只能作为只读、可撤销、fail-closed 的 sidecar，不能替代 DAM/MAM、C2PA viewer、云图搜、供应商 detector、法务或发布系统。`pass`、`gap`、`conflict`、`insufficient`、`unknown`、`review`、相似命中或标识/水印阳性阴性均不能自动映射为内容真实、作者、版权、侵权、训练事实或合规结论。阶段 1–5（身份、上传安全、EvidenceV1/恢复、可复现部署）以及授权 manifest、删除/恢复责任和人工基线完成前，只允许访谈、脱敏 fixture 与资格审查，不读取客户数据。

可证伪的首轮试点门包括字段完整率、机器可读标识保留率、签名/claim/导出冲突回放、原件/版本绑定 precision/recall、ordinary-propagation false upgrade、evidence package 回放成功率、权限越界和静默假成功（必须为 0）、P50/P95、每千件成本、人工复核分钟与报告采纳率。若只能增加拒判、依赖单一供应商信号、改善 IID fixture 或无法跨存储/删除状态回放，方向降级为 metadata/provenance audit sidecar。

## 24. 2026-09-21 CFAEA-v1：交叉拟合的资产—生成器证据审计（D-075 / SS-029）

CFAEA 是当前最窄的 P0 研究候选之一，但仍不是已验证创新。它把 A/B split-index、`asset_registry`/`generator_registry` 分离、五折 cross-fit、matched ordinary-propagation null 和完整 retrieval/selection/replay digest 放入同一事件。A 负责选择并冻结 winner，B 只 direct lookup winner，禁止重排；生成器信号只能进入 generator/conflict/unknown 证据，不能替代来源条件 evidence。

可证伪主张是：在相同 candidate coverage、action budget 和人工预算下，CFAEA 是否相对 ALG-001/RSCPTN、SIPA、generator-only 及去 null/decoy/replay/cross-fit/GR/B-reselect 消融，降低 ordinary-propagation FPR、错误 reference/decoy false-match 或 poisoning route flip，同时保持 accepted-sample selective risk、unknown recall、ROI/边界 F、P95、成本和人工分钟不恶化。

当前只登记 `holdout_consistent`、`source_generator_conflict_review`、`generator_only_unknown`、`ordinary_propagation_consistent`、`selection_contaminated`、`missing_holdout`、`open_set_unknown`、`insufficient`、`not_evaluated` raw route。真实 archive/index、授权图片、独立 null、generator-matched controls、外部生成器/时间切分和 G0–G6 未通过前，不创建代码、不接线上、不输出 AIGC probability、作者、训练来源、版权或侵权结论。若收益只来自更多拒判、降低 coverage、closed-set/IID 或无法独立回放，撤回为 provenance/confounder audit sidecar。

## 25. 2026-09-21 AR-SCMI-v1：反取证压力下的来源条件 matched intervention（D-076 / SS-030）

AR-SCMI 是论文审计后得到的后置白区候选。它不主张新的 detector、反取证免疫或统计理论，只检验：在同一登记原件、canonical frame 和 matched ordinary-propagation null 下，对 observed query 与 null 施加同一份已授权反取证压力，局部干预效应的 robust lower envelope 是否仍保持方向和可回放性。

固定 raw route 为 `attack_stable_candidate`、`attack_fragile_review`、`null_consistent`、`insufficient`。压力操作、参数、预算、随机种子、输入/输出 digest、授权范围、null/operator/schema 和失败状态必须封存；任一压力层缺失、配对变化、未授权或无法回放即拒判。真实评测必须比较 PC-SCFT、CFAEA、去压力、去 null、random/decoy mask、wrong-reference、已知/未见生成器、下一时间窗、JPEG/resize/截图/再数字化，并报告普通传播 FPR、reference false-match、risk@coverage、ROI/边界 F、route flip、P95、成本和人工分钟。

AR-SCMI 当前没有代码、真实数据或效果结果，不能写成“抗反取证能力”或独立学术创新；若只在 clean/IID 有益、只增加拒判、压力操作无授权或 evidence package 不能独立重放，则撤回为 attack-audit sidecar。


## 26. D-077 TLEG-v1：生命周期可回放门（工程/研究前置主张）

TLEG 的最窄主张是：在候选路由前验证 query-as-of、snapshot freshness、单调事件链、删除墓碑、恢复新版本和授权/留存/访问范围，是否能把 future/stale/tombstoned evidence 的错误升级降为零，同时不造成不可接受的 coverage、P95 和人工成本损失。

它不是 detector，也不是 AIGC 归因、来源证明或反取证算法。`lifecycle_consistent` 只代表时序门通过；普通传播、unknown/open-set、source conflict 或 detector 失败不能被它修复。固定 raw route 为 `lifecycle_consistent`、`future_event_leak`、`stale_snapshot_review`、`tombstoned_insufficient`、`deletion_replay_mismatch`、`profile_stale`、`insufficient`、`not_evaluated`。

可证伪对照是 ALG-001/CFAEA+TLEG、去 TLEG、latest-snapshot 和 random split；至少报告 stale/future candidate upgrade（目标 0）、删除/恢复回放成功率、route flip、coverage、unknown/review、P95、存储和人工复核分钟。必须包含过去窗口、未来窗口、删除墓碑和恢复演练；没有真实生命周期 manifest 时，只能称无重量 fixture contract。

当前代码切片 `SS-031` 已完成无重量离线契约、20 项专测、18-case runner 和统一轻量回归，但尚未接入线上。即使契约测试通过，也不能把 digest、route 或 synthetic runner 写成 temporal generalization、AIGC 效果、客户 ROI、合规认证或线上部署证据。

## 27. 第三轮终审后的创新主张收窄

完整 CFAEA 不能直接作为下一项代码任务。当前唯一允许的研究执行顺序是：

1. `SS-032` 先准备真实授权 archive/index、A/B snapshot、rank/membership/tree/selection trace、生命周期/访问审计和 G0–G6；
2. `SS-020/SIPA-LG-v1` 先做 A replay、TLEG-A、fixed winner/region、B direct lookup、TLEG-B 和 matched ordinary-null；
3. 真实 SIPA-LG 结果满足同 coverage/action/review budget 的误报或人工收益门后，才接 generator registry/cross-fit 形成完整 CFAEA；
4. 只有真实结果出现可重复的传播、再数字化或授权压力脆弱性，才评审 AR-SCMI。

SIPA-LG 的可证伪主张是：冻结 A 侧选择后，独立 B direct lookup 与生命周期门能否在 ordinary-propagation、wrong-reference、poisoning 和 open-set 对照下减少来源证据误升级。它不是新的 detector、来源证明、AIGC 概率或法律结论。没有真实 B holdout、独立 null 和 G0–G6 时，所有结果只能写成 raw evidence、review、unknown、insufficient 或 `not_evaluated`。

## 28. 论文终审新增的后置候选：CIVG 与 TMCD

第三轮论文复核又确认了两个“输入有效性/来源角色”缺口，但它们都不改变当前执行顺序。

- **CIVG-v1（Counterfactual Intervention Validity Gate）**：在 PC-SCFT/SCTE 已绑定原件、query、ordinary null、mask 和坐标帧之后，增加非目标保持、目标是否实际生效、mask 外泄漏、语义/因果一致和最小干预审计。固定 raw route 为 `valid_intervention`、`spillover_review`、`counterfactual_invalid`、`insufficient`；无效 counterfactual 不得进入 candidate 或 null p-value。该方向由 [NeurIPS 2025 的因果编辑工作](https://proceedings.neurips.cc/paper_files/paper/2025/hash/54e1419b1cbca8ada96a87c96567e954-Abstract-Conference.html) 和 [CVPR 2026 I2I-Bench](https://openaccess.thecvf.com/content/CVPR2026/html/Wang_I2I-Bench_A_Comprehensive_Benchmark_Suite_for_Image-to-Image_Editing_Models_CVPR_2026_paper.html) 约束支持；当前已完成无重量离线契约、15 项专测和 14 个 scalar fixture，但没有授权编辑标注或真实效果结果。
- **TMCD-v1（Training-Membership Confounder Disambiguation）**：把 `training-set member`、`novel generation` 和 `external source` 作为区别于 `asset_registry`/`generator_registry` 的第三种来源角色。它必须依赖授权 checkpoint/trajectory 与独立 membership manifest；缺少白盒证据时固定 `not_evaluated`，不得从黑盒图像推断训练使用。该方向由 [NeurIPS 2025 的训练轨迹归因研究](https://proceedings.neurips.cc/paper_files/paper/2025/hash/901b713c3d1ecfce0d4556752eed4e02-Abstract-Conference.html) 触发，当前不批准编码。

CIVG 的真实效果只有在 SS-032、ALG-001 真实回放和同预算对照前提下才可评审；TMCD 更后置。两者均不能输出 AIGC 概率、作者、训练事实、版权或侵权结论，也不能替代 SIPA-LG、CFAEA 或阶段 1–5 的工程门。
