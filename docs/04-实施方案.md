## 实施总原则

每个阶段都必须有代码范围、可重复验收和明确失败状态。阶段完成的含义是验收项通过，不是代码已经提交。验收基线按可复现的 clean checkout 定义；当前工作树可能包含其他 Agent 的未提交修改，必须先登记并保留，禁止用清理操作覆盖它们。

```text

仍未验证：
```

## 阶段 1：无假成功的业务边界

目标：任何 AI、链、数据库或 Faiss 失败都不能被报告为成功。

首个代码切片：

- `cm_client.go`：定义结构化 Receipt，保留交易号、交易状态码、合约状态码和消息；处理 nil 回执。
- `server.go`：检查 AI HTTP 状态、JSON、向量 schema 和 Faiss 写入错误；删除 `strings.Contains` 式重复判断和假交易号。
- `contract/main.go`：定义稳定错误码，例如 `E_HASH_REQUIRED`、`E_EVIDENCE_EXISTS`、`E_STATE_READ`、`E_STATE_WRITE`。
- 增加纯函数测试：成功、重复、合约拒绝、网络未知、空回执。

验收分三类：AI 500、非法 JSON、VM 拒绝和网络未知都不能返回 HTTP 200 `registered`；同一用户重复登记同一 CID 返回 200 `already_registered` 并保留真实 `tx_id`；同一 CID 属于其他用户返回 409 `ASSET_OWNED_BY_OTHER`（或按已批准策略隐藏详情）；提交状态未知返回 202 `pending` 并携带 `request_id`。

依赖：无需先恢复完整前端或模型运行，可先使用 mock receipt 和 mock AI 响应。

### 6.1 首客旁路试点：`EvidenceSidecarV1`（SS-018，当前阻塞）

目标客户是已有私有图库、DAM/MAM 或内容发布链，并且每周有供稿预审、标识检查、投诉取证或版本追责任务的团队。交付形态是只读 `provenance/version/evidence sidecar + Review Workbench`，不替代 DAM，不以单图 AIGC 分数、通用图搜或自动法律处置作为交付目标。

实施前置：阶段 1–5 完成；客户提供授权 manifest、删除/恢复责任人、人工基线、适用法域/内容类型和明确重复任务；`EvidenceSidecarV1` 字段按技术方案 §12 分栏保存内容摘要、凭证/规则、版本关系、模型 raw evidence、reviewer 决定、留存/删除和导出回执。没有这些条件时只做访谈或离线 fixture，不读取客户数据。

试点只读门（可撤销假设）：

1. D0–D7：授权样本为 0、跨租户越权为 0、失败假成功为 0，输入/输出 digest 可重放，删除责任和报告 schema 明确。
2. D8–D21：至少 500 个原件和 1,000 个版本/传播样本；版本绑定 precision ≥0.95、recall ≥0.90、字段完整率 ≥98%、指定 reviewer 回放 ≥99%，同时记录 ordinary-propagation FPR、unknown/review、P50/P95、人工复核分钟和每千件成本。
3. D22–D28：证据包一次采纳率 ≥80%、人工净分钟下降 ≥20%、删除/恢复演练 100%、至少连续两周存在重复任务；否则回滚到离线 fixture。

这些数字只是试点起始门，不是生产 SLA、市场事实或购买承诺。停止条件包括未授权样本、解析/依赖失败却返回成功、无法删除/恢复、证据无法独立回放、unknown 被流程强制归类、没有重复任务或净价值为负且无修复路径。

| [Pillow](https://github.com/python-pillow/Pillow/blob/main/LICENSE) | 文件内容识别、解码、EXIF orientation、RGB/RGBA 转换、JPEG/PNG/WebP/TIFF/BMP 编解码 | 当前 Pillow 主线声明 MIT-CMU；实际 wheel 还可能带 libjpeg、zlib、libtiff、libwebp、OpenJPEG 等第三方组件，接入前必须生成 SBOM 并保留其许可证文本。不要为了“支持更多格式”默认启用 GPL 组件。 |
| [NumPy](https://numpy.org/about/) | 将解码后的像素转为确定性数组，做 finite/dtype/shape 检查、灰度化和 residual 原语 | NumPy 官方说明为修改版 BSD；版本、Python ABI 和 BLAS/运行时信息写入实验环境摘要，不把 NumPy 计算结果当作来源证据。 |

第一阶段只承诺以下输入格式：JPEG/JFIF、PNG、WebP、非动画 TIFF 和 BMP。Pillow 的[官方格式表](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html)显示其能够识别更多格式，但格式“可识别”不等于本项目已完成安全解析、颜色管理和传播测试；GIF/APNG/多页 TIFF、AVIF、JPEG 2000、PSD、PDF、RAW 和动画文件先拒绝或进入 `unsupported_format`，不要静默取第一帧。扩展名不参与信任判断，必须基于文件头和解码器识别格式。

adapter 必须按以下顺序处理并保留审计字段：

1. 限制上传字节数和像素总量；使用 Pillow `verify()` 后重新打开并 `load()`，拒绝截断文件、异常长宽比、过大解压结果和无法解码的内容。保留原始字节 `sha256`，不覆盖原件。
2. 应用 EXIF orientation 后转为 RGB（含 alpha 的图片明确记录 alpha 丢弃或合成策略）；记录原始/归一化尺寸、模式、颜色配置、解码器版本和处理链。
3. 用 NumPy 检查 `dtype`、`shape`、有限值和通道顺序，再生成 `source-residual-v1` 所需的确定性灰度数组；任何隐式缩放、gamma、色彩空间或随机操作都必须显式写入 manifest。
4. 生成的每个传播版本都保存 `parent_sample_id`、操作名与参数、工具及版本、随机种子（如有）、输出哈希、尺寸、质量参数和 `postprocess_chain`；同一原作品及其所有衍生版本只能出现在一个 split/group 中。

| 类别 | 最小变体 | 目的 |
| --- | --- | --- |

### 7.4 研究矩阵扩展：主动取证与持续适配

在 A0–A8 之外，研究实验增加两层，但均不得直接改线上模型：

```text
A9  evidence acquisition：在预算内执行 zoom/crop/re-align/re-encode repeat，比较增加观察前后的 risk-coverage-cost 曲线
A10 test-time / few-shot adaptation：shadow mode 更新 prototype/router/calibration，冻结旧版本并做回滚与旧类遗忘测试
```

A9 的每次额外观察必须写入同一个 evidence chain，带操作、参数、耗时、输入哈希和失败原因；预算耗尽才返回 `unknown_or_inconclusive`。A10 的新生成器样本只能进入新版本 profile，历史证据不可被静默重算，且必须在 `known_generator`、`unseen_generator`、`temporal_next_period` 和旧版本回归集上同时验收。

研究终验至少记录：AUROC、AUPRC、FPR@TPR95 或 TPR@FPR1%、balanced/macro-F1、ECE/Brier；开放集记录 OSCR、OOD AUROC、coverage-risk/AURC、risk@coverage、unknown rate；局部取证记录 pixel AP/F1、mIoU、boundary-F、pointing-game、source-match failure；传播记录每种变换跌落、CID 误配率；归因记录 family/model top-1/top-5、unknown recall 和增量遗忘；工程记录 P95、显存、每千张成本、证据包一次复核率。

核心可证伪门是：A8 相对 A0–A7 只需在“高质量登记原件 + 局部编辑”子集上改善 ROI、selective risk 和人工一次复核率；无原件、低质量或来源冲突时 coverage 可以下降，但 `unknown` 必须上升，不能强行归类。若效果只存在于该子集，论文和产品表述必须限定为“source-conditioned local edit forensics”。
