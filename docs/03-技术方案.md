# Smart Shadow 持续开发技术方案

版本：V0.3（待技术方案评审）
更新时间：2026-09-21

## 1. 目标

把比赛版原型改造成可复现、可审计、可恢复的数字作品存证和侵权风险筛查系统。首个版本只聚焦图片作品和图片到图片检索，暂不扩展文本跨模态和全网抓取。

## 1.1 方案变更门

- 本文件描述“批准后的目标契约”，不把研究候选或比赛 README 的宣传语当作接口能力。
- 任何接口、字段、状态机、特征 schema、证据格式、相似度定义或结果路由的变更，都必须先在 `docs/01-项目决策记录.md` 追加决策编号，再在本文件记录版本、兼容性、失败语义和迁移方式。
- 研究区可以先用独立 raw-evidence schema 验证假设；未通过真实数据门和实施阶段门前，不得覆盖 `aigc_result_v1`、比赛版线上 API 或法律/作者结论。
- 目标契约必须同时说明成功、失败、未知、拒判和恢复路径；无法区分这些状态时，默认返回 `insufficient`/`pending`，不能伪造成功。

## 1.2 研究编号口径

- `A0–A8` 是阶段 4 的核心对照协议；`A9–A11` 是在核心协议之外的扩展研究，不能替代核心基线。
- `G0–G6` 是真实数据、授权、校准、对照和部署复核门；它们是进入真实效果或线上候选路径的前置条件。
- `docs/research/` 中的 D-057 等候选保持在研究层；D-060 SAEC-v1 和 D-061 SAEA-v1 虽已批准离线契约，仍不进入本技术方案的默认业务接口。

## 2. 目标架构

```text
浏览器
  -> Go API 网关：身份、上传、业务状态、统一错误
  -> AI 服务：图像校验、AIGC 辅助标注、特征提取、检索
  -> IPFS：原始文件和可选衍生文件
  -> ChainMaker：EvidenceV1 不可变证据锚点
  -> MySQL：用户、请求状态、链上投影、索引状态
  -> Faiss：可重建的区域向量索引
```

职责边界：链上证据不可变；IPFS 保存内容；MySQL 面向业务查询和恢复任务；Faiss 只作为可重建派生数据，不承担唯一事实来源。

## 3. 业务状态机

登记请求建议使用以下状态：

```text
RECEIVED
  -> AI_READY
  -> IPFS_READY
  -> CHAIN_PENDING
  -> CHAIN_COMMITTED
  -> PROJECTION_READY
  -> INDEX_READY
```

异常状态：`AI_FAILED`、`IPFS_FAILED`、`CHAIN_REJECTED`、`SUBMIT_UNKNOWN`、`PROJECTION_PENDING`、`INDEX_PENDING`。只有 `INDEX_READY` 才能向前端报告“登记完成”；链上已提交但投影未完成时必须保留真实交易号并报告 pending。

## 4. 认证和接口契约

### 目标契约与比赛版差异

| 领域 | 当前比赛版事实 | 持续开发目标 | 迁移门 |
| --- | --- | --- | --- |
| AIGC 结果 | `is_aigc`、整数分数和字符串原因 | `aigc_result_v1` 四态、原始证据、校准 ID 和拒判原因 | 先做响应校验和兼容映射，再接入模型 |
| 身份 | 客户端提交的用户名可影响业务路径 | 服务端会话决定用户和资源归属 | 阶段 2 会话与归属验收通过 |
| 检索 | 六区域向量分片写入 `IndexFlatIP` | 保留 raw score，增加版本化 schema、可解释聚合和恢复状态 | 阶段 3 索引恢复验收通过 |
| 证据 | CID、向量 JSON、备注和应用时间 | EvidenceV1 绑定内容摘要、调用者、来源与过程证据 | 决策记录与合约字段评审通过 |

上表用于防止 agent 把目标接口直接当成现有接口。迁移期间保留兼容层，但兼容字段不得覆盖新证据，也不得把目标状态伪装成已上线能力。

### 登录会话

- `POST /api/session/login`：接收 `{username,password}`，成功返回用户摘要并设置 HttpOnly、Secure、SameSite Cookie。
- `GET /api/session/me`：返回当前会话用户；未登录返回 401。
- `POST /api/session/logout`：撤销会话，返回 204。
- `/dashboard`、`/register`、`/check`、`/api/history` 走服务端鉴权。

客户端不再提交具有权威意义的 `username`；资源归属全部从服务端会话取得。

### 登记

`POST /register` 使用 multipart，仅接受 `image` 和 `note`。

- 201：仅当状态已经到达 `INDEX_READY` 时返回 `registered`，包含 `request_id`、`tx_id`、`ipfs_cid`、`chain_status`、`index_status`。
- 200：当前用户已登记同一 CID，返回 `already_registered`。
- 409：同一 CID 已属于其他用户，返回 `ASSET_OWNED_BY_OTHER` 或按产品政策隐藏详情。
- 400/413/415：输入、大小或格式错误。
- 202：请求仍处于 pending 或提交状态未知，响应必须携带 `request_id` 和当前状态。
- 502/503：AI、IPFS、链或投影依赖发生可确认的硬失败；不得伪造 `registered`。

阶段 2 完成真实会话和资源归属前，`already_registered` 与 `ASSET_OWNED_BY_OTHER` 只能作为目标契约，不能把客户端提交的用户名当作 owner 依据。

### 检索

`POST /check` 接受图片，返回：

```json
{
  "similarity_raw": 0.0,
  "matched_cid": "...",
  "match_type": "exact_cid|semantic|none",
  "risk": "low|medium|high|unknown",
  "aigc_result": {
    "status": "human_supported|ai_generated_supported|ai_edited_supported|unknown_or_inconclusive",
    "confidence": null,
    "unknown_reason": "...",
    "evidence": [],
    "generator_hypotheses": [],
    "regions": [],
    "detector_version": "...",
    "calibration_id": "..."
  },
  "compliance_label": "verified_ai|user_declared_ai|suspected_ai|no_signal_or_unknown",
  "current_img_info": {"aigc": "available|unknown", "object": "..."}
}
```

`similarity_raw` 不得被静默修改；`risk` 由验证集校准后的策略产生。

`aigc_result` 是当前目标契约。旧 `current_img_info.aigc` 和历史 `is_aigc` 只能由四态结果派生，作为兼容字段逐步废弃；模型不可用、未校准、证据冲突或低质量都必须保留 `unknown_or_inconclusive`，不得显示为人类创作。来源凭证支持 AI 时 `confidence` 保持 `null`，不能把来源证据伪装成模型概率。

## 5. 特征和检索协议

- schema：`clip-vit-base-patch32/regions-v1`。
- region：`full、top_left、top_right、bottom_left、bottom_right、center`。
- 每区域向量维度：512；总长度：3072。
- 向量必须是有限数值，拒绝空数组、零向量、NaN、Inf 和维度不符。
- 模型、处理器、区域定义和版本写入索引元数据。
- 第一阶段保留 `IndexFlatIP` 作为精确基线；只有评测证明数据规模和延迟需要时，才评估 HNSW/IVF/PQ。
- 查询阶段使用 top-k、按 CID 去重和可解释聚合，避免只取一个偶然最高分。

## 6. EvidenceV1 建议

链上不再保存完整 3072 维浮点 JSON，建议保存固定结构：

```text
schema
cid
content_sha256
feature_hash
feature_schema
owner_org_id?       # 待身份和隐私评审
owner_addr?         # 来自服务端签名身份映射，不等于表单用户名
manifest_digest?    # 来源/编辑过程摘要，待阶段 3 评审
chain_timestamp
note_hash
```

原始向量、可展示备注、C2PA manifest、签名者/提供者、生成或编辑动作、提示词/参数、人工筛选和局部编辑记录放在链下并保存可核验摘要。`tx_id` 由链上回执产生，归入 MySQL 投影和 receipt 审计记录；除非确认 ChainMaker 支持回写，否则不把它当作合约 payload 的先验字段。链上只保存摘要、版本和经过评审的身份字段。时间使用链上交易时间或可验证回执，不使用网关随意传入的本机时间。

## 7. MySQL 投影和恢复

登记表增加：`request_id`、`chain_status`、`projection_status`、`index_status`、`owner_id`、`content_sha256`、`feature_hash`、`feature_schema`、`retry_count`、`last_error_code`、`updated_at`。

唯一约束至少包括 `request_id` 和按产品规则确定的 `ipfs_cid`。启动时 reconciler 扫描 `*_PENDING` 和 `SUBMIT_UNKNOWN`，查询交易或合约状态，补齐 MySQL 和 Faiss。

## 8. 安全和运行约束

- 所有上传使用服务端随机文件名，限制大小、MIME、图片魔数和像素总量，请求结束清理临时文件。
- DSN、会话密钥、AI 地址、IPFS 地址和 ChainMaker 配置从环境或部署配置读取。
- 前端不使用未经转义的 HTML 拼接用户内容；备注和持有人名称优先使用 `textContent` 或 SweetAlert `text`。
- 统一错误格式：`{error:{code,message},request_id}`。
- 启动前检查依赖、证书、合约包、RPC、数据库和 AI readiness；依赖未就绪不能打印 ready。

## 9. 评测方案

建立包含原图、裁剪、截图、缩放、压缩、滤镜和非侵权近邻的固定数据集，按作品分组防止泄漏。报告 Recall@1/5、FPR、PR-AUC、相似度分布、P95 延迟和资源占用。AIGC 辅助检测另报 ROC-AUC、F1、ECE 和 unknown 比例。

阶段 4 的最小验收集为 Recall@K、FPR、PR-AUC、ROC-AUC、ECE、unknown rate 和 P95 延迟；研究终验必须扩展到已知/未见生成器、`temporal_next_period`、局部编辑 ROI IoU、截图/再编码/打印扫描或再拍摄、证据冲突矩阵、coverage-risk、每千张成本和失败率。未完成这三重门时，只能报告工程基线，不能写成通用 AIGC 解决方案。

## 10. 当前不纳入本版本

文本跨模态检索、全网爬虫、多组织用户级链上身份、法律裁决、海量 ANN 集群和未经评测的“精准抗裁剪”承诺不属于 V0.2 首要范围。

## 11. AIGC 取证技术方案（研究主线）

### 11.1 分层证据

AIGC 不是登记成功的前置真假门，而是带版本和不确定性的证据服务：

1. **来源层**：验证 C2PA/Content Credentials、GB 45438-2025 显式/隐式标识、EXIF/XMP、可信水印和用户声明；记录 `valid/missing/invalid/unverified`，普通元数据另记为 `metadata_weak`。缺失不是人类证明。
2. **视觉取证层**：全图和区域 CLIP、SRM/high-pass、DCT 高频/低频、FFT 统计；第一版采用 AIDE 风格的轻量融合做基线。
3. **重建复核层**：LaRE²/AEROBLADE-lite；仅在低置信、高风险或审计请求中异步触发，结果为补充证据。
4. **开放集归因层**：生成器 prototype/验证式距离、energy/OOD 和 conformal 校准；距离未过阈值时返回未知。当前离线 `aigc/calibration.py` 已提供复用 `CalibrationProfile` 的负例单侧 p-value：`(1 + count(negative_score >= score)) / (n + 1)`；`p <= alpha` 只触发 unknown 拒判观察，不构成 AI 或人类结论，也尚未接入线上服务。
5. **源图条件层**：语义检索命中已登记原件后，对齐区域并比较 residual，输出局部 AI 编辑候选 ROI；无可靠匹配时使用单图 fallback。

### 11.2 响应契约

AI 服务新增 `aigc_result_v1`，至少包含：

```json
{
  "status": "human_supported|ai_generated_supported|ai_edited_supported|unknown_or_inconclusive",
  "confidence": null,
  "unknown_reason": "...",
  "evidence": [],
  "generator_hypotheses": [],
  "regions": [],
  "detector_version": "...",
  "calibration_id": "...",
  "compliance_label": "verified_ai|user_declared_ai|suspected_ai|no_signal_or_unknown"
}
```

`compliance_label` 是传播/审计事实层，不能替代四态 `status`：它分别表示可信来源标识、用户声明、经过校准的疑似痕迹和没有足够可靠证据。`no_signal_or_unknown` 不得在 Go 或前端降级为 `human`。C2PA、可信水印和视觉分数发生冲突时，响应必须保留冲突证据并进入人工复核。

旧 `is_aigc` 只能由新状态派生，不作为事实源；`confidence` 必须来自训练外校准，不能直接把 softmax 或原始相似度当概率。视觉分支还必须携带与 `CalibrationProfile` 一致的 detector version、score schema 和数据集摘要；任意字符串不能充当校准 ID。来源凭证单独支持 AI 状态时 `confidence` 保持为空，避免把来源强度伪装成模型概率。

负例 conformal 观察可以作为 `evidence` 的一个版本化条目：

```json
{
  "type": "negative_conformal",
  "negative_p_value": 0.20,
  "alpha": 0.05,
  "unknown": false,
  "negative_score_digest": "...",
  "negative_count": 128
}
```

`unknown=true` 只表示该分数拒绝与冻结负例流一致，必须把四态结果置为需复核；`unknown=false` 只表示没有拒绝负例流，不能单独生成 `human_supported`。条目还必须带 `detector_version`、`score_schema` 和 `calibration_id`，并在校准数据或预处理变更时重新生成。

### 11.3 检索和取证分离

版权检索使用独立的 projection 和有向 query→reference 分数，按 CID 聚合 top-k；AIGC 取证使用自己的 logit、证据和校准。任何一个分支失败都不能伪造另一个分支的成功。链上可锚定 `content_sha256`、`manifest_digest` 和 `feature_hash`，不把未经验证的模型分数写成权属结论。

### 11.4 性能分层

- L0：来源解析、文件质量和元数据检查，优先低延迟。
- L1：区域 CLIP + artifact 特征 + 轻量融合，在线初筛。
- L2：LaRE²/DIRE/FakeInversion 等高成本复核，异步执行并显示 pending。

### 11.4.1 有限预算的主动证据获取

当原件匹配、质量或模型 margin 不足时，系统可以在明确预算内主动获取额外证据：局部放大、不同尺度重对齐、可控重编码复查或多 patch 重算。当前的 `aigc.evidence_budget.plan_evidence_acquisition` 只生成可审计的行动计划，按质量/来源门提前停止，并按优先级、动作数和成本单位做确定性选择；它不执行图像操作，也不输出 AIGC 结论。每次实际操作都必须记录操作参数、输入哈希、输出哈希、耗时、失败原因和产生的 raw evidence；操作预算耗尽后才返回 `unknown_or_inconclusive`。主动获取只改变证据量，不得静默改变历史校准 profile，也不能把“多调用一次得到高分”当作提升准确率。

验收需要报告 risk-coverage-cost 曲线：在相同覆盖率下，额外证据是否降低 selective risk；在相同风险下，额外调用数、P95 延迟和每千张成本是否可接受。无原件、低质量或来源冲突样本应更容易进入拒判，而不是被主动获取强行归入 AI 或人类。

### 11.5 研究评测门

数据、切分、扰动矩阵和指标以 [06-AIGC算法创新调研.md](06-AIGC算法创新调研.md) 为准。核心消融固定为 A0–A8；阶段 4 先完成 A0–A2 的真实数据最小基线，再按数据和算力准入补齐 A3–A8。A9（有限预算主动取证）和 A10（shadow-mode 持续适配）是扩展实验，不得混入核心消融或线上默认路径。没有跨生成器、未见生成器、截图/再编码、局部编辑和校准结果，不得把模型结果写成“解决 AIGC”。

### 11.6 当前代码切片

`aigc/` 先提供不依赖重量模型的 `aigc_result_v1`、来源观察、融合策略和 source-conditioned 区域证据聚合。当前 `aigc/forensic_features.py` 还提供可复现的 `source-residual-v1` 原语和 `source-residual-roi-v1` 候选 ROI：对已对齐的归一化灰度区域先估计全局亮度偏移，再计算中心化残差、95 分位残差、一阶边缘残差、残差覆盖率、质量门和 bbox/mask，并以 `edit_score_raw` 保存原始观察；它不是 AIGC 概率，也不能脱离固定数据校准和人工复核作结论。`aigc/calibration.py` 只从独立验证流生成经验 FPR 受控的 operating point，不把 raw score 变成概率。`aigc/compliance.py` 将可信来源、用户声明、水印和视觉证据映射为传播标签并保留冲突。`aigc.near_duplicate.py` 对同一资产的多版本传播证据按质量加权，拒绝空输入、身份/版本/schema 冲突和全低质量批次，并保留版本审计；其 `weighted_score_raw` 仍是原始观察。`aigc.propagation_stability.py` 进一步要求 observed 传播版本与同传播族的无编辑 counterfactual 成对，计算 counterfactual 加权 p95、观察分数离散度和稳定性调整 raw score；缺少配对族、传播漂移或 hard-negative 高分时必须拒判。模型适配器必须把分数作为 `DetectorSignals` 传入，并明确 `model_available`、`detector_version`、`score_schema` 和 `scores_calibrated`；没有匹配的 `CalibrationProfile` 时，视觉分数只能得到 `unknown_or_inconclusive`。source-conditioned 编辑还必须有原件匹配、质量分数和区域证据。现有 `ai_server.py` 仍使用旧字段，接入新契约前需要同步修改 Go 网关的错误和版本兼容策略。
`aigc/propagation_stability.py` 在 near-duplicate 质量加权之上增加 paired propagation consistency：观察版本和同传播族无编辑 `counterfactual` 必须同时存在；加权观察分数先扣除 counterfactual p95，再乘观察分数一致性，缺少配对族、漂移过大或反事实分数过高时只输出拒判 raw evidence。该模块仍不读取图片、不作 AIGC/法律结论，也没有接入线上服务。

### 11.7 图片输入 adapter 与 PC-SCFT 扩展

真实图片进入取证层前必须通过 `aigc.image_adapter.decode_image_bytes`。adapter 使用锁定的 Pillow 12.3.0 与 NumPy 2.5.3，限制字节数/像素数，执行 `verify()` 后重新解码，按文件内容识别 JPEG、PNG、WebP、非动画 TIFF、BMP，应用并记录 EXIF orientation，显式处理 alpha，并输出 raw/normalized digest、质量分项和固定失败原因。`quality_score` 只表示是否适合取证；任何失败都进入 `unknown`/需复核，不回退为人类创作。当前 `eval/image_adapter_matrix.py` 只覆盖 9 个合成 fixture，接受 5/9，digest=`1a180411885260fb89ebe7656296e8e5e6406ae48eed49334bed22c972a09e99`。

当前 PC-SCFT 切片已经补齐离线的图像网格配准适配器。`aigc/regional_alignment.py` 将 `image_adapter` 的归一化灰度数组做固定版本双线性 resize 和有界整数平移搜索，再按确定性网格切分区域，并要求 observed/counterfactual 共享同一参考坐标帧；`eval/regional_alignment_eval.py` 只用 NumPy 合成网格验证该契约。真实图片局部配准、传播族生成和 detector 适配仍待接入。对已登记原件与 query 做局部配准，按相同传播族生成无局部编辑 counterfactual，在相同区域计算：

```text
regional_delta_i = observed_evidence_i - counterfactual_evidence_i
score_raw = quality_weighted_aggregate(regional_delta_i)
```

输出必须带区域覆盖率、质量权重、传播稳定性、参考匹配和拒判原因；原件缺失、反事实缺失、传播族覆盖不足、分数漂移、参考误配、配准形状/坐标帧不一致或质量不足时只输出 `abstained` raw evidence。该模块不输出 AIGC 概率、四态状态或法律结论，必须与版权检索 head 隔离，并在真实授权图片上通过 A0–A8、ROI、coverage-risk、P95 和证据包复核门后才可进入线上候选路径。

### 11.8 配对 delta 的分层保守校准

`aigc/paired_delta_calibration.py` 只校准“该区域 delta 是否仍与普通传播反事实一致”的 null 假设，不校准 AI/人类概率。每个普通传播校准组把区域级 `observed - counterfactual` delta 汇总成 `max(0, max(delta))`，按 `transform_family` 和质量桶建立冻结的 `PairedDeltaCalibrationProfile`，并保存校准数据、配置、detector、score schema 和 profile digest。

查询使用带平局计数的有限样本单侧 p-value：

```text
p = (1 + count(null_statistic >= query_statistic)) / (n + 1)
```

精确分层样本不足时，结果必须显式标记 `family` 或 `global` fallback；所有 fallback 都保留原请求分层和原因。没有满足最小样本数的兼容 null 时返回 `evaluated=false`、`unknown=false`、`reason=no_compatible_null`，不能把缺乏校准支持解释成普通传播通过，也不能解释成 AI。

当前 `eval/paired_delta_calibration_eval.py` 仅构造 ordinary-propagation 标量 fixture，验证 exact/family/global/unavailable 四种路径和 digest 可复现性。`unknown=true` 只代表拒绝冻结的普通传播 null，仍需进入 `unknown_or_inconclusive`/人工复核；该原语没有接入线上融合、AIGC 四态或业务 API。真实传播族、按作者/时间隔离的校准集、coverage-risk 和外部审计通过前，不得把 p-value 写成 AIGC 概率或生产阈值。

### 11.9 Patch coverage 形状层与证据路由

`aigc/patch_coverage.py`（`patch-coverage-v2`）将已配对的区域 delta 作为形状证据处理。每个 patch 可带 `region_type`；当前推荐的语义类型是 `object`、`stuff`、`background`，未知值必须保留而不能静默归类。对通过质量和 `source_match_score` 门的 patch，计算：

```text
coverage_raw = accepted_weight(delta >= threshold) / accepted_weight
positive_mass_raw = weighted_mean(max(delta, 0))
effective_patch_ratio_raw = exp(entropy(positive_delta_mass)) / accepted_patch_count
concentration_raw = max(positive_delta_mass)
coverage_by_region_type[t] = active_weight(t) / accepted_weight(t)
balanced_coverage_raw = mean(coverage_by_region_type[t])
```

默认模式保持原有路由：当覆盖率和有效 patch 比例同时达到配置门时输出 `global_like` 并路由到全图取证复核；当正证据集中在少量 patch 时输出 `localized_like` 并路由到 ROI 复核；两者之间输出 `ambiguous` 并拒判；没有足够高质量 patch 或没有正 delta 时输出 `abstained`。启用 `require_region_type_diversity` 后，`global_like` 还要求至少达到 `minimum_global_region_types` 个已知类型；接受的 patch 含 `unknown` 或类型支持不足时降为 `ambiguous`。所有值均是 raw evidence，保留被拒 patch、detector/schema、类型摘要、config digest 和 evidence digest。

该层对应的研究假设是：分布式 patch 证据更适合整图取证，集中 patch 证据更适合局部编辑候选；类型平衡覆盖可以识别“同一类区域重复激活”的 few-patch shortcut；形状不稳定或传播质量不足时，主动拒判比强制二分类更安全。它不能凭自身证明图片是 AI 生成、人类创作或发生侵权，也不能把 `localized_like` 直接升级成 `ai_edited_supported`。`eval/patch_coverage_eval.py` 当前覆盖 7 个标量 fixture，其中 2 个启用严格类型门；真实 mask、BR-Gen 风格 `object/stuff/background` 标注、传播扰动和独立阈值校准仍是后续工作。

### 11.10 PC-SCFT 统一决策协议

`aigc/pc_scft.py` 将区域反事实结果、paired-delta null 校准结果和 patch coverage 结果组合为一个可回放的取证路由。它的输入必须来自同一 `detector_version` 和 `score_schema`，并按以下顺序执行：

```text
regional quality/source/coverage gate
  -> calibration evaluated + null support gate
  -> exact stratum/fallback policy gate
  -> patch shape/type gate
  -> candidate_edit | null_consistent | review | insufficient
```

| 状态 | 含义 | 后续路径 |
| --- | --- | --- |
| `candidate_edit` | 普通传播 null 被拒绝，且区域形状证据可用 | 进入 `global_forensic_review` 或 `local_roi_review` |
| `null_consistent` | query 与冻结普通传播 null 一致 | 记录为普通传播观察，不转成人类结论 |
| `review` | null 被拒绝但形状混合或语义支持不足 | 人工复核 |
| `insufficient` | 原件、质量、配对覆盖或校准支持不足 | 拒判并保留失败原因 |

该协议默认拒绝 calibration fallback；只有实验显式开启时才允许 family/global fallback，并在结果中保留 fallback 原因和 null 样本数。四种状态均不等同于 `aigc_result_v1` 四态、作者身份、侵权责任或法律结论。`eval/pc_scft_eval.py` 当前只使用 3 个标量 fixture，验证组合路由和审计 digest；真实图片、ROI、FPR、coverage-risk、跨生成器和人工复核收益仍需 G0–G6 验收。

### 11.11 G1 普通传播变换与配对审计

PC-SCFT 的 ordinary-propagation null 由 `aigc.propagation_transforms` 生成。调用方提供同一个 `TransformSpec` 给登记原件和 query，得到 `PairedPropagation`；两侧必须使用完全相同的传播族和参数，但父文件哈希可以不同。每个 `PropagationAudit` 至少保留：

```text
parent_sha256
output_sha256
input/output bytes
input/output format
input/output size
transform_family
params_digest
operation_chain
toolchain
config_digest
```

第一版只允许 `identity`、`jpeg_reencode`、`resize`、`center_crop`、`blur`、`screenshot_sim` 和有限步数的 `composite`。输入、像素、尺寸和输出字节受 `PropagationConfig` 限制；动画/多页、未知格式、非法参数和编码失败都返回稳定 reason，不回退到原图成功。该层只提供 G1 hard negative/null 生成，不修改 `aigc_result_v1`，也不输出 AIGC 概率。

### 11.12 真实图片离线契约：`real_pc_scft_manifest_v1`

真实图片接入先走私有离线 runner，避免把比赛期服务的路径读取、异常回退和身份边界带入研究结果。manifest 至少包含：

```text
sample_id, asset_id, role, pair_id, transform_family, split,
sample_path, sha256, authorization_id, authorization_scope, authorization_expiry,
authorized_for_research, origin, generator_family, parent_sample_id,
postprocess_chain, resolution, edit_mask?, region_type_map?, c2pa_status
```

`license` 只能描述许可来源，不能单独证明当前样本获准用于本项目。缺少授权编号、用途范围、期限或明确 `authorized_for_research=true` 时，manifest 校验固定返回 `unauthorized_input`；该样本计入拒绝统计，但不参与 detector 分数。真实图片和 mask 只从 runner 的私有 `--root` 读取，结果 JSON 不保存绝对路径、原图、EXIF 人名或其他不必要的个人信息。

同一 `asset_id` 的 `reference`、`observed` 和 `counterfactual` 必须拥有相同 `pair_id`、传播族和 split，并通过父哈希、`TransformSpec` digest 和输出哈希绑定。`observed` 表示待检查询传播版本，`counterfactual` 表示同一 reference 在同一传播操作下的无编辑版本；不能把 source/query 的普通变换配对直接当成 observed/counterfactual。任何坐标帧、region ID、传播族或版本不一致都应返回 `insufficient`/`review`。

### 11.13 `SourceResidualAdapter` 和 evidence sidecar

第一版 adapter 只包装现有 `source-residual-v1`，不重新读取原始文件，也不把 CLIP cosine 当作局部编辑分数。输入必须来自同一个 `ImageAdapterResult` 的归一化像素产物；输出为版本化 `RegionalScoreBatch`，每行至少带：

```text
sample_id, asset_id, pair_id, role, region_id, bbox_xyxy,
score_raw, quality_score, source_match_score,
detector_version, score_schema, adapter_config_digest,
input_normalized_sha256, model_digest, preprocess_version,
channel_order, dtype, shape
```

`score_raw` 只能是 `[0,1]` 内的有限 raw evidence；质量、来源匹配和 detector 分数必须独立保存。模型或解码失败固定返回 `adapter_failed`、`schema_mismatch`、`quality_insufficient` 等错误，禁止用零向量或零分数伪造成功。sidecar 还要保存 manifest/profile/adapter digest、区域坐标帧、输入/输出哈希、拒判原因和版本信息，供 EvidenceV1 后续锚定。

真实 runner 的顺序固定为：manifest 与授权校验 → 文件 SHA-256 校验 → `ImageAdapterResult` 解码 → reference 对齐 → source-residual raw adapter → observed/counterfactual 区域配对 → ordinary-propagation null profile → `decide_pc_scft` → 只读 JSON 结果。没有足够的真实 null 样本时必须保留 `calibration.evaluated=false`，不能为了得到 candidate 路由而使用 fixture 阈值。

### 11.14 多流冲突感知路由（研究切片）

`aigc/multistream.py` 在 pixel residual 和 phase/spectral 两路之间建立证据边界。两路分数、区域明细、detector/schema、config digest、输入 digest 和 evidence digest 都独立保留；路由器不平均分数，也不把 detector/schema 不同误判为冲突。它只检查每一路自身的 sidecar 完整性、质量门、paired counterfactual 门和 raw-score 一致性。

```text
pixel residual sidecar ─┐
                        ├─ metadata/quality/paired gate
phase spectral sidecar ─┘             ├─ concordant positive -> candidate_edit
                                      ├─ concordant low raw -> null_consistent
                                      ├─ score disagreement -> conflict_review
                                      └─ missing/invalid stream -> insufficient
```

`candidate_edit` 仅表示两路独立 raw evidence 在当前研究 gate 下共同支持进入局部编辑复核；`null_consistent` 只表示与当前普通传播 null 一致，不能转译为人类创作。`conflict_review` 和 `insufficient` 必须 abstain。路由器的 `raw_positive_threshold`、`disagreement_margin` 和 `minimum_quality` 是版本化配置，不是生产阈值或概率校准。

该切片通过 `eval/multistream_eval.py` 验证局部编辑、同源普通传播 hard negative、跨流冲突和频谱流缺失四类 fixture，并检查不丢失独立 stream records。它不接 `ai_server.py`、Go 网关或 `aigc_result_v1` 四态；真实图片、独立 null profile、跨生成器/时间切分、传播链和人工复核收益仍未验证。

这条离线契约通过后，才评估 CLIP/SRM/DCT/重建 adapter；任何新增模型都要沿用同一输入归一化 digest、模型权重摘要、预处理版本和独立校准 profile，不能绕过现有证据链直接接入 `ai_server.py`。

### 11.15 研究扩展的准入顺序

真实图片契约通过后，新增算法按“可回放、可消融、可回滚”的顺序接入：

1. **覆盖式 tile 与质量协变量**：在固定六区域基线之外增加 full-coverage tiles 和 JPEG/质量字段；比较中心裁剪、全覆盖和全图缩放，质量字段只作为 null 分层或 detectability gate。
2. **频域对照流**：加入 phase/DCT/SRM 的独立 raw evidence sidecar，与 pixel residual 分开校准；先做 JPEG/resize/screenshot 分层，不能直接融合成概率。
3. **patch 利用率审计**：记录贡献熵/Gini、top-k removal、patch dropout 和 `object/stuff/background` 支持；单个显眼 patch 不能单独升级为 candidate。
4. **开放集回退和持续适配**：real-only profile、生成器 prototype、EditTrack baseline 和 A10 shadow-mode 适配都建立独立版本；新 profile 不静默覆盖旧校准，必须有旧集回归和回滚记录。

这些扩展只能作为 PC-SCFT 的分支或消融，不能因接入了论文组件就改变 `aigc_result_v1` 的四态边界。每个分支都必须在同一 manifest 上报告普通传播 hard-negative FPR、未知生成器/时间切分、ROI、coverage-risk、P95 和每千张成本；若只在高质量登记原件和局部编辑子集改善，发布表述必须限定为 source-conditioned local-edit forensics。

### 11.16 已实现的 phase/spectral raw evidence 对照切片

`aigc/spectral_evidence.py` 提供版本化的 `source-spectral-phase-v1` 独立证据流，在固定参考坐标帧中记录 phase circular incoherence、amplitude delta、high-frequency delta、质量分数、输入 SHA-256、配置摘要和 evidence digest。若提供同一传播族的 counterfactual，query 分数按配对 delta 校正；缺失 counterfactual 时仍可记录未校正 raw observation，但不得把它升级为 PC-SCFT candidate 或 AIGC 状态。

该切片使用 NumPy 合成网格和固定失败原因验证局部编辑、全局变化、普通传播 hard negative、区域窗口、非有限输入和形状不一致。它与 pixel residual 分开保存和校准，不改变 `aigc_result_v1` 四态，也不产生概率、来源证明、作者身份或法律结论。真实生成器、授权局部编辑、频域校准、传播扰动和线上接入仍属于未完成门。

### 11.17 独立多流 ordinary-propagation null 校准

`aigc/multistream_calibration.py` 在 11.14 的 sidecar 路由前增加逐流 null profile。每个 `StreamNullProfile` 固定 `stream_id`、`detector_version`、`score_schema`、普通传播样本的 group/transform family、null 分数、质量门、样本数和 profile digest；查询分数使用 ties-inclusive 上尾 conformal p-value。pixel residual 与 spectral/phase 不能共用 profile，也不能把不同 schema 的分数拼在一起。

默认 `MultiStreamCalibrationConfig` 使用 `alpha=0.05`、`minimum_null_count=20` 和 `alpha / N` 的 Bonferroni 交集。路由逻辑为：

```text
all streams reject own null       -> candidate_edit
all streams consistent with null  -> null_consistent
mixed/borderline stream decisions -> conflict_review (abstain)
missing/poor/unpaired/mismatch    -> insufficient (abstain)
```

profile digest、每流 p-value、alpha、null 样本数、detector/schema 和 evidence digest 必须与结果一起保存；结果不输出跨流平均分、概率、作者身份或法律结论。没有足够的真实 ordinary-propagation null 时，校准结果必须 `insufficient`，不能沿用 synthetic fixture 的阈值或 profile。

`eval/multistream_calibration_eval.py` 目前只构造四类 synthetic fixture，验证局部编辑、普通传播 hard negative、跨流冲突和缺失流；dataset digest=`63683ed8e11ba44e1597fe9e6f1f6f3cf583004a1a71eb7ead0cb29396771576`。真实授权 manifest、独立流校准、流间相关性校正、跨生成器/时间切分、coverage-risk、人工复核收益和线上 P95 仍需 G0–G6 验收。

### 11.18 Patch contribution 与 forensic distraction 审计

`aigc/patch_contribution.py` 接在 `patch-coverage-v2` 之后，输入必须是同一 detector/schema 下、已经通过质量和来源匹配门的 `PatchDelta`。它不把 mask-out 当作因果解释，而是把“证据是否依赖少数显眼区域”记录成可回放 raw evidence：

```text
positive patch deltas
  -> leave-one-patch-out
  -> rank by weight * positive_delta
  -> top-k mask-out
  -> retained mass / coverage / route flip
  -> stable | distraction_sensitive | insufficient | ambiguous
```

对第 `i` 个已接受 patch，贡献占比为：

```text
contribution_share_i
  = w_i * max(0, delta_i) / Σ_j w_j * max(0, delta_j)
```

其中 `w_i = quality_i ** quality_power * source_match_i * area_fraction_i`。top-k 后保留质量为移除前后正证据质量的比例；leave-one-out 还保留正证据质量、覆盖率、去除后路由和是否发生 route flip。所有数值是 raw evidence，带 `config_digest` 与 `evidence_digest`。

路由规则：`global_like` 若最大贡献超过 `maximum_global_dominance`、top-k 后保留质量低于 `minimum_retained_mass` 或路由翻转，返回 `distraction_sensitive` 并 `abstained=true`；`localized_like` 允许保持局部复核路线，但保留 top-k 崩塌记录；基线 `ambiguous`、质量不足、无正 delta 或 patch 数不足均拒判。该层不输出 AIGC 四态、概率、作者身份或法律结论。

当前 `eval/patch_contribution_eval.py` 只有 5 个标量 fixture，覆盖分布式稳定、全局单 patch 干扰、局部集中、形状歧义和无正证据；dataset digest=`3941c63d151ecf96d9254cb18895dc73b3739f34b8353a1f4a500c33247c969f`。真实 edit mask、semantic-boundary overlap、普通传播 hard negative、跨生成器/时间切分、独立校准和人工复核收益必须在 G0–G6 中单独验证。

### 11.19 联合 ordinary-propagation null 校准

现有 `multistream_calibration.py` 默认对每一路独立校准并采用 Bonferroni 交集。`aigc/joint_null_calibration.py` 是并行研究分支：它不平均 stream score，而是要求校准样本属于同一 ordinary-propagation group，先对各流的 p-value 做 Cauchy 组合，再将组合证据放入冻结的联合 null profile。这样可以保留流间相关性，并检验“多个中等但一致的流证据”是否比 Bonferroni 交集有更好的 selective risk/coverage。

协议字段：

```text
JointNullExample(group_id, p_values_by_stream, quality_score)
JointNullProfile(stream_ids, group_ids, null_evidence_raw, dataset_digest, profile_digest)
JointNullResult(combined_p_raw, calibrated_p_value, evidence_raw,
                p_spread_raw, support_stream_count, route, digests)
```

`combined_p_raw = Cauchy(p_1, ..., p_m)` 只作为组合统计量；`calibrated_p_value` 使用联合 ordinary-propagation profile 的 ties-inclusive 上尾经验 p-value。`p_spread_raw` 超过配置门时无论组合值多低都进入 `conflict_review`；联合 profile 缺失、stream set 不一致、null 样本不足或输入缺流进入 `insufficient`。联合 profile 必须与 query 使用不同 group，并保存 upstream stream profile/config digest；本轮 scalar runner 仅验证基本契约。

候选路由仍需至少两个流达到 `consistency_alpha` 支持，并同时满足联合 calibrated p-value、质量/配对/patch 稳定门。`null_consistent` 只表示当前 query 与该 ordinary-propagation profile 一致，不等于人类创作；所有字段都是 raw evidence，不输出 AIGC 概率、作者身份或法律结论。真实实验必须与单流、Bonferroni、无联合校准和无 counterfactual 做同 manifest 消融，并报告 group/生成器/时间/传播/质量分层的 FPR、coverage-risk、unknown、ROI、P95 和人工复核分钟数。

### 11.20 A9 策略级顺序主动证据获取（工程切片已实现，真实验证待做）

现有 `aigc.evidence_budget.plan_evidence_acquisition` 生成静态动作计划；当前已新增 `sequential_evidence.py`、`policy_calibration.py` 和对应测试/runner，把每次 probe 后的 PC-SCFT、独立多流 null 和 patch contribution 路由结果放入可回放状态机。状态至少保存：

```text
                      completed_actions, remaining_actions, spent_cost,
                      policy_digest)

```

### 11.21 区域级 conformal selection（研究切片）

`aigc/regional_fdr.py` 解决一个与 image-level max statistic 不同的问题：在同一登记原件和同一传播族下，哪些区域有足够证据进入人工复核。它不改变 PC-SCFT 的图像级拒判门，而是保留每个 region 的统计量和选择结果：

```text
observed/counterfactual regional delta
  -> transform_family × quality_bucket × region_id × region_type null
  -> ties-inclusive p_value per region
  -> Benjamini–Hochberg q_value selection
  -> candidate_regions | null_consistent | insufficient
```

profile 只允许单一 `detector_version`/`score_schema`，每个 group/region 只能出现一次；缺失 strata、null 支持不足、低质量、来源匹配不足或 schema 不一致都进入 `insufficient`。查询顺序在 digest 前规范化，结果保存 `p_value_raw`、`q_value_raw`、`null_count`、stratum key、选中区域 ID、profile/config/evidence digest。

`candidate_regions` 只表示“区域人工复核候选”，不等于 AIGC 四态、概率或法律结论。BH 的有限样本有效性受区域相关性、选择规则和分层 fallback 影响；真实实验必须与最大 delta、Bonferroni、多流/联合 null、无 counterfactual 和无质量分层做同 manifest 对照，并按生成器、时间、传播族、region type 和质量报告 empirical FDR、coverage-risk、ROI、route flip、P95 与人工复核分钟数。当前 `eval/regional_fdr_eval.py` 只使用 24 组标量 synthetic null，不能支持正式 FDR 保证。

### 11.22 ONMA natural-manifold raw fallback（研究切片）

无登记原件时，允许使用一个独立于 PC-SCFT 的 real-only fallback，但它只能输出 raw evidence 和开放集路由。`aigc/real_manifold_profile.py` 的输入是经过授权、冻结 manifest 产生的固定维度特征，不直接读取图片，也不接受 `origin` 缺失或非 `real_authorized` 的校准样本。

profile 至少保存：

```text
profile_schema, feature_schema, detector_version, dimension
support_count, group_count, minimum_support
feature_median, robust_scale, energy_threshold, energy_scale
dataset_digest, profile_digest, parent_profile_digest, prototype_version
```

每个特征先按坐标计算 median 和 MAD（带显式 scale floor），再计算有界 `energy_raw`。阈值只能由校准流的固定 quantile 学习；profile 支持不足、查询质量不足、feature schema/detector 不一致或非有限输入必须 fail closed。查询路由固定为：

```text
energy_raw <= threshold                 -> in_distribution
energy_raw > threshold                  -> out_of_manifold
support/quality/feature gate unavailable -> insufficient
profile/schema/detector mismatch        -> profile_mismatch
```

`in_distribution` 只表示“没有被当前 real-only profile 拒绝”，`out_of_manifold` 只表示“偏离当前真实校准流”；二者都不能改写 `aigc_result_v1` 四态。适配必须传入完整 replay buffer 和父 profile digest，生成新版本并保留旧版本可回滚；不得把新样本直接追加到旧 profile 的 digest 或静默更新生产阈值。latent on-manifold hard negative、generator prototype、时间下一窗和真实传播校准属于后续切片。

### 11.23 SCTE triadic adapter（研究切片）

`aigc/scte.py` 是从区域 raw 原语到区域选择器的绑定层。它要求同一登记资产的
`reference + observed query + ordinary-propagation counterfactual` 使用同一
`asset_id`、`pair_id`、manifest/reference/observed/counterfactual digest、传播族和
`transform_spec_digest`。观察行还必须共享 detector/schema、传播链和完整区域集合；
每个区域必须同时有一个 `observed` 和一个 `counterfactual`，质量和 source-match 低于
绑定门时直接拒判。

坐标帧不能只比较“同一 transform family”。`SCTEAlignmentFrame` 固定保存
`aligned_shape`、reference/query offset、`dx/dy`、alignment/resize 版本和 config digest，
observed 与 counterfactual 的几何摘要必须完全一致。通过后才计算：

```text
e_edit(region) = e_obs(region) - e_null(region)
  -> RegionalQueryDelta
  -> regional FDR / BH candidate_regions
```

适配器不改变 delta、不平均流、不生成 AIGC 概率；所有结构缺失、重复区域、资产/配对/传播
链/schema/坐标不一致都返回 `insufficient` 且不输出区域 delta。`candidate_regions` 仍只代表
人工 ROI 复核候选。当前实现和 `eval/scte_eval.py` 只验证 synthetic raw binding、digest
确定性和 fail-closed，真实授权图片、独立 ordinary-propagation null、正式 FDR 控制和线上接入
仍未验证。

### 11.24 MPCF matched placebo / negative-control 对照层（研究切片）

`aigc/mpcf.py` 位于 SCTE/PC-SCFT 的区域 delta 与人工复核路由之间。它把一个目标区域的
`target_delta_raw` 与同一资产、同一 pair、同一 manifest、同一区域/区域类型、同一传播族、同一
quality bucket、同一 `transform_spec_digest`/`coordinate_frame_digest`、同一 detector/schema 的 matched placebo controls 放在一个不可拆分的控制集合中：

```text
SCTE target regional delta
  + matched unedited/decoy controls
  -> ties-inclusive p = (1 + count(control_delta >= target_delta)) / (n + 1)
  -> control median / spread / contrast
  -> candidate_edit | control_consistent | insufficient
```

控制行不能因为不匹配而被静默过滤。任意 `asset_id`、`pair_id`、manifest、region、transform family、`transform_spec_digest`、
`coordinate_frame_digest`、detector、schema、quality bucket、质量分、source-match 分、重复 `control_id` 或最小支持数不满足，
整次评估固定返回 `insufficient`，不暴露控制统计量。结果保留 target/control 原始 delta、控制 ID
和排序后的 `control_deltas`，以及 `config_digest`、target binding digest、controls digest 和
evidence digest，保证同一控制集可回放。

`candidate_edit` 只表示目标超过当前 matched placebo 分布且 contrast 达到门；`control_consistent`
只表示目标与控制分布一致。两者都是 raw evidence 路由，不映射到 `aigc_result_v1`、AIGC 概率、
作者身份或法律结论。MPCF 与 ordinary-propagation null 的关系是“先排除传播解释，再检验同资产
负对照”；与 patch contribution 的关系是“前者比较匹配控制分布，后者审计少数 patch 去除后的
证据稳定性”，不得相互替代。

真实实验必须冻结控制构造规则和控制集污染检查，并在同一授权 manifest 上比较：普通传播 null、
matched placebo、patch mask-out、两者联合和无 counterfactual。报告按生成器、时间、传播族、
quality bucket、region type 的 FPR/coverage-risk、unknown/review、ROI、route flip、P95 和人工
复核分钟数；还要测试 logo/边界/压缩纹理 decoy、空间不重叠控制、multiple testing 和控制集
不足的拒判率。当前 `eval/mpcf_eval.py` 只有五个 scalar synthetic cases，不能支持正式统计保证、
AIGC 效果或上线接入。

### 11.25 Source-Conditioned Crop-Consensus（研究切片）

`aigc/crop_consensus.py` 对同一 `reference/observed/counterfactual` pair 的多个 crop
view 做跨视角证据审计。每个 view 必须共享 `consensus_id`、`asset_id`、`pair_id`、
`manifest_digest`、`canonical_frame_digest`、`transform_family`、`detector_version` 和

### 11.33 `reference_specificity_v1`：盲参考特异性门

该层位于“候选原件已匹配”与“局部编辑候选路由”之间。候选 `reference_id` 的 observed-minus-null contrast 必须与同一 query 的多个 decoy references 对照；decoy 共享 query、manifest、canonical frame、transform family、detector/schema、operator、quality bucket 和 source-match bucket，但 reference identity 必须不同。

最小输入字段：

```text

candidate_reference_digest / candidate_contrast_raw
decoy_reference_digest / decoy_contrast_raw / decoy_id
manifest_digest / canonical_frame_digest / transform_spec_digest
operator_digest / detector_version / score_schema
quality_bucket / source_match_bucket
selection_policy_digest / decoy_pool_digest
```

计算 `decoy_upper_quantile_raw`、ties-inclusive `decoy_exceedance_p_value_raw` 和
`specificity_gap_raw = candidate_contrast_raw - decoy_upper_quantile_raw`。只有评估 query 与 decoy
选择/校准分区不同、支持数达到配置门、候选 contrast 过正向门且 gap 达到门时才进入
`reference_specific_candidate`；候选与 decoy 接近时进入 `reference_ambiguous`，候选与 null 一致时进入
`reference_null_consistent`，其余绑定或支持问题进入 `insufficient`。所有结果保留 candidate/decoy
raw evidence 和 digest，不改写 `aigc_result_v1`。

实现约束：`decoy_exceedance_p_value_raw` 固定为 `(1 + exceedances) / (n + 1)`，不把小样本的零值写成显著性；因此在 `alpha=0.05` 下至少需要 20 个 decoy 才可能通过 p-value 门。候选和 decoy contrast 各在 `[-2, 2]` 时，`specificity_gap_raw` 的校验范围为 `[-4, 4]`。当前 `aigc/reference_specificity.py` 已完成无重量契约，公共导出和轻量 runner 已接入；真实参考库、decoy 独立性和 false-match rate 仍未验证。

### 11.34 `evidence-graph-v1`：跨版本拓扑一致性审计

```text

trajectory_inconsistent | insufficient
```

拓扑/绑定/输入证据缺失统一 `insufficient`；普通传播新支持超过门为 `propagation_leak`；兄弟差异超过门为 `branch_conflict`；声明 mask 外支持或后代 persistence 不足为 `trajectory_inconsistent`。所有路由都是 raw audit route，不进入 `aigc_result_v1`、线上 `/check` 或法律结论。真实版本图、授权传播链、编辑 mask、时间/生成器切分、FPR/coverage-risk、ROI、P95 和人工收益仍待 G0–G6 验证。

### 11.37 `invariant-effect-v1`：跨视角 × 多算子不变性效应检验（D-058）

D-058 是对 D-050/D-051/D-052 的选择性组合层。它不重新提取特征，也不平均不同 detector 的分数；调用方必须先执行并绑定 observed/null 的 matched intervention，再把每个 `view_id × operator_id` 的 raw effect 交给本层。研究问题是：局部编辑的 source-conditioned effect 是否同时跨越 canonical view 和预注册 operator 保持，而普通传播 null 是否不会产生同样的 effect。

每个 observation 至少保存：

```text
asset_id / pair_id / manifest_digest / canonical_frame_digest
view_id / view_digest / operator_id / operator_config_digest / execution_digest
detector_version / score_schema / null_profile_digest
quality_score / source_match_raw / observed_effect_raw / null_effect_raw
```

在完整 binding 和支持门通过后，对每个 view/operator 计算 `contrast_raw = observed_effect_raw - null_effect_raw`，再以质量×source-match 做 raw 权重。跨轴统计保留低分位 `invariant_effect_raw`、正向支持比例、离散度和有限样本 ties-inclusive p-value；低分位而非最大值用于抑制单个显眼 patch 或单个 mask-out 算子造成的 winner's curse。p-value 只表示相对冻结 ordinary-propagation null 的 raw route 证据，不是 AIGC 概率。

固定路由为：

```text
invariant_candidate       # 跨 view/operator 的低分位 effect、稳定性和 null p-value 均通过
null_consistent            # 支持完整但 effect 与 ordinary-propagation null 一致
view_operator_inconsistent # 支持完整但跨 view/operator 离散度或正向比例不稳定
insufficient               # 绑定、质量、支持、执行或 profile 缺失
```

该层的可证伪增量不是“又一个 detector”，而是把 few-patch bias、operator-specific shortcut 和传播 null 误激活放进同一个 selective gate。真实评测需比较单视角、单算子、仅 view consensus、仅 operator stability、完整 invariant-effect 和去掉 null 的消融；必须同时报告 ordinary-propagation FPR、ROI/边界 F、risk@coverage、unknown/review、view/operator route flip、P95、每千张成本和人工复核分钟。没有真实 views、operator masks、独立 null 和时间/生成器切分时，结果只能是契约或 `insufficient`，不能接入 `aigc_result_v1`。

### 11.38 `selection-aware-calibration-v1`：检索 winner 的选择后分层校准（D-060）

SAEC 是 D-054/D-058 之后的独立 raw-evidence sidecar。它处理的对象不是 detector 分数本身，而是“先从多个参考中选择 winner，再评价 winner”这一选择过程。调用方必须先完成 D-054 的候选/decoy contrast 和 D-058 的 view/operator stability，再把 scalar contrast 与独立 ordinary-propagation calibration groups 交给本层。

#### 11.38.1 输入契约

每个 query 绑定以下字段：

```text
query_digest / query_group_id
candidate_reference_digest / decoy_reference_digests
candidate_contrast_raw / decoy_contrasts_raw
invariant_route

selection_policy_digest
selection_split_digest / calibration_split_digest / evaluation_split_digest

```

每个 calibration group 绑定：


#### 11.38.2 统计和路由

对每个 calibration group 保存同一选择策略和固定 decoy 数下的 `max_statistic_raw`。候选的选择后 raw p-value 为：

```text
selection_p_value_raw =
  (1 + count(calibration.max_statistic_raw >= candidate_contrast_raw))
  / (1 + calibration_group_count)
```

同时计算 decoy 上分位数和 `specificity_gap_raw = candidate_contrast_raw - decoy_upper_quantile_raw`。该 p-value 是有限样本、ties-inclusive 的选择后校准统计量，不是 AIGC 概率。

固定路由：

```text
selection_specific_candidate  # raw contrast、decoy gap、selection p、D-058 稳定性均通过
selection_ambiguous           # contrast 足够但选择后支持不足、并列或 D-058 不能升级
null_consistent               # ordinary propagation 或 contrast 与 null 一致
insufficient                  # 绑定、分层、split、支持、质量或执行门失败
```

允许的 profile level 由调用方显式声明（例如 `exact`、`family_transform_quality`、`transform_quality`、`global`）；本模块不在支持不足时静默改变 level。任何 fallback 必须产生新的 profile digest、support count 和 evidence digest。

#### 11.38.3 结果卫生和真实验收

真实实验必须在同一冻结 manifest 上比较 query-only、D-054、D-058、SAEC、D-054+SAEC、去 decoy 和去 null；按 known/unseen generator、next-time-window、传播族、质量桶和错误参考分层，报告 reference false-match、ordinary-propagation FPR、risk@coverage、ROI/边界 F、unknown/review、route flip、P50/P95、每千张成本和人工复核分钟。没有 G0–G6 真实数据门时，SAEC 只能输出 raw route 或 `insufficient`。

### 11.39 `selection-aware-acquisition-v1`：选择感知的限预算证据采集（D-061）

SAEA 是位于 D-054、D-058、SAEC 之后的独立策略层。它读取已经执行的选择、普通 null、视角、算子和质量证据，按注册策略选择下一项 probe；它不运行模型、不重算分数，也不把动作结果直接映射为 AIGC 状态。

#### 11.39.1 输入、动作和状态

状态必须绑定：

```text

detector_version / score_schema

completed_actions[]
```

第一版只允许五个预注册动作：

```text
append_matched_decoy     cost=1
build_matched_null       cost=2
alternate_view           cost=2
alternate_operator       cost=2
realign_quality          cost=2
```

每个 `SelectionAwareObservation` 必须保存 `action_id`、顺序号、当前 state input digest、输出 digest、允许的 raw update、成功/失败和可选耗时。动作 ID 不得重复；输入 digest、动作顺序、成本和 `max_actions`/`max_cost_units` 任一不匹配即固定 `insufficient` 或 `review`。

#### 11.39.2 策略和结果卫生

策略优先修复质量/对齐和来源匹配，再处理 selection ambiguity、ordinary-null support、view/operator instability；无可注册动作时返回 `null_consistent`、`review` 或 `insufficient`。失败 probe 固定 `review`，不回退为“没有问题”。结果至少保存 route、status、abstained、reason、steps、spent/remaining cost、policy/input/trace/evidence digest；禁止 probability、confidence、作者、版权和法律字段。

`selection_specific_candidate` 只表示当前 raw gates 在同一回放 trace 上通过，不代表 AIGC 概率。SAEA 的组合价值必须在固定动作预算、相同 manifest 和独立评测 split 上与固定顺序 A9 对照；仅有“会继续采集证据”不能称为算法创新。

#### 11.39.3 当前实现与真实验收

当前代码范围为 `aigc/selection_aware_acquisition.py`、`tests/test_selection_aware_acquisition.py` 和 `eval/selection_aware_acquisition_eval.py`；它们只使用 scalar state/fixture，不接 `ai_server.py`、Go 网关、`aigc_result_v1` 或线上服务。真实实验必须加入错误 reference、普通传播 hard negative、局部编辑、未见生成器、下一时间窗、低质量传播和 probe executor failure，并比较 fixed-order A9、SAEA、去 decoy、去 null 和 no-extra-probe 的 risk@coverage、FPR、ROI、route flip、成本和人工复核分钟。未满足 G0–G6 前，SAEA 只能输出 raw route、`review` 或 `insufficient`。

### 11.40 `source-conditioned-propagation-tree-null-v1`：D-062 树级普通传播 null

SCPTN 位于 D-054、D-058、SAEC 和 SAEA 之后，消费已经计算并绑定的 paired local delta。它把同一登记资产的普通传播版本表示为单根有序树，以树而不是单个传播版本作为统计单位，按固定 `transform_family × quality_bucket × time_bucket × source_match_bucket` 分层，对树内选择后的最大 delta 建立独立 null profile。

首轮契约包括 `PropagationTreeNode`、`PropagationTree`、`PropagationTreeNullProfile` 和 `SCPTNResult`。节点必须绑定 `asset_id/tree_id/version_id/parent_version_id`、节点顺序、传播分层、质量/来源匹配和 `operation_scope`；树必须单根、父节点存在且先于子节点、版本唯一、同一资产和同一分层；profile 只接受独立资产的 `ordinary_propagation` calibration trees，并绑定 manifest、calibration split、detector/schema、selector config、support tree IDs 和 digest。

树级选择统计量固定为：

```text
M_tree = max_{eligible version in tree} paired_delta_raw
p_tree = (1 + count(null_M >= M_tree)) / (1 + null_tree_count)
```

路由固定为 `tree_specific_candidate`、`tree_selection_ambiguous`、`tree_null_consistent` 和
`insufficient`。普通传播查询树、低于 raw delta gate 的树和未超过 tree-level null 的树都不能转成“人类创作”；任何拓扑、授权、split、stratum、schema 或支持不足都 fail closed。结果不修改 `aigc_result_v1`，不输出 probability、作者、版权或法律字段。

SCPTN 与 QuAD/ReWIND 的近重复质量聚合、IAPL 的最高置信 view 选择、BCEA 的 answer/abstain/acquire 和 SAEC 的 scalar winner 校准有明确边界：SCPTN 不训练 detector、不做多视图 TTA，且新增的是来源条件的传播树相关性与树内 max-statistic null。只有在同一授权 manifest 上相对逐版本 null、去树相关性、D-054、SAEC、SAEA 和完整组合降低普通传播 FPR、reference false-match、risk@coverage 或人工复核分钟，才可讨论研究增量。

当前代码范围为 `aigc/propagation_tree_null.py`、`tests/test_propagation_tree_null.py` 和
`eval/propagation_tree_null_eval.py`；只覆盖 schema、拓扑、选择统计、split/digest 绑定和合成 fixture。
真实传播树、局部编辑 mask、未见生成器/下一时间窗、同预算对照、ROI、P95、成本和人工收益仍待 G0–G6，未通过前保持阶段 7 离线 raw sidecar。

### 11.41 `retrieval-aware-tree-null-v1`：RSCPTN 研究契约（D-063，最小契约已完成，待真实评审）

RSCPTN 只作为 SCPTN 之后的阶段 7 研究 sidecar，用于检查“检索候选和传播树是否可信”这一前置条件。它不修改 SCPTN 的结果对象，不接线上服务，也不把近重复相似度当成来源概率。

检索事件必须按同一冻结策略完整回放：

```text

```

最小输入绑定 `retrieval_policy_digest`、retrieval archive/decoy injection digest、候选集合和数量、candidate rank、`membership_tier`（`exact|matched|uncertain|outside`）、tree/parent/branch/depth、传播/质量/运输桶、canonical frame、detector/schema、selection key、动作预算、三类 split、授权期限、输入和 evidence digest。`uncertain` 与 `outside` 只能计入污染诊断，不得作为软权重参与统计。

当前代码范围为 `aigc/retrieval_aware_tree_null.py`、`tests/test_retrieval_aware_tree_null.py` 和 `eval/retrieval_aware_tree_null_eval.py`，已接入公共导出和轻量验证；最小真实对照仍包括 query-only、QuAD-like、SCPTN、D-054、SAEC、SAEA、去检索重放、去污染门和逐节点 null。必须覆盖 clean/missing/false-positive/poisoning retrieval stress、普通传播、局部编辑、wrong-reference、unknown generator 和 next-time-window；G0–G6 未通过前保持 `raw/review/insufficient`。

## 16. `propagation-envelope-audit-v1`：PE-CEA-v1 传播严重度包络审计（D-070，离线契约）

### 16.1 目标和边界

GlobalForge、DailyBench 和 MIRAGE 说明，干净 benchmark 的局部伪影和整图检测在真实传播、现代生成和对象级编辑上会明显失效。PE-CEA 不再把 ordinary-propagation 只压成一个总体 scalar，而是把同一 source/query/counterfactual 配对沿传播严重度路径展开，在每个层级建立独立 null envelope，判断局部干预效应是否持续超出同层普通传播。

它是阶段 7 的 raw-evidence 研究适配器，不加载模型、不读取图片、不改变 `aigc_result_v1`，不输出 AIGC 概率、作者、版权或法律字段。没有授权 manifest、独立 null 和外部切分时，结果只能是 `null_consistent`、`curve_inconsistent` 或 `insufficient`。

### 16.2 输入和 profile

`EnvelopeObservation` 必须绑定 `asset_id`、`group_id`、`severity_level`、`transform_family`、`operation_scope`、observed/counterfactual raw delta、质量、source match、`manifest_digest`、`canonical_frame`、detector/schema 和 `split_digest`。内容编辑 observation 还需要 `edit_mask_digest`；ordinary-propagation observation 不允许携带编辑标签。一个 profile 只接受独立资产的 ordinary-propagation paired groups，按 severity level 保存排序后的 null delta statistics、support、upper envelope、profile/dataset digest 和配置 digest。

### 16.3 统计和路由

对查询的每个严重度层计算：

```text
delta_s = observed_local_effect_s - counterfactual_local_effect_s
margin_s = delta_s - upper_null_envelope_s
auc_excess_raw = Σ_s weight_s · max(0, margin_s) / Σ_s weight_s
positive_level_fraction_raw = Σ_s 1[margin_s > 0] / number_of_levels
```

层级 p-value 使用 ties-inclusive 有限样本 raw 统计，不被解释为 AIGC 概率。固定路由为 `envelope_candidate`、`null_consistent`、`curve_inconsistent`、`insufficient`。`envelope_candidate` 还必须满足内容编辑 scope、最低层级支持、mask/binding 完整、正向层级比例达配置要求和曲线不连续性门；ordinary-propagation scope 永远不能升级为 candidate。

### 16.4 与既有模块的边界

`paired_delta_calibration` 负责单组最大区域 delta 的 scalar null；`propagation_stability` 负责版本间漂移；SCPTN/RSCPTN 负责传播树和检索选择相关性；spectral/phase 只是可替换 observation stream。PE-CEA 只新增 severity-stratified envelope、曲线级超额面积和不连续性拒判，不重复实现 detector、检索器或 conformal 理论。

### 16.5 真实验收和回滚

真实实验必须在同一冻结 manifest、相同 action budget 和 candidate coverage 下比较 query-only、paired delta、propagation stability、tree null、PE-CEA 和去 envelope 消融；覆盖 local edit、ordinary propagation、wrong-reference/decoy、已知/未见生成器、下一时间窗、JPEG/resize/blur/截图/再数字化。报告 ordinary-propagation FPR、reference false-match、risk@coverage、ROI/边界 F、曲线保持率、route flip、P50/P95、每千件成本和人工复核分钟。若收益只来自更多 unknown、只在 IID/closed-set 成立或 P95/成本恶化，撤回为 propagation-audit sidecar。

首轮代码范围为 `aigc/propagation_envelope.py`、`tests/test_propagation_envelope.py`、`eval/propagation_envelope_eval.py`、公共导出和轻量验证脚本；不接线上服务。回滚删除上述文件、文档段落和任务登记即可。

## 18. `MetadataMutationGuardV1`：商业 sidecar 目标契约（D-072，阶段 6 阻塞）

该契约用于私有 DAM/MAM 或内容发布链的只读 shadow，目标是回放“导入/编辑/导出后凭证和标识发生了什么”，不替代 DAM、C2PA viewer、图搜或法律审查。

### 18.1 导入/导出事件

每个事件至少保存：原始字节 digest、导出字节 digest、manifest/claim digest、`c2pa_spec_version`、
validator/trust-list version、hard/soft binding、validation status/errors、AI disclosure raw value、
IPTC/GB 标识原值、provider/platform/content ID、写入工具/版本、变更前后字段 digest、删除墓碑、留存
策略和 replay status。crJSON 只能作为派生交换视图，不能独立验证；缺少字段不得静默补齐。

### 18.2 路由和商业验证

固定 raw route 为 `pass`、`gap`、`conflict`、`insufficient`。签名有效只说明结构/绑定/信任链达到对应验证层级，不能说明内容真实、作者或版权；缺标识也不能自动说明人类创作。P0/P1 shadow 只验证字段完整率、签名/标识失效回放、冲突复核分钟、删除/恢复回放、跨租户权限和人工基线；客户、价格、收入、SLA、合规认证和生产部署均必须由授权试点单独验证。

首轮只改 `configs/`、`artifacts/`、sidecar validator 和离线 fixture 规划，不在阶段 1–5 完成前改线上接口。若无法取得原始字节、责任人、删除墓碑或重复任务，固定为 `insufficient` 并回到访谈/fixture。

## 19. SAEA 的开放集/回放绑定门（D-073，SS-025）

实现状态：SS-025 已完成离线契约。`SelectionAwarePropagationGate` 和扁平化 state
同时绑定 generator/replay route、profile/input/evidence/event/policy digest；unknown、冲突、裸
candidate、支持不足和 digest 不一致均 fail-closed，普通传播固定为 `null_consistent`。专测和

`selection-aware-acquisition-v1` 只负责在固定预算内选择下一项证据动作。它的结果不能脱离上游来源和生成器门单独解释。候选就绪条件必须额外绑定：

```text
generator_route ∈ {known_family_supported, generator_evidence_not_required}

```

以下任一状态都固定拒判或复核：`open_set_unknown`、`conflict_review`、`insufficient`、`not_evaluated`、profile/support/digest 缺失或回放不一致。`real_consistent` 只作为中性 generator evidence，不得映射为 `human_supported` 或 candidate。普通传播仍只能进入 `null_consistent`。

## 20. `CrossFittedAssetGeneratorEvidenceAuditV1`：CFAEA-v1 目标契约（D-075，P0 design-ready / deferred）

CFAEA 只属于阶段 7 的研究 sidecar，前置条件是 ALG-001 的真实 archive/index 事件回放和 G0–G6。它不修改线上 `Evidence`、`aigc_result_v1`、`ai_server.py` 或 Go 网关，也不训练新的 detector。

### 20.1 A/B 选择与证据分流

索引 A 必须从冻结 archive/index snapshot 重算 candidate 顺序、membership、传播树、winner、region proposal 和 ordered action trace，并封存 `selection_trace_digest`；索引 B 只能 direct lookup 这个冻结 winner，不能返回新的 top-K、换 reference、改 region/mask/operator 或重拟合 null。A/B 至少在 archive/time、index/feature build、view/operator/evidence stream 三轴中独立两轴；B 缺失、删除、过期、tie、poisoning、wrong-reference 或 replay digest mismatch 均拒判。

### 20.2 双注册表和五折 cross-fit

`asset_registry` 只包含登记原件、版本/传播树、canonical frame、quality/source-match、edit mask 和 ordinary-null；`generator_registry` 只包含 generator family、real-only/open-set profile、detector/schema、support、C2PA/水印等可替换信号。generator registry 不得参与 A 的 rank、winner、region proposal 或 source-null profile。默认按 asset/group、generator family 和时间执行五折 cross-fit：profile/calibration 用 `-k`，selection A 和 audit B 用 `k`，评价结果封存后才聚合；当前 query、派生版本、B 输出和 evaluation winner 不得进入 `-k` profile。

### 20.3 输入、统计量和路由

`CFAEAInputV1` 至少绑定 `research_manifest_digest`、授权/隐私/删除字段、asset/group/query/split/fold、A/B archive/index/feature/schema digest、candidate/membership/tree/selection trace、fixed winner、canonical frame、observed effect、ordinary-null effect、generator control、support、quality/transport/time/source-match bucket 和 evidence digest。固定 raw route 为：

```text
holdout_consistent
source_generator_conflict_review
generator_only_unknown
ordinary_propagation_consistent
selection_contaminated
missing_holdout
open_set_unknown
insufficient
not_evaluated
```

在 fixed winner/region/operator/canonical frame 下，source contrast 采用
`c_B = observed_effect_B - ordinary_null_effect_B`，`p_B_raw` 采用独立 matched ordinary-null 的
ties-inclusive finite-sample rank；它是 raw evidence，不是 AIGC probability。只有 B direct lookup、source
null、generator/open-set、权限和 replay 门全部通过，才可写 `holdout_consistent`。普通传播只能进入
`ordinary_propagation_consistent`/`insufficient`，generator-only 只能进入 unknown，冲突必须 review。

### 20.4 研究验收、实现顺序和回滚

真实对照必须在同一 manifest、candidate coverage、action budget 和人工预算下比较 query-only、ALG-001/RSCPTN、SIPA、generator-only、CFAEA 完整协议以及去 ordinary-null、decoy、replay、cross-fit、GR、B-reselect 的消融，报告 ordinary-propagation FPR、reference/decoy false-match、poisoning route flip、risk@coverage、unknown/review、ROI/边界 F、P95、成本和人工分钟。若只增加拒判、降低 coverage、改善 closed-set/IID、B/registry 泄漏或成本恶化，撤回为 provenance/confounder audit sidecar。

获批后才按 contract → replay adapter → generator registry adapter → real evaluation runner 四个可回滚切片实施，目标文件限 `aigc/`、`eval/`、`tests/` 和 `docs/07`；在真实数据门前不创建模块、不接线上、不读取客户数据。

## 21. `AttackRobustSourceConditionedMatchedInterventionV1`：AR-SCMI-v1 目标契约（D-076，后置 deferred）

AR-SCMI 是 CFAEA/PC-SCFT 之后的反取证压力扩展，当前只登记研究假设，不批准实现。它复用已登记原件、canonical frame、matched ordinary-propagation null、局部 intervention 和 evidence replay，不新增通用 detector。

### 21.1 压力配对

对 observed query 与同资产/同 pair/同传播族 ordinary-null 施加同一份预注册且已授权的攻击/反取证压力 profile；压力操作、版本、参数、随机种子、输入/输出 digest 和失败状态必须逐项封存。攻击压力只能改变证据压力条件，不能改变 reference、mask、canonical frame、operator、detector/schema 或 null profile；未经授权的水印移除、身份推断或第三方内容处理不得进入项目数据。

### 21.2 robust lower envelope 与路由

对每个压力等级比较 `observed_effect - null_effect`，按预注册聚合得到 robust lower envelope、spread、route flip 和支持量。固定 raw route 为 `attack_stable_candidate`、`attack_fragile_review`、`null_consistent`、`insufficient`；任一压力层输入、配对、授权、null、operator 或 replay 不完整即拒判。该 envelope 不是概率、置信度、抗攻击保证或 AIGC 事实。

### 21.3 真实门和退出

必须在同一冻结 manifest、同一压力预算和同一人工预算下比较 PC-SCFT、CFAEA、去压力、去 null、random/decoy mask、wrong-reference、已知/未见生成器、下一时间窗、JPEG/resize/截图/再数字化和授权反取证操作；报告 ordinary-propagation FPR、reference false-match、risk@coverage、ROI/边界 F、route flip、P95、成本和人工分钟。没有 G0–G6、独立 null、外部切分、授权压力和可回放证据前不写代码；若收益只存在 clean/IID、只靠更多拒判或无法重放，撤回为 attack-audit sidecar。


## 22. D-077 TLEG-v1 生命周期前置门

TLEG 是所有候选 evidence route 的前置 raw gate。它与 AIGC detector、RSCPTN/CFAEA 选择校准和 AR-SCMI 压力验证正交，只判断一条证据是否在指定查询时点、租户和生命周期状态下可被回放。

### 输入契约

每个 `LifecycleEvidenceEvent` 至少包含：

```text
event_id, tenant_id, asset_id, version_id, parent_version_id
query_as_of, snapshot_created_at, index_epoch
effective_from, effective_to, monotonic_seq, prev_event_digest
asset_state, deletion_tombstone_digest, retention_policy_digest
authorization_digest, access_digest, split, time_window
selection_digest, replay_digest, evidence_digest
```

`asset_state` 只允许 `active`、`deleted`、`restored`、`expired`。规范化字段后计算 replay digest；事件顺序、快照、权限或删除绑定被篡改时，结果必须改变或拒判。

### 校验顺序与输出

1. 校验必填字段、时间格式、租户和资产/版本父子关系；失败为 `insufficient`。
2. 校验 `snapshot_created_at <= query_as_of`、事件有效区间和 profile/index epoch；未来证据固定 `future_event_leak`，旧快照固定 `stale_snapshot_review` 或 `profile_stale`。
3. 校验事件 `monotonic_seq` 唯一、连续、`prev_event_digest` 链接正确；重排、重复和断链固定 `insufficient`。
4. 校验删除墓碑、恢复的新版本和 replay digest；删除后仍可见固定 `tombstoned_insufficient`，删除/恢复回放不一致固定 `deletion_replay_mismatch`。
5. 校验授权、留存、访问 digest、split/time-window 和同资产隔离；不一致固定 `insufficient` 或 `not_evaluated`。

固定 raw route 为 `lifecycle_consistent`、`future_event_leak`、`stale_snapshot_review`、`tombstoned_insufficient`、`deletion_replay_mismatch`、`profile_stale`、`insufficient`、`not_evaluated`。输出只保留 route、原因、as-of 摘要、支持量和 replay digest；不得包含 AIGC probability、作者、版权、侵权或“人类创作”字段。`lifecycle_consistent` 只表示允许下游继续。

### 与现有链路的关系

TLEG 可以包在 `RetrievalEventReplay`、RSCPTN、ALG-001、CFAEA 或后置 AR-SCMI 之前；普通传播、unknown/open-set、source conflict 和 detector 失败仍由各自上游/下游门处理，不能由 TLEG 修复。首轮只在 `aigc/`、`tests/`、`eval/` 和轻量验证脚本中实现，不改 `aigc_result_v1`、比赛版服务、Go API 或存储 schema。

### 23.1 数据前置门

## 24. CIVG-v1 counterfactual intervention validity gate（D-080 / SS-033）

CIVG 是 PC-SCFT/SCTE 之前的输入质量门。它不计算 detector 分数、不拟合 ordinary-null，也不输出 AIGC 状态；它只判断一条 observed/query/counterfactual 证据三元组是否足够有效，能否继续进入下游 raw evidence。

其中 target effect、non-target preservation、mask leakage、semantic/causal consistency 和 minimum intervention 应优先来自 mask/几何、质量、独立语义或人工复核等 detector-independent validity signals；不能用待评估的 PC-SCFT 分数反向决定输入是否有效，否则会把下游 detector 的选择泄漏到 counterfactual/null 统计。阈值只能由 calibration/development split 冻结，evaluation split 不得重拟合。

### 24.1 输入契约

`CIVGObservationV1` 至少保存：

```text
asset_id, pair_id, intervention_scope
reference_digest, observed_digest, counterfactual_digest
pair_binding_digest, ordinary_null_digest, target_mask_digest
operator_digest, execution_digest, canonical_frame
detector_version, score_schema
authorized, executed
quality_score, source_match_score
target_effect_raw, non_target_preservation_raw, mask_leakage_raw
semantic_consistency_raw, causal_consistency_raw, minimum_intervention_raw
```

所有 digest 必须是 SHA-256；`intervention_scope=content_edit` 才可能成为有效干预，`ordinary_propagation`、`decoy` 和 `wrong_reference` 永远不能进入 `valid_intervention`。缺少授权、执行记录、pair/null/mask/operator/frame 绑定或任一必需 validity signal 时固定 `insufficient`，不能用其他分数补齐。

### 24.2 路由和阈值

默认配置只用于 synthetic contract，阈值不是生产阈值：

```text
quality_score >= 0.35
source_match_score >= 0.60
target_effect_raw >= 0.20
non_target_preservation_raw >= 0.80
mask_leakage_raw <= 0.20
semantic_consistency_raw >= 0.60
causal_consistency_raw >= 0.60
minimum_intervention_raw >= 0.60
```

- `valid_intervention`：所有输入门和阈值通过，`downstream_eligible=true`；只代表 counterfactual 输入有效。
- `spillover_review`：非目标保持或 mask leakage 失败，但仍保留可供人工审查的完整 trace。
- `counterfactual_invalid`：目标未生效、语义/因果一致或最小干预失败，或 scope 不是 `content_edit`。
- `insufficient`：授权、执行、绑定、质量、来源匹配或必需指标缺失。

结果只能保存 raw score、reason、route、support、绑定 digest 和 config/evidence digest；禁止 probability、confidence、author、training、copyright、infringement 和 legal 字段。普通传播、decoy、wrong-reference 和 invalid counterfactual 不得被下游升级为 candidate。

### 24.3 真实评测门

在冻结授权 manifest、真实 edit mask 和独立 ordinary-null 后，比较 PC-SCFT 与 PC-SCFT+CIVG，至少覆盖目标未执行、mask 外真实变化、因果连带变化、普通传播 hard negative、wrong-reference/decoy、未见生成器和下一时间窗。相同 candidate coverage、action budget 和人工预算下，报告 mask 外 LPIPS/语义保持、target effect、ROI boundary-F、ordinary-propagation FPR、reference false-match、route flip、unknown/review、P95 和人工复核分钟。收益若只来自增加 `insufficient/review`、降低 coverage 或只在单一 operator/合成 fixture 成立，则撤回为输入质量审计 sidecar。
