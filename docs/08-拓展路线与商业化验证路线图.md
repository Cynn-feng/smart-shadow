## 1. 研究和产品的共同问题定义

Smart Shadow 要解决的不是“对任意图片给出一个 AI 概率”，而是帮助拥有图片资产的机构回答四个可复核问题：

1. 这份文件是否能和登记原件、版本链或可信来源凭证对应？
2. 查询图和登记原件之间是否存在超出普通传播的局部变化？
3. 这些变化是否同时得到独立 raw evidence、传播族 null 和质量门支持？
4. 证据不足或证据冲突时，能否明确拒判并把剩余工作交给人工？

因此系统输出是来源/版本证据、候选相似作品、局部 raw evidence、复核路由和可回放证据包。它不自动认定作者、法律权利、人类创作或侵权责任。

## 3. 商业价值如何被证伪

当前不根据公开版权登记量、竞品官网价格或论文准确率估算收入。每个试点只核算客户真实工作流的增量价值：

```text
月度价值
= 节省的初筛/复核分钟 × 客户单位分钟成本
  + 减少的重复检索、外包和证据整理费用
  + 被客户采纳的证据包数量 × 客户认可的单包价值
  - API、存储、模型推理和人工复核成本
```

四周试点必须冻结客户授权 manifest、人工基线和输出版本，并记录：

- 每千张审核的 P50/P95 时间和人工复核分钟；
- Recall@K、作品级 hard-negative FPR、`unknown` 比例和误报复核时间；
- 证据包一次通过率、缺字段率和实际被投诉/授权清查流程采用的数量；
- API 成功率、恢复时间、每千张基础成本和每个复核席位的周使用量。

继续商业验证的门是：客户授权和权限可留档、无严重假成功或数据越界、至少一个真实工作流每周重复使用，并且效率或证据整理成本出现客户认可的改善。只演示一次命中、只提高 raw score 或只得到论文 benchmark 高分都不满足商业门。

## 4. 论文如何转成 Smart Shadow 的对照

论文证据详见 [06-AIGC算法创新调研.md](06-AIGC算法创新调研.md) 和 [research/外部证据索引.md](research/外部证据索引.md)。按问题而不是按模型名称组织对照：

| 问题 | 论文/方向 | 迁移到本项目的形式 | 必须保留的边界 |
| --- | --- | --- | --- |
| 无原件 fallback | RealNet、SACG、real-only/one-class 方向 | A0/A1 单图和 real-only profile | 无原件结果不能替代登记原件、来源凭证或人类创作证明 |
| 局部编辑定位 | X-Edit、EditTrack、Rethinking Where to Edit、GAP-SAM | A2/A3 ROI、source/target 流、语义边界和 mask-out 对照 | 外部 mask/编辑器结果不能外推到客户授权图库 |
| 传播和压缩 | Phase Spectrum、AIGIBench、DADL | G1 传播族 null、phase/pixel 独立流、质量分层 | 普通传播一致不等于人类创作 |
| 开放集和拒判 | DACOM、B-Free、BCEA、RealNet | unknown、conformal p-value、预算化 probe、coverage-risk | p-value 是相对校准 null 的证据，不是 AIGC 概率 |
| 生成器来源 | SAGA、生成器 provenance、model lineage | `generator_hypotheses` 独立 sidecar 和支持集 digest | lineage 不是图片作者、版权或内容真实性 |
| 可解释和证据包 | Skyra、FakeXplain、Forensic Self-Descriptions | ROI、patch attribution、原始分数和人工意见回放 | 文字解释不能覆盖 raw evidence 或人工结论 |
| 视频/多模态 | AIGVDBench、FVBench、CoCoVideo、Omni-Fake | P2 的时间/模态 sidecar 和慢速复核 | 暂无视频数据、部署或跨模态效果证据 |

Smart Shadow 允许的最小创新主张仍是组合协议：同一登记资产、同一传播变换下的 observed/counterfactual 配对；同一坐标帧的区域证据；按传播族和质量分层的 null 校准；独立流冲突拒判；可回放证据包。任何单个组件已经有大量 prior art，不能单独包装为创新。

## 5. 继续创新的算法路线

### 5.1 当前已经落地的层

`source-residual-v1`、区域配准、PC-SCFT、普通传播变换、spectral raw evidence、多流冲突路由、独立多流 conformal 校准、patch contribution mask-out 审计和联合 null 校准已经有无重量模型的契约切片。它们当前只证明 sidecar、digest、拒判和确定性，尚未证明真实 AIGC 效果。

### 5.2 下一项算法切片的可证伪问题

下一项应研究“证据是否依赖少数显眼 patch 或语义边界”，而不是再增加一个闭集分类器。建议保留以下输入和输出：

```text
输入：每个区域的 pixel/spectral raw evidence、bbox、region_type、传播族、质量和 counterfactual 对照
动作：leave-one-patch-out、patch mask-out、语义类型分层和边界/decoy 对照
输出：patch contribution、贡献集中度、跨类型支持数、semantic-boundary overlap、review/insufficient 路由
```

该切片的可证伪条件是：

1. 普通传播 hard negative 中，单个边界 patch 不应单独触发 `candidate_edit`；
2. 局部编辑中，去掉高贡献 patch 后剩余证据应表现出可解释的 ROI 下降，而不是任意区域都同样高分；
3. 跨 `object/stuff/background` 的支持不足、贡献过度集中或边界重合过高时，coverage 可以下降，但必须减少错误升级；
4. 这些门在未知生成器、时间切分和传播扰动上分别报告，而不能只在 synthetic fixture 上报告。

这不是把 patch attribution 叫作新分类器。它是 PC-SCFT 的证据质量门，用来区分“局部编辑证据”与“检测器捷径”。

### 5.4 当前切片结果和进入真实数据的门

`eval/patch_contribution_eval.py` 已覆盖 5 个标量 fixture：分布式稳定、全局单 patch 干扰、局部集中、形状歧义和无正证据。runner digest 为 `3941c63d151ecf96d9254cb18895dc73b3739f34b8353a1f4a500c33247c969f`；A9 顺序状态机和策略校准 runner 已加入，历史快照为 196 个测试、23 个 runner；后续 342 个测试、37 个 runner 也属于历史快照，当前入口为 351 个测试、38 个 runner，另含 explanation、reference、invariant、SAEC、SAEA、SCPTN、RSCPTN、ALG-001 和 PE-CEA 契约切片。

这个结果只说明接口、digest、leave-one-out/top-k mask-out 和 fail-closed 路由可回放。进入真实数据前必须补齐：

1. 授权图片和人工/生成器 edit mask，计算 mask-out faithfulness、ROI IoU 和 semantic-boundary overlap；
2. 普通传播 hard negative、未知生成器、时间下一周期和截图/再编码/再拍摄传播扰动；
3. 与 A0–A8 同一 manifest 的消融，比较加入该审计后 FPR、coverage-risk、unknown、P95、成本和人工复核分钟数；
4. 当 `global_like` 变成 `distraction_sensitive` 时，证据包必须把触发 patch、去除后路由和 raw digest 交给人工复核，而不能改写成“检测到 AI”。

因此该切片的产品价值假设是减少错误升级和缩短复核定位时间，尚无真实 ROI、客户采纳或部署证据。

### 5.5 联合 null 分支的真实验证门

联合 null 分支的商业价值假设是：在相同候选覆盖率下减少不必要的人工复核，或在相同 FPR 下增加可进入局部复核的真实候选。它不能凭 synthetic runner 证明。

进入真实数据前需要冻结：同一资产的 stream sidecar、普通传播 group、quality/region_type、counterfactual 关系、upstream profile digest 和时间/生成器 split。然后在同一 manifest 上比较单流、Bonferroni、联合 null、raw score 平均和无 counterfactual 消融，报告：candidate FPR 及 95% CI、risk@coverage、unknown/review 率、ROI IoU/Dice/boundary-F、p-value 分歧、P50/P95、每千张成本和人工复核分钟。

如果联合 null 只提升 synthetic 或已知生成器而使普通传播 FPR、流间冲突或未知生成器风险上升，保留 Bonferroni 并撤回该分支；如果收益只来自更宽松的拒判门，也不能称为算法创新。

这里的 Cauchy 组合只是依赖感知的组合统计量，联合经验 profile 只是对该统计量做 group-matched ordinary-propagation 校准；二者都不是本项目独立创新，也不输出 AIGC 概率。真实实验必须同时保留单流、Bonferroni、raw score 平均和无 counterfactual 的对照，才能判断收益来自来源条件协议还是门限放宽。

### 5.6 A9 顺序主动取证切片状态

`aigc/sequential_evidence.py` 已把静态 evidence-budget planner 扩展为固定 action order、`policy_digest`、输入/输出 digest 和不可变 replay state；成功 probe 缺输出摘要、probe 失败、重复/乱序、预算耗尽、route flip 或 calibration digest 不一致都会进入 `review`/`insufficient`。`aigc/policy_calibration.py` 对完整 ordinary-propagation replay 统计策略级 empirical FPR 和 Wilson 95% CI，`eval/sequential_evidence_eval.py` 只使用 6 条合成 trace 验证契约和确定性。

这项切片尚未验证真实授权图片、真实 probe 执行器、独立 null profile、跨生成器/时间切分、risk-coverage、ROI、P50/P95、每千张成本、人工复核收益或部署能力；策略级 FPR 仍不能解释为单张图片的 AIGC 概率。

### 5.3 真实实验必须回答的问题

真实授权数据冻结后，至少比较：

- A0 历史比赛版/单图基线；
- A1 real-only 或单流开放集 baseline；
- A2 pixel residual；
- A3 spectral/phase；
- A4 双流 raw route；
- A5 双流独立 conformal route；
- A6 加 patch attribution 和 semantic-boundary gate；
- A7 去掉 counterfactual、质量分层或拒判的消融；
- A8 组合协议在未知生成器、时间下一周期和传播扰动上的结果；
- A9 限预算主动取证；A10 shadow-mode 持续适配。

每个版本都要报告 FPR、coverage-risk、unknown rate、ROI IoU/边界偏差、P50/P95、每千张成本和人工复核分钟数。只有 A8 相对 A0–A7 在同一授权 manifest 上稳定改善，才能讨论研究创新；否则只保留为工程协议。

## 7. 当前禁止外推的结论

- synthetic raw score、p-value、dataset digest、AUROC、ROI IoU 不代表真实 AIGC 准确率；
- `candidate_edit` 只是进入局部编辑复核的候选路线；`null_consistent` 不等于人类创作；
- 缺少 C2PA/GB 标识不等于内容是人类创作；存在视觉异常也不等于侵权；
- 链上时间锚点不等于自动确权，模型来源归因不等于作者身份；
- 论文、采购公告、竞品价格和版权登记量不能直接推出 Smart Shadow 的市场规模、收入或合规认证。

后续 Agent 只需从本文件的当前路线选择一个有明确输入、输出、测试和退出条件的切片，再按 `AGENTS.md` 要求同步决策、技术、实施和验证记录。

## 8. 2026-09-20 市场刷新后的执行收敛

本节把本轮核验到的监管、采购和替代品信号转成可执行的购买假设。`F` 是公开来源事实，`I` 是产品推断，`P` 只有在客户授权试点、运行日志和采购决定出现后才能成立。

### 8.1 先卖“证据工作流”，再卖算法能力

| 购买触发 | `F` 外部信号 | `I` Smart Shadow 的首个交付 | `P` 验证证据 |

### 8.3 12 周后的扩展顺序

1. **P0 来源/标识网关**：只支持一个法域、一个 parser/rule schema 和有限导出格式；先交付体检和回放，再接发布流程。
2. **P0 私有图库证据工作台**：复用同一 provenance/EvidenceV1，增加版本归并、局部差异和人工队列；不承诺全网监测或自动下架。
3. **P1 训练数据来源/许可审计**：等客户提供脱敏 manifest 和权利规则，再做版本 diff、排除/撤回回放和法务协作。
4. **P1 案件证据协作**：只读、可回放、角色隔离；由有资质机构作法律判断。
5. **P2 经授权监测、视频/跨境适配**：需要额外平台授权、时空 manifest、隐私/反滥用评审和独立成本验证。

### 8.4 Crop-Consensus 的研究与商业边界

Source-Conditioned Crop-Consensus 只适合作为阶段 7 的证据质量切片：它检查登记原件条件下
多 crop view 的区域共识是否超过同传播族 crop-null，并把视图不一致、质量桶不匹配和 null 支持
不足交给人工复核。它可以帮助私有图库工作台减少“单个边界 patch 命中”的错误升级，但暂时不能
作为单图 AIGC API、通用裁剪鲁棒性承诺或法律证据。

真实验收必须在同一授权 manifest 上比较单视图 PC-SCFT、简单 crop mean/max、去掉 canonical
binding、去掉 crop-null 和完整共识协议，记录 ordinary-crop FPR、ROI/边界指标、unknown/
view_inconsistent、P95、每样本成本与人工复核分钟数。未完成这些对照前，商业交付只保存 raw
证据包和复核队列，不把 `consensus_candidate` 转成四态结果或自动处置。

当前商业结论仍是窄假设：首单用私有图库的来源与版本证据复核取得真实人工基线和采购决定；PC-SCFT、ONMA、BMEA 等算法路线只有在同一授权 manifest 上减少误报复核、改善 ROI 采纳或保持可拒判性，才有资格进入下一产品包。公开标准、采购金额、供应商单价和论文数字不构成 Smart Shadow 的客户、收入、SLA、认证或 AIGC 解决能力。

## 10. 有序编辑链切片后的路线收敛

新增 `edit_lineage` 只改变阶段 7 的研究契约，不改变阶段 1–5 的产品门，也不把比赛版 `/check` 改成过程级 AIGC 判定接口。近期执行顺序固定为：

1. 先冻结可授权的编辑 trace schema、mask 生成责任和删除/回放规则；没有真实过程日志时只维护 synthetic contract。
2. 为每个编辑 trace 生成同传播族 ordinary-propagation counterfactual，验证 `operation_scope` 能把普通传播与内容编辑分开。
3. 在同一 manifest 上比较 union-mask、无 trace、trace-only、trace+null、trace+matched-placebo 和完整协议；主要看普通传播 FPR、step-level ROI/faithfulness、review 分钟和 route flip。
4. 只有真实 trace、mask、跨工具/生成器/时间切分和人工复核门同时通过，才讨论研究创新或产品试点；否则保留为离线 raw audit，并允许 `insufficient`。

## 11. 多视角 matched-control 轨迹切片后的近期路线

`lineage_view_control` 只作为阶段 7 的组合审计层：它复用 `edit_lineage` 的步骤身份、
PC-SCFT/SCTE 的 observed−counterfactual 区域差异、MPCF 的上游控制摘要和多 crop 的
canonical view，不重新训练 detector 或重算 placebo p-value。它的研究问题是：声明的编辑步骤
是否在多个视角中按顺序出现并持续，而同视角 matched controls 不应一起超过门。

当前 5 个 scalar case 的路由为 `consistent_controlled_lineage=1`、
`trajectory_inconsistent=1`、`insufficient=3`，dataset digest=`28d3ecbe0fd827e766fcdb51f1d245a3c894e575fa8da91f8e171f61050c8ba3`。
这只证明 binding、控制支持、顺序检查和拒判契约可回放。它不能单独支持 AIGC 概率、来源/作者

coverage-risk、P95 和人工复核分钟。缺任何一项就保持 `insufficient`，不接阶段 6 产品轨。

## 20. 持续创新终审后的算法路线（2026-09-21）

因此，短期研究顺序不再是堆叠 detector，而是：

1. 完成 `SS-019/ALG-001` 的真实 archive/index 与 G0–G6；
2. 评审 `SS-020/SIPA-v1` 的跨索引 holdout 回放；
3. 若真实对照仍显示来源/生成器混淆，再评审 `SS-023/DRCS-v1` 的双 registry 分离；
4. `PE-CEA`、SCPTN/RSCPTN、SAEC/SAEA 继续作为 raw-evidence sidecar 组合，不把任一单项写成新
   detector 或 AIGC 概率。

所有候选必须用同一登记原件、同一 ordinary-propagation null、blind decoy/wrong-reference、同
action budget 和外部生成器/时间切分，报告 ordinary-propagation FPR、reference false-match、
risk@coverage、unknown/review、ROI/边界 F、P50/P95、成本和人工复核分钟。只提升 closed-set、只增加
unknown 或无法独立重放时，撤回为 audit sidecar。

## 21. 商业扩展优先级：metadata mutation 与证据冲突回放

`SS-024` 的 P0/P1 假设是 `metadata_mutation_guard + provenance_conflict_replay`：围绕原始字节、
manifest/claim digest、C2PA spec/trust-list、IPTC/GB 标识、provider/platform/content ID、写入工具、
删除墓碑和导出回执，回答“导入/编辑/导出后是否可回放、哪里失效、谁负责处理”。它服务于已有 DAM/MAM
或内容发布链，基础图搜、单图 detector、C2PA viewer 和完整 DAM 作为替代或适配器。

进入条件仍是阶段 1–5、客户授权、删除/恢复责任人、人工基线和重复任务；四周只读 shadow 只看字段完整率、
冲突复核分钟、签名/标识回放、删除恢复、权限越界和净价值。没有客户、价格、收入、SLA、认证或部署证据
前，不得把市场信号写成项目事实。

## 22. 第三轮研究终审后的算法执行顺序

前文关于“ALG-001 后直接评审 SIPA”的表述是历史路线，当前执行顺序由第三轮终审收窄为：

1. `SS-001` 主业务无假成功；
2. `SS-032` 冻结真实授权 archive/index、A/B snapshot、rank/membership/tree/selection trace、生命周期/访问审计和 G0–G6；
3. `SS-020/SIPA-LG-v1`：A replay → TLEG-A → fixed winner/region → B direct lookup → TLEG-B → B ordinary-null；
4. 只有 SIPA-LG 的真实结果通过同预算门后，才评审完整 CFAEA 的 generator registry/cross-fit；
5. 只有真实结果暴露可重复压力脆弱性时，才批准 AR-SCMI。

无真实 B holdout、独立 ordinary-null 和 G0–G6 时，研究线只能做 schema、validator、fixture 或 raw evidence；阶段 1–5 未通过前仍不进入客户 shadow 或线上接入。
