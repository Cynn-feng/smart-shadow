# Smart Shadow 商业试点与拓展收敛

更新时间：2026-09-21
研究类型：商业方向分层、首客资格、四周只读试点、收费单位和停止门
状态：研究输入；不批准线上接口，不代表客户、价格、收入、部署、合规认证或算法效果已经存在。

## 0. 使用口径

本文件把现有市场研究压缩成一条可以执行的资格和试点路径。它补充的是**执行分层**，不替代 `docs/01-项目决策记录.md`、`docs/03-技术方案.md` 或 `docs/04-实施方案.md`，也不改变阶段 1–5 先于阶段 6 的门槛。

每项陈述使用以下标签：

- **F（外部事实）**：法规、标准、正式政府页面或厂商官方文档直接支持。
- **I（项目推断）**：把 F 映射成 Smart Shadow 的产品假设，尚未由客户验证。
- **P（待证明）**：必须有授权 manifest、运行日志、人工基线或书面采购路径才能成立。

公开政策、产品功能和采购公告只能证明需求触发或替代存在。它们不能推出 Smart Shadow 的客户、报价、收入、市场规模、准确率、SLA、认证或司法采信。

## 1. 近期只保留一条商业主线

### P0：私有 DAM/MAM 的 `EvidenceSidecarV1 + Review Workbench`

首个工作流限定为：客户已有原件和版本库，在供稿预审、发布前检查、版本追责、投诉初筛或内部审计时，需要把来源、版本、凭证、模型原始信号和人工决定放到一条可回放的旁路证据链中。

最小交付顺序是：

```text
只读导入
  -> 原件/版本/传播关系绑定
  -> C2PA、GB、IPTC/XMP/EXIF 和平台声明解析
  -> 相似候选与局部 raw evidence
  -> 缺失、冲突、未知和失败进入人工队列
  -> reviewer 决定、留存/删除墓碑和可回放 EvidenceV1
```

这条主线的价值假设是减少重复整理和复核时间、降低证据丢失与错误升级，而不是替代客户的 DAM、发布系统、法律判断或通用 AIGC detector。

### P0 条件方向：单法域、单内容类型的标识/导出 readiness checker

当客户有明确整改或上线日期时，才并行验证一个法域、一个内容类型和两条真实导出链。输出只允许为 `pass`、`gap`、`conflict`、`insufficient`，并保留规则版本、parser 版本、输入/输出 digest 和人工整改责任人。它不是合规认证，也不能把缺少标识改写成“人类创作”。

### P1：训练数据许可/排除/撤回 ledger 与案件 evidence package

只有在客户已经有版本化 manifest、许可字段、排除/撤回责任人和真实处理流程时才进入。第一版记录版本差异、权利信号、受影响派生物和删除/停止处理回放；相似命中只能是线索，不能证明黑盒模型训练使用、侵权或已经完成 unlearning。

### P2：经授权监测、视频/音频和跨模态

这些方向需要独立的平台授权、采集/隐私评审、时空或音轨 manifest、反滥用和成本上限。P0 sidecar 没有完成四周 shadow 和恢复演练前，P2 不进入客户数据或线上接口。

## 3. 从研究假设到商业试点的状态机

方向不能因“有市场信号”直接进入客户数据。每个方向必须依次经过以下状态：

| 状态 | 名称 | 必须有的证据 | 允许的动作 | 不能做的事 |
| --- | --- | --- | --- | --- |
| S0 | 研究输入 | F/I/P 证据表、替代地图、假设买方 | 访谈、离线 fixture、字段草案 | 读取客户数据、报价为已验证价格 |
| S1 | 资格通过 | 明确业务触发日期、工作流、责任人和人工基线；阶段 1–5 仍须通过 | 冻结试点范围和 manifest 模板 | 接入线上发布、下架、发函或法律决定 |
| S2 | 安全沙箱 | 授权、权限、留存/删除、失败语义和回放检查通过 | 只读导入、解析、离线回放 | 让失败任务回退成成功；跨租户访问 |
| S3 | 四周 shadow | 至少两周重复任务，系统与人工并行，输出可回放 | 测量质量、人工分钟、成本和采纳 | 改变客户发布/下架/版权决定 |
| S4 | 收费实验 | 客户书面认可结果，预算负责人和采购路径存在，净价值可解释 | 测试收费单位、实施范围和下一周期 | 用公开采购额或论文指标替代报价验证 |
| S5 | 停止/回滚 | 任一安全硬门失败、无重复任务或净价值无修复路径 | 删除试点数据/凭证，回到离线 fixture | 继续堆功能、扩大样本或宣传成功 |

状态只能向前升级；证据失效时回退，不允许由销售意愿或一次演示直接跳到 S3/S4。

## 4. 首客资格卡：八个硬门和四个角色

### 4.1 八个硬门

只有全部满足才进入 S1；缺任何一项只做访谈或脱敏 fixture。

1. 客户控制一个私有图片库、DAM/MAM 或对象存储，并能指出原件与版本的责任人。
2. 存在明确的四周内业务触发：供稿预审、发布检查、版本追责、投诉初筛或审计截止日。
3. 每周至少有两次同类任务，而不是一次性演示或临时兴趣。
4. 客户可以提供授权 manifest、保留期限、删除/恢复责任人和可撤销访问范围。
5. 客户能提供历史人工决定或在 D0 建立人工基线，并允许记录复核分钟。
6. 客户同意系统只读并行，不把 `unknown`、`review` 或 `conflict` 强制压成 AI/人类二分类。
7. 客户有 IT/安全联系人，能确认数据驻留、租户边界、导出和回滚方式。
8. 有预算负责人或采购路径愿意在 D22–D28 参加复盘；没有预算承诺也可以进入 shadow，但不能写成商业验证通过。

### 4.2 四个必须在场的角色

| 角色 | 要回答的问题 | 缺席后果 |
| --- | --- | --- |
| 业务负责人 | 哪个重复任务要减少多少人工时间？ | 没有可核算价值 |
| 实际 reviewer | 哪些候选、冲突和证据包可用？ | 没有人工基线和采纳判断 |
| IT/安全负责人 | 数据在哪里、谁能访问、如何删除/恢复？ | 不能进 S2 |
| 版权/法务或合规负责人 | 报告哪些只是 raw evidence，哪些必须人工决定？ | 不能确定输出边界和停机条件 |

以下条件是立即排除项：要求自动确权、自动下架、自动发函或“无标识即人类”；拒绝提供删除责任人；拒绝记录失败；要求无授权地抓取公共平台；不能接受数据驻留或回放边界。

## 5. 四周只读 shadow 协议

四周是试点设计，不是生产 SLA。建议同一个客户只选一个内容类型、一个法域和一个工作流。

### D0–D3：冻结范围和安全沙箱

- 冻结 `pilot_manifest_v1`：原件、版本、传播关系、授权范围、split/group、保留期限、删除墓碑和人工标签。
- 冻结 `baseline_v1`：当前人工流程步骤、每步分钟、复核人员、历史错误定义和计时方法。
- 冻结 `report_v1`：来源/版本证据、供应商/模型 raw signal、reviewer 决定、规则/解析器版本和失败原因分栏。
- 运行一组正向、缺失、冲突、失败、删除和恢复 fixture；失败必须显式失败。

**D0 继续门：**未授权样本为零，越权为零，假成功为零，输入/输出 digest 可回放，删除责任和回滚路径明确。任一项不满足，回到 S0/S1。

### D4–D7：干运行和人工并行校准

系统只读导入，人工 reviewer 同时按客户原流程处理同一批次。记录导入失败、字段缺口、重复版本、权限拒绝、`unknown/review/conflict` 和实际人工分钟，不调整客户发布决定。

**D7 继续门：**解析和失败状态能逐样本回放；字段缺口有责任人；人工基线完成；客户确认 `unknown` 是合法流程结果。

### D8–D21：重复任务 shadow

建议起始样本为至少 500 个授权原件和 1,000 个版本/传播样本，或由客户书面说明较小总体及统计理由。每周至少有两次真实重复任务；不足时继续记录但不能升级为商业通过。

每个样本至少写入：

```text
request_id, tenant_id, asset_id, version_id, parent_id,
input/output_digest, parser/spec/detector/report_version,
provenance_status, model_raw_evidence, route,
reviewer_decision, retention_state, deletion/recovery_event,
latency_ms, review_minutes, failure_reason
```

**D21 继续门：**无越权、无假成功；证据可独立回放；字段完整率和人工复核趋势稳定；至少一个 reviewer 能说清楚结果减少了哪一步重复劳动。

### D22–D28：价值复盘和收费实验

由业务、reviewer、IT/安全、版权/法务和预算负责人共同复盘。四种合法结果为：

1. 进入收费试验并扩展同一工作流；
2. 延长 shadow，补数据或修复特定失败；
3. 保留离线 fixture，暂停商业轨；
4. 删除试点数据并回滚。

没有客户书面认可、预算负责人和下一周期日期，不能写成“有付费意愿”。

## 6. 指标、起始门和价值公式

### 6.1 安全硬门（任一失败即停止）

| 指标 | 起始门 | 证据 |
| --- | --- | --- |
| 未授权输入 | 0 | 授权 manifest、访问日志 |
| 跨租户越权 | 0 | 权限测试和审计日志 |
| 失败却返回成功 | 0 | 注入失败 replay |
| 独立证据回放成功率 | ≥99% 起始假设 | reviewer 回放抽样和失败清单 |
| 删除/恢复演练 | 100% 起始假设 | 删除墓碑、恢复记录、责任人签字 |
| `unknown/review/conflict` 被强制二分类 | 0 | 原始 route 与 reviewer 日志 |

这些是试点起始门，不是生产 SLA；任何门未达标时不以其他指标抵消。

### 6.2 业务和质量指标

| 指标 | 计算方式 | 初始继续门（可撤销假设） |
| --- | --- | --- |
| 版本绑定 precision/recall | 在客户确认的原件—版本标注集上计算 | precision ≥0.95、recall ≥0.90；不足只定位修复，不宣传能力 |
| 证据字段完整率 | 必填字段完整记录数/应记录数 | ≥98% |
| 证据包一次采纳率 | 无需补充材料即可进入客户流程的包/导出包 | ≥80% |
| 人工净分钟 | `baseline_minutes - system_minutes - unknown_review_minutes` | 四周趋势为正，且客户确认节省来源 |
| 普通传播误报 | ordinary-propagation null 被升级的比例 | 必须分层报告，不允许被总平均隐藏；阈值由客户风险承受度书面确认 |
| P50/P95 和每千件成本 | 端到端 wall time、人工和运行成本 | 与客户基线比较，不能只报模型 latency |

precision/recall、98%、80% 等数字是试点起始假设，不是论文结果、生产保证或市场标准。真实 AIGC 路由仍须经过项目 G0–G6；商业 shadow 不能把 raw evidence 改写成 AIGC 概率、作者、版权或侵权结论。

### 6.3 价值公式

只在客户书面认可成本口径后计算：

```text
net_value
  = batch_count
    * max(0, baseline_minutes - system_minutes - unknown_review_minutes)
    / 60 * customer_accepted_cost_per_minute
  + customer_accepted_evidence_value
  - integration_and_run_cost
```

`customer_accepted_evidence_value` 只有在证据包进入客户审计、投诉、许可或发布整改流程并被指定负责人书面认可时才能计入。论文分数、版权登记量、公开采购金额和厂商宣传的覆盖量不能代替收入。

## 7. 收费单位实验

首个工作流先测试“证据工作”收费，单图 detector 调用只作为透明的成本项或可替换 adapter。具体价格留到四周日志和客户报价实验之后。

| 收费单位 | 计量 | 适合的购买对象 | 不能计费/必须排除 |
| --- | --- | --- | --- |
| U1 集成与规则包 | DAM/MAM 字段映射、法域/内容类型、导出链、parser/rule 版本和恢复演练 | 首次接入或标识整改 | 不能把标准存在本身写成认证；失败的实施任务不应按成功计费 |
| U2 活跃资产/版本与保留期 | 有效 sidecar、manifest 摘要、版本图和回放保留 | 私有图库、MAM、长期归档 | 重试、临时文件、失败任务、重复 CID 不重复计数 |
| U3 证据包/案件与复核席位 | 可回放证据包、冲突队列、二审和导出量 | 版权运营、内容审核、内部审计、案件协作 | 不按“命中次数”计费；`unknown`、人工补录和失败是否计费须合同明确 |
| U4 私有化实例与年度维护 | 部署环境、升级、SBOM、解析器/adapter 评测、恢复演练和支持级别 | 数据不出域的政企/媒体 | 第三方模型、存储、链交易等成本不能隐含成无限 SLA |

首轮只比较两到三个组合报价：`U1+U2`（sidecar 基础包）、`U1+U3`（复核工作台）和 `U1+U4`（私有化）。比较客户理解度、预计使用量、支持成本和四周净价值，不在没有报价实验时宣布单价、年费或 ARR。

## 8. 方向升级和停止矩阵

| 方向 | 升级到下一阶段的最小证据 | 停止条件 | 停止后的保留物 |
| --- | --- | --- | --- |
| P0 私有 sidecar | 四周 shadow 有重复任务、回放/删除/权限硬门通过、证据包被真实流程采用、净价值有客户认可 | 无触发/人工基线/责任人；假成功、越权、无法删除或净价值无修复路径 | 脱敏 fixture、访谈记录和失败清单 |
| P0 readiness checker | 一个法域/内容类型、两条导出链、责任人和整改日期；结果可回放 | 法域/角色不清；解析失败却通过；要求认证或自动处置 | parser contract 和规则差距清单 |
| P1 许可/撤回 ledger | 两个 manifest 版本、至少一次排除/撤回回放、法务 reviewer 认可字段 | 没有客户 manifest/许可规则；要求证明黑盒训练使用或自动 unlearning | schema、脱敏 diff 和人工操作记录 |
| P1 案件 evidence package | 真实案件或审计流程采用包，角色隔离和留存/删除通过 | 只接受法律结论或自动发函/下架；证据不能独立回放 | raw evidence 结构和报告模板 |
| P2 监测/跨模态 | 书面渠道授权、投诉/删除入口、独立成本上限和媒体 manifest | 无授权抓取、无法处理删除、采集成本失控或隐私边界不清 | 离线 adapter 与权限评审 |

**立即回滚门：**未授权数据、跨租户越权、失败假成功、无法删除/恢复、证据包不可回放、`unknown` 被强制二分类、客户要求自动法律处置。
**商业停止门：**连续两周没有重复任务、没有指定 reviewer、证据包不进入客户流程、人工净分钟不降且没有修复责任人、没有预算负责人或下一周期日期。
**研究停止门：**收益只出现在 synthetic/IID/已知生成器，或只依赖更高拒判、无法独立校准、普通传播 FPR 或成本恶化；此时保留为 raw audit sidecar，不包装为通用 AIGC detector。

## 9. 现有文档的增量与下一步

现有 `docs/05`、`docs/08` 和 `docs/research/2026-09-21-市场拓展第二轮深度调研.md` 已给出方向、来源和指标。本文件新增的可执行层是：

1. 用 S0–S5 状态机控制“访谈 → 沙箱 → shadow → 收费 → 回滚”，阻止一次演示直接升级为客户事实；
2. 用八个硬门和四个角色筛选首客，先验证触发、授权、人工基线和责任边界；
3. 把 D0–D28 的样本、日志、复盘和合法结果固定下来；
4. 把收费单位绑定到集成、资产/版本、证据包/席位和私有化交付，避免按命中次数制造误报激励；
5. 把安全、商业和研究三类停止门分开，任何一类失败都回到离线 fixture。

近期唯一建议动作是：选择一个满足八个硬门的私有资产客户，先完成 P0 sidecar 的资格和 D0–D7 安全沙箱。阶段 1–5 未通过或客户不具备授权 manifest、人工基线、删除责任人和真实重复任务时，只做访谈和脱敏 fixture，不接客户数据、不改核心决策、不新增线上接口。

## 10. 不应外推

- 法规、标准和厂商产品页只支持规则、替代和需求触发，不证明 Smart Shadow 已合规、已集成或已部署。
- 公开采购金额、厂商价格、版权登记量和论文 benchmark 不等于 Smart Shadow 的 TAM、报价、收入、客户数或 ROI。
- C2PA、GB、数字水印、区块链、近邻检索和视觉 raw evidence 不能独立证明内容真实、自然人作者、版权、侵权或黑盒训练使用。
- synthetic runner、无重量测试和离线 raw route 不能证明真实图片 AIGC 效果；真实算法仍须通过 G0–G6、外部时间/生成器切分、人工基线和成本门。
- 试点起始阈值不是生产 SLA；只有客户授权数据、回放日志、人工复核和书面下一周期决定齐备后，才可把对应 `I/P` 假设升级为项目事实。
