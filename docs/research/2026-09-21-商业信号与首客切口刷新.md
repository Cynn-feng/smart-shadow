# 2026-09-21 Smart Shadow 商业信号与首客切口刷新

更新时间：2026-09-21
研究状态：已核验公开一手来源；以下是产品假设、采购线索和四周 shadow 设计，不是客户访谈、合同、收入预测、合规认证、部署报告或算法效果报告。

本文件把“市场、商业价值和继续创新”放在同一条可验收链上：外部规则只作为购买触发，客户自己的工作流和授权数据才是商业证据；算法研究只提供可回放的 raw evidence，不能被包装成 AIGC 概率、作者判断或法律结论。

## 1. 证据口径

文中每条判断使用三种标签：

- **F（外部事实）**：政府/监管机关、标准组织、正式法规、官方采购公告或厂商正式文档直接写明的事实。
- **I（产品推断）**：将 F 与 Smart Shadow 当前仓库能力连接起来的判断，仍需客户试点验证。
- **P（待验证命题）**：只有客户授权 manifest、人工基线、连续运行日志、书面验收或采购决定才能成立。

公开预算、中标金额、法规生效日期、厂商自报覆盖量和论文指标只能证明需求触发或替代品存在，不能推导 Smart Shadow 的客户数、收入、报价、准确率、SLA、司法采信、合规认证或市场份额。

## 2. 结论先行

### 2.1 首单卖证据工作流，不卖单图“真假分数”

**I：**最现实的首个商业对象是接入客户已有 DAM/MAM、内容审核或发布系统的旁路层：

```text
客户原件/版本/导出事件
  -> 读取 C2PA、GB 45438-2025、EXIF/XMP 和客户声明
  -> 绑定 asset/version/parent/permission/retention
  -> 调用可替换的相似检索与 AIGC raw-evidence adapter
  -> 把缺失、冲突、普通传播疑似误报和未知情况送人工队列
  -> 生成带输入/输出 digest、操作、reviewer 和删除回放的 evidence package
```

已有 DAM、云图搜和云端 AIGC 检测已经覆盖基础资产管理、相似检索、凭证展示和单图检测；Smart Shadow 的可辩护空间是跨供应商的 `provenance/version/evidence sidecar`、冲突/拒判语义、私有化权限和可独立回放的复核包。这个空间仍然只是 **I**，须用四周 shadow 升级为 **P**。

### 2.2 首个 ICP 收窄为“有私有图库且有重复复核任务的媒体/图片库/品牌内容团队”

优先找一个已有媒资或图库系统、每周反复进行供稿预审/发布前标识检查/投诉取证、数据不能出域的团队。冠军用户是媒资或版权负责人；IT/安全负责部署和权限，法务/版权负责报告边界，实际审核人员提供人工基线，采购/财务决定下一周期预算。

首单触发应是一个有截止日期的工作流，例如新栏目或品牌素材发布、供稿预审、版权投诉、AI 标识整改或版本追责。泛泛的“想做 AIGC 检测”不构成采购触发。

### 2.3 合规入口可以是 P0 条件项，但必须先固定法域和内容类型

中国《人工智能生成合成内容标识办法》、GB 45438-2025 和欧盟 AI Act Article 50 都把生成、导出、传播和机器可读标识带入工程验收；这支持一个**单法域、单内容类型、两条导出链**的 readiness checker。它只能输出 `pass/gap/conflict/insufficient`、规则版本、证据和整改队列，不能输出“已认证”“无标识即人类创作”或自动下架决定。

### 2.4 训练数据 provenance/许可/撤回是 P1，不应抢跑成 AIGC 鉴定器

欧盟 AI Act Article 53 要求 GPAI 提供者制定版权政策并公开训练内容摘要；美国版权局和英国政府材料都把训练数据透明度、许可和执行难题分开讨论。Smart Shadow 可以做客户 manifest 的来源、许可、排除、撤回和删除/停止处理回放，但近邻命中不能证明某作品实际进入某黑盒模型，更不能自动判侵权。

### 2.5 算法继续创新的市场化表达

可以继续研究 **source-conditioned selective local-edit forensics**：在登记原件存在时，把普通传播版本作为 null，把 blind decoy/wrong-reference、canonical frame、多视角/多算子稳定性和选择后校准纳入 raw evidence，并在证据不足时拒判。当前 SCPTN/SAEC/SAEA 等切片仍处于阶段 7 离线契约；只有 G0–G6 真实数据门、人工基线和同预算对照通过后，才可讨论“指定授权集上的局部编辑取证效果”，不能外推为通用 AIGC 解决方案。

## 6. 首个客户切口和购买路径

### 6.1 建议 ICP

首个切口建议为**地方/行业媒体或商业图片库的图片供稿与发布前审核**，满足以下条件：

1. 已有私有 DAM/MAM、对象存储或图库，资产和传播版本不少于几百条；
2. 每周有供稿预审、重复素材复核、AI 标识检查、投诉或版本责任追溯任务；
3. 作品、原件和审核日志不能直接发往公共云；
4. 能指定实际审核员、IT/安全、版权/法务和采购联系人；
5. 能提供脱敏或授权 manifest、删除/留存规则和一个明确截止日期。

采购链不应从“算法效果演示”开始，而应从客户已有任务开始：

```text
触发日期（发布/整改/投诉）
 -> 业务负责人确认样本和人工基线
 -> IT/安全确认私有化、权限、删除和恢复
 -> 版权/法务确认报告字段和 unknown 处置
 -> 只读 shadow 与人工流程并行
 -> reviewer 验收证据回放和时间节省
 -> 采购决定：扩样/付费/继续无付费 shadow/停止
```

### 6.2 四周 shadow 设计

下表中的数字是**建议的试点起始门**，不是生产 SLA、市场事实或算法承诺；客户规模不足时可以按比例缩放，但不应删除安全和回放门。

| 周期 | 只做什么 | 必须记录 | 继续门 | 停止/回滚门 |
| --- | --- | --- | --- | --- |
| **D0–D7 资格和安全沙箱** | 只读导入、凭证/元数据解析、版本绑定、失败回执和回放；不改变发布、下架、发函或诉讼决定。 | 授权 ID/范围/期限、输入/归一化 hash、租户/角色、parser/detector/schema 版本、失败原因、删除责任人。 | 未授权样本 = 0；跨租户越权 = 0；失败不返回成功；输入/输出 digest 可重放；删除/恢复责任清楚。 | 授权或责任不清；解析失败写成成功；不能删除/恢复；客户要求自动法律处置。 |
| **D8–D21 只读 shadow** | 建议约 500 个授权原件、约 1,000 个传播/版本样本，与人工流程并行至少两周。AIGC 研究样本缺 ordinary-propagation null、编辑 mask 或独立 split 时只输出 `insufficient`。 | 版本绑定 precision/recall、sidecar 字段完整率、候选 Recall@K、普通传播 FPR、unknown/review、人工分钟、P50/P95、每千件成本、证据包版本。 | 版本绑定建议起始门 precision ≥0.95、recall ≥0.90；字段完整率 ≥98%；指定 reviewer 可回放 ≥99%；人工流程出现客户认可的净分钟下降；unknown 没被压成二分类。 | 普通传播误报持续增加人工量；证据字段/回放失败；unknown 被强制改成 AI/人类；没有每周真实任务。 |
| **D22–D28 采购决定** | 只选择扩大样本/角色、签下一周期付费、继续无付费 shadow 或停止回滚。 | 客户认可的证据案例、下一周期预算负责人、运行/集成支持成本、取消原因、删除/恢复结果。 | 建议起始门：证据包一次采纳率 ≥80%；人工净复核分钟下降 ≥20%；删除/恢复演练 100%；至少两周重复任务；预算路径书面确认。 | 只有一次演示命中；客户无法指出预算/流程负责人；净价值为负且无修复路径；要求把外部预算或论文指标当 ROI。 |

建议至少保存以下字段，便于客户和项目自身计算价值：

```text
N, t_base, t_system, t_unknown, c_min, C_run,
version_precision, version_recall, candidate_recall_at_k,
ordinary_propagation_fpr, unknown_rate, review_rate,
sidecar_field_completeness, evidence_replay_success,
deletion_restore_success, cross_tenant_violation,
false_success, p50, p95, weekly_active_reviewers,
next_budget_owner, cancellation_reason
```

客户认可人工成本后，才可以计算：

```text
net_value = N * max(0, t_base - t_system - t_unknown) / 60 * c_min
            + evidence_value_accepted
            - C_run
```

`evidence_value_accepted` 只计入已经进入客户投诉、审计、许可或发布整改流程并由客户书面确认的价值；模型分数、登记量、公开采购金额和论文 AUROC 不得代入。

## 7. 对算法创新的直接约束

### 7.1 市场真正需要的不是“更高的单图概率”

竞争替代已经可以返回单图 AIGC 风险级别、相似图和凭证状态。若继续沿着单模型分类器或泛化 generator-family router 竞争，项目容易落入已有云服务、开放集归因和水印生态的正面竞争。下一算法切片应围绕客户愿意复核的证据对象：

- **登记原件条件化**：先证明 query 与客户登记资产/版本关系存在，再谈局部差异；无原件时允许 `unknown/insufficient`。
- **普通传播 null**：将 JPEG、resize、crop、截图模拟等无编辑传播版本作为独立 null，避免传播伪影被当作 AI 编辑。
- **blind decoy/wrong-reference**：把错误原件选择和同质量近邻纳入控制，避免“挑到最像的参考”造成 winner's curse。
- **canonical frame + 多视角/多算子稳定性**：把局部证据绑定到同一坐标帧，不跨 operator 偷换平均分；不稳定就拒判。
- **选择后校准和树级统计单位**：在 reference/版本选择之后仍控制最大统计量；SCPTN 的传播树 null 只属于研究假设，必须和逐版本 null、去树相关性及同预算基线对照。
- **选择性拒判**：来源、配对、质量、校准、时间/生成器 split 任一缺失，优先 `insufficient`/`review`，不返回人类或 AI 结论。

### 7.2 论文与商业声明的最小分离

在 G0–G6 和客户人工基线未通过前，可以说：

> Smart Shadow 正在研究一种来源条件的局部编辑 raw-evidence 协议，用 ordinary-propagation null、错误参考对照、传播树和选择性拒判减少审计误报。

不能说：

- 已解决 AIGC 或可以检测所有未知生成器；
- p-value 是 AIGC 概率；
- `candidate_edit` 是 AI 生成、人类作者或侵权事实；
- 合成 runner 的 digest、AUROC、ROI IoU 或 route count 是真实客户准确率；
- C2PA/链上 receipt 等于真实性、版权归属或司法采信。

## 8. 商业停止门和不可外推清单

### 8.1 总停止门

遇到任一条件，停止向下一市场或客户扩张，回到数据/流程/工程修复：

1. 客户不能提供授权范围、留存期限、删除负责人和人工基线；
2. 失败、凭证缺失或解析异常被系统写成成功；
3. 跨租户可见、原件不可恢复或删除回放失败；
4. 客户要求自动判侵权、自动下架、自动发函或把 `unknown` 强制改成 AI/人类；
5. 只有一次演示命中，没有连续两周真实重复任务；
6. ordinary-propagation FPR、review 分钟或运行成本使人工净价值持续为负；
7. 试点只能依赖公共样本、未授权图片、未冻结 manifest 或供应商自报指标；
8. 没有书面下一周期负责人、预算路径或取消原因。

### 8.2 明确不可外推

以下说法必须保持禁止状态，除非另有独立证据：

- 政府预算/中标金额 → Smart Shadow 报价、市场规模或成交概率；
- 法规/标准生效 → Smart Shadow 合规认证或客户必然采购；
- C2PA 签名/水印/链上记录 → 内容真实、人类创作、版权所有或侵权成立；
- 单图 detector 的 `Block/Review/Pass` → Smart Shadow 通用 AIGC 准确率；
- 论文/合成 fixture → 真实图片、未知生成器、跨平台传播或部署效果；
- 相似检索近邻 → 某作品实际进入某模型训练或构成侵权；
- 一次客户试点 → 全行业需求、续费、收入和跨法域适用；
- 四周 shadow 起始门 → 生产 SLA、法定阈值或长期 ROI。

## 9. 推荐的下一执行顺序

1. **主工程线：**继续 `SS-001`，先让 AI/链回执、权限和失败语义可审计；没有这一层不能把商业 sidecar 接入客户系统。
2. **算法真实数据线：**继续 `SS-002`，准备授权 `real_pc_scft_manifest_v1`、独立 ordinary-propagation null、编辑 mask 和时间/生成器 split；SCPTN 暂不接线上。
3. **商业发现线：**只找 1 个符合 ICP 的媒体/图片库/品牌内容团队，围绕一个截止日期签订只读 shadow；先验证字段完整、回放、复核分钟和 unknown 处置。
4. **首个产品设计：**在客户字段和删除规则明确后，另行批准 `EvidenceSidecarV1`；先设计 schema 和 mapping，不在阶段 1–5 未验收前改线上接口。
5. **四周后决策：**根据客户确认的人工分钟、证据包采纳率、普通传播 FPR、越权/假成功和预算路径，选择扩大、付费、继续 shadow 或停止；没有这些证据不更新市场规模或商业承诺。
