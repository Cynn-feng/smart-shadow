# 2026-09-21 Smart Shadow 市场拓展第二轮深度调研

更新时间：2026-09-21
研究类型：外部事实、竞争替代、商业假设和论文到产品的映射
本文件状态：研究输入，不修改产品决策，不批准线上接口、收费价格、客户或合规结论。

## 0. 阅读和证据口径

本轮重点补查 DAM/MAM、内容溯源、C2PA、AI Act、训练数据许可/权利保留、内容审核和公共采购。外部来源只选法规/标准组织、政府采购、官方产品文档和正式会议论文。每条结论使用以下标签：

- **F（外部事实）**：来源页面直接支持的规则、功能、采购或论文观察。
- **I（项目推断）**：把 F 映射为 Smart Shadow 的产品或研究方向，尚未由客户验证。
- **P（待证明）**：只有授权样本、试点日志、人工基线或书面采购路径出现后才能成立。

外部事实不等于市场规模、客户、收入、价格、SLA、认证或本仓库效果。研究论文中的 benchmark 也不替代 Smart Shadow 的 G0–G6 真实数据门。当前日期和页面访问日期均为 2026-09-21；网页会更新，后续复核应保存版本、抓取日期和链接。

## 1. 结论先行：市场拓展顺序

### 1.1 P0：已有私有 DAM/MAM 的 provenance/version/evidence sidecar

**I：**最接近 Smart Shadow 现有能力、最容易做四周 shadow 的方向仍是为已有图库、媒资库、内容生产链和对象存储补一层旁路证据工作流：

```text
原件/版本/导出
  -> C2PA/Content Credentials、GB 45438、IPTC/XMP/EXIF 解析
  -> asset/version/parent/permission/retention 绑定
  -> 相似候选与局部 raw evidence
  -> 普通传播、来源冲突、未知输入和权限异常进入人工队列
  -> 带 digest、规则版本、操作记录和 reviewer 决定的可回放 evidence package
```

已有 DAM 已经覆盖资产库、版本、权限、搜索和部分凭证展示；Cloudinary、Bynder、Adobe 等也在接入 C2PA。Smart Shadow 不应重做 DAM、单图 AIGC API 或 C2PA viewer，能争取的白区是跨供应商凭证/版本冲突、普通传播误报、删除与恢复回放、人工证据包和可拒判路由。

### 1.2 P0 条件方向：单法域、单内容类型的 AI 标识与导出链 readiness checker

**F：**中国《人工智能生成合成内容标识办法》及 GB 45438-2025 已要求生成、下载、复制、导出、传播中的显式/隐式标识和传播核验；欧盟 AI Act Article 50 自 2026-08-02 起要求相关生成/操纵内容具备机器可读标记，深度伪造和特定公共利益文本需要向受众披露。[中国标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)；[GB 45438-2025](https://std.samr.gov.cn//gb/search/gbDetailed?id=301E0388CB75788DE06397BE0A0AE1B4)；[欧盟 Article 50 指南](https://digital-strategy.ec.europa.eu/en/policies/guidelines-ai-transparency-obligations)。

**I：**可把交付限制为一个法域、一个媒体类型和两条真实导出链的 `pass/gap/conflict/insufficient` 报告。报告应保存输入/输出 digest、parser/rule 版本、原始 metadata、C2PA 验证状态、转码/导出步骤和人工责任人。它是整改定位和回放工具，不是合规认证、AIGC 真伪裁决或自动下架器。

### 1.3 P1：训练数据权利保留、许可和撤回 ledger

**F：**欧盟 GPAI 规则要求模型提供者建立版权政策、尊重权利保留并公开训练内容摘要；欧盟委员会还就机器可读的 TDM 权利保留协议组织咨询，明确提到 `robots.txt` 和后续机器可读协议。[GPAI Q&A](https://digital-strategy.ec.europa.eu/en/faqs/general-purpose-ai-models-ai-act-questions-answers)；[权利保留协议咨询](https://digital-strategy.ec.europa.eu/en/consultations/commission-launches-consultation-protocols-reserving-rights-text-and-data-mining-under-ai-act-and)；[DSM Directive Article 4](https://eur-lex.europa.eu/legal-content/EN/TXT/PDF/?qid=1788633812424&uri=CELEX%3A32019L0790)。美国版权局的 AI 研究仍将训练材料、许可、责任和市场影响作为持续研究主题，Part 3 在页面上仍标为预发布版本。[美国版权局 AI 主页](https://www.copyright.gov/ai/)；[Part 3 预发布版](https://www.copyright.gov/ai/Copyright-and-Artificial-Intelligence-Part-3-Generative-AI-Training-Report-Pre-Publication-Version.pdf?stream=top)。

**I：**这支持一个治理型 ledger：记录 asset/URL/manifest 版本、许可地域/期限、允许用途、rights-reservation signal、排除清单、撤回请求、受影响派生物枚举和人工处理结果。它解决的是“权利或许可变化后哪些记录需要处理”，不是证明黑盒模型一定训练过某文件，也不自动认定侵权。

### 1.4 P1：内容审核、品牌安全和案件证据包

**F：**欧盟指南把深度伪造、公共利益文本、误导和消费者欺骗列为透明度场景；中国规则要求传播服务核验隐式标识、处理用户声明并提示疑似生成内容。政府采购公告也显示 AIGC 鉴伪、内容安全检测和升级运维可以作为服务器、软件或服务包采购。

**I：**平台、媒体和品牌可以购买“候选 + 来源/版本 + 原始信号 + reviewer 决定”的案件包，减少重新下载素材、查版本、解释冲突和整理投诉材料的时间。系统只给线索和可回放证据，人工或有资质机构作发布、下架、版权和法律判断。

### 1.5 P2：经授权的渠道监测；P2：视频/音频/跨模态

只有客户拥有明确渠道授权、投诉入口和删除责任人时，才做固定站点或渠道的采集和证据绑定。视频/音频需要新的时间轴、帧、音轨和隐私 schema，应先做离线 adapter，不提前扩展当前图片 `aigc_result_v1`。

## 3. 竞争替代：客户已经买了什么

| 替代类别 | 已覆盖能力 | Smart Shadow 不应重复的内容 | 可争取的窄白区 |
| --- | --- | --- | --- |
| 企业 DAM/MAM（AEM、Bynder、Cloudinary 等） | 资产库、版本、权限、搜索、发布、部分 C2PA 展示和 AI 内容工作流。 | 完整 DAM、通用图库、基础 C2PA viewer、单纯元数据面板。 | 跨供应商证据绑定、凭证与视觉信号冲突、删除/恢复回放、reviewer 决定和可导出的 evidence package。 |
| 单图 AIGC detector / 内容安全 API | 输出分类分数、热力图或风险标签，常按张/次计费。 | “更高分数”“全网通用 AIGC 概率”“自动法律或版权结论”。 | 把 detector 当可替换 adapter，与登记原件、传播 null、错误参考和人工队列组合；失败时拒判。 |
| C2PA/Content Credentials 工具 | 写入、签名、验证和显示 provenance；部分产品能跨发布链保留凭证。 | 自建另一套凭证格式、声称凭证等于真实或作者证明。 | 保留原始 manifest 和 trust 状态，建立版本/权限/删除/人工审核的旁路事件链。 |
| 训练数据 catalog/版权顾问 | 数据集目录、许可分析、合同和法律咨询。 | 自动证明黑盒模型使用了某张图、自动完成 untraining、自动出具侵权结论。 | 版本化 manifest、machine-readable opt-out、排除/撤回影响范围枚举和回放日志。 |
| 内容审核/案件管理系统 | 队列、人工处置、投诉、下架、SLA 和报告。 | 替客户作发布、下架、作者、版权或司法判断。 | 将原件、版本、传播、C2PA/标签、模型 raw evidence 和 reviewer 决定合并成可验证案件包。 |

客户购买理由必须是“少花人工时间、少丢证据、少发生假成功/权限事故”，而不是“买一个神奇的 AIGC 分数”。

## 4. 方向排序与付费单位

### 4.1 P0-A：DAM/MAM 证据 sidecar + Review Workbench

| 项目 | 试点定义 |
| --- | --- |
| 首客画像 | 有私有图库、DAM/MAM 或对象存储；每周有供稿预审、发布前检查、投诉、素材追责或版本争议；有媒资负责人和 IT/安全联系人。 |
| 购买触发 | 新平台上线、AI 标识整改、重大活动、供应商迁移、审计截止日、投诉/侵权案件或重复素材治理。 |
| 最小交付 | 只读导入；原件—版本—传播边；C2PA/GB/IPTC/XMP/EXIF 摘要；检索候选；现有 AIGC adapter 的 raw evidence；人工队列；证据包；权限、删除和恢复回放。 |
| 付费单位假设 | 租户 + 资产/版本量 + 保留期；复核席位/月任务量；API/批处理量；私有部署、字段映射和年度维护。具体数字待客户报价实验。 |
| 四周样本假设 | 至少 500 个授权原件、1,000 个版本/传播样本；客户人工基线和删除责任人先冻结。数量是试点起始假设，不是市场标准。 |
| 继续门 | 字段完整率 ≥98%；指定 reviewer 证据回放 ≥99%；证据包一次采纳率 ≥80%；与人工流程并行时总复核分钟有稳定下降；跨租户越权=0；失败却成功=0；删除/恢复演练可回放。阈值需在 D0 由客户书面确认。 |
| 停止门 | 无授权 manifest、无每周重复任务、无人工基线、客户要求自动确权/自动下架、删除责任人不明、权限或失败语义未达标、四周净价值不为正且无明确修复。 |

| 项目 | 试点定义 |

| 首客画像 | 模型研发机构、媒体/图库集团、数据治理或版权法务团队；已有版本化 dataset manifest、许可字段和排除/撤回流程。 |

| 停止门 | 客户没有自己的 manifest/许可规则/责任人；要求系统证明黑盒训练使用或自动完成模型卸载；相似检索被误当训练事实；无法做删除或停止处理回放。 |

### 4.4 P1-B：内容审核/品牌安全 evidence package

| 首客 | 媒体编辑部、品牌内容供应链、平台 Trust & Safety、版权代理/内部审计。 |
| 付费单位 | 案件量、复核席位、证据导出量、留存期、连接器和私有部署。 |
| 关键指标 | 每千件人工分钟、候选 Recall@K、ordinary-propagation FPR、unknown/review 占比、误报升级率、证据包一次采纳率、P50/P95、越权与删除事故。 |
| 边界 | Smart Shadow 只做候选、来源/版本与 raw evidence；发布、下架、版权和法律判断由客户完成。 |

### 4.5 P2：经授权监测；P2：视频/音频/跨模态

监测需要书面渠道范围、采集合规、投诉/删除接口和成本上限；按授权渠道、采集量和人工审查量收费。视频/音频需要独立的 frame/segment/track manifest、存储和隐私评审；在图片 sidecar 的四周 shadow 尚未通过前不扩展。

## 6. 论文和标准对算法商业化的约束

### 6.1 论文共同指出：干净 benchmark 不能直接代表真实审核

- **RRBench（ICCV 2025）**把场景、互联网传输和再数字化纳入评测，并比较 17 个检测器、10 个 VLM 和人类。对 Smart Shadow 的直接要求是：每次试点必须记录传播族、格式转换、截图/再拍、时间切分和 unknown/review；只在干净图上提高 AUC 不足以产生商业价值。
- **Semi-Truths（NeurIPS 2024）**专门关注 AI 增强或局部修改图像。它支持把整图二分类拆成“登记原件条件下的局部变化是否超过普通传播解释范围”，但不证明本项目方法有效。
- **CVPR 2025 的 bias-free/generalization 系列**表明语义内容偏差、未知生成器和跨域变化仍是检测器的主要风险。项目应保留来源/版本条件和拒判，而不是承诺闭集之外的概率。
- **ACL 2026 synthetic-data 法律研究**提醒：即使训练样本由另一个模型生成，也要追踪输入来源、模型许可和派生关系。训练数据 ledger 与 AIGC detector 应分开，不能以生成器标签代替权利证明。

### 6.2 可继续创新的商业相关算法切片（仅研究候选）

| 候选 | 研究问题 | 商业可见输出 | 先例/风险 | 进入条件 |
| --- | --- | --- | --- | --- |
| Source-conditioned selective evidence | 在登记原件、普通传播 null、盲选 decoy 和局部 mask 约束下，哪些局部差异仍值得人工复核？ | `candidate_edit`、`null_consistent`、`review`、`insufficient` raw route + evidence package。 | 不是通用 AIGC detector；收益可能只来自更多拒判。 | G0–G6、同预算 A/B、传播/生成器/时间外部切分、人工分钟和成本均改善。 |
| Provenance-conflict graph | 当 C2PA、IPTC/XMP/EXIF、DAM 版本和视觉证据冲突时，怎样可回放地分层冲突而不丢失原始值？ | 字段冲突、版本冲突、签名无效、传播断点和责任队列。 | 类似数据 lineage/审计图已有先例；不能称新图算法。 | 在真实 DAM 导出链上复核字段、权限、删除和人工采纳。 |
| Rights-aware training ledger | 将 `rights reservation -> manifest -> derived dataset -> review` 作为版本化事件链，发现撤回/期限变化影响范围。 | `rights_gap`、`withdrawal_pending`、`not_evaluated` 及审计包。 | 不能证明黑盒训练使用；法律解释由客户承担。 | 客户提供许可规则、版本 manifest、至少一次撤回回放和法务确认。 |
| Review-budget acquisition | 在固定人工预算下，按失败原因选择下一项证据（更多视角、原件、传播 null 或人工核验）。 | 下一个 probe、预计信息增益、原因标签和成本。 | 选择后校准/主动学习已有先例；不能主张新的统计理论。 | 同预算人工分钟下降、FPR/risk@coverage 不恶化、unknown 可接受。 |

所有候选的产品输出都是 raw evidence 或人工队列。`candidate` 不能写成 AIGC 概率、作者、版权、侵权或法律结论；`null_consistent` 不能写成人类创作证明。

## 7. 四周 shadow 方案、收费实验与停止门

### D0–D7：资格和安全沙箱

冻结：授权 manifest、法域、内容类型、系统角色、权限、保存/删除期限、人工基线、证据包 schema、规则/模型/parser 版本和失败状态机。所有输入建立 digest；越权、缺失、签名无效、未授权候选和解析异常必须成为明确的 `insufficient/review/not_evaluated`，不能返回成功。

### D8–D21：只读并行 shadow

与客户现有流程同时运行，不改变发布、下架或版权决定。按资产/版本/案件记录：

- 绑定完整率、版本 parent 正确率、候选 Recall@K；
- ordinary-propagation FPR、错误参考升级率、unknown/review 率；
- 证据包字段缺口、reviewer 回放成功率、一次采纳率；
- 每千件人工分钟、系统 P50/P95、存储/API/人工成本；
- 权限越界、删除/恢复失败、失败却成功和规则版本漂移。

### D22–D28：业务、IT/安全、版权/法务和采购联合决定

继续门是：有每周重复任务、指定人员实际采用证据包、人工净分钟下降且系统成本可解释、权限和删除回放稳定、预算负责人给出下一周期路径。停止门是：

1. 无书面授权、人工基线或删除责任人；
2. 失败却成功、跨租户越权、原始证据无法删除/恢复；
3. 客户要求自动确权、自动下架、自动发函或“无标识即人类”；
4. 算法只在 synthetic/IID 或已知生成器有效，真实传播后 risk/FPR/复核分钟恶化；
5. 证据包不进入客户审计、投诉、许可或发布流程；
6. 四周净价值不为正且没有具体修复和购买责任人。

### 收费实验

采用三种可比较的试报价，而不是先宣布统一单价：

1. **Sidecar 订阅**：租户 + asset/version volume + retention + API 批次；
2. **Review Workbench**：复核席位 + 月任务量 + evidence export；
3. **治理/私有化**：规则包/法域 + manifest 批次 + 连接器/字段映射 + 部署恢复演练 + 年度维护。

训练 ledger 可按 manifest 版本/撤回事件/审计报告计费；授权监测可按渠道/采集量/人工案件计费。公开采购金额、竞品定制化报价和论文指标只能作为“预算存在/替代存在”的信号，不能直接转成 Smart Shadow 价格。

试点净价值建议按客户认可的人工成本测量：

```text
net_value
  = batch_count * max(0, baseline_minutes - system_minutes - review_minutes)
    / 60 * customer_accepted_cost_per_minute
    + customer_accepted_evidence_value
    - run_and_integration_cost
```

`customer_accepted_evidence_value` 只有在证据包进入客户审计、投诉、许可或发布流程并得到书面认可时才能计入；论文分数、采购预算、公开处罚金额和登记量不能代替收入。

## 9. 仍需补证的市场命题

以下都不能写成当前事实：客户愿意付款；某个行业的 TAM/SAM/SOM；任何价格、续费率、SLA 或 ROI；Adobe/Bynder/Cloudinary API 已与仓库兼容；中国/欧盟规则会直接产生采购；算法可通用于所有生成器、内容类型和传播平台；C2PA、数字水印或视觉证据能独立证明作者、版权、真实性或侵权。

下一步只应选择一个首客和一个工作流，完成授权、四周 shadow、人工基线、删除/恢复和预算决定。没有这些证据，新增市场方向仍保持 `I/P`，不得改写 `docs/01-项目决策记录.md` 或产品接口。
