# 2026-09-21：论文先例覆盖终审（RSCPTN / SIPA / DRCS / CEAT）

更新时间：2026-09-21
研究范围：2025–2026 年可访问的一手论文、会议正式页面、标准规范和作者/官方代码。
文件性质：阶段 7 研究审计；不批准线上接入，不改变 `aigc_result_v1`，不把外部结果写成 Smart Shadow 的效果。

## 1. 先给结论

本轮没有找到一篇论文把下列条件全部合并为同一个可回放事件：登记原件、同资产 ordinary-propagation null、检索 membership、传播树相关性、参考版本选择、检索投毒、独立审计分区和选择后自适应取证。但四个候选的单项组成部分几乎都已有先例，因此“新 detector”“新传播树”“新开放集模型”“新 conformal/e-value 理论”都不能成立。

当前最窄、可被实验直接推翻的主张只能写成协议增量：

> 在冻结的授权 manifest、同一检索候选、同一参考选择策略和同一证据预算下，把普通传播 null 通过完整的 retrieval → membership → version tree → selection 流程重放，并用独立索引/证据分区、来源/生成器双注册库和 cross-fitted null stream 记录污染、混淆与自适应停止；如果它相对已有基线降低 ordinary-propagation FPR、reference false-match、poisoning route flip、selective risk 或人工复核分钟，且 coverage、未知生成器、下一时间窗和传播扰动不恶化，才有资格称为 Smart Shadow 的研究增量。

这仍然不是“解决 AIGC”。它不能证明作者身份、版权归属、侵权、内容真实性或某张图一定由 AI 生成；支持不足、来源冲突、未知生成器、检索污染或回放不一致时必须 `review`/`unknown`/`insufficient`。

## 3. 四个候选逐项终审

### 3.1 RSCPTN-v1：检索与选择校准的来源条件传播树 null

**候选定义。** RSCPTN 把 query 的检索候选快照、membership 判断、版本传播树、参考/版本选择和局部 evidence 作为一个事件；在同一选择策略下对 ordinary-propagation placebo 重放，联合保守 gate `p_joint_raw=max(p_tree_raw,p_retrieval_raw)`，任何污染、树环、选择 tie、开放集或支持不足都进入 review/unknown/insufficient。

**已被覆盖的单项。**

1. QuAD 已覆盖 near-duplicate retrieval、质量感知聚合和受控退化树；不能再主张“检索近重复 + 质量校准 + 传播树”本身新。
2. RCIR 已覆盖具有 coverage guarantee 的图像检索集合；不能再主张“给检索结果做风险/coverage 控制”本身新。
3. GEVT 已覆盖 provenance graph 的方向和拓扑；RITA 已覆盖按步骤的 process-aware localization；C2PA 已覆盖 manifest history/repository receipt；不能再主张“图、步骤、回执”本身新。
4. SIGIR pixel-poisoning 与 ICML PoisonedEye 已直接证明视觉检索/VLRAG 的 corpus poisoning 可通过极少量样本改变 top-k 或下游输出；不能把 retrieval archive 当无污染 oracle。
5. CAP、selection-conditional conformal 和 SAEC 类工作已覆盖 selection-after-calibration 的一般统计问题；不能称 RSCPTN 为新的 conformal theory。

**最窄可证伪差异。** 仅可检验以下事件级命题：

> 相对于 query-only、QuAD-like quality aggregation、SCPTN（只做树级 null）、SAEC/SAEA、逐节点 null 和“去 retrieval replay”版本，在同一候选快照、同一 action budget、同一 manifest 和独立外部切分上，RSCPTN 是否降低 ordinary-propagation FPR、wrong-reference false-match、poisoning-induced route flip 或人工复核分钟，同时保持局部编辑的 accepted coverage、unknown recall、下一时间窗风险和 P95 成本不恶化。

这里的增量是**完整检索事件和污染路径的 null replay**，不是更强的 detector、检索器、树数据结构或概率模型。

**RSCPTN 的直接撤回门。** 以下任一成立即撤回“算法创新”，保留为 retrieval/provenance audit sidecar：

- 只在无污染 IID 或已知生成器上改善；
- 主要收益来自把样本送入 `unknown/review`，接受样本风险没有下降；
- 只增加近重复/质量聚合却和 QuAD-like baseline 无差异；
- poisoning fixture 未能改变 candidate membership/selection trace，或 replay 不能从冻结 archive 独立重算；
- tree-level p-value 的收益在逐节点/去相关性消融中消失；
- recall、人工分钟、存储或 P95 代价超过收益。

### 3.2 SIPA-v1：Split-Index Provenance Audit

**候选定义。** 将“用于检索和 winner 选择的 index/evidence”与“完全不参与选择的独立 holdout index/evidence”分开；先冻结 candidate 和 selection trace，再只在 B 分区审计 source-conditioned contrast、ordinary-null consistency 和 poisoning/漏召回/误召回。

**已被覆盖的单项。**

1. CAP、Online Selective Conformal Inference、Confidence on the focal 已覆盖 selection 后独立 calibration、selection-conditional coverage 和 exchangeability 风险。
2. RCIR 已覆盖 retrieval set 的风险控制/coverage guarantee。
3. QuAD 已覆盖近重复检索和质量分层；SIGIR/PoisonedEye 已覆盖检索库投毒。
4. 交叉拟合、sample splitting、holdout audit 是通用统计和工程卫生做法，不能单独成为算法创新。

**最窄可证伪差异。** SIPA 只能主张一种**来源证据的跨索引泄漏审计协议**：

> 当 candidate selection 只读 A、审计只读 B，且 B 的 candidate coverage、漏召回/误召回和 poisoning 对照被显式记录时，SIPA 是否相对同一 index 上的 RSCPTN/SAEC 降低 reference false-match、selection leakage 或 poisoning route flip，而不靠扩大 `unknown/review` 造成 coverage 崩塌。

它不提供新的检索器，不提供新的 conformal guarantee，也不能仅凭 B 分区“证实”来源或作者。

**必须预注册的关键反例。** A/B 共享 asset/group、B 反过来影响 candidate、候选数不一致、B 只保留成功召回、B 与 calibration/evaluation 时间窗重叠，均应固定 `selection_leak` 或 `insufficient`，而不是删除失败样本后报告更好结果。

**SIPA 撤回门。** 若独立 B 分区只增加拒判、没有降低 ordinary-propagation FPR/false-match/人工分钟，或 candidate coverage 受损导致业务不可用，则保留为审计记录，不称算法增量。

### 3.3 DRCS-v1：Dual-Registry Confounder Separation

**候选定义。** 将 `asset_registry`（登记原件、版本、传播关系和授权状态）与 `generator_registry`（generator family/fingerprint、real-only profile、开放集支持）完全分开；报告 source-conditioned contrast `C_source` 和 generator evidence `C_generator`，只在来源证据在 generator-matched controls 下仍稳定时进入候选，否则进入 `conflict_review`/`open_set_unknown`。

**已被覆盖的单项。**

1. Forensic Self-Descriptions、WACV Origin Attribution、BOSC、GAPL/LTD 等已覆盖 zero-shot/open-set/generator-aware detection 和 attribution。
2. GEVT、Region-Level Data Attribution（[ICCV 2025 正式 PDF](https://www.openaccess.thecvf.com/content/ICCV2025/papers/Nguyen_Region-Level_Data_Attribution_for_Text-to-Image_Generative_Models_ICCV2025_paper.pdf)）和 Fast Data Attribution（[NeurIPS 2025 正式页面](https://proceedings.neurips.cc/paper_files/paper/2025/hash/5ce3a49415f78db65a714b4f05c62f4e-Abstract-Conference.html)）已覆盖 provenance graph、局部训练数据影响和快速 attribution。
3. Nature Communications 2026 的 [Outputs of generative diffusion models are often unattributable](https://www.nature.com/articles/s41467-026-75667-5) 明确用 counterfactual omission 研究 attribution decay，显示“输出 → 单个训练样本/作者”的归因可能不可识别。

**最窄可证伪差异。** DRCS 只能主张**混淆控制与冲突路由**，不能主张 generator attribution 新模型或因果识别：

> 在同一 source/query/null manifest 上，加入 generator-matched controls 和独立 generator registry 后，source false-match、generator-confounded review 和 unknown recall 是否优于只用 asset registry 或只用 generator detector 的基线；`C_source - C_generator` 只能是审计量，不能解释为来源的因果效应。

**必须明确的不可识别边界。** generator family 命中不等于这张图来自该 generator；source registry 相似不等于作者/版权；模型 provenance 不等于训练数据许可；`C_source` 和 `C_generator` 的差值不是“去除生成器因素后的真实来源效应”。未知 generator、局部重绘、真实传播或 registry 不完整时，DRCS 必须拒判。

**DRCS 撤回门。** 如果 generator registry 只让 closed-set accuracy 上升、未降低 source false-match；如果 unknown 被错误压低；或双 registry 共享同一训练/选择资产导致循环泄漏，则撤回为诊断 sidecar。

### 3.4 CEAT-v1：Cross-Fitted Evidence Audit Trail

**候选定义。** 将 SAEA 的自适应 probe（追加 matched decoy、matched null、view/operator、质量重对齐等）放入独立 ordinary-null stream；用 cross-fitted e-value/e-process 记录每步 action、state digest、probe-order、停止时点和总预算，避免“看到最有利 probe 后再选择停止”造成假阳性。

**已被覆盖的单项。**

1. Conformal e-prediction、Conformal e-testing、E-Values Expand the Scope of Conformal Prediction 已覆盖 e-value、cross-conformal e-prediction、交换性检验和 e-process 基本理论。
2. CAP、Online Selective Conformal Inference 和 JRSSB focal-unit 工作已覆盖 selection-conditional calibration。
3. 2026 JRSSB [Anytime validity is free](https://doi.org/10.1093/jrsssb/qkag050) 已覆盖 optional stopping/continuation 的 anytime-valid sequential test；不能把“支持随时停止”称 CEAT 独创。

**最窄可证伪差异。** CEAT 只能主张**来源条件局部编辑证据的 cross-fitted audit trail 工程组合**：

> 在每步 null probe 与 test/evaluation evidence 完全分流、action policy 只依赖过去 state、停止规则预注册且每一步可重放的条件下，CEAT 是否在相同 action budget 下相对 fixed-order SAEA、无 null、无 cross-fit 和简单 p-value 累积，降低 accepted-sample selective risk、route flip 或人工复核分钟，同时不增加普通传播 FPR。

这不是新的 e-process、不是新的 optional-stopping 理论、也不是自动得到 coverage guarantee。若要宣称任何统计保证，必须另行给出 dependent propagation tree、adaptive retrieval membership 和 finite-sample assumptions 下的证明；当前仓库没有该证明。

**CEAT 撤回门。** 任一步骤用 evaluation/人工标签更新 null profile；根据当前最大 e-value 选择 probe 但未记录 policy；重复使用同一 asset 的相关传播节点而未做 group control；停止后丢弃未成功 probe；或只增加拒判而不降低 accepted risk/人工成本，均只能保留为审计轨迹。

## 5. 最小可证伪实验（四候选共用）

### 5.1 固定输入和切分

必须先冻结并签名：

```text
authorized_manifest_digest
asset_registry_digest
generator_registry_digest
retrieval_archive/index_snapshot_digest
candidate_rank/count
membership_policy_digest
selection_policy_digest
tree_parent/branch/depth/digest
canonical_frame_digest
operator_set_digest
detector/schema_digest
selection/calibration/evaluation split digest
ordinary_null_profile_digest
action_budget and stopping policy digest
```

同一 asset/group 的传播版本不能跨 split；B audit index 不能反过来改 candidate；generator registry 不能用 evaluation 目标样本拟合；`uncertain`/`outside` 不能变成软权重。

### 5.2 最小对照

至少运行：

1. query-only detector；
2. reference-only / D-054；
3. SCPTN（仅 tree null）；
4. QuAD-like quality/near-duplicate aggregation；
5. SAEC/SAEA fixed-order；
6. 完整 RSCPTN；
7. RSCPTN + SIPA；
8. RSCPTN + DRCS；
9. RSCPTN + CEAT；
10. 去 retrieval replay、去 holdout、去 generator registry、去 cross-fit、逐节点 null、错误 reference、投毒 candidate 和 unknown generator。

### 5.3 必报指标

```text
ordinary-propagation FPR
reference false-match rate
poisoning-induced route flip
accepted-sample selective risk / risk@coverage
unknown/review/insufficient coverage
local ROI F1 / boundary F（仅真实有 mask 时）
generator-family unknown recall
next-time-window and post-propagation strata
action count, P50/P95 latency, storage and cost per 1k assets
human review minutes and correction/retraction rate
```

不能只报总体 AUROC、单一 accuracy、synthetic runner route count 或只报拒判率。

## 6. 不能外推边界

- 外部论文的 benchmark/攻击数字只说明先例和风险，不能变成 Smart Shadow 的准确率、FPR、概率、ROI 或部署 SLA。
- 当前仓库已有的 RSCPTN/SCPTN/SAEC/SAEA 代码仍属于阶段 7 raw contract；没有 G0–G6 授权 manifest、独立 ordinary-null、真实局部 edit mask、开放集/时间切分和人工基线，就不能写成真实 AIGC 效果。
- `p_tree_raw`、`p_retrieval_raw`、`p_joint_raw`、`C_source`、`C_generator`、e-value、route 和 evidence digest 都不是 AIGC probability、作者身份、版权归属或法律结论。
- C2PA 规范自身要求把 assertions 当作可验证的 provenance/trust signals，不做“好/坏”的事实价值判断；有效 manifest、repository receipt 或 AI disclosure 不能证明内容真实、未编辑、合法拥有或由某个自然人创作。
- unknown generator、没有登记原件、错误 reference、retrieval archive 被投毒、传播树存在环/缺父节点、质量/算子/坐标不匹配或独立支持不足时，正确行为是拒判或人工复核。
- 未找到完整组合不等于专利新颖性、论文 novelty 或文献穷尽证明；本文件是针对当前检索到的一手来源的审计快照。

## 7. 研究顺序和撤回策略

1. 先完成 D-063/SS-019 的真实 retrieval event replay：冻结 archive/index、membership、tree parent/branch/depth、selection trace，再接现有 RSCPTN raw sidecar。
2. 若真实 replay 证明污染/selection route flip 是主要错误源，优先做 SIPA 的双索引无重量契约；没有 leakage fixture 不编码。
3. 只有同时拥有同 generator、不同 source 的授权 controls，才做 DRCS；不训练新 generator detector，不把 registry 差值写成因果效应。
4. CEAT 放在真实 SAEA action trace 之后；先做统计模拟/依赖审计，再决定是否写代码。没有 independent null stream 和 stopping log，不宣称 e-process。
5. 四候选均须与 D-054、SCPTN、SAEC、SAEA 和 QuAD-like baseline 做同 manifest、同预算、同 split 消融。若只增加拒判、只在 closed-set/IID 改善、P95/存储/人工成本变差或 replay 不能独立复现，统一撤回为 provenance/review audit sidecar。
