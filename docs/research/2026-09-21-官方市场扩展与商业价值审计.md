# Smart Shadow 官方市场扩展与商业价值审计

更新时间：2026-09-21
状态：研究输入；不代表客户、报价、收入、部署、合规认证或算法效果
范围：只使用监管、标准、政府/国际组织和厂商官方资料，审计比赛完成后最值得验证的市场扩展。

## 1. 结论先行

官方资料能证明四类外部触发：

1. **P0：合成内容标识与透明度体检**。中国《人工智能生成合成内容标识办法》要求显式/隐式标识，并要求传播服务提供者采取技术措施；欧盟 AI Act Article 50 自 2026-08-02 起要求特定生成内容具备机器可读标记，旧系统的部分标记义务最迟到 2026-12-02 生效。客户的直接痛点是标签在导出、再编码、平台搬运后是否仍可检测和回放。
2. **P0：已有私有 DAM/MAM 的 provenance/version/evidence sidecar**。C2PA 2.4 已定义 durable content credential、fingerprint、manifest repository、repository receipt 和 AI disclosure；这些结构解决“如何表示”，并不替客户解决跨工具导出、缺失、冲突、权限和人工复核。Smart Shadow 应作为旁路证据层接入，而不是替代 DAM。
3. **P1：平台/媒体版权争议取证**。版权所有者、媒体和平台经常需要把原件、版本、传播、许可、沟通和人工判断整理成可复核包；C2PA、近重复检索和供应商 detector 都只能覆盖其中一段。Smart Shadow 可卖只读的争议证据 sidecar，不自动下架、发函或裁决。
4. **P1：模型/数据供应链 provenance（含训练许可、排除与撤回）**。欧盟 GPAI 指南要求版权政策、训练内容摘要以及向下游提供训练/验证数据的类型、来源和整理方法；WIPO 提供组织采用生成式 AI 时的 IP 风险清单，美国版权局持续发布 AI 与训练数据报告。这里适合卖 manifest diff、撤回回放和证据包，不适合宣称某幅图“被模型训练过”。

这些是**需求触发和替代存在的证据**，不是 Smart Shadow 的 TAM、客户、价格、收入或 ROI 证据。近期只应验证一个有明确截止日期、授权 manifest、人工责任人和重复任务的私有资产客户；没有这些条件就停留在访谈与 fixture。

## 3. 四条方向的买方和交付边界

### 3.1 P0：来源/标识/导出链 readiness checker

**目标买方**：有生成式内容供应商、内容平台、媒体集团、品牌营销平台和跨境发布链的内容安全/合规负责人；IT、隐私、安全和采购是共同决策方。只有当买方能指出一个法域、一个内容类型和一个上线/整改日期，才算合格线索。

**痛点与替代**：现有替代包括供应商原生 C2PA/GB 标识、Adobe/Microsoft 等产品的单点生成或检测、脚本检查和人工抽样。它们能够写入或检测某一类信号，却不自动回答“原始字节—导出版本—平台版本之间何时丢失、篡改、冲突或无法解释”。

**最小 sidecar**：

- `MetadataMutationGuardV1`：原始字节 digest、文件头/格式、C2PA/GB/EXIF/XMP/平台 ID 的 parser/spec/trust 状态；
- 导出路径和版本事件 replay，明确 `preserved`、`mutated`、`missing`、`conflict`、`unsupported`、`insufficient`；
- `provenance_conflict_replay`：签名失效、claim/asset 不匹配、时间/工具冲突、删除墓碑和恢复证据；
- 只读报告和人工复核队列，不改变发布决定。

**首轮验证指标**：字段完整率、机器可读标识保留率、不同导出/再编码下的回放成功率、冲突分类准确率、静默失败次数（必须为 0）、P50/P95、每千件成本、人工处置分钟和责任人对报告的采纳率。

**停止门**：没有明确法域/日期/责任人；客户不能提供脱敏导出链和删除规则；解析失败仍被报告为通过；冲突被静默丢弃；四周没有重复任务或净人工时间价值为负。停止时保留为离线 validator，不接发布链。

**不能外推**：readiness checker 不等于 C2PA/GB 认证、法律合规结论、内容真实性、作者身份或“未检测到 AI”。

### 3.2 P0：私有 DAM/MAM provenance/version/evidence sidecar

**目标买方**：已有版权库或媒资库的图片库、媒体机构、电商/广告内容团队、MCN、品牌设计团队和政企媒资部门。首客应能提供原件、版本/传播事件、权限和现有人工复核结果。

**痛点与替代**：原生 DAM/MAM、Adobe Content Credentials、C2PA Inspect、云 provenance API、反向图搜和人工文件夹是现有替代。它们通常各自覆盖存储、单点 provenance、检索或审核；跨系统的父子版本、缺失 metadata、错误 reference、权限、删除和 evidence package 需要另一个审计层。

**最小 sidecar**：

- `EvidenceSidecarV1`：原件—版本—传播—权限绑定、父版本和不可变 digest；
- C2PA/GB/EXIF/XMP 与平台声明的原始摘要，保留 parser、spec、trust 和缺口；
- 语义/近重复候选、blind decoy、wrong-reference 和局部 raw evidence，只作为人工复核输入；
- `Review Workbench`：冲突队列、reviewer 意见、导出/删除墓碑、可回放证据包。

**首轮验证指标**：原件/版本绑定 precision-recall、manifest/字段完整率、错误 reference 率、ordinary-propagation false upgrade、evidence package 回放成功率、权限越界（必须为 0）、删除/恢复演练成功率、证据包采纳率、人工复核分钟、P50/P95 和每千件成本。

**停止门**：阶段 1–5 的身份、错误语义、上传安全、EvidenceV1/恢复和部署门未通过；客户不能提供至少 500 个授权原件、1,000 个版本/传播样本、人工基线和删除责任人；sidecar 不能只读接入或无法被内部流程采用；净价值不为正。

**不能外推**：sidecar 不替代 DAM/MAM，不保证所有权或侵权成立，不把相似候选写成 AIGC 概率、训练事实或法律结论，不做全网监测、自动下架或自动发函。

### 3.3 P1：平台/媒体版权争议取证

**目标买方**：图片库、媒体集团、品牌/电商平台的版权运营和内容争议团队，及受委托处理案件材料的版权代理、法务和取证服务商。政企/司法场景只能作为更严格的交付渠道，由有资质主体作最终判断。

**痛点与替代**：现有替代包括法务案件管理、人工文件夹、反向图搜、C2PA/水印查看器、云厂商 detector 和外部取证服务。它们通常不能共同保存登记原件、版本/传播关系、权限/许可、冲突和 reviewer 解释，也不能稳定回放“当时看到什么、用什么规则得出什么线索”。

**最小 sidecar**：

- `CaseEvidencePackageV1`：原始字节和 digest、原件/版本/传播事件、来源声明、许可范围、时间线和访问主体；
- 相似候选、blind decoy、wrong-reference、C2PA/GB/EXIF/XMP 和供应商 signal 只作为证据线索，保留 parser/spec/trust 状态；
- 冲突/缺失/unknown 队列、reviewer 依据、导出/删除墓碑和可复核的规则/模型版本；
- 面向法务的只读导出，不自动下架、发函、索赔或提交司法结论。

**首轮验证指标**：证据链完整率、原件/版本绑定 precision-recall、错误 reference 率、案件首次复核时间、reviewer 一致率、evidence package 采纳率、回放成功率、人工复核分钟、越权和静默假成功次数（必须为 0）。

**停止门**：没有真实争议流程、案件责任人和授权材料；客户要求系统自动作出侵权/确权结论；不能冻结留存/删除规则或无法回放当时输入；没有人工基线或复核结果不被内部流程采用。停止时只保留内部 evidence adapter。

**不能外推**：证据包只说明已保存的来源、版本、规则和人工意见；不等于侵权、作者、版权归属、事实真伪或司法采信。`not_detected` 不等于人类创作，`null_consistent` 不等于没有 AI。

### 3.4 P1：模型/数据供应链 provenance（训练许可、排除与撤回）

**目标买方**：模型提供商、数据集/图库供应商、出版社与媒体集团、版权代理和 AI 法务/合规团队。购买条件是对方已有许可清单、保留/排除规则和负责删除的组织角色。

**痛点与替代**：现有替代包括合同/法务台账、数据目录、模型自有训练日志、人工 spreadsheet 和企业治理平台。Smart Shadow 的增量只能是把资产、版本、许可、保留/排除、撤回和证据包做成同一可审计 diff；不得把近邻检索冒充 membership inference。

**最小 sidecar**：

- `asset_registry` 与 `generator_registry` 分离，记录来源、许可、期限、地域、用途和访问主体；
- `license_manifest_v1` 的版本 diff、撤回请求、删除墓碑、下游回执和重放 digest；
- 相似检索/局部证据只作为待核线索，冲突进入 `review`，缺失进入 `insufficient`；
- 导出面向法务的事实包：原始记录、规则版本、处理日志和人工意见。

**首轮验证指标**：manifest 字段完整率、许可/排除 diff precision-recall、撤回回放成功率、下游回执覆盖率、冲突复核分钟、误把近邻写成训练事实的次数（必须为 0）、审计重放成功率和法务采纳率。

**停止门**：没有书面许可/排除规则和删除负责人；不能证明删除或下游回执；客户只想要“证明某图训练过模型”；输出被用于自动索赔或下架；没有两次以上真实 manifest 版本变化。

**不能外推**：项目不能证明训练使用、数据集 membership、作者身份、版权归属或侵权责任。必须使用“来源记录/相似线索/待人工核验”。

### 3.5 P2：政企/司法/公共利益内容的保守证据复核（渠道扩展）

**目标买方**：政务/媒体机构的内容可信团队、公共信息平台、数字取证服务商和受委托的专业机构。律所或司法机关只能作为后续合作方，由有资质主体作最终判断。

**痛点与替代**：单一水印、C2PA 或 vendor detector 覆盖有限，且云厂商自己声明不能识别所有 AI 内容；人工专家复核昂贵但仍是责任出口。Smart Shadow 可把多类信号、来源/版本和传播 null 组织为可回放的复核包。

**最小 sidecar**：供应商 signal adapter、原件/传播关系、变换审计、unknown/review/insufficient 路由、复核人和证据包；默认 fail-closed，任何缺失或冲突都不升级为确定结论。

**首轮验证指标**：证据链完整率、不同 reviewer 的一致率、unknown/review 比例、变换下普通传播 FPR、案件周转时间、复核分钟、越权和审计回放失败次数。

**停止门**：采购方要求系统自动作出法律/司法结论；无法取得授权样本或留存/删除规则；高风险误报没有人工复核；没有明确证据采纳标准和责任人。停止时只保留内部研究或 adapter 验证。

**不能外推**：任何 route 都不等于真伪、深度伪造、作者、版权或司法结论；`not_detected` 不等于人类创作，`null_consistent` 不等于没有 AI。

## 4. 收费和商业验证只做假设实验

不要按“每张 AIGC 分数”定价。可以在客户明确需求后分别测试四种计费单位，不预设价格：

| 计费单位假设 | 适用方向 | 价值锚点 | 需要客户证明 |
| --- | --- | --- | --- |
| 资产/版本/manifest 批量 | P0 DAM/MAM、P0 readiness | 回放件数、字段和冲突处理量 | 连续任务量、人工基线和采购科目 |
| 规则包/法域/导出路径 | P0 readiness | 规则维护、导出体检和冲突报告 | 法域范围、责任人和整改日期 |
| 复核席位/案件包 | P0/P2 | 人工复核分钟和证据包采纳 | 复核角色、案件周转和保存要求 |
| 私有部署/隔离运行 | P0/P1/P2 | 数据不出域、审计和恢复演练 | 安全评审、SLA、运维责任和预算 |

公开标准、云厂商 API 和采购研究不构成 Smart Shadow 的价格锚点；先收集书面预算、重复任务和愿意付费的交付单位，再决定报价。

## 5. 四周只读 shadow 的共同验收门

客户 shadow 仍受阶段 1–5 门控。允许启动前必须有：

1. 法域、内容类型、业务责任人、权限范围、留存期限和删除责任人；
2. 脱敏或隔离的授权 manifest，建议至少 500 个原件、1,000 个版本/传播样本；
3. 冻结 parser/spec/rule 版本、供应商 adapter、普通传播 null 和人工基线；
4. 只读接入、可撤销 token、审计日志、删除墓碑和恢复演练；
5. 明确的继续/停止书面门。

每周固定报告：绑定 precision-recall、字段完整率、冲突/缺失/unknown、普通传播 FPR、evidence package 复核采纳率、人工复核分钟、P50/P95、每千件成本、越权、静默假成功和删除/恢复结果。安全项或静默假成功任一失败立即停止；只增加拒判而没有人工或业务收益，方向降级为 audit sidecar。

## 6. 由市场需求反推的算法创新切片

市场研究不批准新算法直接上线，但给出三个可证伪的研究问题：

1. **Metadata mutation guard + provenance conflict replay**：在同一导出链中，能否相对人工脚本减少静默缺失和错误通过，同时保持 P95、成本和回放可复现？
2. **来源条件局部证据**：在已有登记原件、ordinary-propagation matched null、blind decoy 和 wrong-reference 下，能否减少人工误升级，而不是仅增加 `unknown`？
3. **双注册表混淆分离**：能否把资产来源证据、生成器信号和冲突分开，而不把 generator-only 信号当作来源/训练事实？

共同对照必须含规则/脚本基线、供应商 adapter、query-only、去 null、去 decoy、错误 reference、未知生成器、下一时间窗和低质量传播。指标至少包括 ordinary-propagation FPR、reference false-match、risk@coverage、unknown/review、ROI/边界 F、route flip、人工分钟、P50/P95 和每千件成本。若优势只来自更多拒判、只在 IID/closed-set 成立、无法独立重放或成本恶化，撤回为审计 sidecar。
