# CFAEA-v1 研究设计：Cross-Fitted Asset–Generator Evidence Audit

更新时间：2026-09-21（Asia/Shanghai）
状态：**P0 研究设计，尚未批准编码；阶段 7 离线 sidecar**
任务登记：[SS-029](../active-tasks/SS-029-cfaea-v1-cross-fitted-evidence-audit.md)

本文件把已有的 ALG-001/RSCPTN 检索事件回放、SIPA 的分索引 holdout 和 DRCS 的双注册表想法收敛为一条可审计的研究切片。它不改变线上接口、`aigc_result_v1`、主线阶段 1–5 或产品边界；在 G0–G6 和真实授权数据通过前，所有结果只能是 `raw evidence`、`review`、`unknown`、`insufficient` 或 `not_evaluated`。

## 1. 最窄主张

Smart Shadow 不主张训练一个更强的通用 AIGC detector，也不主张提出新的 conformal、e-value、检索或生成器归因理论。CFAEA 只检验下面一个窄问题：

> 在相同候选覆盖、相同动作预算和相同人工复核预算下，先由索引/归档 A 完成检索与 winner 选择，再由与 A 隔离的索引/证据 B 只复核冻结 winner，并用与 A/B 均隔离的 ordinary-propagation null 和 generator-matched controls 做交叉拟合；这是否能降低“检索选择偏差 + 普通传播伪影 + 生成器伪影混淆”造成的来源条件局部证据误报，同时保持真实局部编辑的覆盖和定位质量？

“降低”必须在预注册的同一 coverage/action budget 下比较 ordinary-propagation FPR、错误参考/盲 decoy false-match、检索投毒 route flip 或接受样本 selective risk，并且不以提高 `unknown/review`、丢掉 B 缺失样本、降低覆盖、牺牲 P95/成本来换取。即使该主张成立，它也只表示一个来源条件的证据审计协议有效，不表示检测出 AIGC 事实、作者、训练来源、版权或侵权。

## 2. 先例边界与为什么现在做

以下能力已有先例，不能被 CFAEA 重新命名为独立创新：近重复质量聚合和退化树（QuAD/AncesTree/ReWIND）、局部编辑检测与定位（RADAR/OpenSDI/DICE/RITA/SAFE）、开放集或生成器族检测（GAPL/LTD/OpenSDI 等）、选择后校准（CAP/JOMI/Online Selective Conformal）以及 split/holdout 或 e-process 的一般统计方法。仓库的 `docs/research/2026-09-21-论文前沿补充.md` 和 `2026-09-21-论文先例覆盖终审.md` 已记录这些边界。

CFAEA 的工程白区是把四类独立性放进同一可回放事件，而不是把它们的分数相加：

1. A 只选择候选，B 只审计已冻结 winner，禁止 B 重排或换 reference；
2. `asset_registry` 只保存登记原件、版本、传播树和 ordinary-null，`generator_registry` 只保存生成器/real-only/open-set 对照；两者不共享会反向影响 winner 的 profile；
3. source-conditioned observed/null contrast 和 generator evidence 各自 cross-fit，冲突时拒判；
4. retrieval、membership、tree、selection、B direct lookup 和 null profile 由 digest 完整重放。

这仍是组合协议假设。没有真实授权 archive、独立 ordinary-null、generator-matched controls 和外部 split，不能称“已解决 AIGC”或“已验证创新”。

## 3. 端到端流程

```text
冻结授权 manifest / access / deletion policy
        │
        ├── asset registry AR ── ordinary-propagation null profile C
        └── generator registry GR ── real-only/family/open-set profile Cg
                        │                 （两者与 evaluation group 隔离）
                        ▼
索引 A：retrieval → membership → propagation tree → fixed winner/region
                        │ freeze selection_trace_digest
                        ▼
索引/证据 B：只 direct lookup winner，固定 region/operator，不重选
                        │
                        ├── matched ordinary-null contrast p_B_raw
                        └── generator-matched control evidence g_B_raw
                        ▼
cross-fit source gate + generator confounder gate + replay/privacy gate
                        ▼
holdout_consistent / conflict_review / unknown / insufficient
```

任何 `ordinary_propagation` 作用域都只能路由 `ordinary_propagation_consistent` 或 `insufficient`，不能进入 candidate。`generator_registry` 不能参与 A 的 candidate rank、winner、region proposal 或 source-null profile 拟合。

## 4. 输入契约（CFAEAInputV1）

CFAEA 是独立研究 schema，不能修改线上 `Evidence` 或 `aigc_result_v1`。所有 digest 必须从 canonical 内容重算，调用者只填 digest 时回放失败。

### 4.1 授权与分组

```text
schema = "cfaea-input-v1"
research_manifest_digest
authorization_id / authorization_scope / authorization_expiry
privacy_scope / request_principal_digest / access_policy_digest
access_audit_digest / retention_policy_digest / deletion_tombstone_digest
asset_id / group_id / query_digest / split / fold_id / time_bucket
asset_registry_digest / generator_registry_digest
```

`group_id` 必须把同一原件、所有版本、同一作者/拍摄主体、同一 prompt 或同一传播链放在同一 group；任何 group 跨 A/B、calibration/evaluation 或 generator profile fit/evaluation 泄漏都拒判。原始图片、个人信息和受限模型权重不进入仓库。

### 4.2 A 选择快照与回放

```text
selection_index_snapshot_digest / archive_digest / index_build_digest
selection_feature_schema / preprocessing_digest / selection_retrieval_policy_digest
candidate_ids / candidate_ranks / candidate_scores
membership_decisions / membership_evidence_digest
tree_snapshot_digest / tree_edges / parent / branch / depth
selection_policy_digest / ordered_action_trace / action_budget
winner_id / winner_tree_id / region_proposal_digest / selection_trace_digest
poisoning_stress_route / selection_replay_status
```

A 必须从完整 archive/index snapshot 重算 candidate 顺序、membership、tree 和 winner。人工最后挑选、只保留成功召回候选、A 内 tie、`uncertain/outside` membership 或 poisoning 失败不能作为强 candidate 的输入。

### 4.3 B 直接审计快照

```text
audit_index_snapshot_digest / audit_archive_digest / audit_index_build_digest
audit_feature_schema / audit_preprocessing_digest / audit_view_operator_digest
direct_lookup_digest / fixed_winner_id / fixed_region_proposal_digest
canonical_frame_digest / detector_version / score_schema
observed_effect_B / ordinary_null_effect_B / contrast_B / null_profile_digest
null_support / p_B_raw / quality_score / source_match_score
transform_family / quality_bucket / transport_bucket / time_bucket
membership_recheck / tree_recheck / audit_replay_status
input_digest / evidence_digest
```

B 的 API 必须证明它只读取 `fixed_winner_id`。如果 B 返回新的 top-K、按 B 分数替换 winner、根据 B 结果修改 region/mask/operator，或者 B 用 evaluation 结果重拟合 null，均固定为 `selection_contaminated`。A/B 至少在以下三轴中独立两轴：archive/time snapshot、feature/index build、query view/operator/evidence stream；仅换随机种子不算独立。

### 4.4 两个 registry 与 cross-fit profile

`asset_registry`（AR）字段：

```text
asset_id / version_id / parent_version_id / tree_id / branch / depth
source_match_bucket / transform_family / quality_bucket / transport_bucket
canonical_frame_digest / ordinary_null_profile_digest / asset_group_digest
```

`generator_registry`（GR）字段：

```text
generator_family / generator_profile_digest / real_only_profile_digest
feature_schema / calibration_split_digest / support / open_set_status
generator_control_group_digest / profile_version / profile_expiry
```

AR 与 GR 的 profile fit、calibration 和 evaluation group 必须按 asset/group、generator family 和时间切分交叉隔离。GR 只能产生 `g_B_raw`、`known_family`、`open_set_unknown` 或 `generator_conflict` 等证据；不能替代 AR 的 source match，也不能从“命中某生成器族”推出作者、训练来源或 AIGC 事实。

## 5. 统计量与门

### 5.1 Source-conditioned matched null

固定 winner、region、operator 和 canonical frame 后，B 的 source contrast 为：

```text
c_B = observed_effect_B - ordinary_null_effect_B
p_B_raw = (1 + count(N_B >= c_B)) / (1 + |N_B|)
```

`N_B` 来自独立资产组的同 `transform_family × quality_bucket × transport_bucket × time_bucket × source_match_bucket × operator_set` ordinary-propagation profile。`p_B_raw` 是 ties-inclusive finite-sample rank，只是 raw evidence，不是 AIGC 概率或 coverage 保证。A/B 的 p-value 不相乘、不做未经证明的 Fisher/Cauchy 合并。

### 5.2 Generator confounder evidence

对 B 固定 winner 的同一 canonical region/operator，GR 生成与内容/source 尽量匹配的 controls，得到 `g_B_raw`、`generator_family_support`、`open_set_status` 和 control digest。它只能回答“当前生成器/real-only profile 是否提供冲突或开放集信号”，不能通过简单相减得到“去生成器后的因果来源效应”。

预注册的 confounder 门：

| gate | 通过条件 | 失败路由 |
|---|---|---|
| GR 独立性 | profile fit 不含当前 asset/group/evaluation query；GR digest、version、support 可回放 | `selection_contaminated` / `insufficient` |
| known family | family support 达到冻结下限，且 source evidence 在 generator-matched controls 上方向稳定 | 继续 source gate |
| open set | family/feature/transform 不在支持集或 real-only profile 拒绝 | `open_set_unknown` |
| source–generator 一致 | source `c_B` 通过 null，GR 没有方向相反的强冲突 | 可进入 `holdout_consistent` |
| source–generator 冲突 | source 通过但 GR control 显著相反，或来源/生成器 digest 不一致 | `source_generator_conflict_review` |
| generator-only | 只有 GR 信号，AR source/null 不通过 | `generator_only_unknown` |

`generator_only_unknown` 不是失败的人类标签；普通传播的 GR 信号也不能升级为 candidate。

### 5.3 Selection/retrieval/replay 门

- A retrieval archive/index、candidate rank、membership、tree parent/branch/depth 和 selection trace 必须完整重放；`uncertain/outside` 只用于污染诊断，不得软加权。
- A winner、region proposal、action order 和 candidate coverage 在 B 之前冻结；B 缺失、删除、过期或不能 direct lookup 时禁止回退 A。
- A/B/calibration/evaluation/external 的 manifest、group、time、generator split 必须由 digest 验证；共享同 asset/group 或 B 影响 A 都是 leakage。
- poisoning、wrong-reference、blind decoy、tie、membership conflict 和 replay digest mismatch 固定拒判。

### 5.4 固定路由（CFAEAResultV1）

```text
holdout_consistent
source_generator_conflict_review
generator_only_unknown
ordinary_propagation_consistent
selection_contaminated
missing_holdout
open_set_unknown
insufficient
not_evaluated
```

只有 `holdout_consistent` 表示“当前 raw gates 下，A 选出的 winner 在独立 B 证据和独立 null 上保持来源条件局部对比”；它仍不是 `ai_generated_supported`、`human_supported`、作者/版权/侵权判断。输出禁止字段：`aigc_probability`、`confidence`、`author`、`copyright`、`legal_conclusion`。

## 6. 训练、校准与评测协议

### 6.1 训练与校准角色

P0 contract 不训练新 detector；detector、feature、generator profile 都是版本化 adapter。若之后引入训练，必须固定以下角色且先注册 digest：

1. `fit`：只用于 AR/GR profile、阈值或 adapter；按 asset/group、generator family 和时间分组。
2. `calibration`：只用于 ordinary-null `N_B` 与 GR open-set/family support；禁止出现 evaluation winner。
3. `selection_A`：只用于检索、membership、tree 和 winner/region selection。
4. `audit_B`：只用于冻结 winner direct lookup 与 B evidence；禁止重选、重拟合或改阈值。
5. `external`：未参与任何 profile、policy、模型、阈值或 route 设计，用来做 generator/time/transport 外部审计。

同一 asset、作者/拍摄主体、prompt、传播链和派生版本不得跨角色。默认建议五折 cross-fit；任一折的有效 support 低于预注册下限即为 `insufficient`，不能合并折来掩盖不足。

### 6.1.1 五折 cross-fit 的执行顺序

对每个 evaluation fold `k`，只执行一次下面的固定顺序；`k` 的任何结果不能回写 `-k` 的 profile、阈值或 selection policy：

```text
fit AR[-k] ordinary-null + GR[-k] real/family/open-set controls
        ↓ freeze profile/config digests
replay selection A[k] → membership/tree → winner/region
        ↓ freeze selection_trace_digest
direct lookup winner in audit B[k]（不重排、不重选）
        ↓
apply AR[-k] null gate + GR[-k] confounder/open-set gate
        ↓
write only raw route/evidence; aggregate after all folds are sealed
```

`AR[-k]`、`GR[-k]` 和 `B[k]` 不得共享当前 query 的 asset/group、同一局部编辑派生版本或会泄漏 operator 输出的缓存；若必须共享物理存储，需由 manifest 标出不可读字段并验证 content/evidence digest 不重用。`selection_A[k]` 可以看见候选的登记摘要，但不能读 `B[k]` 或 `GR[-k]` 的 generator control score；`GR[-k]` 可以看见 generator family 标签和 real-only controls，但不能参与 A 的排序。只有在全部 fold 的 trace、profile 和访问审计封存后，才可计算总体 FPR/risk@coverage；禁止根据单折最高收益挑选报告折。

### 6.2 最小真实对照

在同一冻结 manifest、candidate coverage、action budget 和人工预算下至少比较：

1. query-only detector；
2. asset-only / RSCPTN/ALG-001（无 B、无 GR confounder）；
3. SIPA（A/B holdout、无 GR cross-fit）；
4. generator-only/open-set adapter；
5. CFAEA 完整协议；
6. 去 ordinary-null、去 blind decoy/wrong-reference、去 retrieval replay、共享 A/B index、B 重新选择、去 cross-fit、去 GR confounder、无拒判的消融。

每个对照必须记录同一 `coverage/action_budget/manifest_digest`，不能删除 missing/unknown/poisoning 样本后再比较。

### 6.3 指标

- 主要：ordinary-propagation FPR、reference/decoy false-match、poisoning-induced route flip、accepted-sample selective risk；
- 局部证据：ROI IoU/Dice、boundary-F、mask-out/region-swap faithfulness、声明 mask 外激活、跨 view/operator spread；
- 开放集与可靠性：unknown/review recall、generator-conflict recall、coverage、route flip、ECE/Brier（只有真实独立校准后才可报告）；
- 运营：P50/P95、每千件成本、索引/存储、动作数、显存和人工复核分钟。

合成 runner 只验证 schema、digest、拒判和确定性；不填写上述真实效果数字。

## 7. 成功标准与撤回标准

### 7.1 成功标准（必须在解盲前预注册）

CFAEA 只有同时满足以下条件，才可讨论研究增量：

1. A/B/AR/GR/calibration/evaluation 的授权、group、时间、生成器、传播和删除门全部通过，且 `selection_trace_digest` 与 `audit_evidence_digest` 可独立重放；
2. 在预注册的固定 candidate coverage 和 action budget 下，普通传播 FPR 与至少一个主要来源误报指标（false-match 或 poisoning route flip）相对完整基线达到预注册最小改善 `delta_primary`；
3. accepted-sample selective risk 不恶化，coverage、unknown recall、ROI/boundary-F、P95、每千件成本和人工分钟均在预注册非劣化边界内；
4. generator-family leave-one-out、next-time-window 和真实传播/再数字化 external split 至少重复一次方向，收益不能只存在 IID/closed-set；
5. B 缺失、GR unknown、source–generator conflict 和 ordinary propagation 均按固定 route 拒判，没有隐性回退或静默成功。

`delta_primary`、coverage 和成本边界必须写入冻结 config/profile digest；不能看到结果后调整阈值或只报告通过的子集。

### 7.2 撤回标准

任一情况成立，CFAEA 降级为 `provenance/confounder audit sidecar`，不得称 AIGC 算法创新：

- 增益只来自更多 `unknown/review/insufficient`、丢弃 B missing 或降低 candidate coverage；
- A/B、AR/GR、profile/calibration 与 evaluation 有 group、时间、生成器、query/operator 或特征泄漏；
- B 重新选择 winner/region，或 GR 参与 winner、source-null、阈值和停止规则；
- 只在 IID、已知生成器或 synthetic fixture 有增益，外部生成器/下一时间窗/传播后失效；
- ordinary-propagation 被升级为 candidate，或 GR 命中被写成人类/AI、作者、版权或训练来源事实；
- P95、存储、运行成本或人工复核时间超过预注册边界；
- null/profile 无法独立回放、digest 不一致、缺失授权/删除责任，或只能用事后清洗的“成功召回”样本完成评估。

## 8. G0–G6 数据门映射

| 门 | CFAEA 必须有的证据 | 未通过时 |
|---|---|---|
| G0 manifest/权限 | 原件、版本、传播关系、A/B/AR/GR 许可、split/group、保留/删除和访问审计 | `not_evaluated` / `insufficient` |
| G1 ordinary null | 独立资产组的匹配传播族、质量/传输/时间/算子 null，支持量和 profile digest | 不报告 FPR/p_B，固定 `not_evaluated` |
| G2 authorized local edit | 真实局部编辑、独立 edit mask、canonical frame、操作/传播链和 B evidence | 不报告 ROI，保留 raw/review |
| G3 open set/confounder | blind decoy、wrong-reference、retrieval miss/poisoning、未知 generator、GR controls | `open_set_unknown` / `source_generator_conflict_review` |
| G4 stratified reliability/cost | generator/time/transport/quality 分层 FPR、risk@coverage、unknown、漂移、P95、成本和人工基线 | 不得宣称效果或 SLA |
| G5 controls/ablation | query-only、RSCPTN、SIPA、generator-only、去 null/decoy/replay/cross-fit/GR/B-reselect 等同预算对照 | 只保留 sidecar |
| G6 evidence/review/deploy | evidence package 一次回放、人工复核、删除/恢复、权限、失败闭合和部署前审查 | 不接线上、不升级业务结果 |

所有 G0–G6 未通过前，代码只允许离线研究和 raw route；禁止写入生产 AIGC 四态、概率、作者、版权或法律字段。

## 9. 分阶段实现建议（获批后）

本文件只做研究设计，不直接创建代码。若主 Agent 在 ALG-001 真实回放和 G0–G6 评审后批准，按四个可回滚切片实现：

1. **Contract slice**：`aigc/cfaea.py`、专测和 synthetic runner；只验证 schema、digest、A/B 不重选、AR/GR cross-fit 和 fail-closed route。
2. **Replay adapter**：把 `RetrievalEventReplayV1` 输出转换为 A trace，加入固定 winner 的 B direct lookup；复用既有 null/profile，不复制 detector 或改旧 route。
3. **Generator registry adapter**：只读 real-only/family/open-set profile，加入 generator-matched controls、未知/冲突路由和 cross-fit split 检查。
4. **真实评测 runner**：仅接受冻结授权 manifest、独立 ordinary-null、A/B archive、AR/GR profile 和 external split；数据不齐时输出 `not_evaluated`。

每个切片都要在 `docs/07-验证与运行记录.md` 记录真实执行的命令、digest、验证层级和未完成边界。不得接 `ai_server.py`、Go 网关、比赛版 `/check` 或客户数据。

## 10. 禁止外推

- A/B holdout 一致只支持“当前 source-conditioned raw evidence 在独立 B 上复核一致”，不支持 AIGC 概率、来源事实、作者、版权、训练数据或侵权结论。
- generator registry/fingerprint/watermark/C2PA 命中或缺失只是一条独立证据；命中不等于作者，缺失不等于人类，冲突必须 review。
- ordinary propagation、截图、再拍、JPEG/JPEG-AI、神经压缩和语义重写可能改变 detector 信号；任何传播稳定性只在冻结的 null/profile 上解释。
- 合成 fixture、外部论文指标、raw p-value、ROI、digest、路由计数和“通过轻量验证”都不能写成真实准确率、FDR、部署能力、客户价值或商业收入。
- 没有可审计训练删样本/干预实验，不得使用 `training-data attribution`、`used in training` 或等价表述。

## 11. 当前结论

CFAEA 是在 ALG-001/RSCPTN、SIPA 和 DRCS 之间建立明确依赖顺序的 **P0 研究设计**：先完成真实检索事件回放，再检验 A/B holdout；只有真实实验暴露出生成器伪影混淆且 generator registry 有独立 controls，才启用 GR cross-fit。它把 selection/retrieval、propagation null、confounder separation 和拒判绑定在一个可回放审计包中，但不把组合复杂度包装成已证明的新算法。

在当前仓库状态，正确表述仍是：**CFAEA-v1 设计已完成，代码和真实效果未验证；研究结果必须停留在离线 raw/review/unknown/insufficient。**
