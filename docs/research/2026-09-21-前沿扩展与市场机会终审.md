# Smart Shadow 前沿扩展与市场机会终审

更新时间：2026-09-21
定位：一手来源驱动的研究输入、算法候选和商业化排序；不代表 Smart Shadow 已取得论文结果、真实数据效果、客户收入或合规认证。

## 1. 结论

当前公开研究已经把“训练一个更大的单图 AIGC 分类器”变成高重合、易失效的路线。GlobalForge 指出，许多检测器依赖生成器留下的局部伪影，而 JPEG、模糊和其他真实传播会直接破坏这些线索；DailyBench 报告的结果也显示，实验室 benchmark 上的高准确率在现代生成和对象级编辑数据上会明显下降。[GlobalForge](https://arxiv.org/abs/2607.14684)、[DailyBench](https://arxiv.org/abs/2607.24016)

Smart Shadow 的可辩护方向应继续收窄为：在已有登记原件和可回放版本关系的场景，判断 query 是否存在超出普通传播的局部内容变化，并把错误原件、检索选择、未知生成器、隐私范围和证据不足显式路由给人工。它不承诺识别所有 AIGC，也不把检测结果转成作者、版权或侵权结论。

本轮新增的算法候选是 **Propagation-Envelope Causal Evidence Audit（PE-CEA-v1）**：把普通传播 null 从一个总体标量扩展为按传播严重度分层的上包络，观察局部干预效应是否在多个传播等级上持续超出同层 null。它的差异不在于又加入一个 detector，而在于把“传播强度—局部效应—反事实 null”作为一条可回放曲线，并用曲线级支持和不连续性拒判抑制局部伪影捷径。

PE-CEA 先作为阶段 7 的无重量模型契约，不能接入 `aigc_result_v1` 或线上服务。只有在真实授权 manifest、独立普通传播 null、外部生成器/时间切分和同预算对照通过后，才评估它是否值得保留。

## 3. 市场拓展与商业价值

### P0：已有资产库的证据增量层

首客仍然是已经有原件、版本和审核流程的私有 DAM/MAM、广告/电商内容团队、媒体和 MCN。交付形态是旁路 `provenance/version/evidence sidecar + Review Workbench`：读取并验证 C2PA/EXIF/XMP/平台声明，回放版本和传播事件，接入可替换的检测器，导出带 digest、规则版本、人工意见、留存和删除墓碑的 EvidenceV1。

价值指标应围绕流程闭环：版本绑定完整率、普通传播误报、unknown 处置时间、证据包采纳率、人工复核分钟、删除/恢复成功率和每千件成本。收费单位优先是 schema/接入费、月度审核席位、证据包/回放量和保留周期；单张 AIGC 分数不适合作为核心计价单位。

### P1：四个可验证扩展

1. **GLAM/数字档案**：按 TCR4CAP assurance 等级提供 CAP 缺口盘点、批量证据补全和馆藏迁移检查。
2. **新闻与品牌内容治理**：对照片、广告素材和再编辑版本建立来源冲突队列，支持发布前 review 和事后回放。
3. **保险/反欺诈取证**：把图片检测作为案件证据的一部分，保留原件、传播、访问和人工复核链；不直接自动拒赔。
4. **模型训练数据治理**：登记来源、许可、排除/撤回和抓取访问事件；把“图片 AIGC 检测”扩展到供应商模型谱系和训练数据 provenance。

### P2：视频、音频和来源监测

C2PA 已覆盖更多媒体形态，下一步可把同一 EvidenceV1 扩展到帧级/片段级 mask、音频片段、直播 manifest 和跨平台传播链。来源监测必须建立在权限、删除、速率、误报和审计闭环上；在阶段 1–5 未通过前不接客户数据或全网爬取。

## 4. PE-CEA-v1：下一算法切片

### 4.1 可证伪问题

在同一登记原件、同一 query、同一局部 mask/operator 和同一 canonical frame 下，局部内容编辑的 paired delta 是否能在多个传播严重度等级上持续超出同等级 ordinary-propagation null？如果只有低压缩/单一视角出现尖峰，是否应拒判为传播或 detector shortcut？

### 4.2 契约

每条 observation 保存：`asset_id`、`group_id`、`severity_level`、`transform_family`、`operation_scope`、observed/counterfactual raw delta、质量、source match、`manifest_digest`、`canonical_frame`、detector/schema、`split_digest` 和内容编辑所需的 `edit_mask_digest`。普通传播记录不能带 edit mask。

校准 profile 只接受独立资产的 ordinary-propagation paired groups，并按 `severity_level` 保存 null statistics。查询阶段计算：

```text
delta_s = observed_local_effect_s - counterfactual_local_effect_s
margin_s = delta_s - upper_null_envelope_s
auc_excess_raw = Σ_s weight_s · max(0, margin_s) / Σ_s weight_s
positive_level_fraction_raw = Σ_s 1[margin_s > 0] / number_of_levels
```

固定路由为 `envelope_candidate`、`null_consistent`、`curve_inconsistent`、`insufficient`。`p_value_raw` 和 margin 只属于 raw evidence；结果禁止 probability、作者、版权、侵权和 `human_supported`/`ai_generated_supported` 字段。

### 4.3 与现有切片的区别

- `paired_delta_calibration` 校准单个组的最大区域 delta；PE-CEA 校准传播严重度曲线。
- `propagation_stability` 检查多版本分数漂移；PE-CEA 检查每个严重度层的 null envelope 和整条曲线支持。
- `SCPTN/RSCPTN` 处理传播树和检索选择相关性；PE-CEA 处理退化强度造成的 detector shortcut。
- `spectral_evidence` 是可替换的观测流；PE-CEA 不规定像素、频谱或 CLIP detector。

### 4.4 真实评测门

同一冻结 manifest 比较 query-only、现有 paired delta、propagation stability、tree null 和 PE-CEA；固定相同 action budget 和 candidate coverage。必须覆盖 local edit、ordinary propagation、wrong-reference/decoy、已知/未见生成器、下一时间窗、JPEG/resize/blur/截图/再数字化，并报告 ordinary-propagation FPR、reference false-match、risk@coverage、ROI/边界 F、曲线保持率、route flip、P50/P95、每千件成本和人工复核分钟。

PE-CEA 只有在外部切分上降低误报或人工成本，同时不以大量 `unknown` 换取表面收益，才升级为研究增量；否则保留为传播审计 sidecar。

## 5. Agent 执行顺序

1. 主业务继续推进 `SS-001`，先消除 AI/链回执的假成功。
2. 研究线准备 ALG-001 真实授权 manifest、独立 ordinary-propagation null 和 retrieval archive/index；这些数据门优先于重模型和线上接入。
3. 在不改线上接口的前提下，实现 PE-CEA-v1 离线契约、专测和 synthetic runner，作为与现有 scalar/tree null 的可回放对照。
4. PE-CEA 通过真实 G0–G6 后，再决定是否进入 SIPA/DRCS/CEAT 或视频/音频扩展。
5. 商业线优先做 P0 首客访谈和人工基线；阶段 1–5、权限、删除和恢复演练未通过前，不读取客户数据。

## 6. 证据边界

论文、标准、法规和厂商页面只能支持 prior-art、需求和实验设计；外部 benchmark 的准确率、Google API 的产品描述和 TCR4CAP 的 assurance 等级都不能证明 Smart Shadow 的准确率、客户 ROI、法律结论或部署能力。PE-CEA 的第一版也只证明 schema、digest、曲线统计和 fail-closed 路由。
