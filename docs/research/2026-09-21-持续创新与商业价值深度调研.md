# Smart Shadow 持续创新与商业价值深度调研

更新时间：2026-09-21
定位：比赛结束后的研究总入口和执行索引，不是效果报告、客户证明、专利新颖性证明或合规认证。

## 1. 当前结论

比赛展示已经完成。后续目标是把 Smart Shadow 从可演示原型推进为可复现、可审计、可恢复、可评测的数字作品来源与版本存证系统。产品输出是候选匹配、来源/版本证据、风险提示和人工复核队列，不自动认定作者、所有权、侵权责任或 AIGC 事实。

当前最值得验证的产品路径是：

```text
已有私有图库 / DAM / MAM
        ↓
provenance + version + evidence sidecar
        ↓
Review Workbench / 可回放证据包
```

当前最值得验证的算法路径是：

```text
登记原件 → 检索/版本事件回放 → canonical frame
→ ordinary-propagation matched null
→ blind decoy / wrong-reference
→ 同 mask/operator 的局部干预证据
→ 选择后校准、开放集拒判和证据包回放
```

这是一项待真实数据证伪的组合协议。仓库中的 `aigc/`、`eval/`、`tests/` 已有无重量模型的契约、测试和 synthetic runner，但真实授权图片、独立普通传播 null、外部时间/生成器切分、客户人工基线和部署链路仍未完成验证。

## 2. 商业价值假设

首客优先是已经拥有原件、版本和审核流程的图片平台、品牌/电商内容团队、MCN、媒体机构、政企媒资部门和私有 DAM/MAM 使用方。首单只验证旁路 sidecar：读取来源和标识、归并版本、记录传播关系、生成可回放 EvidenceV1、把冲突和不确定样本交给人工复核。

通用图搜、单图 AIGC API、完整 DAM 替代、全网爬虫和自动下架都有成熟替代或更高的权限与误报风险，暂不作为当前独立壁垒。商业验证应按资产/版本、证据包、复核席位、规则包、留存周期或私有部署计价；客户、价格、收入、SLA 和 ROI 都必须通过授权 shadow 试点验证。

阶段 1–5（失败语义、服务端身份、上传安全、EvidenceV1/恢复、真实评测和可复现部署）通过前，阶段 6 只能做访谈、资格筛选和离线 fixture，不读取客户数据。

## 3. 主要创新候选及边界

公开研究已经分别覆盖单图检测、局部编辑定位、近重复检索、C2PA/水印、开放集、生成器归因、普通传播鲁棒性、反事实解释和选择后校准。因此以下内容不能单独写成 Smart Shadow 的创新：CLIP/频域/残差融合、六区域或多裁剪、ROI 热图、mask-out、普通 conformal/p-value、C2PA 解析、普通水印、版本树或区块链存证。

当前最窄、可被证伪的研究主张是：把登记原件、普通传播 null、错误原件/盲选 decoy、canonical frame、真实执行的局部 intervention、多视角/多 operator 稳定性、检索选择回放、开放集拒判和人工复核绑定为同一事件。完整协议只有在相同候选、相同预算、相同时间/生成器外部切分下，能降低 ordinary-propagation FPR、reference false-match、selective risk 或人工复核分钟，才值得对外保留为研究增量。

当前候选按优先级处理：

| 候选 | 当前状态 | 允许表述 | 下一门 |
| --- | --- | --- | --- |
| Source-conditioned local-edit evidence | 研究主线；raw 契约已实现 | 组合协议假设 | 真实授权 manifest、独立 null、G0–G6 |
| SCPTN/RSCPTN 与 ALG-001 | 离线契约已实现 | 树/检索选择审计 raw evidence | 冻结 archive/index 和真实事件回放 |
| PE-CEA-v1 | 离线契约已实现 | 传播严重度 envelope 审计 | 同层 ordinary null、曲线保持率和外部切分 |
| SIPA-v1 | `deferred`，未批准编码 | 后续跨索引来源审计候选 | 先完成 ALG-001 真实门 |
| DRCS/CEAT | 后置候选 | 不进入当前代码或线上接口 | 先例审计、真实混淆样本和重新批准 |

`unknown`、`review`、`insufficient` 和 `null_consistent` 都是证据路由，不等于人类创作；C2PA 有效、水印阳性或检索命中也不等于真实、作者、版权或侵权结论。

## 4. 统一真实评测门

真实 manifest 至少绑定 `reference/query/counterfactual`、传播链、质量桶、编辑 mask、生成器家族、时间窗、C2PA/水印状态、授权范围、访问主体、留存期限、删除墓碑和人工复核结果。同一资产或传播族不得跨 split。

每个研究切片至少与 query-only/比赛版六区域基线、reference-only、去 ordinary null、去 decoy、single-view/single-operator、共享索引和固定顺序 probe 对照；报告 ordinary-propagation FPR、reference false-match、risk@coverage、unknown/review、ROI/边界 F、route flip、P50/P95、存储、每千件成本和人工复核分钟。

G0–G6 任一门未通过时，只能报告 raw evidence、review、unknown、insufficient 或 `not_evaluated`；不得报告 AIGC 概率、通用准确率、作者/版权/侵权结论或部署能力。

## 7. DRCS-v1 的最小研究设计

### 7.1 假设

在相同登记原件、相同 ordinary-propagation null、相同 canonical frame/mask/operator 和相同候选/动作预算下，
把来源证据与生成器证据分注册表，是否比单一融合路由更能降低普通传播误报、错误 reference 升级和跨层冲突遗漏？这是一个可证伪的协议假设，不是新 detector 或因果证明。

### 7.2 输入与路由

`asset_registry` 保存 reference/query/counterfactual、版本树、传播族、质量、mask、ordinary-null、检索/选择 digest；
`generator_registry` 保存 generator/time bucket、real-only/family profile、detector/schema、open-set policy、C2PA/水印 adapter 和 support digest。

固定 route：`source_specific_edit_candidate`、`generator_only_unknown`、
`ordinary_propagation_consistent`、`source_generator_conflict_review`、`insufficient`。来源 registry 的
matched local effect、blind decoy/wrong-reference、普通传播 null、跨视角/算子和独立 split 都通过时才允许第一个 route；生成器信号不能替代来源证据，冲突必须 review，普通传播不能升级为人类。

### 7.3 消融与 G0–G6

先完成 ALG-001 真实 archive/index 回放，再比较 query-only、asset-only、generator-only、双 registry、去 null、
去 decoy、错误 reference 和 provenance×watermark conflict。报告 ordinary-propagation FPR、reference false-match、
risk@coverage、unknown/review、ROI/边界 F、route flip、P50/P95、每千件成本和人工复核分钟；G0–G6 任一失败时只报告
raw evidence/review/unknown/insufficient/not_evaluated。若收益只来自增加拒判、closed-set/IID 或 registry 污染来源结论，撤回为 audit sidecar。

## 8. 商业切口与停止门

`metadata_mutation_guard + provenance_conflict_replay` 只面向一个有授权、责任人和人工基线的私有 DAM/MAM shadow。导入/导出事件保存原始字节、manifest/claim、C2PA/GB/IPTC 原值、provider/platform/content ID、工具版本、签名状态、删除墓碑和回放结果，路由为 `pass`、`gap`、`conflict`、`insufficient`。

继续门是字段完整率、签名/标识失效回放、冲突复核分钟、删除/恢复、权限越界、重复任务和净价值；没有真实触发或无法独立回放时停止。价格、客户、收入、部署、认证和 ROI 必须由授权试点实测，不能由市场公开页面外推。

## 10. SAEA 的安全交接备注

现有 SAEA 负责固定预算内的 probe 顺序和失败闭合，但其 standalone state 尚未强制绑定 generator/open-set/replay route。D-073/SS-025 将补充这一 propagation gate：未知、冲突、缺 profile 或 replay digest 不一致不得继续到 candidate，`real_consistent` 保持中性。完成前，SAEA 只能作为 raw strategy，不能宣称全链路开放集拒判。
