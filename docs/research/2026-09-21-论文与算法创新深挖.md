## 1. 结论先行

2024–2026 的一手证据已经覆盖了 Smart Shadow 比赛版叙事中的大多数单项能力：单图 AIGC 分类、跨生成器泛化、开放集拒判、局部编辑定位、原图—编辑图对照、频谱/像素多流、质量校准、水印和 provenance。因而以下内容不能单独写成 Smart Shadow 的创新：

- 六区域/多裁剪、CLIP 或频谱特征、普通 ROI 热图、mask-out、重建差分和单图概率；
- 给定原图与查询图的局部编辑检测；
- generator family 归因、real-only fallback、open-set unknown、quality-aware calibration；
- C2PA、不可见水印、链上 hash、版本 DAG 或单纯的 evidence digest。

当前仍可检验的差异是一个组合协议假设：

> 在版权工作流中，候选登记原件不是任意相似图，而是经过 blind decoy 控制和选择后校准的参考；query、同传播族 ordinary-propagation null、wrong-reference/decoy 和多视角/多 operator intervention 共享 canonical frame、质量/传播分层和可回放 digest。只有在选择偏差、普通传播 null 和跨视角不稳定都没有触发时，才把结果放入人工复核候选，否则拒判。

这条主张只有在真实授权数据上相对 D-054 的普通 decoy gate 降低 reference false-match、ordinary-propagation FPR 或人工复核成本，并在未见生成器、下一时间窗和传播变换上保持，才可以称为有研究增量。否则它只是更严格的证据审计协议。

## 4. 当前创新主张的收敛方式

建议沿用以下文字，而不要写成“新的通用 AIGC 检测器”：

> Smart Shadow 研究一种 source-conditioned local-edit evidence protocol：登记原件提供 reference，ordinary-propagation 版本提供 matched null，blind decoy/wrong-reference 控制 reference selection，canonical frame 和 digest 提供回放绑定，multi-view/multi-operator 检查稳定性，质量/传播/时间分层 profile 负责校准，证据不足时选择性拒判。

它的可证伪问题是：在相同 query、相同检索候选和相同复核预算下，完整协议是否相对 query-only、reference-only、无 null、无 decoy、single-view、single-operator 和无 abstention 基线降低：

- ordinary-propagation false-positive rate；
- wrong-reference / reference false-match rate；
- selective risk 和 route flip；
- 一次人工复核所需分钟和每千张成本。

同时必须观察局部编辑的 ROI/边界 F、unknown/review coverage、P50/P95 和下一时间窗/未见生成器性能。若完整协议只增加 `unknown`、只在 IID/已知生成器上改善，或收益来自更高的拒判率而非更低的选择性风险，应撤回“创新”表述，保留为审计 sidecar。

## 5. D-060 已完成离线切片：SAEC-v1（选择后分层证据校准）

### 5.1 为什么现在做这个切片

`reference-specificity-v1` 已能将一个候选登记原件与 blind decoy pool 比较，并检查 selection/evaluation split 不同；`invariant-effect-v1` 已能检查同一候选的跨 view/operator 稳定性。但当前仍有一个明确的统计缺口：候选通常是从图库检索后选出的 winner，若校准只看候选与其 decoy 的对比，就可能把“从很多参考中挑到最高分”误读为特异证据。这个问题属于 selection bias/winner’s curse，不能靠增加一个 raw threshold 解决。

SAEC-v1 只做选择后校准和分层支持检查，不训练 detector、不重算局部特征、不改写 D-054/D-058 的结果对象，也不把 p-value 变成 AIGC probability。D-060 已批准该模块作为阶段 7 离线研究契约；当前已有无重量模型实现、专测和 synthetic runner，但不代表真实数据效果或线上能力。

### 5.2 输入和绑定

每个 query 必须同时提供：

```
query_digest
candidate_reference_digest
blind_decoy_reference_digests
candidate_and_decoy_contrast_raw
invariant_effect_result_or_route
asset/pair/manifest/canonical_frame digest
transform_family, quality_bucket, source_match_bucket, time_bucket
detector_version, score_schema, operator_set_digest
selection_policy_digest
selection_split_digest
calibration_split_digest
evaluation_split_digest
```

约束如下：

1. `selection_split_digest`、`calibration_split_digest`、`evaluation_split_digest` 必须互不相同；任何相等、缺失或由同一 asset/group 派生的跨 split 样本固定 `insufficient`。
2. calibration group 以 asset/group 为单位隔离，不能把同一原件的传播版本拆到不同 split；每个 group 使用与评估相同的候选选择策略和固定 decoy 数，避免 decoy 数不同导致 max statistic 不可比。
3. candidate、decoy、ordinary-propagation null 必须共享 detector/schema、canonical frame、transform family、quality/source-match bucket；wrong-reference 必须明确不同 reference digest。
4. 所有 raw contrast、pool digest、profile digest、fallback level 和 route 都进入 evidence sidecar；禁止输出 probability、作者、版权或法律字段。

### 5.3 统计原语

设 query 的候选集合为 (R_q)，候选选择策略在 selection split 上选出 (r_q^*)，每个 reference 都已经有 D-050/D-054 的 source-conditioned contrast (c(q,r))。对 calibration group (g)，使用完全相同的选择策略和 decoy 数构造：

```
M_g = max_{r in R_g} c(g, r)
p_sel = (1 + count_g[M_g >= c(q, r_q*)]) / (1 + number_of_calibration_groups)
gap_decoy = c(q, r_q*) - upper_quantile(decoy_contrasts)
```

`p_sel` 是针对“检索后挑 winner”这一选择过程的有限样本 raw calibration statistic，不是 AIGC 概率。`gap_decoy` 只作为可解释 raw 量；它不能单独替代 max-statistic profile。分层 profile 按以下顺序尝试：

```
exact (generator_family × transform_family × quality_bucket × time_bucket)
  -> family/transform × quality_bucket
  -> transform_family × quality_bucket
  -> global ordinary-propagation profile
```

每级都必须满足最小独立 group 数、最小普通传播支持和无 split 污染；否则不自动回退，直接 `insufficient`。fallback level、support count、profile digest 和未满足门必须显式记录。`ties-inclusive` 规则沿用 `(1 + exceedances) / (n + 1)`，但比较对象是 calibration groups 的 `M_g`，不是当前 query 自己的 decoy 再循环。

### 5.4 Raw 路由

固定 raw route 为 `selection_specific_candidate`、`selection_ambiguous`、`null_consistent`、`insufficient`：

- `selection_specific_candidate`：候选 contrast 达到 raw gate，`p_sel <= alpha`，D-058 路由为 `invariant_candidate` 或等价稳定证据，且没有 wrong-reference、quality、source-match、operator 或 profile 冲突。
- `selection_ambiguous`：候选 contrast 足够但 `p_sel` 未超过选择后门，或多个 reference 近似并列；进入人工复核，不输出 AIGC 结论。
- `null_consistent`：输入属于 ordinary-propagation scope，或候选 contrast 低于 gate / `p_sel` 与 null 一致；这不等于人类创作。
- `insufficient`：三 split、calibration support、decoy 数、绑定、质量、schema、operator 或 profile 任一失败。

现有 D-054 的 `reference_specific_candidate` 不应被静默改名或覆盖；SAEC 结果作为独立 sidecar，只有在同一 manifest 的消融中证明降低 false-match/FPR 后，才讨论是否成为更严格的上游 gate。

### 5.5 已实现代码切片（无重量模型）

本切片使用以下文件，保持与现有 `aigc/reference_specificity.py`、`aigc/invariant_effect.py` 的输入/输出隔离：

```
aigc/selection_aware_calibration.py
tests/test_selection_aware_calibration.py
eval/selection_aware_calibration_eval.py
```

当前实现只接受已计算的 scalar contrasts 和 profile metadata，不加载 CLIP、扩散模型或图片路径；公共导出和 `scripts/verify_lightweight.sh` 已作为同一代码切片接入。仍不能把路由接入 `ai_server.py`、Go 网关或 `aigc_result_v1`。

### 5.6 合成契约验收矩阵

至少覆盖以下 10 类：

1. winner candidate 经选择后 profile 仍通过，得到 `selection_specific_candidate`；
2. candidate 与 max decoy tie，得到 `selection_ambiguous`；
3. ordinary-propagation 的 max statistic 偏高，固定 `null_consistent`；
4. wrong-reference 在单 query 上 contrast 很高，但 blind pool/selection profile 不支持，固定 `selection_ambiguous` 或 `insufficient`；
5. exact 分层支持不足，family/transform/global fallback 的 level 和 digest 可回放；
6. calibration/evaluation/selection split 任意相等、group 泄漏或 decoy 数不一致，固定 `insufficient`；
7. quality/source-match/transform/schema/operator 不一致，固定 `insufficient`；
8. ties-inclusive p-value、max statistic、decoy 顺序和输入顺序均确定；
9. D-058 为 `view_operator_inconsistent` 或 null support 不足，不能升级为 candidate；
10. 序列化结果禁止 `probability`、`confidence`、`human_supported`、`ai_generated_supported` 和法律字段。

预期第一版为 10–14 个单测和 6–8 个 scalar runner case；记录 `profile_digest`、`selection_policy_digest`、`decoy_pool_digest`、`evidence_digest` 和 dataset digest。synthetic 结果只证明选择后校准契约，不代表真实 false-match、FPR 或 AIGC 效果。

### 5.7 G0–G6 真实数据门

| 门 | 必须冻结的内容 | 失败时 |
| --- | --- | --- |
| G0 | 授权原件/query/null/decoy、范围/期限、删除负责人、SHA-256、最小化策略 | `unauthorized_input`，不进入 score |
| G1 | 同 asset 的 ordinary-propagation family、固定 transform spec、质量和时间桶 | 不形成 profile，`insufficient` |
| G2 | 真实局部编辑 mask、编辑工具/生成器、observed/null/counterfactual 配对 | 只保留 raw decode/pair evidence |
| G3 | 随机 decoy、相似 decoy、wrong-reference、开放集/未见生成器和参考选择 split | 不报告 specificity/FPR |
| G4 | exact/family/global profile 的独立 calibration groups、时间下一窗、传播后质量 | 只报告 support/拒判统计 |
| G5 | query-only、D-054、SAEC、D-058、D-054+SAEC、去 null、去 decoy 的同 manifest 消融 | 不能声称增量 |
| G6 | 证据包回放、manifest/profile/digest 校验、人工一次复核、P95、成本和删除恢复演练 | 不进入产品或论文主结果 |

最终至少报告 ordinary-propagation FPR、reference false-match rate、ROI/边界 F、risk@coverage、unknown/review、route flip、P50/P95、每千张成本和人工复核分钟。所有 generator/time/quality/transform 分层都要单独给出支持数；不能只报总体平均。

### 5.8 证伪和回滚条件

SAEC-v1 应在以下任一情况发生时撤回为 reference-audit sidecar：

- 相对 D-054 的 false-match/FPR、risk@coverage 或人工复核分钟没有稳定改善；
- 只在 IID/已知生成器上改善，下一时间窗或传播后失效；
- 主要收益来自把大量样本送入 `unknown/review`，而接受样本风险没有下降；
- exact/family profile 经常无支持，global fallback 与真实分布明显不匹配；
- 选择策略或 decoy pool 的任何字段泄漏到 calibration/evaluation split；
- 增加的 P95、存储和人工成本超过客户可接受门。

回滚只删除 `selection_aware_calibration.py`、对应测试/runner、公共导出和验证脚本接入，不修改 D-054、D-058、`aigc_result_v1`、比赛版服务或 EvidenceV1。

## 6. 建议的研究执行顺序

1. 真实评测前先冻结 reference selection policy、固定 decoy 数、asset/group split 和 ordinary-propagation profile；没有这些输入，不报告真实效果，代码只做合成契约回归。
2. 用 scalar contrasts 先验证 max-statistic、ties-inclusive p-value、分层 fallback 和 fail-closed；不要同时接入新 detector。
3. 将 SAEC 与 D-054、D-058 做同 manifest 消融，先看 false-match/FPR、risk@coverage 和 route flip，再看 ROI、P95 和成本。
4. 只有 G0–G6 全部通过，才把结果写入 `docs/07-验证与运行记录.md` 的真实数据段；在此之前只能记录 raw contract、digest、`review` 或 `insufficient`。

## 7. 研究边界

- 本文件引用的外部论文、benchmark、标准和挑战赛只支持先例、实验设计或工程约束，不证明 Smart Shadow 有同等效果。
- 当前仓库已有的 321 个契约测试和 35 个合成/契约 runner 仍然只属于源码/单测/fixture 层；SAEC 已完成无重量模型的离线契约、专测和 runner，但尚未接入线上。
- `candidate`、`p_sel`、`gap_decoy`、`profile_digest` 和人工复核路由都不是 AIGC probability、作者身份、来源真实性、版权归属或法律结论。
- 没有真实授权 query、普通传播 null、盲 decoy、独立 calibration groups、时间/生成器切分和复核基线时，研究结论必须停在“可回放协议”或“待证伪假设”。

## 9. SAEC 的可证伪假设

设检索候选集合为 `R(q)`，选择策略为 `π`，候选 raw contrast 为 `c(q, π(q))`。对独立 ordinary-propagation calibration group `g` 用同一 `π` 和固定 decoy 数得到 `M_g=max_r c(g,r)`。SAEC 的选择后统计量为：

```text
p_sel = (1 + count_g[M_g >= c(q, π(q))]) / (1 + number_of_calibration_groups)
```

该量只检验“winner 是否超过选择过程的 null 分布”，不检验作者、来源真实性或 AIGC 概率。候选还必须通过 D-054 的 decoy gap 和 D-058 的多视角/多 operator 稳定性；任何 split/group/profile 泄漏均为 `insufficient`。

最小消融固定为 query-only、D-054、D-058、SAEC、D-054+SAEC、去 decoy、去 null。主要指标是 reference false-match、ordinary-propagation FPR、risk@coverage、unknown/review、ROI/边界 F、route flip、P50/P95、每千张成本和人工复核分钟；整体均值不能掩盖 generator/time/quality/transform strata 支持不足。

## 10. 研究边界更新

外部论文证明的是“哪些单项能力已有先例、哪些评测风险必须纳入”，不证明 Smart Shadow 已经解决 AIGC。SAEC 与来源条件证据协议的组合仍是待证伪研究假设；在真实授权数据和 G0–G6 通过前，SAEC 只能输出 raw evidence、`review` 或 `insufficient`，不能称为已证实算法创新。
