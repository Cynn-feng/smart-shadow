## 1. 结论先行

### 1.1 首单仍应是既有媒资系统旁路的证据工作流

**I：**最有机会形成首单的对象是已有私有图库、DAM/MAM、内容审核或发布链的组织。Smart Shadow 作为旁路 sidecar，做以下事情：

```text
原件/版本/导出事件
  -> C2PA、GB 45438-2025、IPTC/XMP/EXIF、客户声明解析
  -> asset/version/parent/permission/retention 绑定
  -> 相似检索与可替换 AIGC raw-evidence adapter
  -> 缺失、冲突、普通传播疑似误报、未知输入进入人工队列
  -> 生成带 digest、规则版本、操作和 reviewer 决定的 evidence package
```

已有 DAM、图搜和单图检测已经覆盖大量基础能力。首单不应包装成“另一个 DAM”或“更高的 AIGC 分数”，而应验证跨供应商证据绑定、冲突复核、拒判、权限和回放是否减少具体人工工作。

### 1.2 监管触发支持两个 P0 方向，但不能混成“合规认证”

**F：**中国《人工智能生成合成内容标识办法》已于 2025-09-01 施行，要求生成、下载、复制、导出和传播链处理显式/隐式标识；2026 年网信专项行动和典型处置继续把标识缺失、导出缺标识、隐式标识互识互认和去标识工具列为问题。[四部门发布说明](https://www.cac.gov.cn/2025-03/14/c_1743654685899683.htm)；[专项行动](https://www.cac.gov.cn/2026-04/30/c_1779289298718765.htm)；[2026-02-12 典型处置](https://www.cac.gov.cn/2026-02/12/c_1772636033171974.htm)。

**F：**欧盟委员会说明 AI Act Article 50 的透明度义务自 2026-08-02 适用；提供者需要机器可读标记，部署者在深度伪造等场景承担告知义务；Code of Practice 是自愿工具，Article 50 本身仍是法律义务。[Article 50 指南](https://digital-strategy.ec.europa.eu/en/library/guidelines-transparency-obligations-providers-and-deployers-ai-systems)；[规则说明](https://digital-strategy.ec.europa.eu/en/policies/guidelines-ai-transparency-obligations)；[Code of Practice](https://digital-strategy.ec.europa.eu/en/policies/code-practice-ai-generated-content)。

**I：**这支持：

1. `Label/Export Readiness Checker`：限定一个法域、一个内容类型、两条真实导出链，输出 `pass/gap/conflict/insufficient`、规则版本、原始证据和整改队列。
2. `Evidence Sidecar + Review Workbench`：把标识状态、来源凭证、视觉 raw evidence 和人工处置放在同一条可回放记录里。

两者都不能输出“已认证”“没有标识就是人类创作”或自动下架结论。

### 1.3 C2PA 和 DAM 生态既是入口也是竞争边界

**F：**C2PA 2.4 新增 `c2pa.ai-disclosure`、`c2pa.repository-receipt` 和 crJSON，并明确 crJSON 是派生视图，不能独立验证输入。[C2PA 2.4 技术规范](https://spec.c2pa.org/specifications/specifications/2.4/specs/C2PA_Specification.html)；[crJSON 说明](https://spec.c2pa.org/specifications/specifications/2.4/crJSON/crjson-format.html)。

**F：**Bynder 已在 DAM 中保留原件和衍生文件的 C2PA 凭证，并结合 SynthID；其文档明确 Content Credentials 只是需要检查的信号。Cloudinary 的 C2PA 交付仍是 Beta、需客户申请且只覆盖图像。Adobe AEM 已覆盖资产、权限、版本、发布和内容凭证工作流。[Bynder provenance](https://support.bynder.com/hc/en-us/articles/38607456493586-Content-Provenance-and-Authenticity-in-Bynder-C2PA-SynthID)；[Cloudinary C2PA](https://cloudinary.com/documentation/content_provenance_and_authenticity)；[Adobe AEM Content Credentials](https://experienceleague.adobe.com/en/docs/experience-manager-learn/assets/metadata/content-credentials)；[AEM 产品能力](https://business.adobe.com/products/experience-manager/assets.html)。

**I：**基础 viewer、签名写入、版本管理和全套 DAM 都是替代能力。Smart Shadow 的可验证白区是跨供应商的 `provenance/version/evidence sidecar`、信任根/规则版本迁移、凭证与视觉证据冲突队列、私有化回放以及可删除的复核材料。

### 1.4 图库政策分化说明“权利与来源记录”比单一检测更可售

**F：**Adobe Stock 要求生成式内容投稿者拥有必要权利、明确勾选 AI 生成标签，并在涉及可识别人物/财产时提供相应 release。[Adobe Stock 生成式内容准则](https://helpx.adobe.com/stock/contributor/submit-your-content/submit-generative-ai-content/generative-ai-content-guidelines.html)。Shutterstock 则明确不接受贡献者提交的 AI 生成内容，理由包括无法验证 IP 归属、模型来源和贡献者补偿。[Shutterstock AI 内容政策](https://submit.shutterstock.com/help/en/articles/10594622-content-policy-updates-ai-generated-content)。

**I：**图库、品牌内容团队和内容审核方需要的是“来源、权利、标签和审核结果的可追溯记录”，而非一个跨平台统一的二分类答案。可把投稿预审、发布前检查、模型/财产 release 缺口和版本争议作为商业场景。

### 1.5 算法应继续解决可验证的局部取证问题，不宣称“解决 AIGC”

**I：**算法主线应保持：登记原件 + ordinary-propagation null + blind decoy/wrong-reference + canonical frame + matched intervention + 多视角/多算子稳定性 + 选择性拒判。它回答“局部差异是否超出普通传播、错误参考、压缩、截图、裁剪和算子伪影的解释范围”，而不是对所有图片输出 AIGC 概率。

当前 RSCPTN/SCPTN、SAEC、SAEA 和相关切片仍是阶段 7 离线 raw contract。只有真实授权 manifest、独立 null、编辑 mask、开放集/时间切分、人工基线和 G0–G6 通过后，才可以写成指定数据集上的研究效果；即使通过，也不能外推为通用 AIGC 解决方案或法律结论。

## 3. 可拓展方向排序

### 3.1 P0：EvidenceSidecarV1 + Review Workbench

| 项目 | 建议 |
| --- | --- |
| 首客 | 地方/行业媒体、商业图库、品牌内容团队；已有私有 DAM/MAM 或对象存储，每周有供稿预审、发布前检查、投诉或版本追责。 |
| 触发 | 新栏目/活动上线、AI 标识整改、重复/过期素材、供稿争议或内部审计截止日。 |
| 第一版交付 | 只读导入或 API；原件—版本—传播边；C2PA/GB/IPTC/XMP/EXIF 摘要；相似候选；raw evidence；人工队列；证据包；权限、删除和恢复回放。 |
| 收费实验 | 租户 + 资产/版本量 + 保留期；或复核席位 + 月任务量；私有部署另计集成/维护。具体数字等客户试点，不预设市场价格。 |
| 关键价值命题（P） | 减少找原件、查版本、整理投诉材料和误报复核的人工分钟；提升指定 reviewer 对证据包的独立回放成功率。 |
| 四周继续门 | ≥500 个授权原件、≥1,000 个版本/传播样本；字段完整率 ≥98%；版本绑定 precision ≥0.95、recall ≥0.90；指定 reviewer 回放 ≥99%；证据包一次采纳率 ≥80%；人工净分钟下降 ≥20%；删除/恢复演练 100%。这些均为可撤销试点起始门。 |
| 停止门 | 无授权 manifest/人工基线/删除责任人；要求替代 DAM、自动确权、自动下架或自动发函；没有每周重复任务；失败却成功或跨租户越权。 |

### 3.2 P0 条件项：AI 标识/导出链 readiness checker

| 项目 | 建议 |
| --- | --- |
| 首客 | 生成平台、发布网关、内容审核平台、跨境品牌；先选择中国或欧盟一个法域与图片一种内容类型。 |
| 第一版交付 | 输入/输出 digest；显式/隐式标识和 C2PA 状态；规则/标准版本；导出、复制、转码链回放；缺失/冲突/不适用原因；责任人和整改截止日。 |
| 收费实验 | 按规则包 + 导出链数量 + 报告批次；若客户只要单图 detector，优先调用已有供应商 API。 |
| 价值命题（P） | 降低标识整改定位时间和导出链复测时间，减少“失败但报告成功”的合规流程风险。 |
| 停止门 | 法域/角色/内容类型不明确；客户要求“认证”“自动下架”或将缺失写成人类创作；无授权导出样本。 |

### 3.3 P1：训练数据许可、排除与撤回 ledger

| 项目 | 建议 |
| --- | --- |
| 首客 | 模型研发机构、媒体集团、图片库、数据治理和版权法务团队。 |
| 依赖 | 客户必须拥有版本化训练/评测 manifest、来源与许可字段、地域/期限、排除清单、撤回责任人和可操作的删除/停止处理流程。 |
| 第一版交付 | manifest schema；版本 diff；许可/地域/期限校验；排除/撤回队列；受影响派生物枚举；删除/停止处理回放；法务人工复核。 |
| 价值命题（P） | 把“来源/许可变化后谁需要处理什么”从表格和邮件转成可审计队列。 |
| 停止门 | 要求系统证明黑盒模型实际训练使用了某文件、证明“没有侵权”或自动完成 untraining；没有客户自己的 ledger。 |

### 3.4 P1：案件 evidence package / 复核协作

首客可以是版权代理、媒体法务、内部审计或平台申诉团队，但销售周期通常比媒资预审长。交付只读时间线、输入/输出 hash、来源/版本/操作、模型 raw evidence、reviewer 决定、权限和导出日志；按案件、席位和保留期做收费试验。系统不代表客户作作者、所有权、侵权或司法事实判断。

### 3.5 P2：经授权的站内/渠道监测

只有在客户拥有书面渠道授权、投诉入口或固定平台范围时才进入。首个切片是受限采集、候选去重、来源/版本绑定和人工案件队列；收费按渠道、采集量和人工审查量。无平台授权、要求全网无边界、无法处理删除请求或采集成本高于人工价值时停止。

### 3.6 P2：视频/音频/跨模态来源链

媒体机构可能有价值，但需要新的时间轴/帧/音轨 manifest、算力、存储和权限策略。先做单一媒体类型的离线 adapter 与 evidence schema，不承诺跨模态一次覆盖，也不提前改写当前图片 AIGC 结果接口。

## 4. 商业价值如何计量

### 4.1 收费对象

建议按**证据工作**收费，而不是按一张图片输出一个 AIGC 概率收费：

- `Evidence Sidecar`：租户、资产/版本量、保留期、API/批处理量；
- `Review Workbench`：复核席位、月任务量、证据导出量；
- `Governance Audit`：规则包、导出链数、manifest 批次和报告量；
- 私有部署：字段映射、部署/恢复演练、年度维护和版本升级；
- `Authorized Monitoring`：授权渠道、采集量、人工审查量。

公开厂商的定制化 DAM 价格、一次政府采购金额和云 API 价格只能作为替代能力存在的信号，不能直接变成 Smart Shadow 报价。

### 4.2 试点 ROI

对批次 `N`、人工基线每件分钟 `t_base`、系统自动阶段分钟 `t_system`、未知/冲突复核分钟 `t_review`、客户认可人工成本 `c_min`、运行与集成成本 `C_run`：

```text
net_value = N * max(0, t_base - t_system - t_review) / 60 * c_min
            + evidence_value_accepted
            - C_run
```

`evidence_value_accepted` 只能计入客户书面认可或已进入投诉、审计、许可流程的证据价值；不能把论文指标、公开处罚金额、登记量或模型分数换算为收入。

### 4.3 四周 shadow 顺序

1. **D0–D7 资格与安全沙箱**：冻结授权 manifest、法域/内容类型、权限、删除/留存、人工基线和报告 schema；仅离线导入与回放。
2. **D8–D21 只读 shadow**：与人工流程并行，记录版本绑定、候选 Recall@K、ordinary-propagation FPR、unknown/review、人工分钟、P50/P95、字段缺口、越权和失败却成功。
3. **D22–D28 购买决定**：业务、IT/安全、版权/法务和采购共同复盘；确认重复使用、净价值、下一周期预算或停止原因。

## 5. AIGC 创新与商业切口的连接

### 5.1 可继续验证的研究对象

把局部取证定义为一个可拒判协议：

```text
reference (登记原件)
  + observed query (传播/交付版本)
  + ordinary-propagation null tree
  + blind decoy / wrong-reference controls
  + canonical frame and declared mask
  + matched intervention and region-swap
  + multi-view / multi-operator stability
  + selection- and retrieval-aware calibration
  -> raw evidence route + replayable package
```

商业上可验证的问题是：这个协议能否降低媒体/图库发布前复核中的普通传播误报、错误原件升级和人工复核分钟；研究上可验证的问题是：在 G0–G6 和 A0–A10 对照下，它是否相对 query-only、普通 detector、逐版本 null、去 decoy、去 intervention、SAEC/SCPTN 等基线改善 selective risk、ROI/faithfulness、unknown/review 和成本。

### 5.2 算法研究的硬边界

- `candidate`、`null_consistent`、`review`、`insufficient` 属于 raw evidence route；不映射为 AIGC 概率、作者、所有权、侵权或法律字段。
- 没有授权原件、独立 ordinary-propagation null、编辑 mask、盲选 decoy、生成器/时间切分和人工基线，只能做离线 fixture 或 raw contract。
- RSCPTN/SCPTN 的树级或检索级校准不是新的 detector、不是通用 conformal 结论；只有同预算外部切分上的 FPR、risk@coverage、人工分钟和成本改善，才有研究增量资格。
- 如果收益主要来自更多拒判、只在 IID/已知生成器成立、或回放/存储成本抵消人工收益，应撤回为 provenance/review audit sidecar。

### 5.3 最小商业 A/B

同一客户样本、同一人工预算下至少比较：

1. 客户现有 query-only / 单图 detector 流程；
2. 只做来源/版本 sidecar；
3. sidecar + 普通传播 null；
4. 完整 matched-intervention、blind decoy、选择后/树级校准；
5. 去掉 null、decoy 或 intervention 的消融。

比较字段：普通传播 FPR、错误原件升级率、unknown/review 率、候选 Recall@K、人工净分钟、证据包一次采纳率、P50/P95、每千件成本和 route flip。没有真实授权数据时，不报告 AIGC 准确率或商业 ROI。

## 7. 不应外推的事实边界

以下结论即使拥有上述官方来源，也不能写进对外宣传或状态更新：

1. 不能从法规生效、执法通报、采购预算或中标金额推出 Smart Shadow 的客户数、TAM、收入、报价、SLA、续约率或合规认证。
2. 不能从 Adobe、Bynder、Cloudinary、腾讯云或阿里云的产品能力推出本项目已经兼容其 API、达到其性能或替代其 DAM/检测服务。
3. 不能把 C2PA/水印/IPTC/EXIF 的存在或缺失映射成真实、自然人创作、版权归属、侵权责任或“不是 AI”。
4. 不能把图库平台的 AI 接受/拒绝政策外推为统一行业规则，也不能把一项 release/标签要求当作司法结论。
5. 不能把 synthetic runner、契约测试、外部论文 AUC/IoU、公开采购服务器或单次演示写成 Smart Shadow 的真实 AIGC 准确率、概率、召回、部署能力或客户 ROI。
6. 不能把“发现近邻”写成“证明某文件被模型训练使用”；黑盒模型的训练使用、撤回和 untraining 必须由客户的 manifest、合同和可操作流程证明。
7. 没有书面授权时不能做站内/渠道采集、全网监测、个人画像或跨租户检索；删除、留存、出域和恢复责任必须先明确。
8. `review_status` 只能代表人工流程状态，`label_status` 只能代表标签/规则检查；两者都不能直接生成法律结论。
9. 试点阈值（字段完整率、绑定 precision/recall、回放率、人工分钟下降等）都是可撤销的设计假设，必须在 D0–D7 与客户冻结，不能在看到结果后调整。
