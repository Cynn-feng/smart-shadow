# 2026-09-21 Smart Shadow 市场与商业化前沿审计

更新时间：2026-09-21
状态：外部一手资料核验后的产品假设和验证设计；不是客户访谈、收入预测、合规认证、部署报告或算法效果报告。

本文件补充已有市场调研，专门回答四件事：

1. 近期哪些监管、标准、采购和产品变化会形成真实购买触发；
2. 哪些能力已经被 DAM、云 API 或标准生态覆盖，Smart Shadow 应主动避开；
3. 哪些拓展方向能与当前“来源/版本存证 + 相似检索 + AIGC 原始证据 + 人工复核”边界相接；
4. 每个方向用什么 ICP、付费对象、试点指标和停止门决定继续、转向或停止。

## 1. 证据口径

文中使用三种标签：

- **F（外部事实）**：来自政府/监管机关、标准组织、正式法规、官方采购公告或厂商正式产品文档；只说明外部规则、产品能力或一次采购事实。
- **I（产品推断）**：把 F 与当前仓库能力连接起来的判断，必须通过访谈、授权数据和运行日志验证。
- **P（待验证命题）**：只有真实客户试点、书面预算、重复使用或续费决定才能成立。

外部采购金额、公开处置量、标准生效日期和厂商功能不能推出 Smart Shadow 的 TAM、收入、准确率、SLA、客户数量、司法采信或合规认证。

## 2. 结论先行

### 2.1 首个商业对象应是 `provenance/version/evidence sidecar`

当前最有工程和购买逻辑的入口是接入客户已有的 MAM/DAM、内容审核或发布系统的旁路证据层：

```text
资产/版本/导出事件
  -> 解析 C2PA、GB 45438-2025 标识和客户自定义字段
  -> 绑定登记原件、传播版本、权限与留存规则
  -> 调用可替换的相似检索和局部 raw-evidence adapter
  -> 将缺失、冲突、普通传播疑似误报和未知情况送入人工队列
  -> 生成带输入/输出 digest 的可回放 evidence package
```

它卖的是跨系统字段绑定、版本关系、失败语义、人工复核和回放能力，不是另一个单图 AIGC 分数或新的 DAM。这个方向仍是 **I**：必须由客户的重复任务、复核分钟和书面预算升级为 **P**。

### 2.2 第二个入口是“一个法域、一个内容类型”的标识/导出链体检

中国的《人工智能生成合成内容标识办法》和强制性国家标准 GB 45438-2025 已自 2025-09-01 实施；欧盟 AI Act Article 50 的相关透明度义务自 2026-08-02 适用。两者都让生成、导出、传播和复核字段成为实际工程问题，但产品输出只能是 `pass/gap/conflict/insufficient` 或待复核队列，不能写成“认证”“合规通过”或“无标识即人类创作”。

### 2.3 训练数据许可/撤回是高价值但高门槛的 P1

欧盟 AI Act Article 53 要求 GPAI 提供者建立版权政策并公开训练内容摘要；中国的网络数据安全规则要求受理删除、限制处理和撤回同意等请求。Smart Shadow 可以做版本化 manifest、排除/撤回队列和删除回放，但相似检索只能形成“待核查线索”，不能证明某作品已被训练或自动判定侵权。没有客户现成的版本化 manifest、责任人和重建流程时，不应把它列为首个代码切片。

### 2.4 数字证据工作台是纵向增值包，不是自动裁决器

ISO/IEC 27037 和 NIST/NIJ 的证据管理材料都强调识别、采集、保存、完整性和 chain of custody。它们支持 evidence package、权限、时间线、删除/恢复和复核意见的产品方向；不支持 Smart Shadow 自动给作者、所有权、侵权或诉讼结论。

## 3. 2025–2026 一手市场信号

### 3.1 中国：标识规则已进入执法和导出链

**F：**国家网信办 2025-03-14 发布《人工智能生成合成内容标识办法》，明确显式/隐式标识、下载复制导出保留要求和传播服务的技术措施；配套强制性国家标准 GB 45438-2025 的实施日期为 2025-09-01。来源：[网信办发布说明](https://www.cac.gov.cn/2025-03/14/c_1743654685899683.htm)、[全国标准信息公共服务平台](https://std.samr.gov.cn//gb/search/gbDetailed?id=301E0388CB75788DE06397BE0A0AE1B4)。

**F：**2026-04-30，中央网信办专项行动明确整治训练语料安全、AI 数据投毒、标识落实不到位和去标识工具；2026-09-15 典型案例中，某 AI 文本/图片小程序因缺少显式标识、文件元数据隐式标识和导出标识被责令下线。来源：[专项行动](https://www.cac.gov.cn/2026-04/30/c_1779289298718765.htm)、[典型案例](https://www.cac.gov.cn/2026-09/15/c_1790876152357946.htm)。

**I：**“生成—导出—传播—复核”链路是明确的体检场景。最小产品应保存法域、规则版本、内容类型、导出路径、解析器版本、输入/输出摘要、缺失/冲突原因、责任人和整改时间。它不应在第一版承诺跨法域、所有媒体类型或自动下架。

### 3.2 欧盟：机器可读标识与检测成为供应链验收字段

**F：**欧盟委员会指南称 Article 50 自 2026-08-02 适用；提供者应添加机器可读标记，使 AI 生成或操纵内容可检测；部署者在深伪和特定公共利益文本场景承担告知义务。[官方指南](https://digital-strategy.ec.europa.eu/en/policies/guidelines-ai-transparency-obligations)。

**F：**透明度 Code of Practice 是自愿工具，但 Article 50 义务本身是法律义务；code 分为 provider 的标记/检测和 deployer 的标注两部分。[官方 code](https://digital-strategy.ec.europa.eu/en/policies/code-practice-ai-generated-content)。

**F：**指南说明标准编辑、机器对机器闭环、某些 B2B/工业场景可能有例外或范围限制。[官方 FAQ](https://digital-strategy.ec.europa.eu/en/faqs/transparency-obligations-under-article-50-ai-act)。

**I：**产品配置必须包含 `jurisdiction + stakeholder_role + content_type + export_path + rule_version + exception_reason`。不能做一个“全球合规”按钮；先选择一个法域、一个角色和一种内容类型做回放。

### 3.3 C2PA：生态成熟提高了接入价值，也压低了解析器独占价值

**F：**C2PA 2.4 新增 `c2pa.ai-disclosure`、`c2pa.repository-receipt` 和 crJSON；规范明确 crJSON 是派生视图，不能独立验证输入。[2.4 技术规范](https://spec.c2pa.org/specifications/specifications/2.4/specs/C2PA_Specification.html)。

**F：**C2PA Conformance Program 和官方 Trust List 已运行，2026-01-01 起 Interim Trust List 冻结；C2PA 鼓励区分旧信任根和 conforming products。[Conformance](https://c2pa.org/conformance/)。

**F：**Bynder 已在 DAM 中保留原件和衍生文件的 C2PA 凭证，并结合 SynthID；其文档明确 Content Credentials 是需要核查的信号，不是单独的真实性保证。[Bynder 官方文档](https://support.bynder.com/hc/en-us/articles/38607456493586-Content-Provenance-and-Authenticity-in-Bynder-C2PA-SynthID)。Adobe AEM 也展示了内容凭证、工具、编辑者和下载/发布后的携带能力。[Adobe 官方文档](https://experienceleague.adobe.com/en/docs/experience-manager-learn/assets/metadata/content-credentials)。

**F：**Cloudinary 的 C2PA 功能仍标为 Beta、需客户申请，仅覆盖图像；签名交付会在既有 manifest 上增加新 manifest，并区分转码和编辑。[Cloudinary 官方文档](https://cloudinary.com/documentation/content_provenance_and_authenticity)。

**I：**仅做 C2PA viewer、签名验证或“内容凭证写入”已被生态和 DAM 覆盖，不应当作 Smart Shadow 独有壁垒。可留下的白区是跨供应商 manifest/版本图、标准冲突、视觉 raw evidence、人工处置、权限和回放。

### 3.4 训练数据与撤回：责任链正在要求可审计记录

**F：**欧盟 AI Act Article 53 要求 GPAI 提供者建立版权政策，并公开“训练内容的足够详细摘要”，同时保留技术文档供监管核验。[EUR-Lex consolidated text](https://eur-lex.europa.eu/eli/reg/2024/1689/2026-07-27/eng)。

**F：**中央网信办 2026-04-30 的专项行动将训练语料来源合规、未经授权使用文字/图片/音视频和 AI 数据投毒列为治理重点。[专项行动](https://www.cac.gov.cn/2026-04/30/c_1779289298718765.htm)。

**F：**中国《网络数据安全管理条例》自 2025-01-01 施行，要求网络数据处理者建立安全制度、访问控制和备份；个人可请求查阅、复制、更正、删除、限制处理或撤回同意，技术上难以删除时至少停止除保存和必要保护外的处理。[中国政府网](https://app.www.gov.cn/govdata/gov/202409/30/520076/article.html)。

**I：**P1 产品应做 `manifest version -> rule evaluation -> withdrawal request -> affected derivative/index/model job -> completion evidence` 的责任链。它不应把近邻命中改写成训练使用证明，也不应承诺从黑盒模型中“撤回记忆”。

### 3.5 数字证据：复核和保存本身有标准化语言

**F：**ISO/IEC 27037 覆盖潜在数字证据的识别、收集、获取和保存；[ISO 官方页面](https://www.iso.org/standard/44381.html)。NIST/NIJ 2025 证据管理报告强调保留、完整性、处置和 chain of custody；[NIST 公告](https://www.nist.gov/news-events/news/2025/12/new-report-reveals-evidence-handlers-common-practices-makes-recommendations)。

**I：**Smart Shadow 的 evidence package 应至少包含原始输入 SHA-256、版本/父版本、解析器和模型 schema、时间戳、每次操作及其 digest、人工决定和导出/删除日志；它只能是可审计材料，不是司法采信保证。

### 3.6 政采信号：存在“检测监测 + 服务器/模块 + 离线交付”的采购形态

**F：**中国信息通信研究院 2026-07-06 公布“生成式人工智能检测监测技术—图像 AIGC 鉴伪服务器等”中标结果，总金额 262.2 万元，采购对象包含视频 AIGC 鉴伪服务器和视频图像有害识别服务器。[中国政府采购网公告](https://www.ccgp.gov.cn/cggg/zygg/zbgg/202607/t20260706_26877676.htm)。

**I：**这证明政企采购可以把服务器、检测模块和运维交付写进验收链；它不证明 Smart Shadow 有资格、中标能力、价格基准或通用检测效果。若未来走政企，离线部署、版本升级、日志/证据回放和国产化适配应作为交付条款单列。

## 6. 付费对象和价值度量

### 6.1 建议按“证据工作”收费

已有 DAM、图搜和云检测会压低“每张图一个分数”的价格。更合理的收费对象是：

- **集成费**：字段映射、只读 API、身份/权限、导出链适配；
- **证据包/案件费**：可回放包、留存期、导出和 reviewer 角色；
- **复核席位/任务量**：人工队列、批次和报告；
- **规则包**：一个法域、内容类型、导出路径和版本化规则；
- **私有化与年度维护**：离线模型/解析器升级、SBOM、日志和恢复演练。

不要把“AI 概率”“登记量”“公开处罚金额”“论文 AUROC”直接换算成收入，也不要在没有客户基线时承诺节省比例。

### 6.2 试点 ROI 公式

仅在客户书面认可的人工成本和实际运行日志存在时计算：

```text
net_value = N * max(0, t_base - t_system - t_unknown) / 60 * c_min
            + accepted_evidence_value
            - integration_and_run_cost
```

其中 `accepted_evidence_value` 只能来自已经进入投诉、审计、许可或发布整改流程的客户确认，不得把模型分数或公开法规金额当作价值。

至少保存：批量大小 `N`、基线/系统/unknown 人工分钟、每千件运行成本、Recall@K、ordinary-propagation FPR、unknown/review 率、证据字段完整率、回放成功率、删除/恢复成功率、越权/假成功数、P50/P95、周活跃 reviewer、下一周期预算负责人和取消原因。

## 7. 推荐的四周试点门

数字是建议的试点设计，不是生产 SLA；可按客户规模缩放。

### D0–D7：资格和安全沙箱

- 只选一个法域、一个内容类型和一个真实业务触发；
- 冻结授权原件、传播/版本关系、保留期限、删除负责人、角色权限和人工基线；
- 只读导入、解析、回放和导出，不改变发布、下架、发函或诉讼决定；
- 失败必须产生结构化状态，不能回退为“成功”。

**继续门：**未授权样本为 0、跨租户越权为 0、输入/输出 digest 可重放、删除/恢复责任清楚、客户能指出流程负责人。
**停止门：**授权、留存或责任不清；解析失败被写成成功；客户要求自动法律处置。

### D8–D21：只读 shadow

建议从约 500 个授权原件和约 1,000 个版本/传播样本起步，连续四周中的至少两周有真实重复任务。系统与原人工流程并行，记录候选、冲突和 unknown，不改变客户处置。

**继续门：**字段完整率、回放和权限门稳定；人工分钟或重复整理步骤出现客户认可的下降；普通传播误报和未知率没有被隐藏。
**停止门：**没有每周重复任务；只产生一次性展示；unknown 被业务强制压成二分类；客户不能提供人工复核者或基线。

### D22–D28：付费和扩张决定

只做一项明确动作：签署下一周期付费、扩大样本/角色、继续无付费 shadow，或停止并回滚。记录预算归属、采购路径、支持成本、客户认可的证据案例和取消原因。没有书面下一步不能写成商业验证通过。

## 8. 对当前仓库的可执行建议

本节是文档建议，不改变当前决策记录或线上接口；阶段 1–5 未通过前，仍只能做阶段 7 离线研究。

### 8.1 建议新增独立 sidecar schema（先设计，不接线上）

```text
EvidenceSidecarV1 {
  tenant_id, asset_id, version_id, parent_version_id,
  content_sha256, normalized_sha256,
  c2pa_manifest_digest, c2pa_spec_version, c2pa_trust_status,
  label_jurisdiction, label_rule_version, label_status,
  transform_family, source_match_status,
  model_evidence_digest, detector_version, score_schema,
  review_status, reviewer_role, review_reason, reviewed_at,
  retention_policy_id, deletion_tombstone, export_receipt_digest
}
```

约束：来源凭证、被动模型 raw evidence、人工决定和法律/版权字段分栏；`review_status` 只能表示人工流程状态；`label_status` 不能映射成“人类创作”；未知、冲突、缺字段和解析失败固定为可见的 `insufficient/conflict/review`。

### 8.2 标识/导出体检的最小回放字段

```text
jurisdiction, stakeholder_role, content_type, export_path,
rule_version, parser_version, input_digest, output_digest,
explicit_label, implicit_label, c2pa_status,
missing_fields, conflict_fields, human_owner, remediation_due_at
```

输出建议为 `pass/gap/conflict/insufficient`；必须保留规则版本和输入/输出摘要，不能输出“合规认证”字段。

### 8.3 训练数据 ledger 的最小责任链

```text
manifest_version, asset_id, license_scope, territory, expiry,
reservation_signal, exclusion_status, withdrawal_requested_at,
affected_derivatives, index_or_job_rebuild_id,
deletion_or_stop_processing_status, owner, evidence_digest
```

相似检索、C2PA 或 detector 只能填入 `needs_review_signal`；不能生成 `training_used=true`、`infringement=true` 或 `rights_owner`。

### 8.4 算法创新与商业价值的连接

当前 SAEA/SAEC、D-054、D-058 等研究切片可作为 sidecar 的 raw evidence provider，但创新是否成立要看同预算对照：

- 相比固定顺序 probe，是否降低错误原件选择和 ordinary-propagation FPR；
- 是否降低人工复核分钟、route flip 和 evidence package 缺字段；
- 未知生成器、来源冲突和低质量输入是否提高 `unknown/review` 而不是被强行二分；
- 同一 evidence package 是否能被第二 reviewer 独立重放。

如果只改善 synthetic fixture 或增加了动作 trace，却没有同预算 risk–coverage–cost 和人工收益，仍只能称为审计 sidecar，不能称独立商业壁垒或论文创新。
