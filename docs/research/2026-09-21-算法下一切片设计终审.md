# 2026-09-21 算法下一切片设计终审：SIPA-v1

更新时间：2026-09-21（Asia/Shanghai）
状态：**研究候选，待主 Agent 在 `01`、`03`、`04` 中批准后编码**。本文件只给出下一切片的设计、可证伪实验和撤回条件；没有改变线上接口、`aigc_result_v1`、主线阶段 1–5 或当前产品结论。

## 1. 终审结论

下一算法切片选择 **SIPA-v1（Split-Index Provenance Audit，分索引来源审计）**，暂建议登记为 `ALG-002 / SS-020`。它不是新的 backbone、局部 detector、检索器、传播树算法或 conformal 理论，而是一条把**候选选择**和**候选证据复核**拆到两个预先冻结、可审计的索引/证据分区的来源条件局部编辑协议。

SIPA 要回答当前最具体、也最容易误报的问题：

> 一个登记原件候选之所以成为 winner，是否只是因为它在选择索引 A 中被检索和挑选；如果固定这个 winner，再用没有参与选择的独立审计索引/证据 B 复核同一局部干预效应，它是否仍然超过同传播族 ordinary-propagation null？

SIPA 的最小主张是：**在登记原件、普通传播 null、固定 candidate 和独立 holdout evidence 同时存在时，降低错误 reference、检索投毒和同索引 winner's curse 导致的局部 AIGC 误升级。** 它不声称仅凭自身识别 AIGC，也不把 `p_A`、`p_B` 或 holdout route 解释为 AIGC 概率、作者身份、版权归属或法律结论。

本报告撰写时，仓库已有 `PC-SCFT`、`MPCF`、`SAEC`、`SAEA`、`SCPTN` 和 `RSCPTN` 的 raw contract，但 `RSCPTN` 仍接收调用者预先给好的候选列表。随后完成的 `ALG-001 / SS-019` 已补上冻结 archive/index snapshot 的离线排序、membership、tree 和 selection trace 回放契约；它仍没有真实 retriever、授权 archive 或效果数据。SIPA 必须等待该契约通过真实数据和 G0–G6 后再编码，不能绕过真实事件重放直接添加一个第二分数。

## 2. 为什么选 SIPA，而不是 DRCS 或 CEAT

| 候选 | 当前价值 | 主要缺口 | 终审结论 |
|---|---|---|---|
| **SIPA** | 直接处理 RSCPTN 的同索引选择偏差、候选污染和错误 reference；可以复用现有 paired local evidence、普通传播 null、membership/tree 和 digest；不需要先训练新模型 | 需要冻结 A/B archive、候选不重选、独立 null 和泄漏检查 | **P0，下一切片** |
| DRCS（Dual-Registry Confounder Separation） | 能把 asset registry 证据与 generator fingerprint 证据分开，解释“来源证据其实是生成器伪影”的混淆 | 需要 generator registry、real-only/family profile、同生成器跨资产 controls；与 LIDA、OpenSDI、real-only/open-set 方向有较多先例重合 | P1，等 SIPA 真实回放暴露 generator confounding 后再做 |
| CEAT（Cross-Fitted Evidence Audit Trail） | 可研究 SAEA 自适应 probe、停止规则和 ordinary-null e-process 的稳定性 | 需要真实 probe executor、cross-fit null stream、交换性/依赖假设和统计评审；JOMI、CAP、Online Selective Conformal、conformal e-prediction 已覆盖一般理论 | P2，先做统计模拟，不进入本轮代码 |

SIPA 的价值在于补**选择事件和证据事件之间的独立性**；DRCS 的价值在于补**来源与生成器混淆**；CEAT 的价值在于补**自适应取证的统计停止**。三者不是同一层问题，不能在一个切片里并行编码后把组合复杂度写成创新。

## 3. 先例边界和可辩护差异

下列能力已经有公开先例，不能单独包装成 Smart Shadow 的创新：

- QuAD/AncesTree 已覆盖近重复检索、质量聚合和传播树形退化；
- JOMI、CAP、Online Selective Conformal 及 e-value 工作已覆盖选择后校准、在线选择和 optional stopping；
- RADAR、DICE、SAFE、RITA 已覆盖局部编辑检测、原图差分、定位和多步编辑；
- LIDA、OpenSDI、生成器族/real-only 工作已覆盖检索式生成器归因和开放集；
- 水印和 C2PA 只能提供独立 provenance signal，不能证明内容真实、作者或版权。

所以 SIPA 不能声称“独立索引是新的统计理论”或“两个模型分数平均提高准确率”。可审计的窄差异是：

1. 先按固定策略在索引 A 中产生候选并完成 membership/tree/reference selection；
2. 冻结 winner、region proposal、action trace 和 selection digest；
3. 在 B 中只对**这个已冻结 candidate**做直接 lookup/evidence evaluation，禁止重排候选和重新选 region；
4. 让 B 的 observed–ordinary-propagation contrast 在独立 B-null profile 上接受检验；
5. A 通过而 B 缺失、冲突、开放集或污染时固定拒判，不能退回 A 的高分。

如果 B 仍对所有候选重新排序，或者 A/B 只是同一 index、同一特征和同一 query crop 的重复打分，则这不是 SIPA；如果只把两个分数取平均，也不能声称解决 winner's curse。

## 4. 研究假设与可证伪主张

### 4.1 主假设 H-SIPA

在同一冻结授权 manifest、相同 candidate coverage、相同 evidence/action budget 和相同人工复核预算下，SIPA 相对 RSCPTN/SAEC 的完整事件在以下至少一个方面改善，且其他核心指标不恶化：

- ordinary-propagation false-positive rate；
- wrong-reference / blind-decoy false-match rate；
- planted near-duplicate 或 retrieval poisoning 导致的 route flip；
- 接受样本的 selective risk 或人工复核分钟。

改善不能只来自把样本全部转成 `missing_holdout`、`unknown` 或 `review`。接受 coverage、局部 ROI/边界质量、P95、存储和索引成本必须同时报告。

### 4.2 可证伪的负结果

以下任一结果都否定“算法创新”主张，并将 SIPA 保留为 provenance/retrieval audit sidecar：

- fixed candidate coverage 后，FPR、false-match 和 poisoning route flip 不下降；
- 只有 unknown/review 增加，接受样本 risk 没有下降；
- B 与 A 的证据高度相关，或 A/B 独立性无法由 snapshot、feature、query/operator 和时间字段审计；
- B 复核成本、P95、索引存储或人工分钟超过业务门；
- 只在 IID/已知生成器有效，在未见生成器、下一时间窗或传播后失效；
- B 缺失时系统仍回退到 A 的 candidate，形成隐性假成功。

## 5. 方法定义：A 选择、B 复核、C 校准

SIPA-v1 使用三类相互隔离的对象：

```
selection index/archive A
  → retrieval policy π_A
  → membership + propagation-tree assignment
  → fixed reference/version/region candidate w_A
  → freeze selection trace and candidate digest

audit index/evidence B
  → direct lookup of w_A only（禁止重新选择）
  → independent view/operator/feature evidence
  → matched ordinary-propagation null check

calibration stream C
  → independent ordinary-propagation groups
  → B-equivalent statistic profile
  → finite-sample raw rank, not probability
```

### 5.1 A 路径

A 路径复用 `ALG-001` 生成的完整事件：检索 archive snapshot、candidate rank、membership tier、tree parent/branch/depth、selection policy、action budget、canonical frame 和上游 `PC-SCFT/MPCF/SAEC/SCPTN/RSCPTN` evidence。A 可以使用现有 RSCPTN 双 raw gate，但不能把 A 的 `p_retrieval_raw` 当作独立证据。

`winner_id`、`region_proposal_digest`、`selection_key_digest` 和所有候选排序必须在 B 计算前冻结。若 A 出现 tie、unknown、污染、未解析 parent、错误 reference 或 split/profile 不一致，SIPA 直接进入 `selection_contaminated` 或 `insufficient`，不启动强 candidate 路由。

### 5.2 B 路径

B 保存和 A 不同的 archive/index/evidence 构建摘要，但只按 `winner_id` 查找同一个固定候选。B 不允许：

- 重新对候选集合排序；
- 根据 B 分数替换 `winner_id`；
- 根据 B 分数新增或删除候选；
- 看见 B 结果后修改 region proposal、mask、operator 或 threshold；
- 用 B 的 evaluation 结果重拟合 null profile。

B 的最低独立性要求是预先冻结并满足以下三个轴中的至少两个：

1. 不同 archive snapshot 或时间窗；
2. 不同 feature/index build、预处理或检索模型版本；
3. 不同 query view/operator 或独立 evidence stream。

只更换随机种子不算独立。若只有一个轴改变，结果可以保存为 `weak_holdout` 诊断，但不能进入强 `holdout_consistent`；若 A、B 是同一 index/feature/query evidence，固定 `holdout_leak`。

### 5.3 局部区域固定规则

为了避免 B 重新挑选显眼 patch，`region_proposal_digest` 必须在 A/B score 计算前冻结，来源只能是：

- 授权评测中的外部/人工 `edit_mask`；
- 不读取 A/B evidence 的确定性几何网格或预注册区域集合；
- 已登记、版本化且在 selection split 之前冻结的 region proposal。

如果 region 是在 A score 上挑出的，B 只能作为弱诊断，输出 `region_selection_reused`，不得报告强 SIPA candidate 或局部定位保证。

### 5.4 B-null 统计

对固定 candidate 和冻结区域，在 B 上计算与普通传播 counterfactual 配对的局部差异：

```
c_A = observed_A - ordinary_propagation_counterfactual_A
c_B = observed_B - ordinary_propagation_counterfactual_B
```

B 的独立 ordinary-propagation profile 为同一 `transform_family × quality_bucket × time_bucket × source_match_bucket × operator_set` 的校准统计量 `N_B`。有限样本单侧 raw rank 为：

```
p_B_raw = (1 + count(N_B >= c_B)) / (1 + |N_B|)
```

`p_B_raw` 仅是 ties-inclusive raw rank；不称概率、coverage 保证或 AIGC 置信度。A 和 B 的 raw ranks 不相乘、不相加、不做未经证明的 Fisher/Cauchy 合并。B 是 holdout gate，A 只提供选择过程和来源条件上下文。

### 5.5 路由

建议固定以下路由，后续代码不得随结果调名或加入软权重：

| 路由 | 条件 | 含义 |
|---|---|---|
| `holdout_consistent` | A 事件完整且通过既定 raw gate；B 找到同一 winner；B quality/source/null/support 通过；`c_A`、`c_B` 同向且达到预注册最小差异；region proposal 未泄漏 | A 选择的 candidate 在独立 B evidence 上仍有来源条件局部支持；仍是 raw evidence |
| `holdout_disagreement` | B 存在，但 B-null 不支持、方向不一致、质量/传播不匹配或 candidate 无法在 B 中保持 | 同索引 winner 不能被独立证据复核；进入人工复核 |
| `missing_holdout` | B archive/index 缺失、删除、过期、无 candidate lookup、无独立 null 或无法回放 | 不允许回退 A；证据不足 |
| `selection_contaminated` | A 的 membership/tree/poisoning/tie/selection trace 失败或发现 A/B 泄漏 | 选择事件不可信 |
| `open_set_unknown` | candidate/family/transform 超出冻结支持集，或 B 只能给未知 generator/open-set evidence | 未知不是人类创作 |
| `insufficient` | 授权、digest、split、schema、mask、operator、支持量或输入契约失败 | fail-closed |

`holdout_consistent` 不得直接映射到 `aigc_result_v1` 的 AI/human 四态，也不得在接口中加入 `aigc_probability`、`confidence`、`author`、`copyright` 或 `legal_conclusion` 字段。

## 6. 目标数据契约（待编码）

建议新增独立研究 schema，不修改线上 `Evidence`/`aigc_result_v1`。所有 digest 必须由 canonical 内容重算，不能接受调用者只填字符串。

### 6.1 `SIPAIndexSnapshotV1`

```
schema = "sipa-index-snapshot-v1"
snapshot_id / archive_digest / index_build_digest
feature_schema / detector_version / preprocessing_digest
query_view_or_operator_digest / created_at / time_window
authorization_id / authorization_scope / authorization_expiry
deletion_owner / retention_policy / split
candidate_membership_policy_digest / retrieval_policy_digest
```

`archive_digest` 必须覆盖候选可见范围、删除 tombstone 和植入/污染清单的版本；只保存最终 top-K 不算 snapshot。

### 6.2 `SIPASelectionTraceV1`

```
event_id / asset_id / query_digest / manifest_digest
selection_index_snapshot_digest
candidate_ids / candidate_ranks / candidate_scores
membership_decisions / membership_evidence_digest
tree_snapshot_digest / tree_edges / branch / depth
selection_policy_digest / ordered_action_trace / action_budget
winner_id / winner_tree_id / region_proposal_digest
upstream_rscptn_digest / selection_split_digest
```

`winner_id` 必须从完整 candidate snapshot 和 fixed policy 重新计算；人工最后选择不能作为输入字段。候选排序、membership、tree parent 或 action 顺序改变时，`selection_trace_digest` 必须改变或回放失败。

### 6.3 `SIPAAuditObservationV1`

```
event_id / winner_id / winner_reference_digest
audit_index_snapshot_digest / direct_lookup_digest
audit_feature_build_digest / audit_view_operator_digest
canonical_frame_digest / region_proposal_digest
observed_effect_B / ordinary_null_effect_B / contrast_B
null_profile_digest / null_support / p_B_raw
quality_score / source_match_score / transform_family / time_bucket
membership_recheck / tree_recheck / open_set_status
input_digest / evidence_digest / replay_status
```

`direct_lookup_digest` 必须证明 B 只读取固定 winner；若 B 的 API 只能返回重新排序的 top-K，必须拒绝作为 SIPA B。

### 6.4 `SIPAResultV1`

```
schema / route / reason_codes / abstained
event_digest / selection_trace_digest / audit_evidence_digest
selection_statistic_raw / audit_statistic_raw / p_B_raw
direction_agreement_raw / region_overlap_raw
holdout_axes / holdout_support / missing_holdout_reason
poisoning_stress_route / replay_status
config_digest / manifest_digest / calibration_split_digest
```

结果禁止出现 `probability`、`confidence`、`human_supported`、`ai_generated_supported`、作者、版权或法律字段。 `p_B_raw`、`direction_agreement_raw` 和 `region_overlap_raw` 全部标记为 raw evidence。

## 7. 最小可实现代码切片

本轮只提出设计，不直接修改代码。主 Agent 批准后，建议分四个可回滚提交；任何一步未通过都保持研究 sidecar。

### Slice A：无重量 contract

建议文件：

```
aigc/split_index_provenance_audit.py
tests/test_split_index_provenance_audit.py
eval/split_index_provenance_audit_eval.py
```

复用 RSCPTN 的 event/profile 对象和 `SAEC` 的 raw gate，但不得复制 detector、重新拟合 null 或修改旧 route。第一步只接受 scalar evidence、冻结 digest 和固定 candidate，验证 B 不重选。

### Slice B：ALG-001 replay adapter

将 `RetrievalEventReplayV1` 输出适配为 `SIPASelectionTraceV1`：

1. 从 A snapshot 生成 candidate/membership/tree/selection；
2. 在 selection 结束后冻结 winner 和 region proposal；
3. 通过 B snapshot 的 direct lookup 读取固定 winner；
4. 将 B observed/null evidence 交给独立 profile；
5. 返回 SIPA route，不改 `RSCPTNResult`。

### Slice C：真实 manifest adapter

只新增研究旁路字段：`edit_mask_digest`、`edit_type`、`edit_steps`、`transform_spec_digest`、`deletion_owner`、A/B snapshot authorization 和 deletion tombstone。普通传播样本不得带局部编辑标签；mask 文件和 bytes 必须独立验哈希。没有真实 mask 时只能保存 raw/review，不能报告 ROI。

### Slice D：评测 runner

`eval/sipa_real_eval.py` 只在授权 manifest 上运行；没有真实 A/B archive 和独立 null 时输出 `not_evaluated`，不以 synthetic runner 填充 FPR、risk@coverage、ROI、P95 或人工收益。

## 8. 合成/契约验证矩阵

第一阶段不加载重量模型，不读客户图片，不声称 AIGC 效果。建议至少 12 个 scalar fixture：

| 编号 | fixture | 预期 |
|---|---|---|
| S1 | A 选择唯一 winner，B 固定 lookup 同向且独立 null 通过 | `holdout_consistent` |
| S2 | B 有更高分的另一个 candidate，但 winner 已冻结 | 仍只评估原 winner，不得换 winner |
| S3 | A winner's curse，B 对同一 winner 不支持 | `holdout_disagreement` |
| S4 | A 有效，B archive 缺失 | `missing_holdout`，不得回退 A |
| S5 | B 没有固定 winner 的直接 evidence，只能返回 top-K | `missing_holdout`/`insufficient` |
| S6 | A 中 planted near-duplicate 或 poisoning，B 不支持 | `selection_contaminated`/`holdout_disagreement` |
| S7 | 普通 JPEG/resize/screenshot/re-capture propagation | 不得进入 `holdout_consistent` |
| S8 | wrong-reference/盲 decoy | `holdout_disagreement` 或 `insufficient` |
| S9 | unknown generator/open-set | `open_set_unknown` |
| S10 | A/B 同一 index、feature 和 view | `holdout_leak`/`insufficient` |
| S11 | B 结果被拿来重新选择 region 或修改 threshold | `region_selection_reused`/`insufficient` |
| S12 | candidate、rank、membership、parent、action 顺序、split 或 digest 被替换 | digest 变化或 fail-closed |

专测还必须验证：重复 event ID、同 asset/group 跨 split、tree cycle/cross-asset parent、null profile 混入 evaluation、expired authorization、非有限 raw 值、序列化字段卫生和输入顺序变化下 digest 确定性。runner 只输出 route counts、支持量、拒判原因、dataset/config digest。

## 9. 真实 G0–G6 门

| 门 | SIPA 必须新增的证据 | 未通过处理 |
|---|---|---|
| **G0 权限与身份** | A/B archive、feature build、query/evidence stream 的授权 ID、期限、删除责任人、bytes hash、snapshot 和 tombstone；reference/query/counterfactual 均可回溯 | `unauthorized_input`，不进入统计 |
| **G1 普通传播 null** | 同 asset/transform/quality/time/source-match 的 ordinary-propagation；B-equivalent null profile 与 A/B operator 绑定；每个主要分层至少达到预注册支持量，建议 50–100 个独立 null events，不足只报 raw rank/区间 | `insufficient`，不形成稳定 profile |
| **G2 局部编辑** | reference/query/counterfactual 配对、真实编辑 mask/步骤、工具/版本、canonical frame、编辑类型和来源权限；B 使用固定 region proposal | 无 mask/步骤只保留 raw/review，不报告 ROI/定位保证 |
| **G3 开放集与污染** | missing/false-positive/planted near-duplicate/wrong-reference、检索投毒、unknown generator、下一时间窗和多轮传播；污染清单必须在 A/B snapshot 中可回放 | `selection_contaminated`/`open_set_unknown`/`review`，不得回退 candidate |
| **G4 选择与校准独立** | selection A、audit B、calibration C、evaluation D 按 asset/group 隔离；B 在 A winner 选择后不重选；至少两条 holdout axes；阈值、region proposal、operator 和 action budget 预注册 | `holdout_leak`/`insufficient` |
| **G5 同预算对照** | 同一 manifest、候选 coverage、evidence/action budget 和时间窗比较 query-only、D-054+SAEC、SCPTN、RSCPTN、SIPA-only、RSCPTN+SIPA、去 B、同 index A=B、去 null、去 source binding | 无法归因或只增加拒判，撤回主张 |
| **G6 回放与业务门** | A/B snapshot 更新、删除/恢复、索引重建、模型/预处理版本变化后，event/evidence digest 可重放；记录 replay success、P50/P95、每千件成本、人工分钟、权限越界、错误是否假成功 | 只保留离线 audit sidecar，不接线上 |

真实评测必须按 `generator_family × edit_type × transform_family × quality_bucket × time_bucket × source_match_bucket` 分层，并同时报告：

```
accepted coverage
ordinary-propagation FPR
wrong-reference / blind-decoy false-match
poisoning route-flip
risk@coverage、unknown/review rate、route flip
ROI IoU/Dice/boundary-F（有真实 mask 时）
P50/P95、索引存储、每千件成本、人工复核分钟
```

不要只比较默认阈值下的 FPR。优先做 coverage-matched 曲线或预注册的 coverage 区间；若 SIPA coverage 下降超过预注册容忍度，不能把更低 FPR 写成算法收益。

## 10. 对照与成功/撤回门

### 10.1 固定对照

1. `query-only` / 比赛版历史基线：没有来源条件和 holdout；
2. `D-054 + SAEC`：blind decoy 与 scalar selection calibration；
3. `SCPTN`：只处理 propagation-tree null；
4. `RSCPTN`：完整 retrieval→membership→tree→selection dual-null，但同索引证据；
5. `SIPA-only`：仅 A/B holdout，不启用树级或检索级双 null（诊断）；
6. `RSCPTN + SIPA`：完整候选协议；
7. 泄漏对照：A=B、B 在选择后生成、B 参与 winner 选择、B 与 A 同 feature/query view；
8. 保守 oracle：仅用于上限参考，不用于宣称生产效果。

所有条件使用同一冻结 manifest、same candidate budget、same action budget、same review budget。去掉 B 后若结果几乎不变，说明 SIPA 没有独立贡献；只比较模型 score 不能代替这些对照。

### 10.2 暂定成功门（正式数值需在 G0–G4 后预注册）

- 在 coverage 差异不超过预注册容忍度（建议先用绝对 3–5 个百分点讨论，不视为最终门）时，SIPA 至少在 ordinary-propagation FPR、wrong-reference false-match、poisoning route flip 三项中的一项有可重复改善；
- 接受样本的 ROI/边界 F 不低于完整 RSCPTN 的预注册非劣 margin；
- unknown/review 增加必须能由降低人工复核分钟或 selective risk 抵消；
- 未见生成器、下一时间窗和深传播链不出现更高的错误升级；
- replay success、P95、存储和每千件成本达到试点预算。

“FPR 降低但 coverage 塌缩”“route 变安全只是因为全部 missing”“只在 closed-set/IID 改善”“B 无法回放”均是失败，不得升级为算法创新。

## 11. 与产品和商业边界

SIPA 只属于阶段 7 离线研究 sidecar。它在阶段 1–5（结构化回执、服务端身份、上传安全、EvidenceV1/恢复、真实部署）未验收前，不得接入：

- `ai_server.py`、Go 网关、比赛页面；
- `aigc_result_v1` 四态或单图 AIGC API；
- 客户 DAM/MAM、全网监测、自动下架、发函或法律工作流。

若真实评测通过，商业上仍应把 SIPA 的结果包装为“跨供应商来源/版本证据 sidecar + 人工复核队列”：它的可卖价值是减少错误 reference、提高证据回放和冲突发现，而不是向客户承诺单图 AIGC 百分比或版权裁决。

## 12. 实施顺序、回滚和状态表述

建议顺序：

```
ALG-001 RetrievalEventReplayV1 评审
  → SIPA scalar contract / leakage fixture
  → SIPA adapter 接入 A/B snapshot direct lookup
  → 同 manifest 的 RSCPTN/SAEC/SAEA/SIPA 消融
  → G0–G6 真实授权回放
  → 只有指标与人工成本均通过，才评估 DRCS
  → 真实 action trace 和统计评审后再研究 CEAT
```

回滚方式：删除 SIPA 新增模块、测试、runner、公共导出和任务单；保留现有 RSCPTN/SCPTN/SAEC/SAEA raw contract，不修改 `aigc_result_v1`、比赛版服务、主线阶段 1–5 或客户数据。

交付时必须使用以下限定：

> 已实现 SIPA 的源码/契约/合成回放，证明了候选冻结、独立 holdout、泄漏拒判和 fail-closed 路由；真实图片、真实 A/B index、独立普通传播 null、局部编辑效果、FPR、risk@coverage、客户价值和部署能力仍未验证。

不得使用以下表述：

- “Smart Shadow 已解决 AIGC”或“准确区分 AI/人类”；
- “SIPA 是新的 detector、新的传播树算法或新的共形理论”；
- “B 通过证明登记原件是作者/版权所有者”；
- “合成 fixture 的 raw rank、route digest 或 ROI 是真实准确率”；
- “holdout 缺失时 A 的高分仍可视为成功”。
