# Smart Shadow 市场、商业化与 AIGC 算法创新终审

更新时间：2026-09-21
定位：研究汇总和执行入口，不是效果报告、专利新颖性证明、客户证明或合规认证。

## 1. 终审结论

比赛阶段已经结束，Smart Shadow 后续不应继续围绕页面展示或单张图片“真假分数”扩张。最值得验证的产品路径是：

```text
已有私有图库 / DAM / MAM
        ↓
provenance + version + evidence sidecar
        ↓
Review Workbench / 可回放证据包
```

最值得验证的算法路径是：

```text
登记原件
→ 检索事件和版本树回放
→ canonical frame 对齐
→ ordinary-propagation matched null
→ 同 mask/operator 的局部干预效应
→ blind decoy、wrong-reference、开放集和选择偏差校准
→ evidence-only 路由，证据不足即拒判
```

这是一组待证伪的组合协议。当前仓库已经有无重量模型的契约、测试和 synthetic runner，但还没有真实授权图片、独立普通传播 null、客户人工基线、真实部署或商业收入证据。因此当前能说的是“离线契约已实现”，不能说“算法效果已验证”或“产品已部署”。

## 2. 研究证据怎样使用

| 证据 | 当前可支持的表述 | 不能推出的表述 |
| --- | --- | --- |
| 官方标准、法规、采购和竞品页面 | 需求触发、互操作约束、替代存在、采购流程信号 | 本项目客户、价格、收入、SLA、合规认证 |
| 正式论文、数据集和挑战 | prior art、对照协议、数据切分和评测要求 | 本项目准确率、泛化率、论文增量 |
| 仓库源码、单测、synthetic runner | schema、digest、拒判、回放和确定性契约 | 真实图片效果、AIGC 概率、法律结论 |
| 授权 manifest、独立 null、外部时间/生成器切分 | 真实选择性风险、局部定位、成本和复核收益 | 自动确权、作者证明、侵权裁决 |

后续 Agent 统一使用 `raw evidence`、`review`、`unknown`、`insufficient` 这些状态。`unknown` 不等于“人类创作”，`null_consistent` 也不等于“没有 AI”。

## 3. 市场判断和首客切口

### 3.1 首客

优先验证已有自有资产库的图片平台、广告/电商内容团队、MCN、品牌设计团队、媒体机构和政企媒资部门。它们已经有原件、版本、审核或发布流程，最容易提供授权样本和人工基线。

首单交付限定为旁路 sidecar：

- 绑定原件、版本、父版本、传播来源和权限范围；
- 读取 C2PA、GB 45438、EXIF/XMP 和平台声明，并保留 parser/spec/trust 状态；
- 给出相似候选、局部 raw evidence、冲突队列和人工复核记录；
- 导出带 digest、规则版本、reviewer 意见、留存和删除墓碑的 EvidenceV1 包。

通用图搜、单图 AIGC API、完整 DAM 替代、全网爬虫和自动下架不作为首个壁垒。腾讯云、阿里云、Adobe、Bynder、Cloudinary、Pixsy、Digimarc 等已经覆盖其中的一部分能力，Smart Shadow 应把它们接成可替换 adapter 或竞争替代。

### 3.2 四周 shadow 门

阶段 1–5 的身份、失败语义、上传安全、EvidenceV1/恢复、真实评测和部署门通过后，才允许进入客户只读 shadow。首轮建议冻结至少 500 个授权原件和 1,000 个版本/传播样本，提前写明删除责任人和人工基线。

每周记录：版本绑定 precision/recall、字段完整率、普通传播 FPR、unknown/review 率、证据包采纳率、删除/恢复成功率、越权和假成功次数、P50/P95、人工复核分钟和每千件成本。安全门任一失败即停止接入；没有重复任务或没有客户认可的净价值，只保留为访谈假设。

### 3.3 进一步拓展顺序

1. P0：来源/标识/版本证据 sidecar、冲突复核、导出与回放。
2. P1：训练数据许可/排除/撤回 ledger、案件 evidence package、单法域标识/导出 readiness checker。
3. P2：经授权的来源监测、视频/音频和跨平台扩展。

顺序不能倒置：没有稳定的权限、删除和回放，扩大监测范围只会扩大合规和误报风险。

## 4. prior-art 审计后的创新白区

公开工作已经分别覆盖局部编辑定位、差异检测、MLLM 解释、开放世界检测、生成器归因、真实传播/再数字化、watermark/provenance、membership privacy、证据选择和选择后校准。因此以下内容不能单独包装为创新：CLIP/频域/残差融合、ROI 热图、mask-out/AOPC、普通 conformal/p-value、传播变换、水印解析、开放集分类、生成器 top-1、自然语言解释、通用图搜或区块链存证。

当前最窄的可辩护白区是把这些组成放入同一可回放事件，并同时绑定：

1. 登记原件、query、counterfactual 和版本/传播关系；
2. 同坐标帧、同质量/传播桶、同 detector/schema；
3. ordinary-propagation null、blind decoy、wrong-reference 和未知生成器拒判；
4. 真实执行过的同一 mask/operator、selection trace、输入输出 digest；
5. 选择后校准、检索/树形污染审计和失败闭合；
6. 可复核的 ROI、成本、延迟和人工工作量。

这仍然只是组合假设。只有当完整协议相对去掉 null/control、query-only、逐版本 null、共享索引和固定顺序 probe 的对照，在相同 coverage/action budget、时间外部切分和生成器外部切分上降低普通传播 FPR、reference false-match、selective risk 或人工复核分钟，才可以讨论研究增量。

## 5. 当前研究切片和优先级

| 方向 | 当前状态 | 下一门 | 失败时的处理 |
| --- | --- | --- | --- |
| D-050/D-051/D-052：matched intervention、operator stability、mask persistence | 离线契约已实现 | 真实编辑 mask、普通传播 null、decoy/wrong-reference | 保留为 raw evidence sidecar |
| D-054/D-058/D-060/D-061：参考特异性、跨视角/算子稳定、SAEC、SAEA | 离线契约已实现 | 同 manifest、同预算、独立 calibration/evaluation split | 撤回为 reference/evidence audit |
| D-062/D-063：SCPTN/RSCPTN 树级和检索级双 null | 离线契约已实现 | 冻结 archive、membership、tree、selection 和污染 stress | 撤回为 propagation/retrieval audit |
| D-065/SS-019：ALG-001 实际检索事件回放 | offline contract implemented | 真实 retrieval archive、授权图片、独立 null、G0–G6 | 不进入 SIPA，保持 not_evaluated |
| SIPA-v1 | deferred，尚未批准编码 | 先完成 ALG-001 真实事件和 A/B split 审核 | 保留为跨索引审计候选 |
| DRCS/CEAT | 更后置研究候选 | 需 ALG-001/SIPA 证明真实混淆或自适应 probe 价值 | 不编码，不改线上接口 |
| real-family-router-v1 | 暂缓编码 | 先例重合且没有真实 family calibration | 保留 D-056 raw fallback |

ALG-001 当前 synthetic runner 为 9 个 case，`real_data_status=not_evaluated`；不能把 `candidate=1` 或 digest 写成真实准确率、概率或部署能力。

## 6. 必须冻结的真实评测协议

真实 manifest 至少记录：`reference/query/counterfactual`、人工或生成器 edit mask、传播链、质量桶、生成器家族、时间窗、C2PA/水印状态、授权用途、访问主体、保留期限、删除墓碑和人工复核结果。

每个算法切片至少比较：

- query-only / 比赛版六区域基线；
- reference/query residual；
- 去 ordinary-propagation null；
- 去 blind decoy 或去 selection replay；
- 逐版本 null、树级 null、完整组合；
- 已知/未见生成器、下一时间窗、截图/再编码/再拍摄、低质量传播和错误参考。

固定报告：ordinary-propagation FPR、reference false-match、risk@coverage、unknown/review、ROI IoU/Dice/boundary-F、mask-out/region-swap faithfulness、route flip、P50/P95、每千件成本、存储和人工复核分钟。

G0–G6 任何一门未通过，结果只能写为 raw evidence、review 或 insufficient；不生成 AIGC probability、作者/版权/侵权字段。

## 7. 对 Agent 的执行顺序

1. 先读 [AGENTS.md](../../AGENTS.md) 和 `docs/00–04`。
2. 主业务先推进 `SS-001`：结构化 AI/链回执、失败校验和无假成功。
3. 研究线先准备 ALG-001 的真实授权 manifest、独立 ordinary-propagation null 和 archive/index replay；没有数据时不继续堆算法。
4. 商业线只做访谈、试点资格和人工基线设计；阶段 1–5 未完成前不接客户数据。
5. 每个代码切片先在 `01` 登记决策，在 `03` 写契约，在 `04` 写验收，再认领 `active-tasks/` 的独占文件。
6. 完成后更新 `02`/`07` 的真实事实和验证记录，并保留回滚方式。
