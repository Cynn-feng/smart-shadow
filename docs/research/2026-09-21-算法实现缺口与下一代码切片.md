# 算法实现缺口与下一代码切片审计

更新时间：2026-09-21（Asia/Shanghai）
审计范围：`aigc/`、`eval/`、`tests/` 当前离线切片，及 `docs/06-AIGC算法创新调研.md`、`docs/09-主要创新点与可证伪主张.md` 中的 AIGC 主张。
状态：研究输入；本报告没有修改算法代码、`aigc_result_v1` 或线上接口。

## 1. 审计结论

当前仓库最值得继续实现的内容不是再增加一个 CLIP、FFT、SRM 或生成器分类器，而是把已经提出的来源条件协议变成一条可被真实数据证伪的闭环：

> **冻结授权的 `reference → query → ordinary-propagation counterfactual`，实际重放检索候选、membership、传播树归属和选择策略，再把已绑定的局部干预效应交给 RSCPTN/PC-SCFT，最后按普通传播误报、错误参考、开放集和成本做分层对照。**

这条切片同时检验“是否真的解决 AIGC 局部编辑误报”和“是否只是增加拒判”。目前代码已经能保存 raw statistic 和 fail-closed route，但还没有真实检索输入、真实编辑 mask、真实 null profile、实际候选生成器或效果指标。因此当前可称为**离线证据契约**，不能称为 AIGC detector、概率、选择后 coverage 保证或已经证实的算法创新。

## 2. 当前实现的事实盘点

| 组件 | 已有证据 | 仍缺的关键能力 | 结论边界 |
| --- | --- | --- | --- |
| `aigc/real_image_runner.py` | 可在私有根目录读取有 SHA-256 和授权元数据的三元组，完成解码、配准、无重量 `SourceResidualAdapter`、区域 delta、PC-SCFT 和无 profile 时 `insufficient` | 没有真实独立 null profile 的拟合流程，没有编辑 mask/`edit_type` 的评测接线，没有检索和树事件 | 只证明输入审计和 raw 回放；当前 adapter 的 `weights=none` 不是 AIGC 模型 |
| `aigc/manifest.py` | 校验身份、授权、路径、字节哈希、三元角色、split 和父哈希声明 | `edit_mask`、`edit_type`、`parent_sha256` 的字节真实性、操作参数和 C2PA/水印状态没有形成强校验；只验证样本文件哈希 | 不能从 manifest 的 `origin` 或 `generator_family` 推出标签正确 |
| `aigc/retrieval_aware_tree_null.py` | RSCPTN 双 raw gate、split/asset 泄漏门、membership 污染拒判、unknown/poisoning route 和 digest；输入输出契约有专测 | 候选集是调用者预先给出的；没有实际 retrieval/index snapshot、membership 判定、selection replay、candidate-set recall/precision 或攻击注入 | `p_tree_raw`、`p_retrieval_raw`、`p_joint_raw` 都是 raw rank/gate，不能写成概率或 coverage |
| RSCPTN tree binding | 有 `parent_version_id`、`tree_id`、`branch_id`、`depth` 和 unresolved-parent 检查 | 没有校验 parent 是否同 asset/tree、depth 是否一致、是否成环；跨树同名 parent 可能被视为已解析 | 当前“树级”主要是事件级 max statistic，不能宣称新的树算法 |
| RSCPTN contamination | `poisoning_stress_route`、`poisoning_route_flip`、membership tier 等字段被保留 | 污染状态主要由调用者自声明，不是由冻结 archive、注入清单和 before/after replay 计算 | synthetic poisoning case 只能证明拒判分支存在 |
| 证据完整性 | 各对象有 `input_digest`、`evidence_digest`、policy/config digest 字段 | 候选的 `input_digest/evidence_digest` 并未由图像、检索快照或局部证据重算，存在“合法格式、伪造内容”的差距 | digest 字段本身不是证据可信性 |
| `eval/retrieval_aware_tree_null_eval.py` | 9 个 scalar case 覆盖 candidate、ordinary propagation、wrong reference、tie、poisoning、unknown、leakage、outside | 没有图片、检索索引、真实 tree、ROI mask、FPR、risk@coverage、P95、人工分钟或跨时间评测 | runner 是 contract regression，不是算法效果实验 |
| 统一入口 | 本研究初始记录为 330 个测试、36 个合成/契约 runner；当前入口已扩展为 342 个测试、37 个 runner，ALG-001 已完成离线契约 | 重量模型、真实授权 manifest、真实 retrieval archive、外部时间窗、链上/部署均未验证 | 轻量验证只覆盖源码、确定性和 fail-closed |

## 3. 最重要的缺口

### 3.1 事件重放缺失：当前 RSCPTN 不是端到端 retrieval-aware

`RetrievalEvent` 接收已经排序的 `candidates`、membership、tree 和 `paired_delta_raw`。模块只检查这些字段是否绑定，并没有执行：

1. 从固定 index snapshot 生成 top-K 候选；
2. 将候选与登记资产做 exact/matched/uncertain/outside membership 判定；
3. 依据父哈希、版本记录和 provenance 解析传播树；
4. 在固定 action budget 下选择 reference/version/local region；
5. 对 clean、missing、false-positive、planted near-duplicate 和 poisoning 做同策略 placebo 重放。

因此当前 RSCPTN 与“外部先给一份干净候选表，再做 max statistic”仍然很接近。下一切片必须保存**候选生成前的快照和完整选择轨迹**，否则无法验证文档中最窄的创新主张。

### 3.2 真实图片 runner 与研究矩阵尚未接通

`RealImageRunner` 的真实路径目前只消费 source residual；它不会消费 `edit_mask`，也不会把 `generator_family`、`postprocess_chain`、`c2pa_status` 变成分层指标。没有独立 ordinary-propagation profile 时，它按设计返回 `calibration_unavailable`，所以当前合成 fixture 不能证明局部编辑检出。

建议先完成 G0–G6 的真实数据闭环，再决定是否加入重量模型。若直接先训练新 detector，可能只改善 IID/closed-set，而无法回答当前项目最关键的问题：普通传播和参考误配是否被误报为 AIGC。

### 3.3 manifest 的标注和权限粒度不足以支撑 ROI/开放集结论

文档要求 `edit_mask`、`edit_type`、编辑步骤、质量、生成器/时间和 provenance 状态，但 `REAL_REQUIRED_FIELDS` 没有强制这些字段；文件校验也只核对 `sample_path` 的 SHA-256。当前 runner 能够在没有真实 mask 的情况下生成区域 raw evidence，这适合作为工程 fallback，却不适合报告 ROI IoU、Dice、boundary-F 或编辑类型 F1。

### 3.4 统计独立性和支持量尚未达到“校准”语义

RSCPTN 的 tree 与 retrieval statistics 来自同一批 calibration events，数值还可能高度相关；`max(p_tree_raw, p_retrieval_raw)` 只能是保守 raw gate。它没有 selection-conditional coverage 或 FDR 的理论证明。`minimum_profile_support=8` 仅够跑契约，远不足以为每个 `selection_key × transform × quality × time` 分层估计稳定误报率。真实实验支持量不足时应只报告 rank、拒判率和区间，不输出概率或保证。

### 3.5 误报威胁模型仍没有落到可计算的对照

当前切片没有将以下样本与真正局部 AI 编辑逐一配对：普通 JPEG/resize/crop/截图/再拍摄、相似但错误的 reference、同源 decoy、语义边界/天空/文字区域、未知生成器、下一时间窗和 provenance×watermark 冲突。没有这些对照，任何 raw candidate 都可能只是质量、边界或检索错误的影子。

## 4. 推荐的下一代码切片（优先级）

### P0：RSCPTN 实际事件桥接与 G0–G3 评测入口

建议暂定为 `ALG-001`，阶段 7 离线研究，不接线上。

**目标**：将一个冻结的真实/私有 research manifest 和一个冻结 retrieval archive 转成可回放 `RetrievalEvent`，并把已存在的 PC-SCFT/MPCF/SAEC raw sidecar 接到事件上。

**建议文件范围**：

- 新增 `aigc/retrieval_event_replay.py`：读取候选快照、selection policy、membership evidence 和版本边，生成候选事件；禁止从最终人工挑选列表反推事件；
- 收紧 `aigc/retrieval_aware_tree_null.py`：校验 parent 同 `asset_id/tree_id`、无环、depth/branch 一致；将 `selection_trace_digest`、candidate snapshot digest、membership decision digest 绑定到 event；
- 扩展 `aigc/manifest.py` 或增加独立研究 manifest adapter：校验 `edit_mask_digest/edit_type/edit_steps`、mask 文件哈希、transform spec、删除/授权期限和 split；不改变现有线上 manifest；
- 新增 `eval/real_retrieval_event_eval.py`：对 calibration/evaluation 资产做清晰的 archive replay，输出 candidate recall/precision、tree reconstruction failure、route flip、ordinary-propagation FPR、reference false-match 和 unknown/review；
- 新增 `tests/test_retrieval_event_replay.py`，并补 RSCPTN 的 parent 跨树、cycle、伪造 digest、候选快照替换、selection split 泄漏和 archive 版本漂移测试。

**输入契约**：

```text
research_manifest_digest
asset/sample/pair/role/parent_sha256/transform_spec_digest
edit_mask_digest + edit_type + edit_steps（局部编辑样本必需）
authorization_id/scope/expiry/deletion_owner
retrieval_archive_digest/index_digest/query_digest/top_k/rank
membership_policy_digest + per-candidate decision evidence
tree_edge_digest/parent-child/version/branch/depth
selection_policy_digest + ordered action trace + action budget
detector/schema/operator/config/profile digest
split = calibration | evaluation | external
```

**输出契约**：只输出 event、raw statistic、route、reason、完整 digest 和 replay audit；禁止 `aigc_probability`、`confidence`、`human_supported`、作者、版权或法律字段。找不到真实 parent、mask、archive 或授权时固定 `insufficient`/`open_set_unknown`/`retrieval_contaminated_review`。

**验收**：

1. 同一 manifest/archive 重放两次结果和 digest 相同；
2. 替换候选 snapshot、rank、membership、parent 或 action 顺序一定改变 binding 或拒判；
3. 同一 asset/tree 不得跨 calibration/evaluation；calibration 与 evaluation 不得共享 selection group；
4. clean、missing、false-positive、planted near-duplicate、wrong-reference、ordinary propagation、unknown generator、next-time-window 各有独立 fixture；
5. RSCPTN 完整事件相对 query-only/SCPTN/SAEC/QuAD-like 的指标入口可运行，但在无真实数据时只打印 `not evaluated`，不伪造效果。

### P1：真实授权 PC-SCFT/MPCF 对照矩阵

在 P0 能生成可信事件后，扩展现有 `eval/pc_scft_real_image_eval.py`，不重写 detector：

- 至少构造互不重复的 calibration、development、evaluation、external asset group；
- 每个 evaluation asset 配置同传播族 ordinary null、授权局部 edit mask、随机/相似 decoy、wrong-reference；
- 按 `generator_family × edit_type × transform_family × quality_bucket × time_bucket` 报告 ordinary-propagation FPR、reference false-match、risk@coverage、unknown/review、ROI IoU/Dice/boundary-F、route flip、P50/P95、每千张成本和人工复核分钟；
- 对照固定为 query-only、SourceResidual、PC-SCFT、MPCF、SAEC、SCPTN、RSCPTN，并有去 null、去 tree、去 decoy、去 retrieval replay 消融；
- 真实支持量不足时只报告 raw evidence、拒判和区间，不能调宽阈值来填满结果表。

### P2：重量 detector 或 generator-family 适配

只有 P1 显示 source-conditioned null 在相同 coverage 和预算下仍有误报/召回瓶颈，才进入 `model_adapter.py` 的重量模型 adapter。优先做可替换的 residual/spectral/patch baseline 和 open-set profile，保存模型、预处理、许可、校准集和回滚 digest。若新模型只提升 closed-set AUROC，或在普通传播、未见生成器、下一时间窗、P95、成本或人工分钟上变差，应保留为诊断 sidecar，不升级创新主张。

## 6. 容易误报的地方和必须保留的拒判

1. **普通传播造成的残差**：JPEG、resize、截图、再拍摄和神经压缩都可能让 `paired_delta_raw` 变大；没有同传播族 null 不能升级 candidate。
2. **配准/坐标帧误差**：reference、query、counterfactual 的 alignment 偏移会制造局部边缘热点；任何 region set、frame 或 transform digest 不一致必须 `insufficient`。
3. **错误 reference 或语义 decoy**：相似图不等于来源原件；candidate 必须通过 blind decoy/reference-specificity 和 selection split。
4. **树误归属与 top-K winner's curse**：同树节点重复计数、父节点缺失或从多个候选挑最大值会放大统计量；必须以 event/tree 为单位并保留 tie/contamination。
5. **内容和边界捷径**：天空、文字、背景、物体边缘以及质量桶变化可能激活残差；要求 `region_type`、mask-out/region-swap 和 semantic-boundary controls。
6. **未知生成器与新时间窗**：未知不是人类创作；只能 `open_set_unknown`/`review`，且 profile 不得把 evaluation generator 混入校准。
7. **provenance/watermark 冲突**：有效、缺失、篡改或被移除的信号只属于独立证据层；冲突固定人工复核，不能覆盖视觉 raw evidence。
8. **拒判率虚假改善**：降低 FPR 但 coverage、ROI、人工成本或 P95 显著恶化时，不能称算法改进；必须报告等 coverage/等 action budget 对照。

## 7. 研究主张、成功门与撤回条件

P0 切片可以使用的表述是：**“实现了来源条件的检索—版本选择事件回放和普通传播 null 的 raw evidence 协议，待真实数据验证。”** 在以下条件全部满足前，不得写“解决 AIGC”或“已证实创新”：

- 同一冻结授权 manifest 上，RSCPTN 相对 query-only、QuAD-like、SCPTN、SAEC 和去 retrieval/tree/null 消融，在相同 coverage 与 action budget 下改善 ordinary-propagation FPR 或 reference false-match；
- 未见生成器、下一时间窗和复杂传播下错误升级不增加，unknown/review 的上升能由人工复核成本或证据完整率抵消；
- 有真实 edit mask 时，ROI/边界指标不低于预注册 margin；没有 mask 的样本只能做 raw/review；
- 证据包能在删除、恢复、索引版本变更后成功回放，字段完整率和人工复核分钟达到预注册门；
- 任何收益不能只来自把困难样本全部转成 `unknown`，也不能只来自 synthetic fixture。

应撤回为 `retrieval/provenance audit sidecar` 的情形：

- 只有 clean closed-set 或 IID 数据改善；
- 完整 retrieval replay 与已清洗候选列表没有差异；
- RSCPTN 只比基线更保守，等 coverage 下没有 FPR、false-match、ROI 或人工成本收益；
- parent/tree/digest 仍能被自声明字段伪造，或独立污染 profile 无法重放；
- P95、存储、动作预算和人工复核成本超过业务收益；
- 真实数据支持不足，只能依赖合成统计。
