# 2026-09-20 Smart Shadow 商业化深度刷新

更新时间：2026-09-20
状态：外部一手资料核验与可证伪商业假设；不是客户、收入、SLA、合规认证或项目效果报告。

## 1. 这轮研究要回答什么

Smart Shadow 已经有数字作品登记、版本关系、相似检索和 AIGC 取证研究切片。本轮不再问“还能不能再加一个检测模型”，而问四个可执行问题：

1. 哪些能力已有强替代，不能作为单独卖点；
2. 哪些工作流有明确的合规、投诉、供稿或媒资触发；
3. 哪个产品切口可以嵌入既有 MAM/DAM，而不要求客户更换主系统；
4. 什么数据和指标能在 30/60/90 天内证明值得续费。

外部资料只支持“市场触发、替代品能力、标准字段和试点设计”。`F` 表示一手事实，`I` 表示基于事实的产品推断，`P` 表示只有客户试点、运行日志或书面采购路径才能成立的命题。

## 2. 已经被官方产品覆盖的能力

### 2.1 单图 AIGC 检测已有可采购替代

[腾讯云图片 AI 生成识别文档](https://cloud.tencent.com/document/product/1124/135204)公开了页面和 API 两种用法，输入限制、批量上限以及 `Block / Review / Pass` 三档结果；[腾讯云 AI 生成识别解决方案](https://cloud.tencent.cn/solution/aigc-detector)还覆盖图片、文本、音频三个模态。**F**：客户不需要为了得到一个三档单图结果而采购 Smart Shadow。**I**：Smart Shadow 的 detector 必须是可替换 adapter，价值应放在原件/版本绑定、冲突复核、可回放证据和业务责任链。**P**：只有在同一客户资产集上减少复核分钟或补齐审计字段，才有商业价值。

### 2.2 通用以图搜图和版权图检索已有规模化替代

[腾讯云图像搜索](https://cloud.tencent.com/product/imagesearch)支持用户自建图库中相同/相似图检索，并明确列出裁剪、翻转、调色、加水印等变换；[阿里云图像搜索产品页](https://ai.aliyun.com/imagesearch)列出版权图片搜索、拼接、加 logo、翻转、局部、色彩变换等场景，并把百亿级检索和毫秒级响应作为产品能力；[阿里云计费页](https://help.aliyun.com/zh/image-search/product-overview/billing)公开了容量/QPS 套餐，例如 10 万张、1 QPS 档的月度价格为人民币 980 元（页面价格可能随地区、促销和时间变化）。**F**：基础检索有成熟云替代和透明价格锚点。**I**：Smart Shadow 不应按“每张图相似度 API”竞争；应把相似命中挂到版本图、权限、标识冲突和人工证据包。

### 2.3 企业 DAM/MAM 已覆盖资产库、工作流和权限

[Adobe Experience Manager Assets](https://business.adobe.com/products/experience-manager/assets.html)把集中资产库、AI 标签、版本/重复检测、权限、合规和跨渠道分发放在一个企业 DAM；[Bynder 官方产品/价格页](https://dev.bynder.com/en/pricing/)公开了 AI 搜索、使用权控制、工作流和按组织定制报价；[Aprimo DAM](https://enable.aprimo.com/explore-aprimo/digital-asset-management)强调元数据、权限、版本、权利管理和人机协同；[Cloudinary 视频 DAM](https://cloudinary.com/products/digital_asset_management/dam-video)覆盖视频生命周期、AI 标签、版本比较、交付和协作。**F**：替换 DAM 主系统的竞争门槛很高，且客户已有系统记录。**I**：首单应是跨供应商 `provenance/version/evidence sidecar` 和人工复核工作台，提供 API、批处理和导出，不要求迁移主库。**P**：客户是否愿意接入由真实字段缺口、复核耗时和现有系统 API 限制决定，不能由厂商页面推断。

### 2.4 来源凭证是开放标准生态，不是项目独占能力

[C2PA 2.4 技术规范](https://spec.c2pa.org/specifications/specifications/2.4/specs/C2PA_Specification.html)记录了 `AI disclosure`、`repository receipt` 和 `crJSON` 等能力，并明确 `crJSON` 是 C2PA 数据的派生视图，不是独立可验证输入；[C2PA Content Credentials 页面](https://spec.c2pa.org/specifications/specifications/2.4/specs/ContentCredentials.html)定义了签名、manifest、硬/软绑定和来源历史；[IPTC Photo Metadata 2025.1](https://www.iptc.org/std/photometadata/specification/IPTC-PhotoMetadata-2025.1.html)继续维护作者、版权、许可和描述等广泛支持的照片元数据。**F**：解析、展示和写入标准本身会被相机、编辑器、DAM 和云服务覆盖。**I**：Smart Shadow 的可售能力应是多标准适配、冲突诊断、版本关系、权限/删除回放和审计报告；`signature_valid` 不应直接映射为“真实”“人类创作”或“版权归属”。

## 3. 监管与合规触发：为什么买“可审计工作流”

### 3.1 中国：生成和传播都需要可核验的标识链

[《人工智能生成合成内容标识办法》](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)规定显式与隐式标识、生成服务导出时保留显式标识、在文件元数据中添加隐式标识，以及传播服务核验元数据、用户声明和生成痕迹；办法自 2025-09-01 施行。**F**：这形成了“生成—导出—传播—复核”的字段和责任链，且恶意删除、篡改、伪造、隐匿标识被明确禁止。**I**：P0 可以做指定法域、指定内容类型和指定导出路径的标识体检/冲突队列，保存 parser、规则、输入 digest、处置人和回放结果。**P**：客户是否付费取决于其整改日期、责任人、失败处置和上线流程，不是法规文本本身。

### 3.2 欧盟：透明度义务使导出链和报告版本变成验收对象

[欧盟委员会 AI Act 官方页面](https://digital-strategy.ec.europa.eu/en/policies/regulatory-framework-ai)说明生成式 AI 提供者要使生成内容可识别，深度伪造等内容需要清晰可见地标注，透明度规则自 2026-08-02 适用，并强调风险管理、日志、文档、人类监督和鲁棒性。**F**：跨境发布会涉及角色、内容类型和适用时间点。**I**：产品应把法域、规则版本、导入/导出路径和人工决定作为报告字段；不要提供“全球合规”开关。**P**：每个客户需要自行确认其角色、市场和业务场景；Smart Shadow 不能以解析结果代替法律意见。

### 3.3 美国版权政策：来源、披露和训练许可仍是持续议题

[美国版权局 AI 研究页面](https://www.copyright.gov/ai/)与[AI 经济影响报告](https://www.copyright.gov/economic-research/economic-implications-of-ai/)把 AI 生成内容、训练数据、透明披露和版权政策的经济影响列为持续研究范围。**F**：政策讨论并不等于统一的侵权判定接口。**I**：训练数据许可/撤回审计可作为 P1，前提是客户已有版本化 manifest、排除规则和删除责任人。**P**：近邻检索只能提供线索，不得写成“证明模型训练使用了某张图片”。

## 4. 竞争替代矩阵与避让边界

| 客户需求 | 现成替代 | Smart Shadow 不应承诺 | 可留下的增量 | 进入条件 |
| --- | --- | --- | --- | --- |
| 单图 AIGC 三档检测 | 腾讯云内容安全、其他内容安全 API | 通用准确率、作者身份、法律结论 | 原件条件下的局部 evidence、unknown/review、证据回放 | 客户授权原件和 ordinary-propagation null |
| 自建图库相似检索 | 阿里云/腾讯云图像搜索、现有 DAM | 百亿规模、毫秒 SLA、全网监测 | 版本图、字段冲突、权限和人工处置链 | 客户已有库和版本 manifest |
| 资产管理与分发 | Adobe AEM、Bynder、Aprimo、Cloudinary | 替换 DAM、迁移全量媒体、品牌工作流全覆盖 | 旁路 sidecar、跨供应商证据 schema、只读审计 | 现有系统 API 和字段缺口确认 |
| 来源凭证解析 | C2PA 工具、Adobe/平台内置 viewer | 签名即真实/版权、官方认证 | 多来源 parser、冲突/缺失分类、manifest/receipt 回放 | 指定标准版本与信任模型 |
| 训练数据许可盘点 | 客户法务/数据治理、厂商自建目录 | 自动证明训练侵权 | manifest diff、排除/撤回回放、责任队列 | 两个版本 manifest 和删除责任人 |
| 投诉/案件材料 | 人工法务、律所和版权代理 | 自动下架、自动胜诉、司法采信 | 只读可回放 evidence package、审计日志 | 角色隔离、留存与导出规则 |

最小可辩护商业差异是“把异构来源、版本、标识、相似候选和人工决定串成可回放的证据对象”。这是产品推断，不是市场已验证壁垒；如果客户只需要一个检测分数，应优先复用云 API 而非自建 Smart Shadow。

## 5. 最适合的客户与购买链

### 5.1 P0：已有私有图库的品牌、电商、MCN、图片库

触发包括供稿审核、发布前检查、素材重复/过期、版权投诉或版本追责。买方组合通常不是单一算法负责人：媒资/版权负责人提出问题，内容运营负责日常复核，IT/安全审查部署与权限，法务确认报告边界，采购确认预算。最小交付是旁路导入、候选版本关系、标识/字段冲突和人工队列。

### 5.2 P0 条件进入：AIGC 内容平台和企业内容中台

适合已有发布网关、内容审核或模型生成服务的客户。切口是“标识保留与冲突体检 + 证据包”，先与既有审核并行，不改变发布决定。没有明确整改日期、内容类型和责任人时，不把法规兴趣当成交机会。

### 5.3 P1：媒体/高校/政企本地部署

客户更看重国产化、离线部署、审计日志、权限和数据不出域。部署前必须通过阶段 1–5 的身份、上传、恢复、依赖和 readiness 门；项目当前 Go、MySQL、IPFS、Faiss、ChainMaker 和部署链路未完成验证，因此只能把本地化写成目标交付形态。

### 5.4 P1/P2：训练数据许可、版权代理和律所

这类客户的证据责任和销售周期更长。只有在客户拥有版本化许可清单、排除/撤回流程和指定复核人时进入；相似检索与来源图只能帮助整理材料，不自动给出侵权或训练使用结论。

## 6. 推荐产品包与收费实验

### 6.1 产品包

| 产品包 | 交付 | 主要收费单位（待验证） | 价值假设 | 当前状态 |
| --- | --- | --- | --- | --- |
| `Evidence Sidecar` | API/批处理接入现有 DAM，解析凭证、绑定原件/版本、输出 evidence JSON 和冲突队列 | 租户 + 资产/版本量 + 保留期 | 减少人工找原件、找字段和整理报告时间 | P0 研究假设 |
| `Review Workbench` | 候选、局部 raw evidence、人工确认、导出审计包、权限和删除回放 | 复核席位 + 资产量 + 私有实例 | 减少误报复核分钟并提高报告一次通过率 | P0 研究假设 |
| `Governance Audit` | 标识/规则版本、manifest diff、排除/撤回和跨导出路径回放 | 规则包 + 批次/报告量 | 让整改和审计有可复现记录 | P1 研究假设 |
| `Authorized Monitoring` | 经授权的站内/渠道采集、候选去重和人工案件队列 | 渠道数 + 抓取/审查量 | 扩大投诉发现范围 | P2，需平台授权和成本验证 |

不要按“每张图的 AIGC 概率”定价。阿里云图搜的公开价格已经给出基础检索的低价锚点，Smart Shadow 的可收费对象应是集成、版本图、审计/复核和责任闭环。

### 6.2 价格实验，不把假设写成报价

首轮只做三个互斥报价实验，每个客户只选一个主包，避免把折扣混成价值证据：

1. **按量 sidecar**：按导入资产/版本、证据保留天数和 API 调用量计费；观察每千资产边际成本和复核分钟；
2. **工作台订阅**：按复核席位、月活任务和报告导出计费；观察每周重复使用和席位扩展；
3. **私有部署/项目制**：一次性接入与数据映射费，加年度维护；观察部署周期、升级责任和客户是否愿意续维。

每次报价必须同时记录客户原流程人工分钟、系统运行成本、未知/冲突复核分钟、证据包采纳率、预算负责人和下一周期预算路径。公开厂商价格只能作为替代成本参考，不能直接换算 Smart Shadow 报价。

### 6.3 ROI 公式和最小计量

对批次 `N`，基线每件人工时间 `t_base`，系统自动阶段时间 `t_system`，未知/冲突复核时间 `t_unknown`，客户认可的人工成本 `c_min`，运行与集成成本 `C_run`：

```text
net_value = N * max(0, t_base - t_system - t_unknown) / 60 * c_min
            + evidence_value_accepted
            - C_run
```

`evidence_value_accepted` 只能计入客户书面认可或实际进入投诉/审计/许可流程的价值；不能把论文指标、检测分数或登记量当成收入。至少记录：`N`、基线/系统/未知分钟、候选 Recall@K、ordinary-propagation FPR、证据字段完整率、指定回放成功率、跨租户越权、假成功、P50/P95、每千件成本和周活跃复核人次。

## 7. 30/60/90 天试点与停止门

### D0–30：资格与安全沙箱

- 只选一个法域、一个内容类型、一个真实触发；冻结授权原件、传播版本、删除/恢复责任人和报告 schema；
- 先跑离线导入和回放，不改变发布、下架、发函或诉讼决定；
- 硬门：未授权样本为 0、跨租户越权为 0、失败不返回成功、删除/恢复责任清楚、输入/输出 digest 可重放；
- 任一硬门失败，回滚到 fixture，停止商业演示外推。

### D31–60：只读 shadow mode

- 至少 500 个授权原件和 1,000 个传播/版本样本（数量是试点设计假设，不是市场事实）；
- 运行四周，与人工流程并行，不自动改变业务处置；
- 每周复盘：人工总分钟、unknown/review 占比、候选 Recall@K、hard-negative FPR、证据包字段缺口、P50/P95、每千件成本；
- 继续门：指定人员每周重复使用，至少一个工作流的净人工分钟下降，证据包能被内部流程回放；
- 停止门：误报使人工量上升、unknown 被强行改写为 AI/人类、回放失败、客户无明确责任人或净价值为负。

### D61–90：有限购买决定

- 连续四周固定范围运行，业务、IT/安全、法务/版权和采购共同复盘；
- 记录书面预算路径、续用范围、数据删除/退出责任、升级/支持责任和单位成本；
- 继续门：至少一个工作流被重复采用，证据实际进入审计/投诉/许可流程，并出现下一周期预算或采购路径；
- 停止门：只有演示命中，没有重复任务或预算负责人；任何授权、恢复、错误语义问题重复出现。

起始阈值（可撤销假设）可设为证据字段完整率 ≥98%、指定证据回放 ≥99%、证据包一次通过率 ≥80%，并要求四周人工复核总分钟下降、净价值为正。它们不是 Smart Shadow 当前 SLA。

## 9. 算法创新如何转成商业可验证的优势

基础 detector 会快速同质化，因此算法路线应服务于证据工作流，形成以下可检验闭环：

1. **来源条件化**：登记原件/版本作为查询上下文；没有原件时显式回退到开放集或 `unknown`，不伪造同等置信度；
2. **普通传播 null**：对裁剪、压缩、缩放、调色、水印等同传播族变换建立独立 null，优先压低普通传播误报；
3. **匹配 intervention**：同坐标、同 mask、同质量和同传播族比较 observed/counterfactual/placebo，减少边界伪影把任意差异冒充 AI 编辑；
4. **盲选 reference/decoy**：先测试原件是否特异，再解释局部差异，避免 reference 误配；
5. **选择性拒判**：把未知生成器、冲突、质量不足和支持不足保留为 `unknown/review/insufficient`，用 risk@coverage、unknown recall 和人工复核分钟评价；
6. **证据可回放**：保存 manifest、profile/config digest、mask/operator、控制集、解析器版本和人工决策，供客户审计和算法迭代。

真实数据中需要比较 ONMA-only、GAPL-like prototype、LIDA-like retrieval、当前 source-conditioned 协议和人工基线；报告 ordinary-propagation FPR、selective risk@coverage、ROI/faithfulness、family flip、未知回召、P50/P95、每千件成本和复核分钟。只有在真实授权 manifest 上减少错误复核并保持可拒判，才可把算法收益升级为产品卖点。

## 10. 事实、推断、假设和禁止外推

| 类型 | 本轮结论 | 证据/验证要求 |
| --- | --- | --- |
| `F` | C2PA、IPTC、云图搜、云检测和企业 DAM 已覆盖大量基础能力 | 官方标准/产品页；不等于 Smart Shadow 已接入 |

| `I` | 以 sidecar、证据包和人工复核切入比替换 DAM 或单卖 detector 更可行 | 需客户访谈、现有系统 API 和 shadow 数据 |
