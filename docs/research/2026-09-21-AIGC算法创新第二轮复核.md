# 2026-09-21 AIGC 算法创新第二轮复核

更新时间：2026-09-21（Asia/Shanghai）
证据范围：2025–2026 年正式会议论文、会议官方页面、作者代码/数据页面、arXiv 预印本和正式期刊页面。
用途：为 Smart Shadow 选择下一轮可证伪的算法切片；本文件不改变线上接口、`aigc_result_v1` 或核心决策，也不证明本项目效果、概率、部署或法律结论。

## 1. 结论先行

本轮复核得到四个结论：

1. **“训练更大的 AIGC detector”仍不能解决项目问题。** AIGIBench 在 23 个 fake 子集和真实社交/AI 平台样本上报告了受控数据到真实数据的明显跌落；SAFE、RRBench、NTIRE 2026 又把局部编辑、社会传播、再数字化和未知生成器列为独立困难。DoU、SACG、single-class attribution、RAW–RGB、phase spectrum 和 RGB/NPR 等工作说明模型表征仍在快速进步，但它们处理的是被动检测泛化，不是登记原件、传播来源或候选选择的可信性。
2. **RSCPTN 的大部分零件已有先例，完整事件协议仍未被单篇工作覆盖。** QuAD/AncesTree 覆盖近重复检索、质量聚合和传播树；LIDA 把生成器归因做成检索；PADHASH 和 Collisio 证明检索数据库可能被投毒；JOMI、CAP、Online Selective Conformal 和 e-value 工作覆盖一般选择后/自适应校准；RADAR、DICE、RITA、SAFE 覆盖局部编辑检测、定位和步骤。RSCPTN 只能主张“登记原件 + ordinary-propagation tree null + 完整 retrieval→membership→tree→selection 的 placebo replay + fail-closed”，不能称新 detector、新树结构或新共形理论。
3. **下一步最有价值的是审计选择和混淆来源。** 推荐先做独立索引/证据 holdout（SIPA），再做来源资产与生成器指纹的双注册库分离（DRCS），最后才研究支持自适应 probe 的 e-process（CEAT）。三者都是协议增量，必须与 RSCPTN、SAEC、SAEA 做同预算、同 manifest 的消融。
4. **真实创新的判定标准是选择性风险和复核收益。** 只有在同一授权数据上降低 ordinary-propagation FPR、错误 reference 命中、投毒 route flip 或人工复核分钟，同时保持局部编辑召回和未知/时间下一窗的拒判质量，才可讨论研究增量。若收益只来自更高 `unknown/review`，应退回 provenance/retrieval audit sidecar。

## 3. 对 RSCPTN 的独立判断

### 3.1 已被覆盖的部分

- **传播树与近重复质量聚合**：QuAD/AncesTree 使树、质量桶、近重复聚合和野外退化不再是空白。
- **局部编辑和开放集**：RADAR、OpenSDI、DICE、SAFE、RITA 已覆盖局部编辑、定位、真实传播或多步操作；RSCPTN 不应再训练一个同类 patch detector。
- **检索式归因**：LIDA 说明检索可以用于生成器来源归因；因此“用检索做来源”本身不构成新意。
- **选择后校准**：JOMI、CAP、Online Selective Conformal 和 e-value 先例覆盖一般理论；RSCPTN 的 `p_tree_raw`/`p_retrieval_raw` 不能直接叫 selection-conditional guarantee。
- **数据库污染威胁**：PADHASH 与 Collisio 说明缺失 near-duplicate、错误候选、植入样本和语义稳定投毒应成为 threat model，而非只做干净图库实验。

### 3.2 仍可辩护但尚未验证的窄差异

> 在有登记原件和同传播族 ordinary-propagation null 的条件下，不把检索结果当作固定输入；让 ordinary-propagation placebo 经过与真实 query 完全相同的 `retrieval → membership → tree → version/reference selection → local evidence selection`，并以独立树级 null 与独立检索事件 null 同时约束 raw route。

这是**来源条件、检索事件级的证据审计协议**。它不是新的 detector、树结构、检索器、投毒防御或共形理论。要保留该主张，真实实验必须在同一候选预算和人工复核预算下对照：query-only、QuAD-like、SCPTN、D-054、SAEC、SAEA/fixed A9、RSCPTN 去检索 replay、RSCPTN 去 tree null 和完整 RSCPTN。

### 3.3 RSCPTN 的额外风险

1. 两路 `p` 值可能共享检索或 detector 伪影，`max` 只是一项保守 raw gate，不能写成联合概率或定理。
2. 如果检索 archive 已经清洗掉漏召回、误召回和 poisoned candidate，再跑 placebo 无法验证检索污染。
3. 如果 tree profile 只按节点而不按 asset/group 校准，会把传播树相关样本当成独立样本。
4. 如果提高 `unknown/review` 是唯一收益，RSCPTN 只是更严格的人工队列过滤器，不是 detector 创新。

## 4. 推荐的三个新可证伪切片

以下方向均为研究候选，不直接改接口。命名用于文档和实验，不代表批准的 API 或四态结果。

### 4.1 P0：SIPA-v1（Split-Index Provenance Audit）

**研究问题**：候选 reference 是否只因为在同一个检索索引中被挑成 winner，而表现出局部异常？如果在候选选择后使用一个未参与选择的独立 index/evidence holdout 复核，是否能在相同候选 coverage 下减少错误 reference 和检索投毒造成的 route flip？

**协议**：

```text
selection archive/index A
  → fixed retrieval policy π_A
  → candidate reference + tree/membership selection
  → freeze candidate and selection digest

independent audit archive/index B
  → no re-selection; candidate is fixed
  → independent query view / embedding or operator / held-out propagation view
  → source-conditioned local contrast + ordinary-null check
  → holdout_consistent | holdout_disagreement | missing_holdout | insufficient
```

`B` 必须在选择前冻结，至少满足以下两个独立性条件中的两个：不同 archive snapshot 或时间窗、不同 feature/index build、不同 query view/operator；同一 asset/group 不得同时成为 calibration 与 evaluation。若 B 缺少候选、传播族支持或独立 null，固定 `missing_holdout/insufficient`，不能退回 A 的高分。

**最小 sidecar 字段**：

```text
query_digest, candidate_reference_digest, selection_index_digest,
audit_index_digest, selection_policy_digest, audit_policy_digest,
selection_split_digest, calibration_split_digest, evaluation_split_digest,
candidate_membership_tier, candidate_rank_A, candidate_rank_B?,
tree_shape_A, tree_shape_B?, ordinary_null_profile_digest,
observed_contrast_A, observed_contrast_B,
holdout_route, retrieval_missing_reason, poisoning_stress_route_flip
```

`candidate_rank_B` 仅记录审计信息，B 不重新选择 winner；结果禁止 `probability`、作者、版权和法律字段。

**同预算对照**：

| 对照 | 目的 |
|---|---|
| query-only / 历史比赛版 | 估计没有 source 条件和 holdout 时的基线 |
| D-054 + SAEC | 隔离 blind decoy 与 scalar selection calibration 的贡献 |
| SCPTN / RSCPTN | 区分 tree/retrieval placebo 与 holdout 审计的贡献 |
| SIPA only | 检验独立 audit 是否已足够 |
| RSCPTN + SIPA | 检验两种独立性约束的互补性 |
| 去掉 B、换同一 index、泄漏 B 到 selection | 证伪独立 holdout 的必要性 |

必须注入 clean/missing/false-positive/planted near-duplicate/poisoned retrieval、ordinary propagation、wrong reference、unknown generator 和 next-time-window。主要指标是 ordinary-propagation FPR、reference false-match、poisoning route flip、candidate coverage、unknown/review、risk@coverage、ROI/边界 F、P50/P95、索引存储和每千件成本。

**为什么不是已有 RSCPTN 的重复**：RSCPTN 以同一策略在 placebo 上重放选择事件；SIPA 再加一个**选择后不参与 winner 选择的独立审计证据分区**。如果实现只是用两个模型对同一个候选重复打分，不能称 SIPA；必须验证 selection/audit 分区、候选冻结和泄漏检测。

**撤回条件**：

- 固定 candidate coverage 后，SIPA 不降低 ordinary-propagation FPR、false-match 或 poisoning route flip；
- 收益完全来自大量 `missing_holdout/unknown`，接受样本风险不降；
- B 的样本、特征或 operator 在选择阶段泄漏，或独立性无法审计；
- holdout 延迟、索引成本和人工复核增加超过客户门；
- 只在已知生成器/IID 样本改善，时间下一窗或传播后失效。

### 4.2 P1：DRCS-v1（Dual-Registry Confounder Separation）

**研究问题**：局部 evidence 真的来自“这个登记原件的局部编辑”，还是仅仅来自某个生成器家族、编码器、风格或内容语义的共同伪影？LIDA 等工作表明生成器指纹可以通过检索归因；如果 Smart Shadow 只保留一个 reference registry，可能把 generator evidence 误写成 source evidence。

**协议**：维护两个互不混用的 registry：

1. `asset_registry`：登记原件、传播版本、ordinary-propagation null、授权和版本关系；
2. `generator_registry`：已知生成器/编辑工具、质量/传播桶、real-only profile 和 generator fingerprint prototype。

对 query 同时计算：

```text
C_source = source/query/local intervention contrast
C_generator = generator-family or real-only fingerprint evidence
C_null = ordinary-propagation matched null evidence
```

只有 `C_source` 在 `C_null` 和 blind decoy/wrong-reference 门后仍成立，且 `C_generator` 不能单独解释该区域效应，才进入 `source_conditioned_candidate`；若生成器证据强而 source contrast 不特异，进入 `generator_confounded_review`；两路均无支持或 profile 外，进入 `open_set_unknown`。这是冲突路由，不是把两个分数平均。

**必要 controls**：

- 同一 generator、不同 asset/reference 的 matched negatives；
- 同一 asset、ordinary-propagation 但不同 generator/编码器的 null；
- 同语义内容、不同 generator 的 cross-generator controls；
- wrong-reference/盲 decoy 和无原件 unknown generator；
- 去掉 generator registry、去掉 source registry、只保留单 registry 的消融。

**指标**：source false-match、generator-confounded review rate、ordinary-propagation FPR、unknown recall、route flip、局部 ROI/边界 F、risk@coverage、人工复核分钟和 P95。必须按 generator family、quality、transform、time 和 source-match 分层报告支持数。

**先例边界**：LIDA、OpenSDI、SACG、DoU 和 real-only 工作覆盖 generator attribution/open-set；DRCS 的窄主张只是把 generator evidence 作为**混淆控制变量和冲突路由**，不声称新的归因模型或因果识别。`C_source - C_generator` 不能被解释为因果效应。

**撤回条件**：

- 同 generator 的无关 asset 仍大量通过 source candidate，或去掉 generator registry 没有变化；
- 只提升 closed-set generator attribution，不降低 source false-match/人工分钟；
- generator profile support 不足却通过 global fallback 强行升级；
- generator conflict 被压成 AI/human 二分类，或 unknown 率下降但 selective risk 上升。

### 4.3 P2：CEAT-v1（Cross-Fitted E-value Audit Trail）

**研究问题**：SAEA 允许按失败原因选择下一项 probe，但普通 p-rank/max-statistic 在自适应停止、重复视角和 action budget 变化下容易被重新选择。能否在独立 ordinary-propagation null 上预先学习每个 action 的 e-value factor，用 cross-fitting 形成可回放 e-process，使“继续取证、提前停止、预算耗尽”不会改变 raw false-positive gate？

**协议草案**：

1. 将每一个 probe（decoy、ordinary null、view、operator、re-align）定义为带输入/输出 digest 的 action；
2. 在与 evaluation asset/group 隔离的 ordinary-propagation calibration stream 上拟合 action-specific nonnegative factor `e_t`，要求 null 下的期望不超过 1；
3. 每步只消费当时可用的 action，不重新使用 evaluation 结果调参；通过 cross-fitting 或预注册 profile 生成 `E_t = E_{t-1} × e_t`，预算/停止只影响观察长度；
4. `E_t` 只进入 `evidence_supported`/`review`/`insufficient` raw route，不输出 p-value 以外的概率或 coverage theorem，除非后续完成严格理论审计。

**必须承认的理论边界**：JOMI、CAP、Online Selective Conformal 和 2025 e-value 论文已经覆盖选择后、online pick、e-prediction 和 optional stopping 的一般理论。Smart Shadow 不主张新 e-value 理论；最多检验“source-conditioned matched local effect 是否能在这些已知统计工具下作为稳定的 action-level evidence”。若 ordinary-propagation stream 不是交换/可控依赖，不能声称 finite-sample validity。

**对照与指标**：SAEA fixed-order、SAEA adaptive p-rank、CEAT fixed-order、CEAT adaptive、无 null、无 cross-fit；覆盖 ordinary propagation、local edit、wrong reference、poisoning、unknown generator、next-time-window。报告 ordinary-propagation FPR、risk@coverage、unknown/review、route flip、停止步数、action cost、P50/P95 和人工复核分钟；同时做 optional-stopping 和 probe-order 红队。

**撤回条件**：

- action-level e-profile 不能在独立 null 上保持预注册门，或依赖 evaluation 样本调参；
- CEAT 只增加拒判而不降低接受样本风险/人工分钟；
- 依赖假设无法在传播树相关样本上说明，或结果只在 IID synthetic trace 成立；
- 额外状态、计算和存储成本超过 SAEA，且没有可测的风险/复核收益。

## 5. 推荐优先级与最小执行顺序

| 优先级 | 切片 | 先决条件 | 最小首个动作 | 通过门 |
|---|---|---|---|---|
| P0 | SIPA | 已有 RSCPTN/SAEC raw sidecar；可构造两个冻结 index/evidence archive | 先做无重量 contract：候选冻结、B 不重选、missing/泄漏 fail-closed、poisoning route flip | 同预算下比 RSCPTN 降低 false-match/FPR 或 route flip，且 coverage 不由拒判塌缩 |
| P1 | DRCS | 有 generator family/real-only profile 和至少一组同 generator 不同 source 的 controls | 先写 dual-registry manifest 和冲突路由；不训练新 detector | source false-match 和 generator-confounded review 可分离，unknown 不被压低 |
| P2 | CEAT | SAEA 有真实 action trace、独立 null stream 和统计评审人 | 先做数学/模拟审计，不接线上；验证 optional stopping、action order、group dependence | 独立 null 下 raw gate 可回放，且同预算 risk/人工成本优于 SAEA |

推荐实际顺序：

```text
RSCPTN contract review
  → SIPA contract + poisoning/selection leakage fixture
  → same-manifest SIPA/RSCPTN/SAEC/SAEA ablation
  → DRCS dual-registry controls
  → only after real action traces: CEAT statistical prototype
```

任何一步没有授权 manifest、独立 ordinary-propagation null、生成器/时间切分、编辑 mask 或人工基线时，只能输出 raw evidence、`review` 或 `insufficient`。不得把合成 runner 的 p-value、e-value、route digest、ROI 或 AUROC 写成真实 AIGC 效果。

## 7. 不应再使用的表述

- “Smart Shadow 已解决 AIGC”或“可准确区分 AI/人类”；
- “RSCPTN 是新的传播树算法/共形理论”；
- “检索到生成器样本即可证明 query 来源于该登记原件”；
- “`p_tree_raw`、`p_retrieval_raw`、e-value 或 route digest 是 AIGC 概率”；
- “C2PA/水印缺失证明人类创作，阳性证明作者或版权”；
- “合成传播/投毒 fixture 已证明真实平台鲁棒性”；
- “接受样本 coverage 下降而 unknown 上升就是效果提升”。

可使用的限定表述是：

> Smart Shadow 正在研究一种 source-conditioned selective local-edit evidence protocol。它以登记原件和 ordinary-propagation null 为条件，把检索、版本选择、局部干预和拒判作为可回放事件；SIPA、DRCS、CEAT 是待证伪的后续审计切片。当前证据仅到源码/契约/synthetic 层，真实授权数据和客户价值尚未验证。

## 8. 来源清单（核验日：2026-09-21）

除上表所列正式论文外，本轮特别使用以下一手来源审计威胁模型和统计边界：

- [Clean Image May be Dangerous: Data Poisoning Attacks Against Deep Hashing，arXiv 2503.21236 / TMM 2025](https://arxiv.org/abs/2503.21236)：干净 query 也可能因数据库/训练集投毒触发恶意检索，说明 retrieval candidate integrity 必须进入 null 与红队。
- [Image Provenance Analysis via Graph Encoding With Vision Transformer，IEEE TIFS 2025](https://ieeexplore.ieee.org/document/10969789/)：来源图和关系结构已经有端到端学习先例，Smart Shadow 不能把 version-DAG 本身称作新图算法。
- [Attribution as Retrieval: Model-Agnostic AI-Generated Image Attribution，CVPR 2026](https://openaccess.thecvf.com/content/CVPR2026/html/Wang_Attribution_as_Retrieval_Model-Agnostic_AI-Generated_Image_Attribution_CVPR2026_paper.html)：生成器归因的检索范式已有公开先例，资产来源检索必须和 generator attribution 分离。
- [Conformal e-prediction，Pattern Recognition 2025](https://doi.org/10.1016/j.patcog.2025.111674) 与 [E-Values Expand the Scope of Conformal Prediction，arXiv 2503.13050](https://arxiv.org/abs/2503.13050)：e-value、cross-conformal 和 anytime-valid 是已有统计工具；CEAT 不能声称新理论。
- [AI-generated Image Detection: Passive or Watermark?，CVPR 2026 Workshop](https://openaccess.thecvf.com/content/CVPR2026W/SAFE/html/Guo_AI-generated_Image_Detection_Passive_or_Watermark_CVPRW_2026_paper.html) 与 [Watermarking Autoregressive Image Generation，NeurIPS 2025](https://proceedings.neurips.cc/paper_files/paper/2025/hash/67cef321196556c4f1e17989ed7a8adb-Abstract-Conference.html)：主动 watermark 与被动 detector 都要分开记录适用范围、攻击和缺失状态。
- [From Detection to Audit: EvidenceSPOTL，CVPR 2026 Workshop](https://openaccess.thecvf.com/content/CVPR2026W/PPMisDet/html/Matsukura_From_Detection_to_Audit_Deterministic_WhereWhen_OoC_Verification_with_EvidenceSPOTL_CVPRW_2026_paper.html)：可审计、确定性、证据不足即 abstain 的工程思想可以迁移到 evidence sidecar，但该工作不证明 AIGC 检测能力。
