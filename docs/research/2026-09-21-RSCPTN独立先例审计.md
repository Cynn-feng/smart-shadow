# RSCPTN 独立先例审计

更新时间：2026-09-21（Asia/Shanghai）
审计范围：2024–2026 年正式会议论文、JMLR/TMLR/OpenReview、官方论文页、C2PA 官方规范和公开攻击研究。
用途：独立检查 `RSCPTN-v1`（Retrieval- and Selection-Calibrated Source-Conditioned Propagation-Tree Null）的重合风险，并把仍然可辩护的主张收敛为可证伪的真实实验。
状态：研究输入；未修改代码、`aigc_result_v1`、核心决策记录或线上服务。本文的“未找到完整组合”不是专利新颖性结论，也不是穷尽式文献检索证明。

## 1. 结论

RSCPTN 的核心问题是合理的，但目前不能把它描述为“新的 AIGC detector”“新的传播树算法”或“新的 conformal 理论”。2024–2026 年的先例已经分别覆盖了 RSCPTN 的绝大多数组件：

- QuAD/AncesTree 已把近重复检索、退化树、质量估计和多版本分数聚合用于野外 AIGC 检测；
- image phylogeny/near-duplicate 工作已经把版本关系组织成树或图；
- RADAR、OpenSDI、DICE、RITA、X-AIGD 等已覆盖局部扩散编辑检测、定位、真实场景、多步编辑或可解释证据；
- JOMI、CAP 和 Online Selective Conformal Inference 已覆盖选择后校准、selection-conditional coverage 和在线选择错误；
- 深度哈希检索投毒、语义水印伪造和 provenance/watermark 冲突工作已经说明候选集合与来源信号本身可能被污染。

因此，RSCPTN 仅有一个较窄且目前尚未验证的可辩护差异：

> 在有登记原件和同传播族 ordinary-propagation null 的场景，把“检索候选生成 → membership/树归属 → reference/version 选择 → 局部证据选择”作为同一个可回放事件，用独立 placebo **端到端重放**检索选择过程，并把树级相关性与检索污染同时作为拒判条件。

这个差异是**来源条件证据协议和评测设计的组合主张**，不是单个模型组件。只有在真实授权数据上相对于 QuAD-like 聚合、SCPTN、SAEC、SAEA 和检索 oracle 的等预算对照中，RSCPTN 同时降低 ordinary-propagation FPR、wrong-reference/false-match、poisoning route flip 或人工复核时间，且在未见生成器和下一时间窗保持，才有资格称为研究增量。若收益只来自更多 `unknown/review`，应退回 provenance/retrieval audit sidecar。

## 3. RSCPTN 与先例的重合审计

### 3.1 分解到最小组件

| RSCPTN 组件 | 已有先例覆盖度 | 当前重合风险 | 可保留的表述 |
| --- | --- | --- | --- |
| 近重复检索 | 很高（QuAD、通用 image phylogeny、检索投毒研究） | 把“检索候选”写成算法创新 | “候选生成的可审计输入” |
| 版本树/传播树 | 高（AncesTree、image phylogeny） | 把树拓扑或深度字段写成新结构 | “树级统计单位，防止相关节点重复计数” |
| quality-aware aggregation | 很高（QuAD） | 把质量加权或多版本融合写成新方法 | “作为 baseline，或作为 RSCPTN 的固定输入条件” |
| 局部 residual/patch/ROI | 很高（RADAR、DICE、OpenSDI、RITA、X-AIGD） | 再做一个 detector/heatmap | “消费已验证的 raw local effect，不重新发明 detector” |
| max statistic/winner selection | 高（SAEC、JOMI、CAP） | 把最大值校准或 conformal 术语写成原创理论 | “应用层 selection event 重放” |
| 普通传播 null | 中高（RRBench/NTIRE/QuAD 有传播和退化，但不完全是 source-conditioned） | 仅做 JPEG/crop/null 变换便称创新 | “登记原件条件下的 matched ordinary-propagation null” |
| retrieval event replay | 中（检索投毒研究说明必要性，未见完整相同 forensic 组合） | 未证明整个文献没有同类 protocol | 暂可称“待验证的 retrieval-selection audit protocol” |
| 双 null gate (`max(p_tree,p_retrieval)`) | 未找到完全相同应用组合；理论部件已有选择后校准 | 把双门写成统计保证或新的 conformal method | “保守 raw gate；待真实验证，不是概率” |
| fail-closed `unknown/review` | 高（DACOM、EvidenceSPOTL、选择性检测方向） | 把拒判状态名称写成创新 | “产品可靠性/审计边界” |

### 3.2 目前可辩护的最小主张

可暂时保留以下研究主张：

1. **事件单位不同**：不是先取已经清洗好的 near-duplicate 集合，而是把 retrieval policy、candidate membership、tree assignment、reference selection 和 local evidence budget 作为同一事件，令 ordinary-propagation placebo 完整重放。
2. **来源条件不同**：候选的局部差异只有在登记原件、query 和同传播族 counterfactual 绑定时才有意义；没有原件或只有视觉近重复时进入 `open_set_unknown`，不强行升级。
3. **相关性单位不同**：树内相关版本以 tree/event 为统计单位，避免把一个传播树拆成多个独立样本。
4. **污染是结果的一部分**：漏召回、错误 membership、wrong-reference 和 planted near-duplicate 不是实验外的异常，而是 route/拒判需要报告的失败模式。

这些主张组合了已有部件，仍不等于已证明创新。必须明确写作“来源条件、检索事件级的待验证证据校准协议”。

### 3.3 必须撤回的主张

- “RSCPTN 是新的通用 AIGC detector”；
- “传播树结构或近重复检索是本项目首创”；
- “`p_tree_raw`/`p_retrieval_raw` 是 AIGC 概率、置信度或人类创作概率”；
- “双 null 已获得 selection-conditional coverage/FCR 保证”；
- “检索污染被解决”“能抵抗所有 poisoning/对抗攻击”；
- “未知生成器被识别”或“`open_set_unknown` 等于人类创作”；
- “C2PA/watermark 冲突自动判定为伪造、侵权或作者身份”。

## 4. 仍可继续探索、但必须先做先例审计的方向

### 4.1 检索污染的部分识别和证据上下界（优先级 P0）

研究问题：当真实 parent 可能漏召回、候选集中存在 uncertain/wrong-reference、或检索库被植入近重复时，能否输出在明确污染预算下的**局部 effect 下界/上界**，而不是未经证明的单一概率？

可辩护差异不在“上下界”这个统计词本身，而在把 bounds 绑定到：

```text
登记原件 + ordinary-propagation tree + retrieval candidate snapshot
       + membership uncertainty + decoy/poisoning stress + matched intervention
```

最小输出应是 `effect_lower_raw`、`effect_upper_raw`、`contamination_budget_raw`、`bound_support` 和 `reason_codes`。在候选缺失或预算超限时返回 `retrieval_contaminated_review`/`open_set_unknown`。需要另外审计 partial identification、sensitivity analysis 和 robust conformal 先例；未完成前不要称理论创新。

### 4.2 Source-conditioned adversarial red-team（优先级 P0）

用登记原件和 ordinary null 生成“忠实但逃逸”的局部编辑、wrong-reference、quality-matched decoy 和 planted near-duplicate，测试 RSCPTN 是否因候选集合或树结构而失效。SPARED 和 deep-hashing poisoning 说明静态数据集与干净 retrieval 假设不足。

该方向的可辩护贡献是**协议盲点的可重复压力测试**，不是“攻击生成器本身”。每种攻击必须保存输入 digest、攻击预算、目标 candidate rank、route flip 和是否仍符合 declared edit mask；不把攻击成功率变成真实世界风险概率。

### 4.3 检索候选一致性与版本责任图（优先级 P1）

在不改变 detector 的前提下，对候选之间的 source/quality/transform/parent 一致性做独立 sidecar：候选排序、来源证据、变换链和 C2PA/watermark 状态若冲突，强制 `review`。这更接近产品可交付的 evidence workbench；算法新颖性弱于真实数据质量和人工效率。

### 4.4 跨时间窗的校准漂移与删除回放（优先级 P1）

将 calibration profile、retrieval index snapshot、删除/恢复事件、模型版本和 manifest digest 绑定，验证下一时间窗、生成器更新、图库删除和恢复后是否仍能回放。动态 conformal 已有先例，因此贡献应放在客户可审计的 provenance/version lifecycle，而不是新的在线理论。

### 4.5 不建议立即重启的方向

- 再加一个 CLIP/FFT/SRM/entropy detector：已有 RADAR、MLEP、WaRPAD、ConV 等先例，不能解决 source/retrieval contamination。
- 单独做 generator-family classifier：OpenSDI、GAPL/RealStats 等已覆盖开放集/归因；未知输入仍应拒判。
- 单独做水印/C2PA verifier：标准和攻击先例成熟，项目应做冲突和审计适配器。
- 把 SAEA/A9 的主动 probe 数量增加当成算法创新：采证策略需要与同预算 FPR/risk/cost 对照。

## 5. 最小真实实验：先证伪 RSCPTN，再决定是否编码扩大

### 5.1 数据和授权门

下列是建议的**最小 pilot**，不是已完成的数据要求；论文级实验应扩大支持量。

| 项目 | 最小 pilot 建议 | 硬门 |
| --- | --- | --- |
| 登记原件 | 至少 60 个互不重复的授权资产；按 asset/group 分为 calibration、development、evaluation 三组，每组至少 20 个；实际 profile 分层后若支持不足则 `insufficient` | `authorization_id/scope/expiry`、删除责任人、文件 SHA-256、隐私最小化和可回放 manifest 齐全 |
| ordinary propagation | 每个原件至少 4 个可回放后代，覆盖 JPEG/resize/crop/blur/截图模拟中的至少 3 类；形成独立 propagation tree | 同一 asset/tree 不得跨 split；父哈希、transform spec、输出哈希和质量桶齐全 |
| 局部编辑 | 每个 evaluation asset 至少 1 个真实授权局部编辑和人工/生成器 edit mask；至少 2 类编辑器或编辑机制 | mask 与 observed/query 绑定；没有 mask 只能 raw/review，不能报告 ROI 效果 |
| 参考误配 | 每个 query 至少 2 个 blind decoy/wrong-reference，其中 1 个质量/传播匹配、1 个语义近但来源错误 | decoy 选择在 evaluation 前冻结；不得用 query 标签调参 |
| 检索快照 | 同一确定性 retrieval policy 记录 candidate set、rank、embedding/index digest、K、membership policy 和查询时间 | 需要保留召回前候选快照；只保存最终人工挑选列表不合格 |
| 开放集/时间 | 至少 1 个未见生成器或编辑器族、1 个下一时间窗/新传播 profile | 未知输入必须能单独计数，不回退为 real/human |
| provenance 信号 | C2PA/水印存在、缺失、无效和冲突样本各一小组 | 标识状态为独立 adapter，不能覆盖视觉 raw evidence |

60 个资产只足以打通协议和暴露失败模式；若要估计分层 FPR，建议每个主要 `selection_key × transform_family × quality_bucket` 至少有 50–100 个独立 null events。不能达到该支持量时，应只报告 raw rank、置信区间和拒判率，不报告稳定 operating point。

### 5.2 冻结的对照组

必须在同一 retrieval snapshot、同一 detector/schema、同一动作成本预算和同一 split 上比较：

1. **Query-only baseline**：只对 query 评分，不使用来源/树；
2. **QuAD-like baseline**：近重复质量感知聚合，但不做 source-conditioned paired null；
3. **SCPTN**：已知传播树上的树级 ordinary-propagation null，不重放检索事件；
4. **SAEC**：参考/decoy winner selection 后的选择感知 scalar 校准；
5. **SAEA/fixed-order acquisition**：同一 action budget 下追加 probe；
6. **Retrieval-oracle**：给出人工验证的完整 candidate set，测检索缺失造成的上限差；
7. **RSCPTN-v1**：完整 retrieval → membership → tree → selection → dual-null replay；
8. **Ablation**：去 `p_retrieval_raw`、去 tree、去 source binding、去 decoy stress、只保留更多拒判。

如果 RSCPTN 只优于 query-only 而不优于 SCPTN/SAEC/QuAD-like，说明增量主要来自已有组件；如果只通过降低 coverage 获得更低 FPR，不能称为改善。

### 5.3 必须注入的污染场景

每种污染应作为单独 evaluation slice，不能混成一张平均表：

- **漏召回**：删除真实 near-duplicate/parent，记录 retrieval recall@K 和 route；
- **误召回**：注入视觉相似但错误 asset 的 candidate，记录 wrong-reference rate；
- **质量错配**：让 decoy 与真实版本质量/传播深度匹配，避免简单质量阈值解决；
- **planted near-duplicate**：将恶意近重复插入 top-K，记录 route flip、candidate rank 和人工复核；
- **树误归属**：合并错误 parent、断裂 branch 或引入 unknown node；
- **局部编辑/普通传播混淆**：相同 crop/resize/JPEG 链同时生成有 mask 与无 mask 版本；
- **未知生成器/编辑器**：evaluation 中不出现在 detector 或 calibration 的生成器/编辑器；
- **新时间窗**：冻结旧 profile 后评估新平台、新压缩或新模型；
- **provenance 冲突**：有效/缺失/篡改 C2PA 与 watermark 组合，验证是否固定 `review/unknown`。

### 5.4 指标和最低报告集

主结果不能只报 AUROC。每个 slice 至少报告：

| 指标 | 目的 | 解释边界 |
| --- | --- | --- |
| ordinary-propagation FPR | 测普通传播误报 | 必须按 tree/event 统计，不能把同树节点当 IID |
| reference false-match rate | 测检索/参考误配 | 需要 blind decoy 和人工确认 |
| retrieval recall@K / candidate precision@K | 测候选生成质量 | 是检索指标，不是 AIGC 准确率 |
| route flip under poisoning | 测候选污染敏感性 | 只针对预注册攻击预算，不外推所有攻击 |
| risk@coverage、AURC、unknown/review rate | 测选择性拒判 | `unknown` 上升可能代表更保守，必须与 FPR/人工成本联合解释 |
| ROI pixel AP/F1、mIoU、boundary-F、mask faithfulness | 测局部证据 | 只在有真实 mask 的局部编辑集报告 |
| generator/time/transport 分层 FPR、unknown recall | 测开放集/漂移 | 不得把 closed-set top-1 当未知泛化 |
| P50/P95 延迟、每千张成本、动作次数 | 测部署代价 | 记录 detector、检索、存储和人工复核分项成本 |
| 人工复核分钟、一次通过率、重复复核次数 | 测真实工作流价值 | 需要客户或盲法证复核基线，不能用合成数字代替 |
| evidence replay success / missing-field rate | 测证据包可审计性 | 必须验证删除、恢复、版本回放 |

### 5.5 建议的预注册成功/停止门

下列是可撤销的实验建议，不是行业标准：

- 在**相同 coverage、相同动作预算**下，RSCPTN 相对于 SCPTN+SAEC/QuAD-like 使 ordinary-propagation FPR 或 false-match 至少相对下降 20%；
- poisoning stress 下 route flip 和错误升级率下降，同时不把所有困难样本简单改为 `unknown`；
- 局部编辑集 ROI/边界 F 相对最强 detector baseline 不降低超过预注册 margin（例如 2 个百分点）；
- 未见生成器和下一时间窗保持保守：unknown/review 可上升，但错误 candidate escalation 不上升；
- P95 和每千张成本不超过现有工作流可接受预算，人工复核分钟或重复复核次数有可测下降；
- 证据包字段完整率、重放成功率和删除/恢复回放达到客户预先约定的硬门。

若收益只来自 coverage 大幅下降、额外动作预算或人工先验挑选 candidate，停止算法主张，保留为审计 sidecar。所有阈值和 margin 应在锁定 manifest 后再注册，不能看完 evaluation 结果再选择。

## 6. 商业相关性：RSCPTN 应卖什么结果

RSCPTN 的商业价值不应写成“提高 AIGC 准确率”，而应验证它是否减少私有图库/DAM/MAM 的错误升级和重复复核。首客假设仍是拥有授权图库、版本链和内容审核流程的机构；公开竞品和政策只能证明需求触发，不能证明客户、收入或采购。

### 6.1 直接可售的工作流结果

1. **候选可信度审计**：审核员能看到 candidate rank、membership reason、tree shape、ordinary-null 对照和污染原因，知道为什么需要复核。
2. **版本/来源证据包**：把原件、query、传播后代、检索快照、C2PA/水印状态、模型 raw evidence、人工意见和 profile digest 一起导出。
3. **低误报复核队列**：普通传播和质量变化不应重复进入局部 AI 编辑队列；不确定样本应单独进入 `unknown/review`。
4. **可回放的删除/恢复**：客户删除或恢复某版本、索引或 manifest 后，能够证明旧结论是否受影响。

### 6.2 首轮 shadow mode 指标

四周只读试点应至少记录：

| 指标 | 业务问题 |
| --- | --- |
| 版本绑定正确率、candidate precision@K、false-match rate | 系统是否把真正相关版本放到复核前面 |
| ordinary-propagation false escalation | 压缩/截图/裁剪是否被误报为局部 AI 编辑 |
| unknown/review 占比和人工采纳率 | 审核员是否接受保守拒判 |
| 上传到人工决定的 P50/P95、每千张人工分钟 | 是否减少审核时间和重复劳动 |
| 证据包一次通过率、缺字段率、补录分钟 | 报告是否能进入内部审计/投诉流程 |
| retrieval/index/manifest 一致率、删除恢复回放成功率 | 数据治理和版本生命周期是否可控 |
| P50/P95 API 与检索延迟、每千张成本 | 是否能在客户预算内运行 |
| 每周活跃复核人、实际复核任务、复用/续用意愿 | 是否形成稳定工作流，而不是一次演示命中 |

商业试点中应同时保留客户原人工流程基线和系统组日志。若系统只减少了“显示结果”的时间，却增加了核验、补录或争议处理时间，不应把它记为 ROI。`unknown`、失败重试和人工升级的计量规则要在试点前冻结。

### 6.3 与算法结论隔离

- RSCPTN raw route 不是客户的法律结论、版权确权或作者判断；
- C2PA/watermark 通过、缺失或冲突不替代视觉 evidence，也不证明人类创作；
- 低 false-match 不能外推全网监测召回；
- 试点工作流的人工分钟和证据包采纳率不能反向证明算法跨生成器准确率；
- 没有客户授权 manifest、人工基线和权限/删除责任人时，只做离线 fixture，不进入真实 shadow。

## 7. 进入代码前的门与建议

1. 将本审计和既有 `2026-09-21-检索污染感知传播树选择校准.md` 一起提交 D-063 评审，明确 RSCPTN 是应用协议候选，不是新的 detector 或 conformal theorem。
2. 先完成 prior-art 对照表和实验预注册，再决定是否新增 `aigc/retrieval_aware_tree_null.py`；不先写接口和 route。
3. 若批准代码切片，新增模块只能消费已有 source/query/null sidecar，不能改写 D-050–D-062 结果对象或线上接口。
4. 先做 retrieval snapshot、membership uncertainty、tree integrity 和 poisoning stress 的 contract runner；没有真实 manifest 时固定 `insufficient`/`open_set_unknown`。
5. 真实数据阶段按 G0–G6：授权、普通传播 null、局部编辑 mask、开放集/误配、分层 FPR/漂移/成本、对照消融、证据包复核/部署门逐项记录。
6. 若最小真实实验未同时改善 FPR/false-match、selective risk 和人工成本，停止把 RSCPTN 写成算法创新，保留为 provenance/retrieval audit sidecar。

## 8. 来源索引与不可外推边界

本文引用的一手来源用于先例和实验约束。它们不能证明 Smart Shadow 已取得同样效果，也不能替代项目自己的授权 manifest、独立 null profile、模型版本、运行日志或客户验收。

| 来源类别 | 主要来源 | 仅可支持的结论 |
| --- | --- | --- |
| 近重复/树 | QuAD/AncesTree、image phylogeny | 近重复质量聚合和树形关系已有研究；需要做 source/retrieval selection 对照 |
| 真实传播 | RRBench、AIGIBench、NTIRE 2026 | 静态/干净数据会高估泛化；必须分层传播、时间、生成器和质量 |
| 局部编辑 | RADAR、OpenSDI、DICE、RITA、X-AIGD | detector/定位/解释已有先例；Smart Shadow 不能把 patch/heatmap 本身称创新 |
| 选择校准 | JOMI、CAP、Online Selective Conformal、Online Conformal Optimization | selection event 和相关序列需要独立校准；没有自动授予 RSCPTN 理论保证 |
| 检索/来源攻击 | deep hashing poisoning、WMCopier、watermark forgery、Authenticated Contradictions | candidate/provenance 信号可被污染；必须做冲突和 stress 审计 |
| 规范 | C2PA 2.4 | provenance 是独立证据通道；凭证状态不等于内容真实性或法律结论 |

截至本审计，没有检索到一篇一手论文把“登记原件条件 paired local intervention + ordinary-propagation tree null + retrieval candidate poisoning/membership + selection replay + fail-closed unknown”五项完整组合为同一图像取证协议；这是检索到的研究空白线索，而不是完整新颖性证明。所有对外、论文或专利表述必须等真实 G0–G6 证据完成后再决定。
