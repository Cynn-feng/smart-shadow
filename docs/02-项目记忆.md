## 1. 项目阶段

项目已经完成原有比赛展示，当前目标从“证明有一个演示闭环”转为“建设可复现、可审计、可持续迭代的数字作品存证与风险筛查系统”。比赛版代码和 README 仍保留在仓库中，后续开发以本目录的当前决策和技术方案为准。

## 2. 当前产品定位

当前定位：**数字作品来源与版本的链上存证、视觉语义相似检索和侵权风险筛查原型**。

产品输出是存证记录、候选相似作品和风险提示，最终判断需要人工核验。系统不自动认定法律上的作品所有权、侵权责任或 AIGC 事实。

## 3. 当前源码已经实现的能力

- `super_algo.py` 将图片划分为全图、四象限和中心区域，使用 CLIP 提取六组视觉向量。
- `ai_server.py` 将六组向量按 512 维分片写入本地 Faiss，并按 CID 保存映射；查询时逐片搜索。
- `server.go` 将 AI 分析、IPFS CID、ChainMaker 合约调用、MySQL 历史和 Faiss 入库串联起来。
- `contract/main.go` 提供 `save_evidence` 和 `query_evidence`，以 CID 作为状态键，拒绝重复写入并发送事件。
- `templates/dashboard.html` 提供作品登记、相似图片扫描和作品历史三个主要页面流程。

这些能力说明了源码链路存在，不等于当前 checkout 已经完成运行、部署或效果验证。

## 4. 已确认的技术事实

- 当前特征是六组 512 维向量，拼接后长度为 3072；“六维”是六个区域视图，不是六维数学空间。
- 当前 Faiss 索引是 `IndexFlatIP` 精确平坦内积检索，不是 ANN。
- 当前接口只接收图片；没有文本编码、文本检索或外部网站抓取，因此不能称为已经实现的跨模态检索或全网监测。
- YOLO 只产生主体展示标签，不参与版权向量和相似度计算。
- 当前合约记录包含 CID、向量 JSON、备注和应用时间，没有 owner、调用者身份或特征摘要。
- 业务交易使用配置中的后端证书，客户端提交的用户名不等于链上发送者。

## 6. 当前主要风险

1. 登录只返回用户名，业务接口信任客户端 `username`，没有服务端会话和资源归属隔离。
2. AI HTTP、JSON、向量和 Faiss 写入错误没有被完整阻断，可能把失败结果当作正常结果。
3. 链、MySQL、Faiss、IPFS 没有统一状态机和补偿机制，可能出现半成功状态。
4. 上传文件使用原始文件名，前端把备注等字段拼入 HTML，存在文件覆盖和 XSS 风险。
5. 当前 README 的跨模态、ANN、精准抗裁剪、链上 owner 等表述超过了源码证据。

## 8. 2026-09-20 市场和算法调研结论

- 商业首个切入点暂定为有自有图库的电商、品牌、图片库、MCN、设计机构，以及需要 AIGC 标识审计的内容平台；产品形态是私有图库证据工作台、B2B API 和私有化部署。
- 直接竞争已有腾讯云、阿里云、版权监测和数字水印产品，因此“CLIP + 区块链”本身不构成壁垒；差异化方向是来源证据、局部可解释匹配、人工复核、国产链/国标适配和真实传播评测。
- 国家版权局公布的 2025 年作品著作权登记为 749.4 万件，其中美术和摄影约占 87.3%；这是需求规模信号，不是 Smart Shadow 的市场份额或收入证明。2026-09-14 发布的《人工智能安全治理框架 3.0》可作为审计、容错、追溯和恢复设计的治理参考。
- AIGC 研究主线是来源感知的开放集证据融合。C2PA/GB 标识、水印、区域语义、低层伪影、可选重建、生成器归因必须分层保存；缺失、冲突、未知生成器和模型失败都进入 `unknown_or_inconclusive`。
- 暂定研究假设是 Source-Conditioned AIGC Edit Forensics：先检索已登记原件，再对齐区域并分析差异，输出局部 AI 编辑候选 ROI；只有完成数据、消融和外部测试后才能称为算法创新。
- 详细证据和限制见 `docs/05-市场与商业化调研.md`、`docs/06-AIGC算法创新调研.md`；当前仍没有 AIGC 效果、商业收入或部署能力的验证。
- 商业排序已进一步收敛为 P0“来源/标识合规网关 + 私有图库来源与版本证据工作台”，P1“来源条件的局部 AIGC 编辑取证 API”，P1/P2“训练数据来源/许可审计”，P2“深度伪造证据”；基础图搜对标云厂商，不作为单独壁垒。最高法 2026-09 人工智能纠纷意见强化了训练来源、参与过程、必要措施和获利等证据字段要求，但客户、收入和付费意愿仍未验证。
